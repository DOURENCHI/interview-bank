# CareerOS · 求职功能台

> 原名「面试题库 / Interview Bank」。已从静态题库升级为个人求职工作台：
> `content/` 仍是唯一内容源，`dist/bank.html` 是编译产出的单文件离线页。
> 网页顶部标题、六视图与数据口径见 `docs/architecture.md`。

**定位：软硬件协同的 AI 系统工程师**

技术主线 `C++ / Linux + AI 推理部署 + 软硬件系统集成`。以推理部署为切入点，以 C++/Linux 工程能力为核心竞争力，以 ROS2、嵌入式和汽车电子作为系统集成能力。

面向自动驾驶、具身智能、智能硬件行业求职，2029 年目标年总包 40 万以上。

**岗位偏好链**：`SDK 开发 > 系统集成 > 推理部署 > 算法研发 > 电子硬件开发`

> 题库不是八股合集。每一道题尽量挂到自己的项目或文档上——这是和"背题库的人"拉开差距的地方。

## 二、模块与优先级

优先级依据三年规划的分阶段任务（2026 补基础 → 2027 做工程 → 2028 拿实习 → 2029 就业），以及"三条执行原则"：**C++/Linux/算法是基础不能降投入**、**AI 部署是现有优势要深化**、**ROS2 与硬件是差异化**。

| 模块 | 目录 | 优先级 | 理由 |
|---|---|---|---|
| 项目深挖 | `content/project` | **P0** | 面试官最有兴趣、最容易追问、也最难造假。**按项目分子方向**：YOLO 部署 / 二维云台 / 西门子杯 / Linux 日志分析 / 跟骨分割 / 本科毕设。**全部人工出题，每题配手写 SVG 插图**，题干带实测数据 |
| C++ | `content/cpp` | **P0** | 就业基础，与项目同步练。**子方向**：语言基础 / 对象模型 / STL 容器 / 时间与算法 / Qt / **工程化与 SDK**（动态库、ABI、接口设计，对应岗位偏好链第一位的 SDK 岗）；已吸收原 Linux 考点的系统与进程 / 并发 / 网络编程（Linux 系统编程与调试并入此处） |
| 算法与机考 | `content/algo` | **P0** | 校招笔试硬门槛。**ACM 模式读写在 2026 年内就要解决** |
| 模型部署 | `content/deploy` | **P0** | 现有优势，要继续深化而不是重做入门项目 |
| ROS2 | `content/ros2` | **P1** | 差异化方向，靠小车项目产出（建图→导航→点云） |
| 机器人学 | `content/robot` | **P1** | 机器人软件 / 系统集成岗位（Momenta、ABB、追觅） |
| 硬件嵌入式 | `content/hardware` | **P1** | 本科护城河；**含汽车电子**（CAN / CAN FD / ECU / 实时系统）；已吸收原 Linux 考点的内核与驱动 |
| 医学影像 | `content/imaging` | **P1** | 科研主线，也是医疗设备方向（联影 / 迈瑞 / 西门子医疗）的落点 |

| Python | `content/python` | **P1** | 训练脚本、数据处理、工具链的日常语言。**子方向**：语言机制 / 数据结构 / 迭代器与生成器 / 并发与 GIL / 异常与资源 / 性能与工程。机考里的 Python 读程序题在 `algo`，这里只讲语言与工程机制 |
| 后端基础 | `content/backend` | **P2** | Java/后端八股（27 届秋招博主面经），拓宽岗位面 |
| Agent 应用 | `content/agent` | **P2** | Agent/检索/LLM 应用面试题（27 届 AI 全栈方向新增考察项） |
| 场景系统设计 | `content/scene` | **P2** | 场景系统设计题方法论 + 实例（27 届秋招新考察项） |

## 三、三个核心项目（简历竞争力）

题库里的"项目深挖"模块就是围绕这三个项目建的：

1. **YOLO AI 推理部署**（已有，重点深化）— 训练评估 → ONNX Runtime C++ 部署 → TensorRT FP32/FP16/INT8 对比 → 性能分析 → Docker 封装。对应 AI 推理、边缘部署、感知 SDK。
2. **AI 视觉驱动的移动机器人**（旗舰项目）— ROS2 + C++ + 摄像头 + YOLO 感知 + SLAM/Nav2 + STM32/CAN 电机控制。
3. **医学影像 AI 科研**（科研主线）— 跟骨 X 光、PyTorch / U-Net / MONAI，争取一作论文。

## 四、怎么用

```bash

python tools/import_lab.py

# 3. 给没有本地文档的模块补索引题（幂等，各管一摊，互不覆盖）
python tools/seed.py            # 算法机考 / 医学影像 / 机器人学 / 深度学习
python tools/seed_python.py     # Python 模块 40 道（骨架，正文在 tools/cards/）
python tools/seed_algo.py       # 算法题（40/20/20/20 分布）
python tools/seed_acm.py        # ACM 输入输出专项
python tools/seed_cpp_sdk.py    # C++ 工程化与 SDK 子方向
python tools/seed_yolo.py       # 项目深挖：YOLO 部署（16 道）
python tools/seed_gimbal.py     # 项目深挖：二维云台 + 本科毕设（22 道）
python tools/seed_sie.py        # 项目深挖：西门子杯 MRP 环网（15 道）
python tools/seed_log.py        # 项目深挖：Linux 日志分析（15 道）
python tools/seed_bone.py       # 项目深挖：跟骨分割科研（10 道，答案待填）

# 4. 写答案：正文写 tools/cards/*.cards（纯文本，免转义），再灌进题卡
python tools/apply_cards.py tools/cards/py_a.cards

# 5. 校验字段、号段、小节完整性
python tools/validate.py

# 5. 生成单文件题库网页 dist/bank.html（双击即开）
python tools/build.py

# 6. 岗位雷达：离线重算招聘性质分类（不联网）/ 联网扫描由 Actions 每日 09:30 跑
python tools/job_radar.py --reclassify   # 校招 / 实习 / 社招 / 未标明
python tools/radar_test.py               # 状态机 + 分类逻辑回归
python tools/ui_test.py                  # Edge/Playwright 全视图回归
```

### 网页的六个视图

`🏠 首页` / `📚 题库` / `🎯 训练` / `💼 岗位` / `🏢 公司` / `📈 分析`（hash 直达，如 `#comp`）。

- **看全部公司、全部岗位**：点「🏢 公司」或首页「查看全部公司 / 全部岗位」。公司池 52 条（启用 24 源）
  + 目标公司池 130 家，同名合并后 **158 家**；岗位表列出雷达快照 **775 岗**（技术岗 616 · 非技术 159 默认隐藏），含已收藏 / 已忽略，
  不再因为折叠区只显示 40 条待处理新发现而看不到。
- **校招还是实习**：岗位表按 `实习 / 校招 / 社招 / 未标明` 分组，每行标出判定依据
  （岗位标题明确 > 来源批次标签 > 校园招聘入口推定）。当前 638 校招 / 136 实习 / 1 社招；
  「入口推定」不等于官方写明校招，投递前点 JD 原文核实。
- **真实面经**：「🏢 公司」顶部「📰 真实面经」面板，**80 篇**牛客公开面经（公司 / 方向 / 轮次 / 题目原文摘录 /
  原帖链接），题目旁的 `Q-xxxx` 点一下直接跳题库复习；下面 124 套公司真题卷只登记元数据（题干有平台版权限制）。
- **考点地图（V1.9.1）**：「📈 分析」顶部「📚 牛客面试宝典 · 考点地图」，把牛客
  【C++工程师面试宝典】(30 篇) 与【机器学习/算法工程师面试宝典】(38 篇) 的 16 章 40 节接到题库上，
  每章给 题量 / 已自测 / 均分 / 加权准备度，并标出**结构性缺口**（如数据库 2 题、设计模式 2 题、NLP 0 题）；
  点「练这一章 N 题」直接筛出这批题，节 chips 还能细到「STL 14 题」。
- **适配度不只看关键词（V2.0）**：「💼 岗位」卡片给五个独立维度——**相关度**（核心/工程/场景三级技能判定）、
  **知识覆盖**（题库有料占比）、**理论掌握**（只算已自测，没有就写「数据不足」）、**工程证据**（项目档案能证明几项）、
  **招聘资格**（学历/届别/在校身份/实习时长/每周到岗，JD 没写就标「未说明」，绝不默认符合）。
  每条技能都附 **JD 原文命中片段**，判断错了一眼能看出来。
- **投递决策中心（V2.1）**：「💼 岗位」顶部按 `资格 → 相关度 → 证据/掌握` 把收藏岗位分成
  **优先投递 / 持续关注 / 仅供学习 / 不符合** 四类，点卡片筛列表；下面还有**五大岗位族**的
  「在招 / 高相关 / 我的覆盖 / 我的掌握」对比，直接看出该主攻哪一族。
- **训练闭环**：「📈 分析」给 7 天均值变化、P0 掌握率、连续两次低分、**跨 7 天复测通过率**、卡点模块；
  点「生成今日训练」按 到期 P0 → 未自测 P0 → 连续低分 → 薄弱 抽 12 题。
- **项目证据链**：「📈 分析」里 6 个项目 × 技能栈 × 代码/指标/测试/文档四类证据，仓库没填就标「证据不完整」。
- **系统健康**：13 项数据质量检查（题库完整性、采集成功率、快照新鲜度、JD 完整率、条件可抽取率、
  岗位族待复核、非技术岗隔离、公司入口、面经题号关联、本地数据体积…），红色必须处理、黄色待观察。
- 点公司表任意一行 → 只看该公司的岗位；清空搜索框恢复全部。

### GitHub 操作

```bash
python tools/gh.py whoami                          # 当前账号
python tools/gh.py create interview-bank           # 建私有仓库（--public 改成公开）
python tools/gh.py info DOURENCHI/interview-bank   # 查仓库状态
```

令牌从系统凭据管理器（GCM）读取，**不落盘、不写进任何文件**。SSH 只负责推代码，创建仓库必须走 REST API，所以两者都需要。

网页支持：全文搜索、多维筛选（**公司** / **岗位** / 模块 / 子方向 / 优先级 / 状态）、答案折叠、错题标记（存 localStorage）。

**按公司 / 岗位找题**：筛选栏有两个下拉——选「公司」或「岗位族」后，只留这家这个方向真正要对口的模块。在搜索框直接输 `Momenta`、`推理部署`、`SDK` 也能识别（命中公司名或岗位名就自动套那套口径）。
口径来自 `companies/targets.json`，**全部是按 JD 推导的，不是该公司的真实考题**；算法机考 317 道是所有人的门槛项，不参与这个口径（页面上会注明）。
链接可分享：`bank.html?co=Momenta`、`bank.html?rl=C`、`bank.html?q=推理部署`。

**按公司找题**：题目卡片上会出现红色标签，显示这道题**真实**出现在哪家公司哪个岗位（`appearances` 字段）。一个都没有就留空——不填预测，只填面经。填写规范见 `docs/schema.md`。

## 六、三条硬规则

1. **网页内容不许手改**。所有修改落到 `content/**.md`，再跑 `build.py`，否则网页和源文件必然不一致。
2. **来源必须可追**。`source_ref` 不许空；来自开源仓库的必须在 `sources/upstream.md` 登记并遵守许可证。
3. **不编造面试经历**。`source_type: inferred` 的题是按 JD 推导的预测，不是真实面经；真实面经必须记公司、岗位、年份、来源、可信度。
