# 面试题库 · Interview Bank

**定位：软硬件协同的 AI 系统工程师**

技术主线 `C++ / Linux + AI 推理部署 + 软硬件系统集成`。以推理部署为切入点，以 C++/Linux 工程能力为核心竞争力，以 ROS2、嵌入式和汽车电子作为系统集成能力。

面向自动驾驶、具身智能、智能硬件行业求职，2029 年目标年总包 40 万以上。

**岗位偏好链**：`SDK 开发 > 系统集成 > 推理部署 > 算法研发 > 电子硬件开发`

> 题库不是八股合集。每一道题尽量挂到自己的项目或文档上——这是和"背题库的人"拉开差距的地方。

## 二、模块与优先级

优先级依据三年规划的分阶段任务（2026 补基础 → 2027 做工程 → 2028 拿实习 → 2029 就业），以及"三条执行原则"：**C++/Linux/算法是基础不能降投入**、**AI 部署是现有优势要深化**、**ROS2 与硬件是差异化**。

| 模块 | 目录 | 优先级 | 理由 |
|---|---|---|---|
| 项目深挖 | `content/01_project` | **P0** | 面试官最有兴趣、最容易追问、也最难造假。**按项目分子方向**：YOLO 部署 / 二维云台 / 西门子杯 / Linux 日志分析 / 跟骨分割 / 本科毕设。**全部人工出题，每题配手写 SVG 插图**，题干带实测数据 |

## 三、三个核心项目（简历竞争力）

题库里的"项目深挖"模块就是围绕这三个项目建的：

1. **YOLO AI 推理部署**（已有，重点深化）— 训练评估 → ONNX Runtime C++ 部署 → TensorRT FP32/FP16/INT8 对比 → 性能分析 → Docker 封装。对应 AI 推理、边缘部署、感知 SDK。
2. **AI 视觉驱动的移动机器人**（旗舰项目）— ROS2 + C++ + 摄像头 + YOLO 感知 + SLAM/Nav2 + STM32/CAN 电机控制。
3. **医学影像 AI 科研**（科研主线）— 跟骨 X 光、PyTorch / U-Net / MONAI，争取一作论文。

## 四、怎么用

```bash
# 1. 从本地教学/项目文档批量抽取题目草稿（会跳过操作步骤类标题）
python tools/extract.py --scan

# 2. 从两个考点实验台导入机考题（幂等，重跑自动去重）
python tools/import_lab.py

# 3. 给没有本地文档的模块补索引题（幂等，各管一摊，互不覆盖）
python tools/seed.py            # 算法机考 / 医学影像 / 机器人学 / 深度学习
python tools/seed_algo.py       # 算法题（40/20/20/20 分布）
python tools/seed_acm.py        # ACM 输入输出专项
python tools/seed_cpp_sdk.py    # C++ 工程化与 SDK 子方向
python tools/seed_proj_a.py     # 项目深挖 A：YOLO 部署 / 二维云台 / 本科毕设
python tools/seed_proj_b.py     # 项目深挖 B：西门子杯 / Linux 日志分析 / 跟骨分割

# 4. 校验字段、号段、小节完整性
python tools/validate.py

# 5. 生成单文件题库网页 dist/bank.html（双击即开，手机可用）
python tools/build.py
```

### GitHub 操作

```bash
python tools/gh.py whoami                          # 当前账号
python tools/gh.py create interview-bank           # 建私有仓库（--public 改成公开）
python tools/gh.py info DOURENCHI/interview-bank   # 查仓库状态
python tools/gh.py push                            # 推送
```

令牌从系统凭据管理器（GCM）读取，**不落盘、不写进任何文件**。SSH 只负责推代码，创建仓库必须走 REST API，所以两者都需要。

网页支持：全文搜索、多维筛选（模块 / **子方向** / 优先级 / 状态）、答案折叠、错题标记（存 localStorage）。

**按公司找题**：题目卡片上会出现红色标签，显示这道题**真实**出现在哪家公司哪个岗位（`appearances` 字段）。一个都没有就留空——不填预测，只填面经。填写规范见 `docs/schema.md`。

## 六、三条硬规则

1. **网页内容不许手改**。所有修改落到 `content/**.md`，再跑 `build.py`，否则网页和源文件必然不一致。
2. **来源必须可追**。`source_ref` 不许空；来自开源仓库的必须在 `sources/upstream.md` 登记并遵守许可证。
3. **不编造面试经历**。`source_type: inferred` 的题是按 JD 推导的预测，不是真实面经；真实面经必须记公司、岗位、年份、来源、可信度。
