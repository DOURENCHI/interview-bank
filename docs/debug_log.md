## 2026-11-12 · V2.1（投递决策 / 训练闭环）

### 1. 五大岗位族每次筛选都重算 616 岗，切个 chip 卡半秒
- **现象**：决策面板一进来就把雷达 616 个技术岗逐个 `jobMatch()`，再叠加列表筛选，交互明显发顿。
- **解决**：`famStats()` 按 `Object.keys(review).length` 做缓存键——自评不变就不重算；自评变化才失效。
- **验证**：连续点 4 个决策卡，`#joblist` 渲染无延迟；改一题自评后族表「我的掌握」随之更新。

### 2. 「今日训练」提示条文案重复
- **现象**：显示「🎯 今日训练： 今日训练 12 题 · 12 题」，因为 label 自己带了前缀、banner 又加了一次。
- **解决**：label 只放数量（`12 题`），前缀由 `tutFilter.kind` 决定（`tut` → 宝典章节，`today` → 今日训练）。
- **验证**：`ui_test` 断言 banner 含「今日训练」，且题库只剩 12 题。

### 3. 决策规则不能先看相关度
- **现象**：初版按「相关度 + 覆盖 + 掌握」排序，把 2027 届岗位排进推荐，用户点进去才发现不能投。
- **解决**：`decideOf()` 第一分支判资格，`eligibility.cls === 'lo'` 直接归「不符合」，不再进入任何推荐池；
  推荐理由里写明「高相关 + 有 N 项工程证据」或「资格待确认」，保证每个结论可追溯。
- **验证**：8 个收藏岗 6 个判「不符合」，卡片与岗位徽标一致；`ui_test` 点「不符合」卡后列表从 8 → 6。

## 2026-11-12 · V2.0（五维匹配 / 资格字段 / 备份 v2 / 健康面板）

### 1. `const PROJ` 与项目题池重名，整页白屏
- **现象**：加项目证据档案后，控制台 `Identifier 'PROJ' has already been declared`，岗位/分析视图全空。
- **原因**：页面里早有 `const PROJ = {}`（按 sub 归类的「项目题池」，供项目连环问用），我又声明了一个同名常量。
- **解决**：项目档案改名 `PROJD`，注释写清两者区别；用 `pg.on('pageerror')` 兜住这类错误。
- **验证**：`ui_test` 的「无 JS 运行时错误」断言通过；岗位 8 卡、分析 6 卡正常渲染。

### 2. 岗位族「低置信」451 条，等于没筛
- **现象**：`family_conf` 初版把 `families == ['其他']` 全算低置信，775 岗里 451 条，队列失去意义。
- **原因**：岗位族关键词太窄，功能安全、训练平台、数据闭环、Data Infra、Agent 全落「其他」。
- **解决**：扩五族关键词（含 `功能安全/训练平台/数据闭环/infra/agent/算子/kernel` 等），
  并把「待复核」限定为 `tech_relevant && family_conf=low`（187 条）；`--annotate` 离线重算，不用重扫。
- **验证**：`radar_test` 新增「标注·族命中/低置信」两项；健康面板显示待复核 311（占 40%，阈值 30% 报警）。

### 3. 2027 届岗位原来只说「仅作参考」，等于放水
- **现象**：用户 2029 届，旧逻辑对非本屆岗位只标「面向 2027 届·仅作 JD 参考」，容易被当成可投。
- **解决**：`eligibilityOf()` 对 `grad_range` 做区间判断，`2029 ∉ [2027,2027]` 直接判 **不符合**；
  只有「JD 没写届别」才是 `资格未说明`（虚线 chip），不再用岗位类型（校招/实习）替代资格判断。
- **验证**：岗位卡首条显示「资格 不符合」，明细行「硬性不符：限 2027 届（你是 2029 届）」；
  `ui_test` 断言资格三态（ok/unknown/warn）同时存在。

### 4. 备份导入直接覆盖，且不认 v1
- **现象**：旧导入 `if (d.review) review = d.review` 全量替换，没有版本、没有校验、没有预览。
- **解决**：`schema_version=2` + 逐字段校验 + 预览「新增/更新/跳过」+ 默认合并（自测按 `ts` 取新）；
  兼容 v1（无 `data` 包裹时读根字段）；`lsSet()` 捕获 QuotaExceeded 并弹窗。
- **验证**：页面内 `parseBackup('{oops')` 报错、`parseBackup` 对不存在的题号返回 1 条 warn；
  构造 `[id1]{ts:100}` 本机 + 备份 `{ts:200}`，`planImport` 返回 `revUpd=1`。
- **测试坑**：不要硬编码 `Q-0001` 当「有效题号」——题库从 Q-0002 起，会得到 2 条 warn；改为 `DATA[0].id`。

### 5. 雷达「再看 18 条」在测试里点不到
- **现象**：Playwright 报 element is not visible，但 DOM 里确实有 `[data-rmore]`。
- **原因**：`#radarbox` 是 `<details>`，前一步点击 summary 把它关上了（默认 open 状态被 toggle）。
- **解决**：测试里用 `document.getElementById('radarbox').open = true` 强制展开，不依赖 toggle 状态。
- **验证**：卡片数 18 → 36；`ui_test` 的「雷达分页加载」通过。

### 6. 6 个项目「代码证据完整 0 个」不是 bug
- **现象**：项目证据链头部显示「完整 0 / 部分 6 / 缺 0」，看起来像没做好。
- **原因**：`projects.json` 里 6 个项目的 `repo` 都为空，代码证据按规则记 `partial`。
- **处理**：不把 `partial` 冒充 `present`，如实显示；岗位卡的「工程证据」按 `present|partial` 计入但标注「仓库未登记」。
- **待办**：补 GitHub 仓库链接与测试报告后改 `status: present`，工程证据会自动变成 x/y 满格。

## 2026-11-12 · V1.9.1（牛客宝典考点地图）

### 1. 关键词匹配用了正文，数据库一章被算成 113 题
- **现象**：首版 `_rule_hit` 的 `terms` 在「标题 + 正文」里搜，数据库章 113 题、数学基础 146 题，
  比实际多两个数量级，缺口提示完全失真。
- **原因**：正文里「加锁 / 梯度 / 期望 / 索引」这类词到处都是（互斥锁、梯度下降、数组索引），
  关键词一泛就全命中。
- **解决**：`terms` 只匹配 **标题 + 子方向 + 标签**，不碰正文；数据库再剔除泛化的「锁」，只留
  `SQL / 索引 / 事务 / B+树 / MVCC / 行锁 / 表锁 / 乐观锁 / 悲观锁`。
- **验证**：数据库 113 → 2 题（真实只有「B+ 树索引」与「慢 SQL 执行计划」两张卡），
  算法宝典 NLP 0 题、设计模式 2 题；与人工 `grep` 标题结果一致。

### 2. 同一规则拆成(一)(二)，两个节显示相同数字
- **现象**：「面向对象(一) 35 / 面向对象(二) 35」「计算机网络(一) 13 /(二) 13」看着像复制粘贴 bug。
- **原因**：宝典把一章拆成上下篇，但题库没有对应的子方向切分，只能套同一规则。
- **解决**：只在第一节保留 `rule` 并标数，第二节不给 `rule`（显示节名、不显示题数），
  避免「两个一样的数字」误导；需要细化时再补子方向。
- **验证**：截图复核节 chips：`面向对象(一) 35`、`面向对象(二)`（无数字）。

### 3. 「本书映射到题库 N 题」直接累加各章，重复计数
- **现象**：C++ 宝典各章相加 713，但实际去重只有 696 —— 网络编程属于操作系统模块、
  设计模式题也在 C++ 模块里，被算了两次。
- **解决**：改成 `new Set(所有章 ids)` 求并集后再统计题数与已自测数。
- **验证**：页面显示 696；`document.querySelectorAll('#list .q').length` 在点击任一章后仍等于该章按钮数字。

### 4. 目录节点不是链接，拿不到逐章深链
- **现象**：想给「读宝典 ↗」做 `&uuid=` 深链，但牛客目录是 `div.tw-h-10`，点击不改变 URL；
  `__INITIAL_STATE__` 只有 `prefetchData`（38 字节），没有章节目录数据。
- **解决**：放弃深链，按钮统一指向教程首页（左侧目录本身可点）；不做逆向，避免脆弱依赖。
- **验证**：`pg.url` 点击前后不变；页面按钮 `href` 为教程根地址。

## 2026-11-10 · V1.8.2（4 种 ATS 接入 + 城市选项 + 牛客同步）

### 1. Moka 门户接口加密，requests 拿不到岗位

- **现象**：`POST /api/outer/ats-apply/website/jobs/v2` 返回 `{"data":"ZWAJSGmj3…"}`——密文；`group-by-job` 同样加密。
- **解决**：不逆向加密，改走 DOM——Playwright 渲染 `{url}#/jobs` + 滚动触发懒加载，抓 `a[href*="#/job/"]` 卡片（文本含标题/类别/城市/简介）。
- **验证**：大疆抓到 30 岗，标题/城市齐全。

### 2. 大易（wecruit.hotjob.cn）接口"能连上但返回空"

- **现象**：JSON body 试 `{"pageNumber":1}` 等四种格式，`pageData` 全空。
- **原因**：大易用 **form-urlencoded**（`recruitType=1&currentPage=1&pageSize=10`），JSON 体被忽略。
- **解决**：抓浏览器真实 request（Playwright `request.post_data`）确认格式后直连，翻 `totalPage` 页。
- **验证**：地平线 48 岗、TCL 站 47 页均可分页拉全。

### 3. 飞书 /s/ 内推分享页永远抓不到（两次扫描 failed）

- **现象**：小马智行 / 蔚来的 `/s/{id}` 入口，`expect_response(search/job/posts)` 25s→45s 都超时。
- **原因**：`/s/` 是**内推分享页**，根本不发 `search/job/posts`（那是标准 campus 列表页的接口）——超时调多长都没用。
- **解决**：①适配器加点击兜底「查看全部职位 / 校招内推」后再等 XHR；②蔚来改用标准 `https://nio.jobs.feishu.cn/campus` 列表页（分享页只回 10 条）；③failed 源自动重试一次。
- **验证**：单独跑两个 site 各抓到 10 岗；全量扫描 23/23 success。

### 4. 65% 岗位城市是「待核实」——城市筛选形同虚设

- **现象**：685 岗里 449 条待核实；联影 133 岗 `LocNames` 是空数组。
- **原因**：zhiye 系门户把城市写在**标题尾部**（`电力电子工程师 - 上海(J19796)`），`LocNames` 字段反而常为空。
- **解决**：新增 `city_from_title()` 两个正则兜底（`- 城市(J编号)` 尾部 / 标题内 `（城市）`），scan_zhiye 与 moka 的 city 兜底都接上；**key 里 city 变化 → 清空快照重扫**（备份在 `_cache/jobs_radar_pre_cityfix.json`），避免旧 key 全部 missing 产生 suspect 垃圾。
- **第一次实现的两个坑**：①城市词表正则多写了一个闭括号（`...)[市]?)\s*[)）]`），`re` 编译报 `unbalanced parenthesis at position 134`，**23 个源里 8 个 zhiye 源全部失败**且报错在扫描期才暴露——教训：新增正则必须先单独编译/单测再全量扫描；②第一个正则把 `-27届校招(J11525)` 的「27届校招」提取成了城市。修正：城市词表抽成 `CITY_WORD` 常量 + `re.fullmatch` 校验尾缀。
- **验证**：8 个用例单测全过（含"不误收批次"负例），用例固化进 `radar_test.py`；重扫后 zhiye 系岗位城市还原，待核实占比大幅下降。

### 5. 城市 chips 数字之和 ≠ 岗位总数

- **现象**：chips 显示 8 个固定城市 + 其他 + 待核实，计数和 770 ≠ 792；广州 10 / 成都 4 / 西安 6 有计数却**没有 chip**，无法筛选。
- **原因**：chips 是写死的固定列表，而 `CITY_LIST` 归一化出的城市集合是开放的。
- **解决**：chips 改为 JS 动态生成——苏南五城 + 实习五城固定优先，其余按岗位数降序全部生成（测试断言改为 chips 计数之和 == `citiesOf` 总数）。
- **验证**：`ui_test.py` 城市计数断言通过，chips 数字之和与逐岗位城市展开总数一致。

### 6. Moka 卡片首行「热招」徽标导致 title 为空

- **现象**：大疆快照里出现 `title: ""`、城市列反而是岗位名的记录。
- **原因**：卡片首行是「热招」徽标，`re.sub(r'^热招','',lines[0])` 后得到空串，且没有空标题检查。
- **解决**：遍历卡片行取第一个「长度 ≥5 且不是 职位简介/投递/收藏/分享」的行做标题；city 再从标题括号兜底提取。
- **验证**：重扫后大疆 30 岗 title/city 无空值。

### 7. 牛客新题骨架里混入叙述句与水帖（40 张里 17 张不可用）

- **现象**：`nc_seed.py` 自动入库的题卡出现「面试中真正有价值的回答，不是…」「官网上一直卡在面试中，是不是挂了」「🎯 后来怎么调整的？」这类碎片。
- **原因**：面经解析按问句特征抓行，长帖的对话式追问、水帖叙述也会命中。

## 2026-11-10 · CareerOS V1.8（全部公司总览 + 招聘性质分类）

### 1. 用户看到「其余 81 道已收藏/忽略，不重复显示」，看不到全部公司与岗位

- **现象**：岗位雷达折叠区只列 40 条待处理新发现，其余岗位被隐藏；文案还把「被 40 条截断」与「已收藏/忽略」混为一谈。

- **解决**：新增第 6 个视图 `#comp`（`renderCompanies()`），公司表列两池去重后的全部 152 家，岗位表列全部 351 岗（含已收藏/已忽略），按 `实习 / 校招 / 社招 / 未标明` 分组；雷达区改为精确文案「显示 X / 待处理 Y；已收藏或忽略 N 条、未展开 M 条」并加跳转按钮；首页、岗位页也加入口。

### 2. 351 岗全部被硬编码成「校招」，实习岗被误标 2027 届

- **现象**：快照 `type` 全是 `校招`；`batch` 245 条为空、`grad_year` 274 条为空；4 个标题带「实习生」的岗位里 3 个带着从批次推来的 `grad_year=2027`。
- **原因**：`scan_zhiye` 用 `site.category=="2"` 兜底、`scan_feishu` 用 `site.type_label` 默认值，都是**入口级**信息；`grad_year` 又允许从 `batch` 回推，实习岗因此被套上届别硬条件。
- **解决**：新增 `classify_job()`，按「标题 > 批次标签 > 入口推定」三级证据产出 `job_class / class_basis / class_conf / class_evidence`；实习岗清掉批次推定的届别并留 `grad_year_raw`；新增 `--reclassify` 离线回填；快照与报告附 `class_stats / class_basis_stats`。
- **结果**：校招 347 / 实习 4；依据分布 标题明确 96 · 批次标签 46 · 入口推定 209。首页「技能参考」从 77 降到 74（3 个实习岗不再被当作 2027 届校招）。
- **验证**：`radar_test.py` 新增 10 项（标题/批次/入口/无线索/社招、实习届别清除、幂等、统计、池映射）→ 22/22 通过；`--reclassify` 实跑输出核对。

### 3. 公司总览全空：`byCo is not defined`

- **现象**：切到「🏢 公司」后统计卡、公司表、岗位表全空，但视图切换本身正常；手动打开单页时却正常。
- **原因**：编辑时把 `const byCo = {};` 那行随旧代码一起替换掉了，只留下 `const jobsByCo = {}`，函数执行到 `byCo[k]` 抛 `ReferenceError`；`showView()` 里 `classList.toggle` 在 `renderCompanies()` 之前，所以视图看起来「切成功了」，错误被掩盖。
- **解决**：补回声明；并在 `ui_test.py` 开头注册 `pageerror` 监听，末尾加「无 JS 运行时错误」断言——以后任何渲染期异常都会被测试直接抓住。
- **验证**：修复前复现得到 `PAGEERROR: byCo is not defined`；修复后 `getComputedStyle`/行数检查与 47 项 UI 全通过。

### 4. 岗位标题全是红色斜体

- **现象**：岗位表里 349 条「待处理」行标题呈红色斜体，像报错/已作废。
- **原因**：行 CSS 类直接用了 `todo / saved / dismissed`，与题卡全局样式 `.todo{color:#a63a2e;font-style:italic}` 撞名，整行继承红色斜体。
- **解决**：处理状态类统一加 `hs-` 前缀（`hs-todo / hs-saved / hs-dismissed`），筛选判断改为 `h !== 'hs-' + st`（`h` 本身已是 `handleOf()[1]` 字符串，**不要再写 `h[1]`**）；约定新组件类名一律加前缀。
- **验证**：`getComputedStyle(.jt).color` 从 `rgb(166,58,46)` 恢复 `rgb(45,42,33)`，`fontStyle` 从 `italic` 恢复 `normal`，截图复核。改前缀时曾误写成 `h[1] !== ...`（对字符串取下标恒为单字符），导致「已收藏 / 已忽略」筛选结果为空，被 `ui_test.py` 的两项断言当场抓到并修正。

### 5. 统计卡第 7 张单独换行、右侧大片空白；雷达卡片「发现 undefined」

- **原因**：7 张卡 `flex:1 1 145px` 在 1060px 容器里放不下一行；`renderRadar()` 读 `j.found`，而快照字段是 `first_seen`。
- **解决**：卡片精简为 6 张（`flex:1 1 140px`），目标池 128 家改在说明行写清；`found` 改为 `j.found || j.first_seen || ''`；公司表/岗位表最后一列设 `min-width:118px`。
- **验证**：截图核对 6 张卡一行、表格列不挤压。

### 6. 重跑体检脚本后，人工复核附录被覆盖丢失

- **现象**：`python tools/audit.py` 之后 `sources/audit_report.md` 少了末尾 18 行「附：相似题复核记录（4 张污染卡修复 + 25 对有意保留）」。
- **原因**：脚本每次都用 `"\n".join(L)` **整份重写**，而这段附录是人工补写的、不在自动生成内容里。
- **解决**：写报告前读旧文件，若含「## 附：」则把该段落原样带回并追加；本次已从 git 版本恢复原文。
- **验证**：再跑一次 `audit.py`，`git diff sources/audit_report.md` 为空（附录仍在），报告主体也保持 913 题 / 24 对可疑重复 / 缺来源 0。
