# 牛客网内容接入可行性评估

> 探测时间：2026-11-10。所有结论都来自实际请求，不是推测。凡标注「实测」的都有对应的 HTTP 响应或渲染结果。

## 一、结论先说

| 内容 | 可行性 | 判断 |
|---|---|---|
| **面试经验帖（面经）** | ✅ **高** | 无需登录，含**完整题目原文**+公司+岗位+轮次。与本库 `appearances` 设计完全吻合，**优先做** |
| 题卷元数据（124 套） | ✅ 高 | 一个接口拿全，含 paperId / 题量 / 公司 / 练习人数 |
| 题库分类树与题量 | ✅ 高 | 渲染后可读，可用来校核自己的模块覆盖度 |
| OJ 编程题题干 | 🟡 中 | 单题页 SSR 可直接取，但价值与自己已有的机考题重叠 |
| **选择题的答案与解析** | ❌ **低** | **需登录**，且试卷页有明确禁止第三方使用的声明 |
| 试卷内题干（企业真题） | ❌ **不建议** | 同上，且页面写明"未经许可不得私自使用，违者必究" |

**一句话建议：抓面经，不抓题库正文。** 面经是"公司×岗位×轮次×真实题目"的独家信息，题库正文是既拿不到答案、又和自己 893 道高度重复的内容。

## 二、实测到的技术事实

### 2.1 robots.txt（实测）

```
User-agent:*
Disallow:/search
Disallow:/nccommon
Disallow:/ab/ab-test-flow
Sitemap: ... /sitemap/question/sitemap.xml ...
```

题库页、面试页、题目页**都不在 Disallow 列表**里，并且平台主动提供了题目与讨论的 sitemap。这是"允许搜索引擎收录"的信号，但不等于允许批量转载——见第四节。

### 2.2 页面渲染方式（实测）

| 页面 | 原始 HTML | 渲染后 | 结论 |
|---|---|---|---|
| `/exam/intelligent` | 121 KB，无列表内容 | 180 KB，分类+题量齐全 | **CSR**，需渲染 |
| `/interview/center` | 55 KB | 836 KB，面经列表齐全 | **CSR**，需渲染 |
| `/exam/test/{paperId}/summary` | — | 只显示题数、时长、岗位标签 | 题干在"开始答题"之后 |
| `/feed/main/detail/{uuid}` | **6.5 KB，只有 title/og** | 460 KB DOM / 6600 字正文 | **CSR**，需渲染 |
| `/practice/{uuid}` | 题干**在 HTML 里**（含 LaTeX） | — | **SSR**，curl 直取 |
| `/questionTerminal/{uuid}` | 题干在 HTML 里 | — | **SSR** |

注意：面经详情页的原始 HTML 只有 6.5 KB，靠 curl 拿不到正文；必须走无头浏览器。这是抓取成本的主要来源。

### 2.3 接口（实测可用，无需登录）

网关：`https://gw-c.nowcoder.com/api/sparta/`

| 接口 | 方法 | 返回 | 用途 |
|---|---|---|---|
| `company-question/get-paper-list` | POST | `total: 124`，每项含 `paperId / paperName / questionCount / practiceCnt / companyTag` | 枚举全部真题卷 |
| `test/summary?paperId=` | GET | 题数、时长、`jobNameStr`（岗位标签）、题型分布 | 试卷元数据 |
| `job-experience/experience/job/list` | POST | `contentId / title / content（前 303 字）/ userBrief` | **枚举面经** |
| `question-tab/query-all-tab-list` | GET | 分类树 | 分类映射 |

请求头只需 `User-Agent` + `Referer`，无需 Cookie。

**两个必须知道的坑（实测）：**

1. **`total` 字段是假的。** `pageSize=10 → total=1000`，`20 → 2000`，`30 → 3000`。它等于 `pageSize × 100`，即"最多给 100 页"。终止条件不能信 `total`，要用「连续 N 页没有新 id」。
2. **`pageSize` 有上限。** `pageSize=50` 直接返回 `系统未知错误`，`30` 正常。按 30 算，面经单次筛选最多拿到 3000 条。

### 2.4 sitemap（实测）

| 文件 | 条数 | 内容 |
|---|---|---|
| `sitemap/question/questionurl1.txt` | 45,000 | `/practice/{uuid}` 编程题页 |
| `sitemap/question/questionurl2.txt` | 45,000 | `/discuss/{id}` 帖子页 |

9 万条 URL 全量抓既不必要也不合规，实际应按岗位/公司筛选后取几百条。

## 三、合规判断（这一节比技术更重要）

### 3.1 两类内容的法律地位不同

**企业真题卷（`/exam/test/*`）**：试卷页原文写着——

> 本试卷由企业提供，牛客网用户可免费申请练习……未经许可，任何第三方不得以任何理由私自使用，违者必究。

这是平台在页面上给出的**明确禁止声明**。绕过登录去取这类内容，即使技术上做得到，也不应该做。本库不收录。

**面经帖（`/feed/main/detail/*`）**：用户生成内容（UGC），著作权属于发帖人，平台用户协议通常保留"不得转载"的权利。robots 不禁止抓取，只代表允许搜索引擎建索引，**不等于允许复制正文**。

### 3.2 采取的策略

沿用你处理 `huihut/interview`（CC BY-NC-SA）时的同一套做法——**只存索引和链接，答案自己写**：

| 做 | 不做 |
|---|---|
| 存「题目原文摘要（≤40 字）+ 公司 + 岗位 + 轮次 + 日期 + 原帖链接」 | 不整段复制面经正文 |
| 答案由自己写（口述稿体） | 不搬运他人答案与解析 |
| 标注来源、抓取日期、可信度 | 不绕过登录、不绕付费墙 |
| 作者昵称/学校**脱敏**，只留链接 | 不存用户个人信息 |
| 串行请求 + 1–2 秒间隔，单日上限 300 条 | 不高并发、不做全站镜像 |

### 3.3 频率控制

面经详情是 CSR，一条要 3–5 秒渲染。串行抓 300 条约 20 分钟，对平台压力可接受。**并发不要超过 2**，否则既容易触发风控，也不礼貌。

## 四、数据结构化方案

### 4.1 映射到现有 schema

面经天然是"公司 × 岗位 × 轮次"的三元组，正好填进 `appearances`：

```yaml
# 题卡前端新增字段
source_type: nowcoder          # 新增来源类型
nc_url: https://www.nowcoder.com/feed/main/detail/xxx
nc_company: 小鹏汽车
nc_role: 电机结构开发培训生
nc_round: 二面
nc_date: 2026-11-10
```

正文的「出现记录」表直接复用：

```markdown
## 出现记录

| 日期 | 公司 | 岗位 | 轮次 | 来源 | 可信度 |
|---|---|---|---|---|---|
| 2026-11-10 | 小鹏汽车 | 电机结构开发培训生 | 二面 | 牛客面经（链接） | 社区经验 |
```

### 4.2 面经正文 → 题目的切分规则

面经正文是口语化的自由文本，但结构高度固定，实测样例：

```
二面 11.10
- 请做一下自我介绍。
- 挑选一个你参与深度、工作量最大的项目，详细讲讲……
反问：
- 电机开发部门分为哪几个专业板块？
答：电机开发部门主要分为 3 个专业方向……
```

切分规则（按优先级）：

1. **轮次块**：匹配 `^(一面|二面|三面|四面|HR面|主管面|交叉面)\s*(\d{1,2}[./-]\d{1,2})?`
2. **题目行**：以 `-`、`*`、`•`、`1.`、`问：`、`Q：` 开头，且满足任一：以 `？/?` 结尾、含疑问词（什么/为什么/怎么/如何/区别/说一下/讲讲）
3. **回答块**：`答：`、`A：` 开头的行归入上一题的「答案要点」
4. **反问段**：`反问` 之后到下一个轮次之前，单独标记 `qtype: reverse`（反问是加分项，值得单独一类）
5. **丢弃**：纯情绪句（"挂了""接好运""许愿"）、广告、内推码

### 4.3 数据落盘形态

| 产物 | 路径 | 说明 |
|---|---|---|
| 面经档案 | `companies/experiences/{公司}/{岗位}_{轮次}.md` | 一帖一档，含来源链接与日期 |
| 题卡 | 现有 `content/*/Q-XXXX.md` | 题目并入对应模块 |
| 试卷元数据 | `sources/nowcoder_papers.csv` | 124 套，用于对照岗位覆盖 |
| 分类树 | `sources/nowcoder_taxonomy.json` | 用于映射到自己的 11 个模块 |
| 抓取台账 | `sources/nowcoder_fetch_log.jsonl` | 已抓 id、时间、状态，支持断点续传 |

### 4.4 去重

三层去重，缺一不可：

1. **帖级**：按 `contentId` 去重（同一帖会被不同岗位标签重复收录）
2. **题级（跨帖）**：同一道题在 10 篇面经里出现，只建一张题卡，`appearances` 记 10 条 —— 这正是"出现次数"的价值，出现越多越该背
3. **题级（与既有库）**：用 Dice 二元组相似度（你现有 `dedup` 思路）比对 893 道，阈值 0.7 以上人工确认

注意：面经里的问法口语化（"说说你对虚函数的理解"），与库里的书面问法（"虚函数表的实现原理是什么？"）字面相似度低，**字面去重会漏**。需要用「考点关键词」二次归并：抽 `虚函数 / vtable / 多态` 这类特征词命中同一考点簇。

## 五、实现思路

### 5.1 三层架构

```
采集层  ──  API（列表/元数据）  +  无头浏览器（面经正文）  +  curl（SSR 单题页）
   │
归一化层 ──  轮次切分 / 题目识别 / 公司岗位抽取 / 问法归一化
   │
入库层  ──  复用现有 apply_cards.py（.cards 纯文本）+ fill.py + validate.py
```

**不需要新框架。** 无头浏览器就用本机 Edge 的 `--dump-dom`（已在用，`dist/_shot.png` 那套流程），不必装 Playwright。

### 5.2 关键实现要点

| 要点 | 做法 |
|---|---|
| **枚举面经** | `job-experience/experience/job/list` POST，`pageSize=30`，按 `job/selector` 的岗位过滤；终止条件用「连续 3 页无新 contentId」，**不要信 `total`** |
| **取正文** | `msedge --headless=new --virtual-time-budget=12000 --dump-dom URL`，再用正则剥标签；单条约 4 秒 |
| **断点续传** | 每抓一条追加写 `fetch_log.jsonl`，重启时跳过已有 `contentId` |
| **频控** | 串行 + `sleep 1.5`，单日 300 条上限；失败重试 1 次即跳过，不纠缠 |
| **题目抽取** | 规则优先，不做模型抽取——面经结构太固定，规则准确率更高且可解释 |
| **公司/岗位识别** | 先从列表接口的岗位 selector 拿结构化值；正文里再用「公司名库 + 岗位名库」兜底 |
| **去重** | contentId → 考点关键词簇 → Dice 相似度，三级 |
| **入库** | 生成 `.cards` 文件（你已定型的纯文本格式），`apply_cards.py` 一次灌入，`validate.py` 校验 |
| **合规硬约束** | 题卡正文只写「题目摘要 + 来源链接」，不存原帖正文；作者昵称不入库 |

### 5.3 工作量估算

| 步骤 | 量级 | 耗时 |
|---|---|---|
| 124 套试卷元数据 | 124 请求 | 约 5 分钟 |
| 面经枚举（按目标岗位筛） | 约 10 页 × 30 | 约 2 分钟 |
| 面经正文（300 篇） | 300 × 4 秒 | 约 20 分钟 |
| 题目抽取 + 人工复核 | 预计 300–600 道 | 半天 |
| 去重 + 入库 | — | 半天 |

**首次接入约 1 个工作日**，之后按周增量（只看 `最新` 排序的第一页）。

## 六、优先级建议

按对你的实际价值排，不按技术难度排：

| 优先级 | 做什么 | 理由 |
|---|---|---|
| **P0** | 抓面经，筛出 Momenta / 华为 / 蔚来 / 小鹏 / 地平线 / 联影 / 迈瑞 / ABB / 追觅 九家的 C++ / SDK / 推理部署 / 机器人 岗位 | 直接喂 `appearances`，把"通用八股"变成"这家公司问过" |

| P2 | 抓 OJ 编程题题干（仅题干，不抓题解） | 与已有 317 道算法题重叠度高 |
| **不做** | 抓试卷内题干、答案、解析 | 页面明确禁止；且需登录，性质变成绕过访问控制 |


## 六之二、用这张分类表校核自己的缺口（已生成 `sources/nowcoder_taxonomy.json`）

牛客"软件开发"标签页共 **63 个分类、29,486 道**。按大类归并后，和自己 893 道对照：

| 大类 | 牛客 | 自己 | 缺口判断 |
|---|---|---|---|
| 计算机基础（网络/OS/DB/编译/Linux） | **7,231** | Linux 11，其余 **0** | **最大缺口**。网络、数据库、操作系统理论全空 |
| 语言（C++/C/Python/Java…） | 7,047 | C++ 155 + Python 40 | 数量不落下风，但**广度**只有两门 |
| 行测（常识/数学/判断/资料） | 6,126 | 0 | 你的目标岗位不考，**忽略是对的** |
| AI/数据（含大模型 6 类） | 3,701 | 深度学习 11 + 影像 12 | **大模型、RAG、推理优化全空**，而"推理优化"正是你 P1 方向 |
| 研发基础（数组/树/图/DP…） | 2,386 | 算法 317 | 算法反而**超配**（含 177 道语言细节题） |
| 测试/其他（含设计模式） | 1,734 | 0 | 设计模式 308 道可补，SDK 岗会问 |
| 中间件（Redis/Kafka…） | 1,261 | 0 | 后端岗才考，你的岗位**可忽略** |

**三条可执行的结论：**

1. **网络 + 数据库 + 操作系统理论是真空区**（牛客 4 千多道，自己 0 道）。C++ SDK / 系统集成岗位一定会问 TCP、进程调度、内存管理——这三块应该立刻补，优先级高于任何新来源的抓取。
2. **"推理优化"（190 道）、"大模型概念"（408 道）**这类分类你目前完全没有，而它对应你规划的 P1 方向，值得借分类名去补题。
3. **算法机考已经超配**：317 道里 177 道是"读程序写结果"的语言细节，真正的算法题 83 道。牛客整个"研发基础"才 2,386 道，你不需要再往上堆。

> 这张表只用了分类名和题数，不含任何题面——放在 `sources/` 里可以随时重跑校核。
