## 题目

**背景**：接着重试话题，面试官追问退避参数怎么定。

**问**：指数退避的基数取多少合适？为什么一定要加抖动？

## 口述答案

> 基数一般取 100 到 500 毫秒，常用 200 毫秒，上限 2 到 5 秒。太小退避没意义，太大会让服务恢复后流量迟迟回不来。抖动是为了打散重试时刻：如果所有客户端同时失败、又按同一节奏重试，会在服务刚恢复的瞬间形成同步脉冲，把它再打挂一次。full jitter 从 0 到上限随机，峰值最低；equal jitter 保留一半固定值，长尾延迟更可控。

## 讲深一层

```python
def backoff(n, base=0.2, cap=5.0, mode="full"):
    hi = min(cap, base * 2 ** n)
    if mode == "full":   return random.uniform(0, hi)
    if mode == "equal":  return hi / 2 + random.uniform(0, hi / 2)
    return hi
```
n=0..4 时 full jitter 上限为 0.2 / 0.4 / 0.8 / 1.6 / 3.2 s。

## 高频追问

1. **不加抖动会怎样？** —— 惊群：失败时间同步的客户端会在同一毫秒重试，形成周期性尖峰。
2. **重试要不要设总时限？** —— 要，通常 8 到 10 秒，超过就失败快速返回，别让用户干等。
3. **同步重试和异步重试怎么选？** —— 用户可感知的走同步短退避，后台任务走队列加长退避。

## 易错点

- 基数设 10 ms，退避形同虚设
- 只做指数不设上限，几轮后等到几十分钟
- 抖动写成固定比例（±10%），仍会聚集
