## 题目

**背景**：拼多多服务端研发二三面的 JVM 组合题，三小问一口气问：GC 原理、对象可回收判断、GC Roots 为什么要充分且正确。这是 Java 后端的高频地基题，考察分代收集的整体图景和可达性分析的细节理解，答好要能把「判定-回收-收集器」串成一条线。
**问**：JVM GC 的原理；如何判断一个对象是否可回收；如何保证 GC Roots 充分且正确？

## 口述答案

> 我按「怎么判定该回收、怎么回收、谁来回收」三段讲。
> 判定可回收：主流 JVM 用可达性分析，不用引用计数——引用计数解决不了循环引用（A 引用 B、B 引用 A，计数都非零但实际都死了），Python 那种才靠引用计数加额外的环检测。可达性分析的思路是从一组确定的根对象 GC Roots 出发，沿着引用链遍历，能到达的对象是活的；遍历完剩下的、从任何 Root 都走不到的对象，就是可回收的。另外还有软引用、弱引用、虚引用这些特殊强度引用，会在内存紧张或下次 GC 时被特殊处理，属于正常可达性判断的补充。
> GC Roots 具体有哪些：虚拟机栈里正在执行的方法引用的局部变量和参数（线程当前正在用的对象）；方法区的类静态字段引用的对象；方法区常量引用的对象；JNI 引用的对象，也就是 native 方法持有的；还有 JVM 内部的引用，比如基本类型对应的 Class 对象、常驻的异常对象、系统类加载器；以及所有被同步锁持有的对象。一句话概括：线程正在执行、类和常量、native 层、JVM 自身，这四个来源是根。
> GC 原理按分代收集讲。堆分新生代和老年代，新生代又分 Eden 和两个 Survivor 区。绝大多数对象朝生夕死，所以新生代用复制算法：Eden 满了触发 Minor GC，把存活对象复制到一块 Survivor，另一块和 Eden 整体清空，代价只跟存活对象数量成正比，适合存活率低的场景；对象每熬过一次 Minor GC 年龄加一，到阈值（默认 15）晋升老年代。老年代对象存活率高、体积大，用标记-整理或标记-清除：CMS 是标记-清除，并发低停顿但有碎片；G1 把堆切成 Region，按垃圾比例优先回收收益最高的 Region，停顿目标可控；ZGC/Shenandoah 用着色指针和读屏障做到亚毫秒级停顿。工程上重点还是那三件事：看 GC 日志和停顿分布，选对收集器（低延迟上 G1/ZGC，吞吐优先 Parallel），根据分配速率和晋升速率调堆和代的比例。
> 第三问「GC Roots 充分且正确」怎么保证：这是 JVM 的实现责任，不是应用开发者手动维护的。正确性靠 Stop The World 期间的安全点机制——GC 发生时所有线程停在安全点，栈帧、寄存器里的引用被准确快照（JIT 会把哪些位置是引用的元数据记在 OopMap 里），避免分析过程中根集合变化导致漏标；充分性靠根枚举覆盖上面说的全部来源，比如 JNI 全局引用表、线程栈全量扫描。应用层能做的配套是：避免长生命周期集合持有大对象引用（静态 Map 越攒越多是内存泄漏的头号来源）、类加载器泄漏（容器化部署时旧 ClassLoader 卸不掉）、以及用 MAT/jmap 分析堆快照验证没有意外强引用链。

## 讲深一层

- 可达性分析的「正确性」建立在 STW 快照上：并发标记之所以需要三色标记法加增量更新/写屏障（CMS 用增量更新，G1 用 SATB），就是因为用户线程和 GC 并发时引用会变——漏标对象会被误杀，这是致命错误，所以并发收集器都要写屏障兜底。
- 「充分且正确」的另一个工程视角：根集合遗漏会漏标（活对象被回收，程序崩），根集合多算会浮动垃圾（死对象这轮回收不掉，下轮再说）——宁可浮动不能漏，这是所有收集器的设计底线。
- 复制算法在老年代不划算的原因：老年代存活率高，复制存活对象的开销远大于原地标记整理；算法选择本质是对存活率的假设。
- Minor GC 频繁但快、Full GC 慢且要命：排查 JVM 问题先分清是哪种 GC，晋升过快（Survivor 太小或对象太老才死）会诱发老年代频繁收集，这是调参的第一信号。

## 高频追问

1. 三色标记法是什么，漏标怎么解决？——白（未访问）灰（自身已标、引用未扫完）黑（扫完）；黑指向白且灰到白的引用被删就漏标；CMS 用增量更新（记录新增引用重新扫描），G1 用 SATB（记录删除的引用按快照处理）
2. 怎么排查内存泄漏？——jmap dump 堆快照，MAT 看支配树和 GC Roots 引用链；配合 jstat 看 Old 区回收后是否持续上涨，上涨即泄漏
3. 引用计数在 JVM 里完全没用吗？——有用但不是主判定：JVM 里某些场景（如对象在多个线程间转移）会用类似思想，但堆回收主链路一定是可达性分析

## 易错点

- 答成引用计数——JVM 不用引用计数，循环引用这一条就能把它问死；可达性分析才是 Java 的标准答案
- GC Roots 背不全或漏掉 native/JVM 内部——栈上局部变量、静态字段、JNI 引用是三大概率考点，漏 JNI 是常见扣分点
- 分代算法张冠李戴——说老年代用复制算法就是硬伤；新生代复制、老年代标记整理/清除，CMS 和 G1 的差异（碎片、SATB）要能展开
