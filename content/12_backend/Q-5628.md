## 题目

**背景**：JVM 运行时数据区的细节题，面试官注意到"两个栈"这个说法，追问为什么要分开定义。

**问**：为什么 Java 虚拟机要区分两个栈呢？

## 口述答案

> 规范里确实分两个：Java 虚拟机栈服务 Java 方法，栈帧里放局部变量表、操作数栈、动态链接和返回地址；本地方法栈服务 native 方法，栈帧布局由具体语言和 ABI 决定，JVM 描述不了。分开的原因是两类代码执行模型不同：字节码由解释器或 JIT 按 JVM 规范管理，native 方法直接跑在宿主 CPU 上，栈大小、对齐方式、调用约定都不一样，没法用同一套结构表达。规范对错误的定义也不同，栈深度超限抛 StackOverflowError，申请不到内存抛 OutOfMemoryError。不过 HotSpot 实现上把两者合并成一个栈，所以 -Xss 同时管它们。

## 讲深一层

| 栈帧组成 | 作用 |
| --- | --- |
| 局部变量表 | 参数和局部变量，按 slot 存，long/double 占两个 |
| 操作数栈 | 字节码计算的临时区，深度编译期确定 |
| 动态链接 | 指向运行时常量池中该方法的引用 |
| 返回地址 | 方法返回后继续执行的 pc |

## 高频追问

1. **栈帧什么时候创建销毁** —— 方法调用时压栈，正常返回或抛异常时弹出，随线程结束整体释放
2. **栈溢出怎么复现** —— 深递归，或者 -Xss 设很小；抛 StackOverflowError 不是 OOM
3. **-Xss 调大有什么代价** —— 每个线程独占，调大后同样的内存能创建的线程数变少

## 易错点

- 说"HotSpot 里真的是两个栈" —— 规范分两个，HotSpot 实现上合并了
- 把 StackOverflowError 和 OOM 混为一谈 —— 前者是深度超限，后者是申请不到内存
- 认为栈是线程共享的 —— 两个栈都是线程私有
