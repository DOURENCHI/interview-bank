## 题目

**题目**：`pip freeze > requirements.txt` 之后换台机器装，版本冲突了。

**问**：依赖管理怎么做？`requirements.txt` 有什么坑？

## 口述答案

> `pip freeze` 导出的是**当前环境的全部包（含传递依赖）**，会把无关的包也带上，而且不区分"直接依赖"和"间接依赖"，导致环境臃肿、难以维护。
> 现代做法：`pyproject.toml` 里只写**直接依赖**，再用锁文件（`uv.lock` / `poetry.lock` / `pip-tools` 生成的 `requirements.lock`）固定全部版本。

## 讲深一层

```toml
# pyproject.toml
[project]
name = "mytool"
requires-python = ">=3.10"
dependencies = [
  "numpy>=1.26,<3",
  "requests~=2.31",
]
```

| 文件 | 内容 | 用途 |
|---|---|---|
| `requirements.txt` | 手写的直接依赖 | 简单项目够用 |
| `pip freeze` 输出 | 全部包（含传递） | 复现环境，但脏 |
| `pyproject.toml` | 直接依赖 + 元数据 | 现代标准 |
| lock 文件 | 精确版本 + 哈希 | **可复现构建** |

**版本约束符号**：
- `==1.2.3` 精确
- `~=1.2.3` 兼容（允许 1.2.x）
- `>=1.2,<2` 范围
- `*` 任意（危险）

**必做的三件事**：**用虚拟环境**（`python -m venv .venv`）、**锁定版本**、**区分开发依赖**（`pytest`、`black` 不该进生产镜像）。

**一个实际教训**：不加约束的 `numpy` 会在某次发布后引入不兼容变更，CI 突然全红——锁文件就是为了防这个。

## 高频追问

1. **pip 和 conda 能混用吗？** —— 能但容易冲突，同一环境尽量只用一种。
2. **`pip install -e .` 是什么？** —— 可编辑安装，改代码立即生效。
3. **怎么减小镜像体积？** —— 多阶段构建 + 只装运行时依赖 + `--no-cache-dir`。

## 易错点

- 直接把 `pip freeze` 当依赖清单
- 不锁版本，构建不可复现
- 全局安装不建虚拟环境
