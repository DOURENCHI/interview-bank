## 题目

**题目**：

```python
def f():
    try:
        return 1
    finally:
        print("finally")
        return 2
print(f())
```

**问**：输出是什么？`else` 什么时候执行？`finally` 会覆盖 `return` 吗？

## 口述答案

> 输出 `finally` 然后 `2`——**`finally` 里的 `return` 会覆盖 `try` 里的返回值**。这是"finally 一定执行"的副作用，也是写代码时要避免的模式。
> `else` 在**没有异常时**执行，`finally` **无论如何都执行**。

## 讲深一层

```python
try:
    x = int(s)
except ValueError:
    print("转换失败")
else:
    print("成功了才执行这里")     # 无异常
finally:
    print("一定执行")             # 即使 return / 抛异常
```

| 子句 | 执行条件 |
|---|---|
| `try` | 总是 |
| `except X` | 匹配到异常 |
| `else` | **没有异常**（且没被 except 捕获） |
| `finally` | **总是**（含 return、break、未捕获异常） |

**`else` 的价值**：把"成功路径"和"异常处理"分开，避免把不该被 `except` 捕获的代码放进去。

**`return` 与 `finally` 的细节**：
1. `finally` 里有 `return` → 覆盖前面的返回值（且吞掉异常）；
2. `finally` 里改了可变对象，值会生效；
3. `finally` 里抛异常 → 覆盖原异常。

**什么时候必须用 `finally`**：释放锁、关闭文件/连接、恢复状态。但能用 `with` 就别手写 `finally`。

## 高频追问

1. **`except Exception` 能捕获所有异常吗？** —— 不能捕获 `SystemExit`/`KeyboardInterrupt`（它们是 `BaseException`）。
2. **`except (A, B) as e` 是什么语法？** —— 同时捕获多种异常并绑定变量。
3. **异常没被捕获会怎样？** —— 向上传播，最终由解释器打印栈并退出。

## 易错点

- 在 `finally` 里 `return`
- 用 `except: pass` 吞掉所有异常
- 把大段逻辑塞进 `try`，误捕获不该捕获的
