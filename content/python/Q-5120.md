## 题目

**题目**：一个程序要同时请求 100 个 URL，用多线程 8 个线程跑；另一个程序要算 100 个矩阵乘法，也开 8 个线程。

**问**：哪个会变快？CPU 密集为什么加了线程反而更慢？

## 口述答案

> **请求 URL 会快很多**，因为等网络时线程会释放 GIL，其他线程能继续跑；**矩阵乘法不会变快甚至更慢**，因为纯 Python 计算抢同一把 GIL，还要付线程切换的代价。
> 判断标准只有一条：**这段时间里 CPU 在算还是在等**。

## 讲深一层

| 任务类型 | 特征 | 方案 |
|---|---|---|
| I/O 密集 | 等网络/磁盘/数据库 | 多线程 / asyncio |
| CPU 密集 | 一直在算 | **多进程** / C 扩展 / numpy |
| 混合 | 两者都有 | 多进程 + 每进程内多线程 |

```python
# I/O 密集：线程池
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor(max_workers=16) as ex:
    results = list(ex.map(fetch, urls))

# CPU 密集：进程池
from concurrent.futures import ProcessPoolExecutor
with ProcessPoolExecutor() as ex:
    results = list(ex.map(heavy, data))
```

**CPU 密集为什么更慢**：8 个线程轮流持有 GIL，上下文切换（保存/恢复状态、缓存失效）是纯开销；而且切换间隔 5 ms 意味着单次计算可能被频繁打断。

**线程数怎么定**：I/O 密集可以远大于核数（16–100 都常见）；CPU 密集设成核数，且应该直接用多进程。

## 高频追问

1. **怎么判断是 I/O 还是 CPU 密集？** —— 看 CPU 占用：跑满就是 CPU 密集，低就是 I/O 密集。
2. **线程数开太多有坏处吗？** —— 有，内存和切换开销，还可能打爆对方服务。
3. **asyncio 比线程池好吗？** —— 高并发 I/O 更省资源，但要全链路异步。

## 易错点

- 用多线程做数值计算
- 线程数开到几百
- 不区分任务类型就套线程池
