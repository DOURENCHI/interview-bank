## 题目

**追问**：`yield from` 和"for 循环里 yield"有什么区别？

**问**：`yield from` 做了什么？什么时候必须用它？

## 口述答案

> `yield from sub` 把迭代**完全委托**给子生成器：不仅转发产出的值，还转发 `send()`、`throw()`、`close()`，并且能拿到子生成器的**返回值**。
> 只写 `for x in sub: yield x` 就只能转发值，双向通信和返回值都会丢——写协程/任务调度时必须用 `yield from`。

## 讲深一层

```python
def inner():
    x = yield 1
    yield x * 2
    return "done"

def outer_ok():
    r = yield from inner()      # ✅ 能收到 send 的值，能拿到返回值
    print(r)                    # "done"

def outer_bad():
    for v in inner():           # ❌ send 的数据不会传进 inner
        yield v
```

| 能力 | `for + yield` | `yield from` |
|---|---|---|
| 转发产出值 | ✅ | ✅ |
| 转发 `send()` | ❌ | ✅ |
| 转发 `throw()`/`close()` | ❌ | ✅ |
| 获取子生成器 return | ❌ | ✅ |
| 性能 | 多次进出解释器 | 更少的帧切换 |

**`yield from` 的典型用途**：把一棵树的遍历拆成多个生成器递归组合。

```python
def walk(node):
    yield node.value
    for child in node.children:
        yield from walk(child)     # 递归摊平
```

**asyncio 的 `await` 就是 `yield from` 的进化版**（Python 3.5 后），理解 `yield from` 就理解了协程调度的雏形。

## 高频追问

1. **递归用 `yield from` 会爆栈吗？** —— 深递归会，考虑显式栈。
2. **`yield from` 后面能跟列表吗？** —— 能，任何可迭代对象。
3. **和 `await` 什么关系？** —— `await` 语义上类似 `yield from`，但只用于 awaitable。

## 易错点

- 用 `for + yield` 写协程委托
- 以为 `yield from` 只是语法糖
- 递归深度过大
