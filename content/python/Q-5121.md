## 题目

**追问**：既然 GIL 挡住了并行，那 `multiprocessing` 是怎么绕过去的？有什么代价？

**问**：multiprocessing 怎么绕过 GIL？代价是什么？

## 口述答案

> 因为它**开的是进程不是线程**：每个进程有独立的解释器和独立的 GIL，操作系统可以把它们调度到不同核心上，真正并行。
> 代价有四条：**启动开销大**（fork/spawn 一个进程要几十到几百毫秒）、**内存不共享**（数据要用 pickle 传，大对象很贵）、**进程间通信受限**（Queue/Pipe/共享内存）、**平台差异**（Windows 用 spawn，Linux 默认 fork）。

## 讲深一层

```python
from multiprocessing import Pool

def heavy(x):
    return sum(i*i for i in range(x))

if __name__ == "__main__":          # Windows 必须
    with Pool(processes=4) as p:
        print(p.map(heavy, [10**6] * 8))
```

| 维度 | 线程 | 进程 |
|---|---|---|
| 内存 | 共享 | 独立（要拷贝/pickle） |
| 启动成本 | 微秒级 | 几十~几百毫秒 |
| 真正并行 | ❌（GIL） | ✅ |
| 通信 | 直接共享 | Queue / Pipe / 共享内存 |
| 崩溃影响 | 全进程挂 | 只挂子进程 |

**`if __name__ == "__main__"` 不是可选项**：Windows/macOS 用 spawn 启动，子进程会重新 import 主模块，没有这个保护会无限递归创建进程。

**大数据的替代方案**：`shared_memory`（3.8+）或 `numpy.memmap`，避免 pickle 开销。

**池化很重要**：池复用进程，别每次任务都 `Process()` 新建。

## 高频追问

1. **fork 和 spawn 有什么区别？** —— fork 复制父进程内存（快但可能复制锁状态）；spawn 重新启动解释器（干净但慢）。
2. **子进程能改父进程的变量吗？** —— 不能，各是各的内存。
3. **进程池数量怎么定？** —— CPU 核数，或核数 ±1。

## 易错点

- Windows 上不加 `if __name__ == "__main__"`，无限创建进程
- 传递大对象导致 pickle 开销爆炸
- 每次任务都新建进程
