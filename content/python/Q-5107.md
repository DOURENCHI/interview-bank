## 题目

**题目**：`s = "abc"; s[0] = 'x'` 报错；但 `lst = [1,2]; lst[0] = 9` 可以。

**问**：可变与不可变对象有什么区别？这个区别对工程有什么实际影响？

## 口述答案

> 不可变对象的**值不能改**，任何"修改"都会创建新对象（`s = s + 'd'` 是新字符串）；可变对象的**内容可以原地改**。
> 实际影响有三处：**能否当 dict key**（必须可哈希，通常要求不可变）、**函数传参行为**（可变对象会被函数改掉）、**多线程安全性**（不可变对象天然线程安全）。

## 讲深一层

| 类型 | 可变 | 可哈希（可当 key） |
|---|---|---|
| `int` `float` `str` `bool` | ❌ | ✅ |
| `tuple` | ❌ | ✅（元素都可哈希时） |
| `None` | ❌ | ✅ |
| `list` `dict` `set` | ✅ | ❌ |
| `frozenset` | ❌ | ✅ |

```python
def f(lst):
    lst.append(1)      # 会改到调用方的 list

def g(s):
    s += "x"           # 只改局部名，调用方不受影响
```

**"传参是值传递还是引用传递"**：Python 是**传对象引用**（call by object reference）——函数拿到的是同一个对象的引用，但重新赋值只是让局部名指向新对象。

**不可变的代价**：字符串拼接会产生新对象，循环里 `+=` 可能退化成 O(n²)（见字符串拼接那题）。

**tuple 不总是不可哈希**：`(1, [2])` 含可变元素就不能当 key。

## 高频追问

1. **为什么 dict 的 key 必须可哈希？** —— 要靠哈希值定位，值变了哈希就变了，找不到。
2. **自定义对象能当 key 吗？** —— 实现 `__hash__` 和 `__eq__`，且参与哈希的字段不能变。
3. **`tuple` 比 `list` 快多少？** —— 创建快、内存小（约 40 vs 56 字节起），遍历差异不大。

## 易错点

- 用 list 当 dict key（报 unhashable）
- 以为函数传参是纯值传递
- 用含 list 的 tuple 当 key
