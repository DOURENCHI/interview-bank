## 题目

**题目**：两个 100 万元素的数组相加，Python 循环要 0.3 秒，numpy 只要 2 毫秒。

**问**：numpy 向量化为什么比 for 循环快几十倍？

## 口述答案

> 四个原因叠加：**循环在 C 层执行**（没有解释器开销）、**连续内存 + 相同 dtype**（缓存友好、无需装箱拆箱）、**SIMD 指令**（一次算多个）、**释放 GIL**（可以多线程）。
> 而 Python 的 `for` 每次迭代都要创建 int 对象、查类型、调字节码——差了两个数量级。

## 讲深一层

```python
import numpy as np, timeit

n = 1_000_000
a = list(range(n)); b = list(range(n))
timeit.timeit(lambda: [x+y for x,y in zip(a,b)], number=1)   # ~0.06 s

aa = np.arange(n); bb = np.arange(n)
timeit.timeit(lambda: aa+bb, number=1)                        # ~0.002 s
```

| 层面 | Python list | numpy array |
|---|---|---|
| 元素存储 | PyObject 指针（分散） | 连续原始字节 |
| 元素类型 | 逐个装箱 | 统一 dtype |
| 循环 | 解释器逐条 | C 循环 + SIMD |
| 内存占用 | 28 字节/int | 8 字节/int64 |

**向量化的关键写法**：
1. **避免 Python 层循环**：用 `np.where`、布尔索引、`np.dot` 替代 `for`；
2. **避免 `append`**：预分配数组或一次构造；
3. **利用广播**：`a[:, None] - b[None, :]` 代替双重循环；
4. **注意 dtype**：`float32` 比 `float64` 省一半内存和带宽。

**常见误区**：`for i in range(len(arr)): arr[i] = ...` 比 list 还慢，因为每次索引都要创建 numpy 标量对象。

## 高频追问

1. **numpy 什么时候反而不快？** —— 小数组（<1000 元素）时，调用开销占主导。
2. **`np.vectorize` 会加速吗？** —— 不会，它只是语法糖，内部还是 Python 循环。
3. **能真正并行吗？** —— 部分操作释放 GIL，但多数单线程；多进程或 numba 才行。

## 易错点

- 用 `np.vectorize` 以为能加速
- 循环里逐元素索引赋值
- 混用 dtype 导致隐式转换和复制
