## 题目

**题目**：面试官问"dict 查找为什么是 O(1)"，接着追问"那最坏情况呢"。

**问**：Python 的 dict 底层是怎么实现的？为什么 3.7 起"有序"？

## 口述答案

> dict 是**哈希表**：key 先算哈希值定位到槽位，冲突用**开放寻址**（探测下一个空槽），所以平均 O(1)。
> 3.6 起 CPython 改成了 **compact dict**：用一个稀疏的索引数组 + 一个紧凑的 entries 数组，entries 按插入顺序追加，所以**遍历顺序等于插入顺序**；3.7 起这个行为写进了语言规范。

## 讲深一层

```
3.5 之前：稀疏的哈希槽，每个槽存 (hash, key, value)
3.6 之后：
  indices: [None, 0, None, 1, ...]     ← 稀疏，只存 entries 的下标
  entries: [(h, k1, v1), (h, k2, v2)]  ← 紧凑，按插入顺序
```

| 维度 | 说明 |
|---|---|
| 平均查找 | O(1) |
| **最坏查找** | **O(n)**（所有 key 哈希冲突，退化） |
| 插入顺序 | 3.7 起保证 |
| 内存 | compact 布局比旧版省约 20–25% |
| 扩容 | 装载因子约 2/3 时扩容，重新哈希 |

**最坏情况怎么发生**：构造大量哈希值相同的 key。Python 的字符串哈希是随机化的（`PYTHONHASHSEED`），所以外部很难构造；但自定义类如果 `__hash__` 返回常数，就会全部冲突。

**dict 有序 ≠ 可以排序**：有序是"插入顺序"，不是"按 key 大小"。要排序得 `sorted(d.items())`。

**3.7 之前的写法要避免**：依赖 dict 顺序的代码在老版本上会随机出错。

## 高频追问

1. **能一边遍历一边删吗？** —— 不能，报 `RuntimeError: dictionary changed size during iteration`；用 `list(d)` 或 `list(d.items())` 做副本。
2. **`dict.get` 和 `d[k]` 区别？** —— 前者缺 key 返回默认值，后者抛 `KeyError`。
3. **`defaultdict` 什么时候用？** —— 需要"缺 key 自动初始化"时，比 `setdefault` 快。

## 易错点

- 说 dict 查找永远是 O(1)
- 遍历中删除元素
- 依赖旧版本的 dict 无序行为（或反过来依赖新版本行为却部署在老环境）
