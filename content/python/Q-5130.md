## 题目

**题目**：读文件前先 `os.path.exists` 判断，还是直接 `open` 再 `except FileNotFoundError`？

**问**：EAFP 和 LBYL 两种风格该怎么选？

## 口述答案

> Python 社区**偏好 EAFP**（Easier to Ask Forgiveness than Permission）：直接做，出错再处理。因为 Python 的异常开销相对小，而且 `exists` 之后文件仍可能被删——**检查和使用之间有竞态**。
> LBYL（Look Before You Leap）适合**检查成本低、失败代价高**的场景，比如参数校验。

## 讲深一层

```python
# EAFP
try:
    with open(path) as f:
        data = f.read()
except FileNotFoundError:
    data = default

# LBYL
if os.path.exists(path):     # 检查完可能被删（TOCTOU）
    with open(path) as f:
        data = f.read()
```

| 风格 | 优点 | 缺点 |
|---|---|---|
| EAFP | 无竞态、代码短 | 异常有开销（尤其在热路径） |
| LBYL | 流程清晰、无异常开销 | 有 TOCTOU 竞态、代码冗长 |

**什么时候 EAFP 不合适**：
1. **热循环里**——异常构造和栈展开很贵（比一次判断贵几个数量级）；
2. **异常是常态**——比如用 `KeyError` 控制流程；
3. **需要原子性**——检查和使用必须一起完成。

**`dict.get` 是折中**：`d.get(k, default)` 既避免了异常，也不用两次查找。

**TOCTOU 是什么**：Time-of-check to time-of-use，检查时成立、使用时已变——安全漏洞的经典来源。

## 高频追问

1. **异常有多贵？** —— 无异常时不贵（try 本身近乎零成本），抛出时才贵。
2. **`try` 块会影响性能吗？** —— Python 3.11 起零成本异常表，无异常时没有额外开销。
3. **多线程下 `exists` 有什么用？** —— 基本没用，建议直接 EAFP。

## 易错点

- 在热循环里用异常做流程控制
- 用 `exists` 判断后再打开（竞态）
- 以为 `try` 本身有性能开销
