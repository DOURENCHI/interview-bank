## 题目

**题目**：用 list 实现队列，`pop(0)` 取出头部，数据量上万后明显变慢。

**问**：为什么 `list.pop(0)` 慢？该用什么替代？

## 口述答案

> 因为 list 是**连续数组**，`pop(0)` 要把它后面所有元素**前移一位**，O(n)。循环 n 次就是 O(n²)。
> 用 `collections.deque`（双端队列），两端插入删除都是 **O(1)**。

## 讲深一层

```python
from collections import deque
import timeit

q = deque()
q.append(1)          # 右端入，O(1)
q.popleft()          # 左端出，O(1)

# 性能差距
timeit.timeit(lambda: [].pop(0), number=1)   # 示意，实际要预填充
```

| 操作 | list | deque |
|---|---|---|
| 尾部 append/pop | O(1) | O(1) |
| **头部插入/删除** | **O(n)** | **O(1)** |
| 随机访问 `q[i]` | O(1) | O(n) |
| 中间插入 | O(n) | O(n) |
| 内存 | 紧凑 | 分块，略大 |

**为什么 deque 能 O(1) 头部操作**：内部是**分块的双向链表**（每块是一个数组），头尾各有一个指针，不需要整体搬移。

**`deque(maxlen=N)` 的妙用**：自动丢弃旧元素，适合"最近 N 条日志/最近 N 帧"这类滑动窗口，不用手动 pop。

**什么时候还是用 list**：需要频繁随机访问、需要切片。deque 不支持切片。

## 高频追问

1. **deque 能排序吗？** —— 不能直接 `sort`，要转 list。
2. **队列在多线程里用哪个？** —— `queue.Queue`（线程安全），不是 deque。
3. **优先级队列？** —— `heapq`（基于 list 的堆）。

## 易错点

- 用 `list.pop(0)` 做队列
- 用 deque 做随机访问
- 用 deque 做线程间通信（应该用 queue.Queue）
