## 题目

**题目**：一个脚本跑 30 秒，只知道"慢"，不知道慢在哪。

**问**：怎么定位 Python 程序的性能瓶颈？工具怎么选？

## 口述答案

> 先用 **`cProfile`** 找"哪个函数占大头"，再用 **`line_profiler`** 看"函数里哪一行慢"，微基准用 **`timeit`**，线上不侵入用 **`py-spy`**。
> 顺序很重要：**先定位到函数，再定位到行**，别一上来就猜。

## 讲深一层

```bash
python -m cProfile -s cumulative script.py | head -20
```

```python
import cProfile, pstats
cProfile.run("main()", "prof.out")
pstats.Stats("prof.out").sort_stats("cumulative").print_stats(15)
```

| 工具 | 粒度 | 用途 |
|---|---|---|
| `cProfile` | 函数级 | 找热点函数 |
| `line_profiler` | 行级 | 找热点行 |
| `timeit` | 代码片段 | 微基准（多次取最小） |
| `py-spy` | 采样 | **线上/生产**，无需改代码 |
| `memory_profiler` | 行级内存 | 找内存增长点 |

**看哪个列**：`cumulative`（含子调用）找"整体耗时大户"，`tottime`（不含子调用）找"自己耗时长"的函数。两者要一起看。

**cProfile 的局限**：对每个函数调用都有开销，会**放大函数调用密集的代码**的耗时；纯 C 扩展内部的耗时它看不到。

**线上排查用 py-spy**：`py-spy top --pid 1234` 直接看实时火焰，不需要重启服务、不需要装依赖。

## 高频追问

1. **cProfile 会让程序变慢多少？** —— 明显变慢（2–5 倍），但相对比例仍有效。
2. **为什么用 `timeit` 不用 `time.time()`？** —— `timeit` 多次重复取最小值，抵消系统噪声。
3. **火焰图怎么生成？** —— `py-spy record -o prof.svg --pid`。

## 易错点

- 凭直觉优化
- 只看 total 不看 cumulative/tottime
- 用 `time.time()` 单次测量下结论
