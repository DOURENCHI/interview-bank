## 题目

**场景**：跨进程共享内存读写的追问题。**怎么避免 Python 进程读取共享内存时读串/越界？**

## 口述答案

> 共享内存只是裸内存，防串读靠**协议 + 同步**两件事：
> 1. **固定布局协议**：头部定长（如 64B：magic + 数据长度 + 校验 + 序号 + 状态标志），数据区紧跟其后。读取方先读头部拿到本条数据的真实长度，再按长度读，永远不越过写入方写好的边界；
> 2. **同步互斥**：写入方写完置序号/标志，读取方校验（序号变化 + CRC 一致）才算读到完整一条；进程间用 `multiprocessing.SharedMemory` + `semaphore`，或 mmap + `fcntl` 锁；
> 3. **边界自检**：读到的长度 > 缓冲区容量直接报错丢弃，别硬读——这是最后一道防线。
> Python 侧注意：`multiprocessing.shared_memory.SharedMemory` 要用 `buf[:n]` 切片读，切片长度必须来自头部字段且被 clamp 过。

## 讲深一层

```python
hdr = struct.unpack_from("<IIQ", shm.buf, 0)
magic, n, seq = hdr
if magic != 0x4D534747 or n > MAX_LEN:
    raise BufferError("bad header")      # 防越界第一关
data = bytes(shm.buf[HDR:HDR + n])       # 按头部长度读
```
C 写入端对应 `memcpy(hdr+HDR, data, n)` 后加写屏障再更新 seq（x86 上 store 有序，arm 需要 `__atomic_store_n` release 语义）。

## 高频追问

1. **读到一半写入方覆盖了怎么办？** —— 双缓冲/环形缓冲 + 序号，读的时候固定引用旧槽。
2. **为什么不用 pickle 直接存对象？** —— 版本与内存布局不可控，跨语言共享用定长 struct 字节协议。

## 易错点

- 相信"读了就会得到完整数据"——没有协议和校验，读到撕裂数据是常态
- Python 侧直接 `bytes(shm.buf)` 把整块共享内存读出来，越过头部协议
