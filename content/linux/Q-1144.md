## 题目

**问**：**从建立共享内存映射到删除，完整流程涉及哪些 API？每一步在做什么？**

## 口述答案

> POSIX 风格五步：
> ```c
> int fd = shm_open("/my_shm", O_CREAT|O_RDWR, 0666);  /* ① 创建/打开共享对象 */
> ftruncate(fd, size);                                  /* ② 定大小（新建必须） */
> void *p = mmap(NULL, size, PROT_READ|PROT_WRITE,
> MAP_SHARED, fd, 0);                    /* ③ 映射进本进程 */
> /* 各进程像访问普通内存一样读写 p（同步自加信号量） */
> munmap(p, size);                                      /* ④ 解除映射 */
> shm_unlink("/my_shm");                                /* ⑤ 删除对象（最后一个使用者后销毁） */
> ```
> ①在 `/dev/shm` 下建一个 tmpfs 文件作为共享对象；③由内核把同一批物理页映射进各进程页表；⑤是引用计数语义，unlink 后已映射的进程仍能用，新 open 才会失败。
> System V 那套是 `shmget/shmat/shmdt/shmctl`，功能等价，新代码建议 POSIX。

## 讲深一层

同步必须另配：信号量 `sem_open("/my_sem",...)` 或文件锁——共享内存只负责"共享"，不管互斥。调试看 `ls /dev/shm`、`ipcs -m`（SysV）。

## 高频追问

1. **忘了 ftruncate 会怎样？** —— 对新建空对象 mmap 后访问直接 SIGBUS，因为页面不存在。
2. **进程崩溃映射会泄露吗？** —— 映射随进程消失；但 shm 对象在 /dev/shm 里留着，要 shm_unlink 清理。

## 易错点

- 新建后不 ftruncate 直接用——SIGBUS 很难查
- 把 shm_unlink 当成"立即删除内存"——它只删名字，等最后一个映射消失才真正释放
