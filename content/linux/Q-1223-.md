## 题目

**背景**：嵌入式群里最常见的争论：临界区到底用 mutex 还是 spinlock。
**问**：互斥锁和自旋锁有什么区别？获取不到锁时各自会怎样？

## 口述答案

> 行为差异就一个字：等的方式。mutex 拿不到锁就**睡**——线程被挂到等待队列、让出 CPU，等持锁者解锁后被唤醒；代价是上下文切换，好处是不占 CPU。自旋锁拿不到就**原地转**——忙等循环反复试，代价是白烧 CPU，换来的是持锁者一解锁立刻接上，没有切换延迟。所以选型看临界区长度：几条指令的极短临界区用自旋锁合算，切换开销比等的时间还长；临界区长或要睡眠（拿内存、IO）必须 mutex。还有一条硬规则：中断上下文不可睡眠，只能用自旋锁。单核系统里自旋锁退化成"关中断"，因为自旋等一个永远调度不到的持锁者就是死锁。

## 讲深一层

| | mutex | spinlock |
|---|---|---|
| 等待方式 | 睡眠让出 CPU | 忙等 |
| 适合 | 临界区长 / 可睡 | 极短 / 中断上下文 |
| 代价 | 上下文切换 µs 级 | 空转烧 CPU |
| 单核形态 | 正常睡眠 | 关中断 |

## 高频追问

1. 持自旋锁时能调用可能睡眠的函数吗？——绝对不能，包括 kmalloc(GFP_KERNEL)
2. 自适应自旋锁是什么？——先自旋一小段，超时再睡，兼顾两者

## 易错点

- 在 ISR 用 mutex
- 单核上用纯自旋锁不关中断
