## 题目

**背景**：性能分析工具题，面试官想确认你是否真用 perf 定位过问题。

**问**：perf 工具用过吗？cycles、instructions 这些统计值是什么意思？

## 口述答案

> cycles 是核心时钟周期数，反映耗时；instructions 是退休指令条数，反映干了多少活。两者比值就是 IPC，衡量流水线效率：IPC 低说明有 stall，常见原因是 cache miss、分支预测失败或长依赖链。还看 cache-misses、branch-misses 等指标。用 perf stat 看总量，perf record 加 report 定位到函数和指令。

## 讲深一层

```bash
perf stat -e cycles,instructions,cache-misses,branch-misses ./app
perf record -g ./app && perf report
```

| 指标 | 含义 | 异常信号 |
|---|---|---|
| IPC | insn / cycle | <1 通常有 stall |
| cache-miss rate | miss / refs | >5% 需关注 |
| branch-miss rate | miss / branches | >2% 偏高 |

注意：多核、变频、虚拟化下 cycles 可能不精确，需固定频率对比。

## 高频追问

1. **IPC 高就一定好吗？** —— 不一定，可能是在跑大量空转指令，要结合任务完成时间看。
2. **怎么区分前端瓶颈和后端瓶颈？** —— 看 frontend stalls 与 memory-bound 指标，结合 `perf stat -d`。
3. **采样和计数有什么区别？** —— stat 是计数，record 是周期采样，采样有偏差但能定位热点。

## 易错点

- 把 cycles 当成"CPU 使用率"
- 只看 IPC 不看绝对耗时
- 在变频环境下直接对比两台机器的 cycles
