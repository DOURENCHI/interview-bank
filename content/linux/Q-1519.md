## 题目

**题目**：面试必问的 TCP 三次握手四次挥手，追问"为什么不是两次""为什么挥手要多一次"。

**问**：TCP 三次握手和四次挥手为什么是 3 和 4？

## 口述答案

> **握手 3 次**是为了让双方都确认"我的发送和接收都正常"：SYN（我能发）→ SYN+ACK（我能收也能发）→ ACK（我能收）。两次的话服务端无法确认客户端能收到自己的包。
> **挥手 4 次**是因为 TCP 是**全双工**，两个方向要分别关闭：FIN → ACK（对方可能还有数据要发）→ FIN → ACK。中间的 ACK 和 FIN 不能合并，所以比握手多一次。

## 讲深一层

```
握手：C --SYN--> S
      C <--SYN+ACK-- S
      C --ACK--> S
挥手：C --FIN--> S
      C <--ACK-- S      （S 可能还有数据）
      C <--FIN-- S
      C --ACK--> S      （进入 TIME_WAIT）
```
- **TIME_WAIT 为什么等 2MSL**：保证最后一个 ACK 能到达（丢了可重发），并让旧连接的残留包在网络中消失。
- 大量 TIME_WAIT 的应对：`SO_REUSEADDR`（重启端口）、调 `tcp_tw_reuse`，但不要盲目调小 `tcp_fin_timeout`。

## 高频追问

1. **SYN 泛洪怎么防？** —— SYN cookie、增大半连接队列、限速。
2. **TIME_WAIT 在哪一端？** —— 主动关闭方。

## 易错点

- 说"两次握手就够了"
- 把 TIME_WAIT 说成 1 个 MSL
