## 题目

**问**：`>`、`>>`、`|`、`2>&1` 分别是什么？为什么 `2>&1 > file` 和 `> file 2>&1` 结果不同？

## 口述答案

> `>` 是覆盖写、`>>` 是追加、`|` 把前一个命令的 stdout 接到后一个的 stdin。
> `2>&1` 是把「标准错误」指向「标准输出当前指向的地方」——
> 注意是**当前指向**，所以顺序很重要。
> `> file 2>&1` 先让 stdout 指向 file，再让 stderr 跟着 stdout 走，两者都进文件；
> `2>&1 > file` 先让 stderr 跟着当时的 stdout（还是终端），再把 stdout 改到 file，
> 结果 stderr 仍打终端。

## 讲深一层

| 符号 | 含义 |
|---|---|
| `>` | stdout 覆盖重定向 |
| `>>` | stdout 追加 |
| `2>` | stderr 重定向 |
| `2>&1` | 把 fd 2 指向 fd 1 当前的目标 |
| `&>` | 两者都重定向（bash 扩展） |
| `<` | stdin 重定向 |
| `<<` | Here Document |
| `|` | 管道，前者 stdout → 后者 stdin |

重定向的求值顺序是**从左到右**，这是理解 `2>&1` 位置的关键。

## 高频追问

1. **管道两端是什么？** —— 前者 stdout 写进管道，后者 stdin 从管道读；两者并发执行。
2. **`tee` 干什么？** —— 既写文件又往 stdout 输出，用于「分流」。
3. **管道会丢数据吗？** —— 不会，但缓冲区满时写端会阻塞。

## 易错点

- ❌ 把 `2>&1` 写在 `>` 前面还想两个都进文件
- ❌ 以为管道是串行执行（实际并发）
- ✅ 记住「求值从左到右」
