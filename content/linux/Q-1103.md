## 题目

**背景**：面试官先问"多线程共享一个缓存怎么做同步"，候选人答"Python 有 GIL，不用锁"，于是被追问。

**问**：既然 CPython 有 GIL，为什么多个线程共用一个缓存时仍然可能需要加锁？

## 口述答案

> 结论：**GIL 只保证单条字节码原子，不保证业务操作原子**。缓存"读—算—写"三步之间线程可能被切走，两个线程都 miss、都回源、都写回；`counter += 1` 同样会丢更新。而且 GIL 在 I/O 和部分 C 扩展里会释放，临界区真正并行。所以只要存在**跨对象的复合不变式**（cache 与 DB 一致、LRU 链表与字典同步），就必须用 `threading.Lock` 保护。

## 讲深一层

```python
# 错误：check-then-act 存在竞态
if key not in cache:
    cache[key] = load(key)      # 两个线程都会 load

# 正确：双重检查 + 锁
with lock:
    if key not in cache:
        cache[key] = load(key)
```
| 场景 | GIL 能否保护 |
|---|---|
| 单次 `dict[k] = v` | 能（C 层原子） |
| `d[k] += 1` | 不能（LOAD/ADD/STORE 三步） |
| 复合不变式 | 不能 |
| 含 I/O 的临界区 | 不能（GIL 被释放） |

## 高频追问

1. **那不加锁会怎样复现？** —— 开 8 个线程对同一 key 并发 get-or-load，在 load 里 `sleep(0.01)` 放大窗口，统计 load 调用次数，通常远大于 1。
2. **用 `dict` 的 `setdefault` 够吗？** —— 够做单 key 的原子占位，但 `setdefault(k, load(k))` 的 `load` 会被无条件求值，仍需先判断；且无法保护多 key 的一致性。
3. **替代方案？** —— 单线程 + 队列、`functools.lru_cache`（内部有锁）、或直接用 Redis 的 `SET NX` 做跨进程互斥。

## 易错点

- 认为"有 GIL 就没有竞态"，忽略字节码间隙与 I/O 释放
- 用 `threading.Lock` 保护了写却忘了读，读到半更新状态
- 持锁做网络/磁盘 I/O，把并发退化成串行
