## 题目

**题目**：`i++` 在多线程下丢更新，那 `std::atomic<int>::fetch_add` 为什么就不会？

**问**：什么是原子操作？它是怎么保证不被中断的？

## 口述答案

> 原子操作是**不可分割**的操作：其他线程要么看到它完全没发生，要么看到它已经完成，绝不会看到中间状态。
> 实现靠**硬件指令**（x86 的 `lock xadd`、ARM 的 `ldrex/strex` 或 `LDXR/STXR`），CPU 保证这条指令执行期间总线/缓存行被独占，不需要关中断。

## 讲深一层

```cpp
std::atomic<int> cnt{0};
cnt.fetch_add(1);              // 原子加
cnt++;                         // 也是原子的（重载了）
int expected = 0;
cnt.compare_exchange_strong(expected, 1);   // CAS
```
| 手段 | 粒度 | 代价 |
|---|---|---|
| `atomic` | 单个变量 | 一条带 lock 前缀的指令 |
| `mutex` | 任意临界区 | 系统调用（无竞争时较轻） |
| 关中断 | 单核 | 影响实时性 |
- `atomic` 只保证**单变量**原子；多变量保持一致仍要锁。
- 内存序：默认 `seq_cst` 最安全，`relaxed` 最快但要自己推理。
- `atomic<int>` 不一定无锁（`is_lock_free()` 可查）。

## 高频追问

1. **`atomic` 是无锁的吗？** —— 通常对整型是指令级无锁，大对象可能退化成内部加锁。
2. **`volatile` 能替代吗？** —— 不能，它不保证原子性和内存序。

## 易错点

- 用 `volatile` 做原子操作
- 以为 `atomic` 能保护多个变量的不变量
