## 题目

**题目**：串口中断里直接 `printf` 加解析协议，结果主循环卡顿、偶尔丢数据。

**问**：ISR 为什么要短？为什么必须清标志？

## 口述答案

> 因为 ISR 执行期间**同级和低优先级中断无法响应**（高优先级还能抢占），时间一长，实时性就崩了。而且 ISR 用的是主栈，深度调用可能溢出。
> **必须清标志**是因为硬件不会自动清——不清就退出，中断线仍处于挂起状态，会立刻再次进入，形成"进中断出不来"的死循环。

## 讲深一层

```c
// ❌ ISR 里做重活
void USART1_IRQHandler(void) {
    char buf[64];
    sprintf(buf, "rx: %d\n", data);     // 吃栈 + 慢
    uart_send(buf);                     // 阻塞
    parse_protocol(buf);                // 长逻辑
}

// ✅ ISR 只搬运，逻辑交给主循环/任务
void USART1_IRQHandler(void) {
    BaseType_t woken = pdFALSE;
    uint8_t d = USART1->DR;             // 读 DR 顺带清 RXNE
    xQueueSendFromISR(rx_q, &d, &woken);
    portYIELD_FROM_ISR(woken);
}
```

| ISR 里禁止 | 原因 |
|---|---|
| `printf` / `sprintf` | 慢、吃栈、不可重入 |
| `HAL_Delay` / `vTaskDelay` | 阻塞 |
| `malloc` | 不确定耗时 |
| 长循环/协议解析 | 拖长中断 |
| 浮点大量运算 | 上下文切换开销 |

**ISR 的正确结构**：读数据 → 清标志 → 投递到队列/信号量 → 快速返回。真正的处理在主循环或任务里做。

**"短"的量化**：一般建议 ISR 执行时间 < 10 μs；有硬实时要求时更短。

## 高频追问

1. **清标志和读 DR 是一回事吗？** —— 对 USART 的 RXNE，读 SR 再读 DR 就清了；其他外设可能要写 0。
2. **ISR 里能调用 HAL 的阻塞函数吗？** —— 不能，只能用 `_IT`/`_DMA` 版本。
3. **怎么量 ISR 时间？** —— 进 ISR 拉高一个 IO，出来拉低，示波器看脉宽。

## 易错点

- ISR 里 `printf`
- ISR 里不清标志，反复进入
- 长逻辑写在 ISR 里，主循环饿死
