## 题目

**场景**：两份面经连环追问 I2C 挂死：原力灵机（机器人公司）问「I2C 卡死怎么处理」；智元机器人追问「SDA 被拉低的原因」以及「为什么标准恢复方法是发 9 个时钟脉冲」。这是 I2C 方向的必考深度题。

**问**：I2C 总线卡死的现象和原因是什么？9 个时钟脉冲恢复的原理是什么？代码和预防怎么设计？

## 口述答案

> **卡死的现象**：SCL 正常、**SDA 被从设备一直拉低**——主机发停止条件（SCL 高时 SDA 由低变高）发不出来，总线永久占用，所有后续传输都超时。I2C 是开漏+线与：**任一设备拉低，总线就是低**。
> **怎么卡死的**：从设备在**ACK 或读数据某一步被主机复位/干扰打断**——比如主机读到一半被复位重启，从机还停在「该输出一个 0 位」的状态，死死拉着 SDA 等一个永远不会来的时钟。
> **9 个时钟的原理**：**手动在 SCL 上打时钟脉冲，每打一个，从机内部移位一次、SDA 上的位就吐出一个**；最多 9 个是因为**一个字节 8 位 + 1 个 ACK 位**——打满 9 拍，从机必然走完「当前字节+ACK」的完整回合，回到等待下一个 START 的空闲态，松开 SDA。打完检测 SDA 是否已释放：释放了就补发一个 STOP（或 START+STOP）彻底复位总线状态机，然后正常重试；**还没释放**说明不是移位卡死（可能是硬件故障/供电异常），走错误分支：重试限次、必要时**对从设备断电复位**。
> **代码骨架**：GPIO 把 SCL 从外设接管改回**软件推挽/开漏输出**，打 9 个脉冲（100kHz 节奏、每拍留足延时），逐拍检查 SDA；恢复后把 SCL 还给外设。
> **预防**：每次传输**带超时**（等待事件不能死等）；初始化前先**探测总线**（SDA/SCL 是否高电平），不正常先跑恢复序列；关键从设备**供电可独立控制**，留最后手段；复杂系统优先选带**硬件超时/总线清除功能**的外设（不少新 MCU/外设支持 SMBus 超时或自动总线清除）。

## 讲深一层

```c
/* I2C 总线卡死恢复：9 个时钟脉冲 */
void i2c_bus_recover(void) {
    gpio_set_af(scl_pin, GPIO_FUNC_GPIO);      /* SCL 改软件控制 */
    gpio_set_mode(scl_pin, GPIO_OUTPUT_OD);
    for (int i = 0; i < 9 && gpio_read(sda_pin) == 0; i++) {
        gpio_write(scl_pin, 0);  delay_us(5);  /* 手动打时钟 */
        gpio_write(scl_pin, 1);  delay_us(5);
    }                                          /* 每拍让从机移位吐一位 */
    if (gpio_read(sda_pin) == 0) {
        power_cycle_slave();                   /* 还拉低：硬件级手段 */
    } else {
        i2c_send_stop();                       /* 释放了：补 STOP 复位 */
        gpio_set_af(scl_pin, GPIO_FUNC_I2C);   /* SCL 还给外设 */
    }
}
```

**判断技巧**：答这题先讲清「线与」——SDA 低不一定是主机拉的，是「有人拉低」；然后按「打时钟→逐位吐出→9 拍覆盖字节+ACK→补 STOP」的因果链讲，最后必须提预防（超时/总线探测），只背 9 下不打表。**记忆锚点**：「8 位数据 1 位 ACK，9 拍吐完从机放线；放线补 STOP，不放就断电」。

## 高频追问

1. **为什么最多 9 个而不是 8 个？** —— 一个完整回合是 8 个数据位+1 个 ACK 位；从机可能停在回合中任何一拍，打满 9 拍保证走完整个字节+ACK，回到字节边界。
2. **发 STOP 前要保证什么？** —— SCL 高电平期间 SDA 产生上升沿才是合法 STOP；所以必须先确认 SDA 已被从机释放，否则发不出有效 STOP。
3. **SCL 也被拉死了怎么办？** —— 说明有从机正在拉低 SCL（时钟拉伸卡死或硬件故障），打脉冲无效，只能从设备断电复位或整板复位；排查供电和该设备状态。
4. **预防上还能做什么？** —— 所有 I2C 等待点带超时并返回错误码；系统级看门狗兜底；关键器件供电可控；上电先跑一次总线探测+恢复再初始化外设。

## 易错点

- 以为 SDA 低是主机问题——线与结构下是某个从机没松手。
- 打时钟不检查 SDA——打完 9 下就当恢复，其实可能还在拉低。
- 恢复后不补 STOP——从机状态机没复位，下一个传输又卡。
- 传输死等无超时——卡死后整个系统跟着挂，恢复机制都没机会跑。
