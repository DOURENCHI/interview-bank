## 题目

**题目**：`heap_3.c` 里为什么到处是 `vTaskSuspendAll()` / `xTaskResumeAll()`？

**问**：`heap_3` 为什么要暂停调度器？它和其他 heap 方案差在哪？

## 口述答案

> 因为 `heap_3` 直接调用 C 库的 `malloc/free`，而 **C 库的 malloc 不是线程安全的**——两个任务同时调用可能破坏内部的空闲链表。
> 暂停调度器保证调用期间不会发生任务切换，等价于"独占 malloc"。这就是它和其他方案的本质区别：别人自己管内存，它借 C 库的但要用调度器保护。

## 讲深一层

```c
// heap_3.c 的核心（简化）
void* pvPortMalloc(size_t xWantedSize) {
    void* pvReturn;
    vTaskSuspendAll();          // 禁止任务切换
    pvReturn = malloc(xWantedSize);
    xTaskResumeAll();
    return pvReturn;
}
```

| 方案 | 内存来源 | 线程安全手段 | 可释放 |
|---|---|---|---|
| `heap_1` | 静态数组 | 不需要（只分配） | ❌ |
| `heap_2` | 静态数组 | 挂起调度器 | ✅ |
| `heap_3` | **C 库 malloc** | 挂起调度器 | ✅ |
| `heap_4` | 静态数组 | 挂起调度器 | ✅（合并） |
| `heap_5` | 多块区域 | 同上 | ✅ |

**`vTaskSuspendAll` 和临界区的区别**：
- `vTaskSuspendAll` **只禁止任务切换，不关中断**，所以中断仍能响应（但中断里不能调 malloc）；
- `taskENTER_CRITICAL` **关中断**，时间必须极短。

**`heap_3` 的适用场景**：C 库 heap 已经够大、且你希望 FreeRTOS 和 `printf` 共用同一块内存（省 RAM）。

## 高频追问

1. **`heap_3` 有什么风险？** —— C 库 heap 太小会失败；`malloc` 的实现质量不可控。
2. **中断里能调 `pvPortMalloc` 吗？** —— 不能，任何 heap 方案都不允许。
3. **`vTaskSuspendAll` 能嵌套吗？** —— 能，内部有计数。

## 易错点

- 用 `heap_3` 但 C 库 heap 只有 0x200
- 在中断里调 `malloc` / `pvPortMalloc`
- 以为 `vTaskSuspendAll` 会关中断
