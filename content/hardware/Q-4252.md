## 题目

**问**：串口/总线上大消息要分片传输，现场又有多台设备并发，出现丢片和时序冲突，你会用哪些方案解决？

## 口述答案

> 分两层解决。
> **分片完整性**：帧头 + 序号 + 总片数 + 负载长度 + CRC，接收端按序号重组，缺片用超时或位图发现，再按序号请求重传；发送端保留窗口，收到 ACK 才滑窗前移。粘包靠长度字段定界，不靠"读一次就是一帧"。
> **并发时序**：物理层用总线仲裁（CAN）或主从轮询（Modbus）避免撞车；应用层给每台设备分配时隙或令牌，共享总线加互斥锁，发送队列按优先级排队。重传必须带序列号做幂等，否则重发会变成重复写。

## 讲深一层

| 问题 | 手段 |
|---|---|
| 丢片 | 序号 + 位图 + 超时重传 + 窗口 ACK |
| 粘包/半包 | 帧头魔数 + 长度字段 + CRC 校验 |
| 多设备撞车 | 主从轮询 / TDMA 时隙 / 令牌 / 总线仲裁 |
| 重传重复 | 序列号 + 接收端去重表 |
| 缓冲不足 | 环形缓冲 + 背压（拒收/流控） |

## 高频追问

1. **为什么不用固定延时错开？** —— 延时随负载抖动，设备多了必然撞；时隙或轮询才是确定性的。
2. **重传几次放弃？** —— 按业务定，一般 3 次；超过就上报链路故障，不要无限重试把总线拖死。
3. **CRC 够吗？** —— 抗随机误码够用，抗恶意篡改要用 MAC/签名。

## 易错点

- 只加 CRC 不做分片重组，长包一断就整帧丢弃。
- 多设备靠"谁先发谁占线"，没有仲裁就会互相踩。
- 重传不做幂等，导致重复执行。
