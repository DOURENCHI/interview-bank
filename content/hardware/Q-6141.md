## 题目

**场景**：三份面经都考多核：未注名公司问「两个核的 MCU 你怎么分配任务、共享内存怎么处理」；拓竹科技（嵌入式软件岗）问 MCU 与 Linux 主控怎么交互、协处理器怎么用；兆易创新问「双核/多核间的同步」。候选人的项目正是「双核 MCU：一个核跑传感器采样与实时控制，另一个核跑协议栈与通信」。

**问**：双核 MCU 的任务划分原则是什么？核间通信/同步怎么做？多核启动顺序与看门狗怎么设计？

## 口述答案

> **任务分配按「实时性+耦合度」切，不按核数平摊**：**核 A（M4 等强实时核）**放硬实时的活——中断驱动的传感器采样、电流环/位置环控制、PWM 输出；**核 B（M0 等协核）**放协议与交互的活——通信栈、人机接口、日志、非实时业务。划分标准是**耦合最小化**：两个核各管一摊，核间只传必要数据，不要把一个功能拆到两个核上跑——拆开则每次交互都要同步，得不偿失。**中断尽量固定在各自核**，跨核共享的外设要么一核独占、要么明确仲裁。
> **核间通信用「共享内存+硬件邮箱+中断」三板斧**：数据放**共享 RAM**，用**硬件邮箱（mailbox/ipi）**发「有新数据」的通知，通知到达触发对方核中断。共享数据的一致性靠**临界区/自旋锁（硬件信号量 HSEM）+缓存管理**——这是最容易翻车的地方：若核有 D-Cache，**共享内存要配 Cache 一致性策略**（该区域不开 Cache 或每次收发做 clean/invalidate），否则核 B 读到的是自己 Cache 里的旧值。
> **核间队列**最好用**无锁单生产者单消费者环形缓冲**：写指针只归生产者、读指针只归消费者，配合内存屏障，天然免锁。
> **启动顺序**：通常是**主核先起**（跑 bootloader 初始化时钟/内存/外设），再**拉起从核**（释放其复位、把入口地址写进从核向量寄存器）；从核起来后向主核发「就绪」信号，主核才下发配置。**看门狗**：每个核独立喂各自的窗口看门狗，任一核饿死都能独立复位它，不能让一个核代喂另一个核的狗——那就测不出它死没死。
> **MCU 与 Linux 主控分工**（拓竹场景）：MCU 管毫秒级以下的实时 IO，Linux 管业务/网络/UI，之间用 UART/SPI/共享内存+心跳协议交互，协议要带序号和校验，防串扰和丢包。

## 讲深一层

| 设计点 | 做法 | 典型翻车 |
|---|---|---|
| 任务划分 | 实时核/非实时核分治 | 一个功能拆两核，同步开销吃光收益 |
| 核间数据 | 共享 RAM+SPSC 环形队列 | 直接互斥锁全包，临界区超长 |
| 一致性 | 硬件信号量+Cache 规避 | 忘了 Cache，读到旧值 |
| 通知 | 硬件邮箱+核间中断 | 只靠轮询，实时性差 |
| 看门狗 | 各核独立窗口狗 | 一核代喂，测不出对方死活 |

**判断技巧**：多核题的核心考点是「数据一致性」——任务分配讲完必须主动讲到 Cache 一致性和内存屏障，这是面试官在等的那一层；只答「一个核跑 A 一个核跑 B」只算入门。**记忆锚点**：「实时一核、协议一核；共享内存、邮箱通知；信号量锁、Cache 要清；各自喂各自的狗」。

## 高频追问

1. **为什么共享内存要管 Cache？** —— 核写共享区后若只 clean 不及时、或对方读前不 invalidate，读到的都是各自 Cache 的旧副本；要么共享区映射成不缓存，要么严格按「写后 clean、读前 invalidate」纪律管理。
2. **自旋锁和互斥量在核间怎么选？** —— 核间没有统一调度器，硬件信号量+自旋等是唯一低开销手段，且临界区必须极短；RTOS 内任务间才用互斥量，跨核通信基本都走队列+邮箱。
3. **从核崩溃主核怎么知道？** —— 心跳+独立看门狗：从核周期喂狗和上报心跳，主核检测超时后按策略复位从核并告警；不能靠主核代喂从核的狗。
4. **双核启动顺序能反过来吗？** —— 看芯片引导设计：多数是主核先起再放行从核；关键是「谁先谁后都要有明确的握手」——从核就绪信号是主核下发运行配置的前提。

## 易错点

- 任务按核数对半分——不看实时性和耦合度，同步开销反噬。
- 共享数据不上锁也不用队列——「反正写完就读」在 Cache 面前不成立。
- 通知全靠轮询——延迟不可控，浪费 CPU。
- 看门狗一个核代喂两个——失去独立检测能力。
