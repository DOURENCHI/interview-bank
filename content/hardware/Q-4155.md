## 题目

**题目**：HAL 里 `HAL_UART_RxCpltCallback` 定义在 `stm32f1xx_hal_uart.c` 里，是空的，但我在 `main.c` 里重写一个同名的就能生效。

**问**：`__weak` 是什么？为什么能被覆盖？如果不加会怎样？

## 口述答案

> `__weak` 是**弱符号**声明：链接器允许同名的强符号覆盖它。HAL 用弱符号提供"空实现"，用户重定义就自动生效——这是 C 语言里实现"可选回调"的标准手法。
> 如果不加 `__weak`，用户重定义会报 `multiple definition`（重复定义）。

## 讲深一层

```c
// HAL 里（弱定义）
__weak void HAL_UART_RxCpltCallback(UART_HandleTypeDef* huart) {
    UNUSED(huart);            // 默认什么都不做
}

// 用户代码里（强定义，覆盖）
void HAL_UART_RxCpltCallback(UART_HandleTypeDef* huart) {
    if (huart->Instance == USART1) { /* ... */ }
}
```

| 符号属性 | 含义 | 冲突时 |
|---|---|---|
| 强符号（默认） | 普通定义 | 报重复定义 |
| `__weak` | 弱定义 | 强符号覆盖它 |
| 两个弱符号 | 都弱 | 任选一个（不确定） |
| 无定义 | 未定义 | 链接错误 |

**`__weak` 的底层**：GCC 用 `__attribute__((weak))`，编译出的符号是弱符号，链接器按"强优先"规则选择。

**相关坑**：`__weak` 函数里如果调了 `Error_Handler()` 死循环，说明你**没实现回调**，程序卡在默认实现里——这是新手常见困惑"为什么我的回调没被调用"。

## 高频追问

1. **能覆盖非弱函数吗？** —— 不能，会重复定义。
2. **`__weak` 和 `inline` 有关系吗？** —— 没关系，前者是链接属性。
3. **怎么确认覆盖成功了？** —— 在回调里点灯，或看 map 文件里符号地址。

## 易错点

- 回调签名写错（参数类型不对），变成新函数而不是覆盖
- 以为覆盖了但程序仍进默认实现（签名不符）
- 两个源文件都定义了强符号
