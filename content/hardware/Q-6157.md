## 题目

**场景**：沁恒微电子（CH32V RISC-V MCU 原厂）校招面：「从复位入口开始，CH32V20x 启动代码要完成哪些初始化才能安全进入 main」「编译能过但烧录后程序不运行，怎么检查启动文件、链接脚本、向量表和芯片型号」「RISC-V 内核的异常入口和 Cortex-M 有哪些差异」；兆易创新（GD32 MCU 原厂）也问「Cortex-M 从复位向量到 main 经历哪些步骤」。

**问**：通用启动流程是什么？RISC-V 与 Cortex-M 的机制差异？烧录成功却不运行的排查链？

## 口述答案

> 通用流程六步：**①复位向量取入口 → ②关中断+初始化栈指针 → ③时钟初始化（HSI 起步，按需切 PLL）→ ④内存初始化：.data 从 flash 搬到 RAM、.bss 清零 → ⑤C 运行时准备 → ⑥跳 main**。`.data` 必须搬是因为初值掉电要保存在 flash，运行时变量却活在 RAM；`.bss` 清零是因为 C 标准保证未初始化全局变量为 0。
>
> **架构差异**：**Cortex-M 硬件包办得多**——向量表由 VTOR 定位，复位时硬件自动从向量表 [0] 取 SP、[1] 取 Reset_Handler，中断由向量表直接分发；**RISC-V（CH32V）这些要软件自己做**——启动代码手动 `la sp, _eusrstack` 装栈指针、手动 `csrw mtvec` 设异常入口（CH32V 是集中入口+分发），中断上下文保存的约定也和 Cortex-M 不同。**移植启动代码最容易漏的就是 mtvec 没设/设错和 sp 没装**——编译能过，一跑就飞。段地址全由**链接脚本**决定：flash 基址、RAM 起止、_eusrstack 符号都从这来。
>
> **烧录后不运行的排查链**：①**下载器日志**——校验是否真过、擦写是否成功；②**链接地址 vs 芯片 flash 基址**——同系列不同型号 RAM/Flash 大小不同，bootloader 是否占了头部；③**向量表偏移**——有 bootloader 跳转时 VTOR/mtvec 要加偏移；④**时钟/晶振**——外部晶振没焊或频率不符，PLL 起不来就卡死；⑤**看门狗/读保护**——读保护开着仿真器连不上，看门狗没喂就反复复位。

## 讲深一层

| 步骤 | Cortex-M | RISC-V（CH32V） |
|---|---|---|
| 栈指针 | 硬件从向量表[0]自动装载 | 启动代码 la sp 手动装 |
| 异常入口 | VTOR 指向量表，硬件分发 | csrw mtvec 指集中入口 |
| 复位入口 | 向量表[1] 硬件跳转 | 复位地址固定，代码自己组织 |
| .data/.bss | 启动文件搬运/清零 | 同左，符号来自链接脚本 |

**判断技巧**：六步流程先背熟，差异题落到「谁做」——M 核硬件做、RISC-V 软件做；排查题按「从下载器到芯片」由外向内的顺序讲，显出方法论。**记忆锚点**：「M 核硬件送 SP，V 核自己设 mtvec 和 sp；不运行先查下载日志，再对链接地址和向量偏移」。

## 高频追问

1. **`.data` 为什么必须从 flash 搬？** —— 已初始化全局变量的初值要掉电保存，编译时存 flash；运行时变量在 RAM，启动代码不搬，全局变量读出来全是 0。
2. **bootloader 场景向量表怎么处理？** —— 应用向量表不在芯片默认基址：Cortex-M 重设 VTOR 到应用基址，CH32V 同理把跳转目标/异常入口加偏移；链接脚本同步改。
3. **烧录成功但串口无输出，第一反应？** —— 别先改代码：看下载器校验日志、示波器抓复位脚和晶振是否起振，再核对时钟树配置和实际硬件频率。
4. **中断向量可以放 RAM 吗？** —— 可以，VTOR/mtvec 都可重定向到 RAM；改向量表时内容和偏移要一致，中断频繁的场景放 RAM 还能省 flash 等待周期。

## 易错点

- 拿 Cortex-M 启动文件直接套 RISC-V——mtvec/sp 机制不同，编译过不等于跑得动。
- 改链接脚本不同步启动文件——_eusrstack 对不上，栈插进别的段中间。
- 排查不先看下载器日志——工具早就报了校验错误，还在埋头读代码。
- 忽略同系列型号差异——RAM/Flash 大小不同的型号共用一份链接脚本，地址越界跑飞。
