## 题目

**场景**：未注名公司（MCU+GUI 语境，同场连问 SPI 屏和 DMA）：「LVGL 的屏幕刷新机制是什么？底层如何实现」「图片资源一般存哪里、怎么加载」「常用图像格式有哪些区别」「显示缓冲区设多大、为什么」。

**问**：从脏区到屏幕的完整链路？三种 buffer 模式怎么选？图片放哪最合适？

## 口述答案

> 刷新主线：**脏区合并 → 渲染到 draw buffer → flush 回调搬运到显存**。LVGL 由内部定时器驱动（默认刷新周期约 30ms）：控件变化时先标记脏区（invalidate），刷新时把重叠脏区合并成尽量少的矩形，逐块渲染进你分配的 draw buffer，再调你注册的 flush 回调把像素写进屏幕——SPI 屏走 SPI 发送，RGB 屏写帧缓冲。**flush 是异步的**：DMA/SPI 传输完成后要调 flush_ready 通知 LVGL 才能继续，不调它刷新就卡住。
>
> **buffer 三种模式**：**单 buffer**（一块 draw buffer，渲染和传输串行，最省内存但可能撕裂）；**双 buffer**（一块在渲染、一块在传输，交替进行，流畅主流）；**全尺寸 buffer**（整屏大小，可局部重绘零撕裂，最占内存）。小 RAM 设备常用「1/10 屏大小的双 buffer」折中。有 DMA2D（Chrom-ART）就让它做填充/拷贝/混合加速，别让 CPU 手搬。
>
> **图片资源三放法**：**内置 C 数组**（编译进固件，const 进 flash，免文件系统）；**文件系统**（SD/FatFS，运行时读取，灵活但慢）；**XIP flash 内存映射**（QSPI flash 映射成内存地址，零拷贝直接读）。**格式与成本**：RGB565 无 alpha 2 字节直渲最快；ARGB8888 带透明 4 字节；**A8** 只有 alpha 通道配前景色，字体和单色图标最省；palette 索引色 1/2/4/8bpp+调色板。原生格式直接搬运，PNG/JPG 要解码——**解码型格式必须先转成原生格式缓存**，否则每次绘制都解一遍，帧率崩。

## 讲深一层

| buffer 模式 | 内存占用 | 撕裂风险 | 适用场景 |
|---|---|---|---|
| 单 buffer | 1×块大小 | 可能 | RAM 极紧张 |
| 单全尺寸 buffer | 1×整屏 | 可能（无交换） | 折中：显存即缓冲 |
| 双 buffer | 2×块大小 | 基本无 | 主流选择 |
| 全尺寸双 buffer | 2×整屏 | 无 | RAM 富余、动画多 |

**判断技巧**：按「定时器驱动→脏区→渲染→flush」四步讲机制；buffer 大小题主动说「看 RAM 预算和撕裂要求」而不是报一个数。**记忆锚点**：「脏区合并、draw buffer 渲染、flush 搬运；单省双稳全无撕；RGB565 直搬最快，A8 字体最省」。

## 高频追问

1. **flush_ready 不调会怎样？** —— LVGL 一直等上一次 flush 完成的信号，刷新流程卡死、屏幕再也不更新；应在 DMA 传输完成中断里调它。
2. **撕裂是怎么产生的？** —— 屏幕正在读显存时渲染又往同一块写，上半新下半旧；双 buffer 交换或等传输完成再写可避免。
3. **图片放 QSPI flash 怎么提速度？** —— XIP 映射+原生格式免解码；还慢就换小格式（RGB565/A8）或把热点图预取进 RAM。
4. **屏上颜色不对/花屏是 LVGL 的锅吗？** —— 先分界：draw buffer 内容就对→渲染配置问题（RGB565 字节交换、颜色宏配错）；buffer 对屏上错→SPI/RGB 时序问题。

## 易错点

- draw buffer 配成整屏还开双份——RAM 直接爆，先算预算再配。
- flush 回调里死等 SPI 发完——刷新卡死，应 DMA+中断里 flush_ready。
- PNG/JPG 直接当纹理用——每帧解码，帧率崩；先转原生格式。
- 颜色不对先重配屏参——八成是 RGB565 字节序交换，先查软件再动硬件。
