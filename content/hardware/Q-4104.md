## 题目

**现象**：程序跑几分钟就死机，或者变量莫名其妙被改值，重启后又能跑一会。

**问**：任务栈给小了会有什么现象？怎么发现和定位？

## 口述答案

> 典型现象是**随机性故障**：栈溢出会踩坏相邻内存（通常是 TCB 或别的任务的栈），表现为变量被改、HardFault、任务跑飞、莫名重启——而且**位置每次都不一样**，极难复现。
> 发现手段：开启 `configCHECK_FOR_STACK_OVERFLOW`，用 `uxTaskGetStackHighWaterMark` 看余量。

## 讲深一层

```c
// FreeRTOSConfig.h
#define configCHECK_FOR_STACK_OVERFLOW 2    // 2 = 切换时检查 + 栈底填充值
```

```c
// 溢出钩子必须实现，否则链接失败
void vApplicationStackOverflowHook(TaskHandle_t xTask, char* pcTaskName) {
    taskDISABLE_INTERRUPTS();
    printf("STACK OVERFLOW in %s\n", pcTaskName);
    for (;;);
}
```

```c
// 定期检查余量（单位：字）
UBaseType_t hw = uxTaskGetStackHighWaterMark(NULL);
printf("stack left: %u words\n", hw);
```

| 检查级别 | 机制 | 开销 |
|---|---|---|
| 0 | 不检查 | 0 |
| 1 | 切换时看栈指针是否越界 | 小 |
| 2 | 加栈底填充图案（0xA5），切换时检查 | 略大，**推荐** |

**为什么级别 2 更好**：级别 1 只能发现"栈指针已经越界"，此时可能已经踩坏了数据；级别 2 通过填充图案能更早发现。

**定位方法**：看 `pcTaskName` 就知道是哪个任务；再看剩余水位历史最小值。**建议所有任务都定期打印水位**，尤其是在加了新功能之后。

## 高频追问

1. **水位多少算安全？** —— 剩余 ≥ 20–30% 比较稳；接近 0 就要加。
2. **中断也用任务栈吗？** —— Cortex-M 上中断用主栈（MSP），和任务栈分开，但中断里调用的函数也会吃栈。
3. **`printf` 会吃多少？** —— 视实现，几百字节很常见，带浮点更多。

## 易错点

- 不开栈溢出检查，出问题只能靠猜
- 只看当前余量不看历史最小值
- 加了新的 `printf` 却没重新评估栈
