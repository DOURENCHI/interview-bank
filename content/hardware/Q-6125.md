## 题目

**场景**：沁恒微电子面经原题：USB 收发过程中，端点缓冲区、应用层队列和中断回调之间如何管理所有权，避免数据被覆盖——USB 芯片厂最爱问的并发设计题。

**问**：USB 收发链路里，端点缓冲、应用队列和中断回调之间的数据所有权怎么设计，才能不被覆盖、不撕裂？

## 口述答案

> 直答：**一份缓冲区任一时刻只属于一个执行流，交接即「过户」**：DMA/硬件写端点缓冲（所有权在硬件）→ 传输完成中断 ISR 把数据拷出、或只把缓冲指针入队（所有权过到 ISR → 队列）→ 协议任务从队列取走处理（所有权归任务），用完归还空缓冲。**谁拥有谁读写，不拥有的不碰**，覆盖和撕裂就从机制上消掉了。
> 理由：竞态只出在两个地方——「硬件还在写、CPU 同时读」和「ISR 拷一半、任务开始改」。硬件级对策是**双缓冲乒乓**：硬件填 A 时软件处理 B，完成中断交换角色，收、发两个方向各一套互不踩；软件级对策是**ISR 只做交接不做处理**——拷出/入队+清标志立刻退出，协议解析放任务里。
> 应用层队列再挡一层：传输层和协议层速率不匹配，队列削峰。**队列满或帧要被覆盖时，宁可整条流断掉（复位端点、断开重枚举），也不把错帧交给上层**——USB 帧有序号和状态机，错帧后状态全乱，将错就错比断开重来更难恢复。

## 讲深一层

```c
/* 双缓冲 + 队列交接：全链路任何时刻只有一个「主人」 */
volatile uint8_t active = 0;
uint8_t epbuf[2][64];

void USB_IRQHandler(void) {          /* ISR：只交接，不处理 */
    if (xfer_complete) {
        uint8_t done = active;        /* 满缓冲所有权 → 队列 */
        active ^= 1;                  /* 硬件切到另一块继续填 */
        if (!queue_push(done))        /* 队列满：整帧放弃 */
            stream_reset_and_reenum();/* 宁可断开，不给错帧 */
    }
}
```

**判断技巧**：审一段收发代码有没有所有权问题，问三个问题——这块缓冲现在谁能写？交接发生在哪一行？队列里放的是数据还是指针？**放指针就必须有缓冲池回收**，入队后 ISR 与 DMA 不再碰它。**记忆锚点**：「DMA 产、ISR 交、任务收；乒乓轮流坐庄，满了宁可断线不给错帧」。

## 高频追问

1. **单缓冲为什么必踩？** —— DMA 还在写后半段，ISR 已来取前半段，取到的帧前后撕裂；要么 ISR 全量拷出再交接，要么双缓冲轮换。
2. **队列入队放数据还是指针？** —— 指针省一次拷贝，但要配缓冲池回收机制；拷贝实现简单，代价是 ISR 里 memcpy 时间，按实时预算选。
3. **Cache 一致性要不要管？** —— 带 Cache 的 MCU/SoC 上，DMA 写完后 CPU 读之前要 invalidate 对应 Cache 行，否则读到旧数据；无 Cache 的小 MCU 可略。
4. **为什么不能「丢一帧继续收」？** —— 协议帧靠序号维持状态机，丢帧后错序解析比断开更危险；断开重枚举让上下位机回到已知初始状态。

## 易错点

- ISR 里做协议解析——中断时间被拉长，下一帧来不及收；ISR 只交接。
- 队列满了还硬塞——覆盖旧数据正是错帧的根源，满即整流放弃。
- 缓冲池不回收——指针入队没人还，跑久了无缓冲可用。
- 共享标志不加 volatile/屏障——编译器把「等硬件写完」的判断优化掉。
