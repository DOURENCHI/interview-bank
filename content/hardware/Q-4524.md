## 题目

**题目**：一个任务要严格每 10 ms 采一次样，用 `vTaskDelay(10)` 写，采样周期越跑越长。

**问**：vTaskDelay 和 vTaskDelayUntil 有什么区别？

## 口述答案

> `vTaskDelay(n)` 是**相对延时**：从"调用这一刻"起等 n 个 tick。所以实际周期 = 等待时间 + 任务执行时间，会**累积漂移**。
> `vTaskDelayUntil(&last, n)` 是**绝对周期**：等到"上次唤醒时刻 + n"，会自动扣掉执行时间，周期严格。

## 讲深一层

```c
TickType_t last = xTaskGetTickCount();
for (;;) {
    sample();                          // 假设耗时 2 ms
    vTaskDelayUntil(&last, pdMS_TO_TICKS(10));   // 仍然每 10 ms 一次
}
```
| 场景 | 选择 |
|---|---|
| 周期性采样/控制 | `vTaskDelayUntil` |
| "隔一会儿再试" | `vTaskDelay` |
| 非固定周期 | `vTaskDelay` |
- 用 `vTaskDelayUntil` 时 `last` 必须是**每次更新的变量**，且任务执行时间不能超过周期（超了会连续唤醒，失去周期意义）。
- 第一个参数要求是上次唤醒的时间戳，初值用 `xTaskGetTickCount()`。

## 高频追问

1. **执行时间超过周期会怎样？** —— `vTaskDelayUntil` 立即返回，任务连跑，周期被压缩。
2. **精度受什么限制？** —— tick 分辨率（1000 Hz 就是 1 ms）。

## 易错点

- 用 `vTaskDelay` 做严格周期
- `last` 每次重新取 tick（退化成相对延时）
