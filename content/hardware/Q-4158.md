## 题目

**追问**：APB1 明明配成 36 MHz，为什么 TIM2/TIM3/TIM4 的时钟是 72 MHz？

**问**：APB1 上的定时器为什么是 72 MHz？其他外设呢？

## 口述答案

> 因为 STM32 的时钟树有一条特殊规则：**当 APB 预分频系数 ≠ 1 时，挂在 APB 上的定时器时钟 = APB 时钟 × 2**。
> F103 的 APB1 分频是 2，所以 APB1 = 72/2 = 36 MHz，而 TIM2–TIM7 = 36 × 2 = **72 MHz**。这条规则只对**定时器**生效，其他 APB1 外设（USART2、I2C1 等）仍然是 36 MHz。

## 讲深一层

```
SYSCLK 72 MHz
 ├─ AHB 72 MHz
 │   └─ APB2 (÷1) = 72 MHz  → GPIO/USART1/ADC1, TIM1/TIM8 = 72 MHz
 └─ APB1 (÷2) = 36 MHz
     ├─ USART2/3、I2C1/2、SPI2、CAN  → 36 MHz
     └─ TIM2~TIM7  → 36 × 2 = 72 MHz  ← 特殊规则
```

| 外设 | 时钟 |
|---|---|
| TIM1 / TIM8（APB2） | 72 MHz |
| TIM2–TIM7（APB1） | **72 MHz**（不是 36） |
| USART2（APB1） | 36 MHz |
| ADC（APB2，再分频） | ≤ 14 MHz |

**为什么这样设计**：定时器需要高分辨率，用高时钟能得到更细的计数；而总线本身跑 36 MHz 是为了功耗和时序。

**实际影响**：算 PWM 频率时用 72 MHz，算 USART2 波特率时用 36 MHz——**用错就全错，而且不报错**（只是频率偏一半）。

**怎么看真实时钟**：CubeMX 的 Clock Configuration 图，或运行时读 `HAL_RCC_GetPCLK1Freq() * (PCLK1 == HCLK ? 1 : 2)`。

## 高频追问

1. **F4 也这样吗？** —— 一样，规则适用于所有 STM32 系列。
2. **APB 分频设 1 呢？** —— 定时器就是 APB 时钟本身，不乘 2。
3. **怎么验证？** —— 输出 PWM 用示波器量，或用 `HAL_RCC_GetClockConfig` 读配置。

## 易错点

- 算 PWM 时用了 36 MHz，频率差一半
- 以为所有 APB1 外设都是 72 MHz
- 改了 APB 分频但没改定时器参数
