## 题目

**题目**：

```c
void my_task(void* p) {
    do_something();      // 没有 while(1)，直接返回
}
```

**问**：任务函数为什么必须是死循环？返回了会怎样？

## 口述答案

> 因为任务函数返回时，FreeRTOS **没有"任务结束"这个概念**——它不会自动删除任务，而是继续用这个已经被弹出的栈帧执行，行为未定义：可能 HardFault，可能跳回某个随机地址。
> 正确做法有两种：**写成死循环**（最常用），或者在末尾调用 `vTaskDelete(NULL)` 自杀。

## 讲深一层

```c
// ✅ 死循环
void task_a(void* p) {
    for (;;) {
        work();
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

// ✅ 一次性任务，主动删除自己
void task_once(void* p) {
    work();
    vTaskDelete(NULL);      // 删除自身，释放 TCB 和栈
}
```

| 写法 | 结果 |
|---|---|
| `for(;;)` + 阻塞 | ✅ 正常 |
| 直接 return | ❌ 未定义（多数是 HardFault） |
| `vTaskDelete(NULL)` | ✅ 任务被清理 |
| `while(1);` 无阻塞 | ⚠️ 高优先级会饿死别人 |

**`vTaskDelete(NULL)` 的两个注意点**：
1. **内存不会自动回收**——栈和 TCB 要空闲任务来清理，所以空闲任务必须能跑；
2. **`configSUPPORT_DYNAMIC_ALLOCATION` 必须为 1**。

**为什么"返回"这么危险**：Cortex-M 上任务首次运行是由 SVC 手工构造栈帧启动的，返回地址是故意设的陷阱（`prvTaskExitError`），所以通常会进入 HardFault 或死循环。

## 高频追问

1. **任务函数能有返回值吗？** —— 签名是 `void (*)(void*)`，不能有返回值。
2. **参数怎么传？** —— 通过 `xTaskCreate` 的 `pvParameters`，注意生命周期（不要传栈上变量的地址）。
3. **删除任务后内存什么时候回收？** —— 空闲任务下一次运行时。

## 易错点

- 任务函数忘了 `for(;;)`
- 传了局部变量的地址当参数，任务还没跑变量就销毁了
- `vTaskDelete` 之后还访问任务句柄
