## 题目

**题目**：`main()` 第一行就调用 `HAL_Init()`，之后打印 `SystemCoreClock` 是 72 MHz。但有人问"上电瞬间就是 72 MHz 吗"。

**问**：`SystemInit` 做了什么？为什么进入 `main` 时时钟已经是 72 MHz？

## 口述答案

> **上电瞬间不是 72 MHz**——芯片默认用内部 HSI（8 MHz）。是启动流程把时钟配到 72 MHz 的。
> 流程是：启动文件 `Reset_Handler` → 调 `SystemInit()`（设 Flash 等待周期、向量表、FPU 等基础项）→ 进 `main()` → `HAL_Init()` → 调 `SystemClock_Config()`（配 PLL 到 72 MHz）。所以"进入 `main` 时"严格说还是 8 MHz，配完才是 72 MHz。

## 讲深一层

```c
// Reset_Handler（汇编）
//   → SystemInit()        基础配置（时钟源、等待周期、向量表）
//   → __libc_init_array()
//   → main()
//       → HAL_Init()       设 NVIC 分组、SysTick、HAL 时基
//       → SystemClock_Config()  ← 这里才真正切到 72 MHz
//       → 外设初始化
```

| 阶段 | 时钟 | 做什么 |
|---|---|---|
| 上电复位 | HSI 8 MHz | 硬件默认 |
| `SystemInit` | 仍 8 MHz | Flash 等待周期、向量表基址、FPU |
| `SystemClock_Config` | **72 MHz** | 开 HSE → 配 PLL → 切 SYSCLK |
| 之后 | 72 MHz | 外设按 72 MHz 计算 |

**验证方法**：在 `HAL_Init` 前后各打印一次 `SystemCoreClock`，会看到 8 MHz → 72 MHz 的变化。

**`SystemCoreClock` 变量**：由 `SystemCoreClockUpdate()` 或 `HAL_RCC_GetHCLKFreq()` 更新，是后续所有延时和外设计算的基础，配错了所有时序都错。

## 高频追问

1. **`SystemInit` 会配 PLL 吗？** —— 标准库版本的 `SystemInit` 会（`system_stm32f10x.c` 里按宏配置）；HAL 版本不会，交给 `SystemClock_Config`。
2. **HSE 起振失败会怎样？** —— 卡在等待 HSE 就绪的循环里，或回落到 HSI（取决于代码）。
3. **怎么确认用的是 HSE 还是 HSI？** —— 读 `RCC->CFGR` 的 SWS 位，或看 `HAL_RCC_GetSysClockFreq()`。

## 易错点

- 以为上电就是 72 MHz
- `SystemClock_Config` 没调用就配外设（时序全错）
- `SystemCoreClock` 没更新，`HAL_Delay` 不准
