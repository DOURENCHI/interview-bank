## 题目

**背景**：奇瑞嵌入式二面真题。做过 Bootloader/IAP 的候选人几乎必被追问这一条，答得出链路细节才算真做过。
**问**：讲一下从复位到 main 的启动过程，你项目里 Boot 和应用是怎么衔接的？

## 口述答案

> 以 Cortex-M 为例，复位后 CPU 做两件事：从向量表第 0 项取主栈指针 MSP 的初值，从第 1 项取 Reset_Handler 的地址，然后开始执行。Reset_Handler 标准三步：把 .data 段的初值从 Flash 拷到 RAM（装载域到执行域）、把 .bss 清零、调 SystemInit 配好时钟，之后进入 C 运行时（ARMCC 走 __main 完成散转再跳 main，GCC 由 _start 做完再调 main）。Boot 和应用的衔接：Bootloader 常驻 Flash 起始地址（如 0x08000000），应用放在偏移处（如 0x08010000）。Boot 决定跳转后按固定四步走：先校验应用区合法（栈顶指针落在 RAM 范围、复位向量在 Flash 范围），然后关全局中断、把用过的外设恢复复位状态，再把向量表偏移寄存器 VTOR 指到应用的向量表，最后取应用向量表前两项设置 MSP、跳应用的 Reset_Handler。应用侧工程要把 Flash 起始地址和中断向量表偏移改到对应位置（链接脚本 + VECT_TAB_OFFSET），否则中断一进来就跑飞。

## 讲深一层

- 向量表本质：一段按固定顺序排列的 32 位字数组，第 0 项是 MSP 初值、第 1 项起是各异常/中断入口地址，所以「跳转」就是换一张表再重新走复位流程。
- 为什么跳转前要关中断并复位外设：Boot 里开着的中断在应用里未必配置了处理函数，残留的挂起标志会在跳转瞬间触发未初始化的向量；DMA 残留传输还可能继续搬数据踩内存。
- OTA/IAP 场景的加固：双分区（A/B）+ 分区头部存放版本与 CRC，启动时 Boot 校验当前分区，失败则回滚到备份分区，「变砖」问题就是这么防的。
- MSP/PSP：复位后用 MSP；上了 RTOS 后任务跑在 PSP、内核与异常用 MSP，跳转阶段全用 MSP。

## 高频追问

1. OTA 升级怎么防止变砖？——A/B 双分区 + CRC 校验 + 回滚标志，Boot 只信任校验通过的分区
2. 应用里 SysTick 已经被 Boot 开着，会有什么问题？——tick 中断向量已切到应用，若应用没配好优先级和处理函数会触发默认 handler，跳转前应停掉
3. Boot 用过的 DMA 没停就跳应用会怎样？——残留传输继续写内存，可能踩坏应用的数据段

## 易错点

- 只说「拷 .data、清 .bss」，漏掉 MSP/向量表这条硬件主线——这是复位到 main 的骨架
- 跳转前不关中断、不复位外设、不设 VTOR——三条漏任何一条，应用都会莫名跑飞
- 应用工程忘了改 Flash 起始地址和向量表偏移，调试半天发现中断进不去
