## 题目

**题目**：往队列里发一个结构体，任务收到后发现数据被改了；改成发指针，又出现数据错乱。

**问**：队列是按值拷贝还是按引用？两种方式各自的坑是什么？

## 口述答案

> 队列**按值拷贝**：`xQueueSend` 会把 `itemSize` 字节复制进队列的存储区，接收时再复制出来。所以发结构体是安全的（两份独立数据）。
> 发**指针**时复制的是指针值，指向的仍是原来那块内存——如果发送方在接收方处理前修改或释放了它，就会读到错数据。
> 两个坑正好相反：**按值时结构体不能太大**（拷贝开销 + 队列内存），**按指针时要管生命周期**。

## 讲深一层

```c
// ✅ 按值：安全，但结构体别太大
typedef struct { uint16_t id; float val; } sample_t;
QueueHandle_t q = xQueueCreate(8, sizeof(sample_t));
sample_t s = {1, 3.14f};
xQueueSend(q, &s, 0);            // 拷贝 8 字节进队列

// ⚠️ 按指针：必须保证生命周期
QueueHandle_t qp = xQueueCreate(8, sizeof(sample_t*));
sample_t* p = pvPortMalloc(sizeof(sample_t));
*p = s;
xQueueSend(qp, &p, 0);           // 发送方不能释放 p，接收方负责释放
```

| 方式 | 拷贝量 | 生命周期 | 适合 |
|---|---|---|---|
| 按值 | 整个对象 | 安全 | 小结构体（≤ 几十字节） |
| 按指针 | 4/8 字节 | **发送方要保证** | 大缓冲区、零拷贝 |
| 按指针 + 内存池 | 指针 | 池管理 | 高频大对象 |

**经验阈值**：结构体超过 32–64 字节就考虑传指针或指针 + 内存池。队列存储是按 `itemSize × length` 静态分配的，8 个 1 KB 的结构体就是 8 KB RAM。

**按指针的安全做法**：用内存池（固定大小块）+ 引用计数，或者干脆用 `xQueueSend` 传"索引"而不是指针。

## 高频追问

1. **能发引用吗？** —— C 里没有引用，本质都是拷贝值（指针也是值）。
2. **队列满了怎么办？** —— 用超时参数，或 `xQueueOverwrite`（长度 1 的队列专用）。
3. **接收方怎么知道数据有效？** —— 协议里带长度/校验；指针方式还要约定谁负责释放。

## 易错点

- 发局部变量的地址，函数返回后失效
- 发完指针立刻释放，接收方读到野内存
- 大结构体按值发，RAM 不够
