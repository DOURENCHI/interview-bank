## 题目

**场景**：拓竹科技（消费级智能硬件公司）嵌软面：「MCU 和上位机之间用什么通信协议？数据帧怎么设计的」，追问「固定帧长还是可变帧长，为什么」「粘包和异常数据怎么处理」「RS485 收发方向切换时机不对会怎样」。

**问**：一帧里该有哪些字段、为什么？字节流怎么重组出完整帧？半双工方向怎么切？

## 口述答案

> 帧结构五件套：**帧头 + 长度 + 序号 + CRC + 载荷**。帧头（如 0xAA 0x55）在字节流里定位帧起点；长度字段说明载荷多长；序号做丢帧/重复检测；CRC16 保完整性；载荷放命令字+参数。**定长 vs 变长**：定长解析最简单但带宽浪费、扩展性差；变长灵活，但**长度字段必须限上界**（≤缓冲区余量），否则一个坏长度就把缓冲区打爆——这是面试官想听到的边界意识。
>
> **粘包/断包处理**：串口是字节流，一次可能收到 1.5 帧、也可能只有半帧，标准做法是**环形缓冲区攒字节+逐字节解析状态机**：找帧头 → 读长度 → 收满载荷 → CRC 校验。CRC 失败整帧丢弃，只前进一个字节、重新找帧头；序号跳变说明丢帧，按命令幂等性决定补发还是跳过。
>
> **RS485 方向切换**：收发器靠 DE/RE 引脚切方向——**发送前置高，发送完等 TC 标志（移位寄存器彻底空）再拉低**；用 TXE 判会截掉最后一个字节，从机 CRC 永远算不对。主从协议还要留 turnaround 时间：主机发完到从机应答之间留出方向切换余量，从机别抢线。

## 讲深一层

```c
enum { FIND_HEAD, READ_LEN, READ_BODY, CHECK_CRC } st = FIND_HEAD;
for (每从环形缓冲区取一字节 b) {
    switch (st) {
    case FIND_HEAD: shift_push(b); if (head_matched()) st = READ_LEN; break;
    case READ_LEN:  len = b; st = (len <= LEN_MAX) ? READ_BODY : FIND_HEAD; break;
    case READ_BODY: body[idx++] = b; if (idx == len) st = CHECK_CRC; break;
    case CHECK_CRC: if (crc_ok()) deliver_frame(); else drop_frame();
                    st = FIND_HEAD; /* 成败都重新同步 */ break;
    }
}
```

**判断技巧**：设计题按「字段—作用—出错后果」三列讲；主动说「长度限上界」「CRC 失败重新同步」「TXE vs TC」三个细节，是把协议真正调通过的标志。**记忆锚点**：「帧头对齐、长度封顶、CRC 把关、序号记账；485 切向等 TC 别等 TXE」。

## 高频追问

1. **CRC 失败后怎么重新同步？** —— 丢弃整帧，缓冲区指针只前进一个字节，重新扫帧头；帧头用两字节以上+载荷首字节做命令字校验，降低把数据当帧头的概率。
2. **为什么切方向要等 TC 不等 TXE？** —— TXE 只表示发送数据寄存器空、字节已进移位寄存器；TC 才表示移位寄存器也发完，切早了最后一个字节被截断。
3. **序号具体怎么用？** —— 发端逐帧 +1；收端检查连续性：+1 正常、跳号=丢帧（请求重发或跳过）、重复=发端重发（按命令幂等去重）。
4. **波特率不高为什么还丢帧？** —— 别先怀疑带宽：方向切换截尾、接收缓冲区被覆盖（读得不及时）、处理线程阻塞、线缆干扰误码，按「先软件后硬件」逐项排除。

## 易错点

- 长度字段不设上界——异常长度直接越界写缓冲区，越界比丢帧严重得多。
- 只找帧头不验 CRC——把载荷里的「假帧头」当真帧解析，越错越远。
- RS485 用 TXE 切方向——尾部字节被截，对端 CRC 校验永远失败。
- 收发共用一块缓冲——发送还没完成就被接收数据覆盖，自己打自己。
