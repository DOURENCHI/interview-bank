## 题目

**题目**：一个高优先级任务里写了 `while (1) { do_work(); }`，没有 `vTaskDelay`，结果低优先级任务和看门狗全都不动了。

**问**：为什么必须用 `vTaskDelay` 让出 CPU？不阻塞会怎样？

## 口述答案

> 因为**抢占式调度下，高优先级任务只要就绪就永远占着 CPU**。它不阻塞，低优先级任务（包括空闲任务）就永远得不到运行机会——这就是"任务饥饿"。
> `vTaskDelay` 把任务从就绪链表移到延时链表，让调度器去跑别的任务，时间到了再放回就绪链表。

## 讲深一层

```c
// ❌ 高优先级死循环，饿死所有低优先级任务
void task_fast(void* p) {
    for (;;) { do_work(); }
}

// ✅ 让出 CPU
void task_fast(void* p) {
    for (;;) {
        do_work();
        vTaskDelay(pdMS_TO_TICKS(10));   // 阻塞 10 ms，期间别人能跑
    }
}

// ✅ 或者等事件（更精确）
void task_event(void* p) {
    for (;;) {
        if (xSemaphoreTake(sem, portMAX_DELAY) == pdTRUE) do_work();
    }
}
```

| 让出方式 | 多久回来 | 适合 |
|---|---|---|
| `vTaskDelay(n)` | 固定 n 个 tick | 周期任务 |
| `vTaskDelayUntil` | 固定**周期**（补偿执行时间） | 严格周期采样 |
| 等信号量/队列 | 事件到来时 | 事件驱动 |
| `taskYIELD()` | 立刻（同优先级） | 让给同优先级 |

**`vTaskDelay` 和 `vTaskDelayUntil` 的区别**（重要）：前者是"从现在起等 n 个 tick"，执行时间会累积成周期漂移；后者是"到下一个绝对时刻"，周期严格。

**空闲任务的重要性**：它负责回收被删除任务的栈和 TCB。高优先级任务不让出，删除的任务内存永远不回收。

## 高频追问

1. **`vTaskDelay(0)` 有用吗？** —— 有用，等于 `taskYIELD()`，让给同优先级。
2. **延时精度多少？** —— 一个 tick（1000 Hz 时 1 ms），实际可能多一个 tick。
3. **中断里能调用 `vTaskDelay` 吗？** —— 不能，中断没有任务上下文。

## 易错点

- 高优先级任务死循环不让出，饿死低优先级
- 用 `vTaskDelay` 做严格周期，累积漂移
- `HAL_Delay` 当让出（它是空转）
