## 题目

**问**：FreeRTOS 的任务有哪几种状态？从 Running 切到另一个任务，底层到底保存和恢复了什么？

## 口述答案

> 四个基本状态：**Running**（正在跑）、**Ready**（就绪等 CPU）、**Blocked**（等事件或延时，有超时）、**Suspended**（被挂起，不参与调度，只能显式恢复）。
> 切换由 **PendSV** 完成：SysTick 或任务主动让出后，PendSV 被挂起，等所有中断退出后执行。它先把当前任务的 R4–R11 压到自己的栈里（R0–R3、R12、LR、PC、xPSR 由硬件自动压栈），把栈顶存回 TCB；然后 `pxCurrentTCB` 指向下一个任务，从它的 TCB 取栈顶、弹出 R4–R11，异常返回时硬件再弹出剩下的寄存器。
> 所以"上下文"= 硬件自动压的 8 个寄存器 + 软件压的 8 个 + 任务自己的栈。

## 讲深一层

```
SysTick_Handler → xTaskIncrementTick() → 需要切换则挂起 PendSV
PendSV_Handler:
  MRS   r0, PSP
  STMDB r0!, {r4-r11}      ; 手动保存剩余寄存器
  STR   r0, [r2]           ; 存回当前 TCB
  LDR   r0, [r3]           ; 取下一个 TCB 的栈顶
  LDMIA r0!, {r4-r11}      ; 恢复
  MSR   PSP, r0
  BX    LR                 ; 异常返回，硬件恢复 r0-r3...
```

| 状态 | 进入方式 | 退出方式 |
|---|---|---|
| Ready | 创建 / 被唤醒 / 时间片用完 | 被调度器选中 |
| Running | 调度器选中 | 被抢占 / 阻塞 / 让出 |
| Blocked | 等队列、信号量、延时 | 事件到达或超时 |
| Suspended | `vTaskSuspend` | `vTaskResume` |

## 高频追问

1. **ISR 里能调 `vTaskDelay` 吗？** —— 不能，中断里只能用 `FromISR` 版本，延时类 API 会断言。
2. **同优先级任务怎么跑？** —— 时间片轮转（`configUSE_TIME_SLICING`），每个 tick 换一次。
3. **任务栈给多大？** —— 用 `uxTaskGetStackHighWaterMark` 看水位，留 30% 余量。

## 易错点

- 把 Blocked 和 Suspended 当成一回事——Blocked 有超时或事件，Suspended 只能手动恢复。
- 在中断里调用非 `FromISR` API。
