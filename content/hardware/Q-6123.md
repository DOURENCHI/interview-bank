## 题目

**场景**：沁恒微电子（USB 接口芯片厂）面经问 CH32V203 USB Device 的描述符、端点配置和枚举各承担什么职责；另一篇面经单刀直入问控制/批量/中断/同步四种传输各适合什么场景——USB 原理加落地都在考。

**问**：USB 设备从插入到「就绪」中间发生了什么（枚举流程）？四种传输类型的带宽、延迟、重试语义和典型外设各是什么？

## 口述答案

> 直答：**枚举就是主机在默认端点 0 上跑的一段控制传输序列**，把设备「问清楚、编上号、配上电」。插入后主机检测到 D+（全速）或 D-（低速）上的上拉 → 复位总线 → 设备以地址 0 应答 → 主机先 GET_DESCRIPTOR(Device) 只取前 8 字节（拿 EP0 最大包长，防止后面包长对不上）→ SET_ADDRESS 分配唯一地址 → 完整读设备/配置/字符串描述符 → SET_CONFIGURATION 激活配置 → 驱动绑定，设备就绪。
> 理由：描述符是「自描述」的树——**设备 → 配置 → 接口 → 端点**四级，配置可含多个接口（复合设备），接口下挂端点；主机不认识新设备，只能按这套固定格式逐级读目录，端点的 wMaxPacketSize、bInterval 就是从这里报给主机的。
> **四种传输按「带宽/延迟/重试」三维记**：①**控制传输**——枚举与配置专用，有重试、可靠但带宽无预留；②**批量传输**——大吞吐、用剩余带宽、重试保证不丢，U 盘/打印机；③**中断传输**——保证轮询间隔（有界延迟）、可重试，键盘鼠标 HID；④**同步传输**——保证带宽和节奏、**不重试**（错了就丢），音频/视频流。**记忆判断**：要可靠选批量，要准时选中断，要恒速选同步，配置设备走控制。

## 讲深一层

| 传输类型 | 带宽保证 | 重试 | 典型外设 | 端点配置要点 |
|---|---|---|---|---|
| 控制 | 无（按需） | 有 | EP0 枚举/配置 | EP0 包长 8/16/32/64，双向 |
| 批量 | 用剩余带宽 | 有 | U 盘、打印机 | FS 上限 64B、HS 常配 512B |
| 中断 | 轮询间隔保证 | 有 | HID、传感器 | bInterval 决定轮询周期 |
| 同步 | 带宽预留 | 无 | 音频流 | 等长带宽，预算要预扣 |

端点描述符三要素：**bEndpointAddress**（bit7 定 IN/OUT，低 4 位端点号）、**wMaxPacketSize**（决定缓冲区预算）、**bInterval**（中断/同步的周期）。**缓冲区预算**：单片机 USB 外设的端点 RAM 有限，各端点 wMaxPacketSize 之和必须落进预算——EP0 先保住 64B，剩余再分给批量和中断端点，分超了收发互踩。

**判断技巧**：答枚举按状态机讲（插入→复位→取描述符→设地址→设配置），答传输类型按三维对比，两条线都带「验证手段」（抓总线包看卡在哪一步）。**记忆锚点**：「EP0 问名，SET_ADDRESS 上户，SET_CONFIGURATION 分房；控制管配置、批量跑大货、中断保准时、同步保节奏」。

## 高频追问

1. **为什么先只读 8 字节描述符？** —— 复位后设备 EP0 包长未协商，先取 Device Descriptor 前 8 字节拿到 bMaxPacketSize0，之后主机按该包长通信，避免长包一次收不完。
2. **枚举失败常见原因？** —— D+/D- 上拉接反或位置不对、EP0 包长与描述符不符、描述符长度字段写错、SET_ADDRESS 后仍用地址 0 应答；抓包看卡在哪个请求即可定位。
3. **复合设备怎么组织描述符？** —— 一个配置多个接口，用 IAD（接口关联描述符）把成组接口标成一类功能（如 CDC+HID），主机按接口绑各自驱动。
4. **wMaxPacketSize 写大点行不行？** —— 不行，各速度有上限（FS 批量 64B、HS 批量 512B），超限枚举直接失败；写小了徒增包开销。

## 易错点

- 把枚举当黑盒——追问「卡在第几步」就答不出，要能按请求序列报顺序。
- 以为同步传输可靠——没有重试，丢就丢了，音频靠算法补偿。
- 中断传输 ≠ GPIO 中断——它是主机按 bInterval 的定时轮询。
- 端点缓冲超预算——各端点包长之和超出端点 RAM，运行期互相覆盖。
