## 题目

**题目**：`FreeRTOSConfig.h` 里几十个宏，哪些必须改、哪些可以默认？

**问**：哪些配置最关键？配错会怎样？

## 口述答案

> 六个必须按板子改：**`configCPU_CLOCK_HZ`**（CPU 频率，错了所有延时都错）、**`configTICK_RATE_HZ`**（节拍频率）、**`configMAX_PRIORITIES`**（优先级数量）、**`configMINIMAL_STACK_SIZE`**、**`configTOTAL_HEAP_SIZE`**（堆大小）、以及两个**中断优先级**宏。
> 最危险的错法是 `configCPU_CLOCK_HZ` 写错——`vTaskDelay(1000)` 可能变成 0.5 秒或 2 秒，而且不会报错。

## 讲深一层

```c
#define configCPU_CLOCK_HZ                    (72000000UL)   // 必须与时钟树一致
#define configTICK_RATE_HZ                    ((TickType_t)1000)  // 1 ms
#define configMAX_PRIORITIES                  (7)
#define configMINIMAL_STACK_SIZE              ((uint16_t)128)     // 单位：字
#define configTOTAL_HEAP_SIZE                 ((size_t)(20*1024))
#define configMAX_SYSCALL_INTERRUPT_PRIORITY  (5 << 4)   // 数值越大优先级越低
#define configKERNEL_INTERRUPT_PRIORITY       (15 << 4)
#define configCHECK_FOR_STACK_OVERFLOW        2
#define configUSE_PREEMPTION                  1
#define configUSE_TIMERS                      1
```

| 宏 | 配错的表现 |
|---|---|
| `configCPU_CLOCK_HZ` | 延时全错、tick 频率不对，**不报错** |
| `configTICK_RATE_HZ` | 时间片和延时精度不对 |
| `configMAX_PRIORITIES` | 任务创建失败（优先级越界） |
| `configTOTAL_HEAP_SIZE` | `pvPortMalloc` 返回 NULL，任务创建失败 |
| `configMAX_SYSCALL_INTERRUPT_PRIORITY` | 中断里调 API 导致 HardFault |

**中断优先级那两个宏是最容易搞错的**：Cortex-M 的 NVIC 优先级**数值越小优先级越高**，而 FreeRTOS 的"可调 API 中断"要求**优先级数值 ≥ 该宏**（即优先级更低）。配反了会在中断里调用 API 时崩溃。

## 高频追问

1. **`configTOTAL_HEAP_SIZE` 设多大？** —— 按"任务栈总和 + 队列 + 定时器 + 动态分配"估算，留 30% 余量。
2. **`configUSE_TIMERS=0` 会怎样？** —— `xTimerCreate` 不可用，`timers.c` 也不用编进来。
3. **怎么确认配对了？** —— 用示波器量一个 `vTaskDelay(1000)` 的翻转周期。

## 易错点

- `configCPU_CLOCK_HZ` 写成 8 MHz（实际 72 MHz）
- 中断优先级宏没左移 4 位
- 堆开太小，任务创建静默失败
