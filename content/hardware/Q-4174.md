## 题目

**题目**：串口接收用 `while(!(USART1->SR & RXNE));` 死等，主循环里其他任务全卡住。

**问**：轮询和中断相比，CPU 利用率差在哪？

## 口述答案

> 轮询是**主动空转等待**：CPU 一直在检查标志，这段时间什么有用的事都做不了，利用率接近 0（都在等）。
> 中断是**被动唤醒**：CPU 平时干别的，事件到来才打断，处理完立刻返回。等待期间 CPU 利用率是 100%（在做别的事）。

## 讲深一层

| 方式 | CPU 占用 | 响应延迟 | 代码复杂度 | 适合 |
|---|---|---|---|---|
| 轮询 | 空转 100% | 取决于轮询间隔 | 低 | 极简单场景、短等待 |
| 中断 | 按需 | 微秒级 | 中 | 异步事件 |
| DMA + 中断 | 最低 | 按块 | 高 | 高速大批量 |

```c
// ❌ 死等，CPU 空转
while (!(USART1->SR & USART_SR_RXNE));

// ✅ 中断
void USART1_IRQHandler(void) { HAL_UART_IRQHandler(&huart1); }
void HAL_UART_RxCpltCallback(UART_HandleTypeDef* h) { /* 处理 */ }

// ✅ RTOS 里也可以阻塞等（让出 CPU）
xQueueReceive(uart_q, &byte, portMAX_DELAY);
```

**"轮询也可以，但要带超时"**：`while(!flag && ++timeout < N);` 至少不会死锁，但仍然是空转。

**真正的资源浪费**：115200 波特率下一个字节约 87 μs，如果轮询等待，CPU 有 87 μs 完全浪费；中断方式只花几微秒。

## 高频追问

1. **中断一定更好吗？** —— 不一定，高频事件（如每微秒一次）中断开销反而大，用 DMA。
2. **轮询什么时候合理？** —— 初始化阶段、调试、等待极短（几个周期）。
3. **HAL 的 `HAL_UART_Receive` 是轮询吗？** —— 是，阻塞式；异步要用 `_IT` 或 `_DMA` 版本。

## 易错点

- `HAL_UART_Receive`（阻塞）放在主循环里
- 死等没有超时，外设故障就卡死
- 高频事件全用中断，CPU 全在中断里
