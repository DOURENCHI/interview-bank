# Q-6164 什么是可重入函数？为什么中断里不能调 printf 和 malloc？

## 口述答案

**可重入（reentrant）= 一个函数被「打断后再次进入」仍然正确**：执行到一半被中断/高优先级任务打断，新的执行流再调一次这个函数，两层调用互不干扰、结果都对。

判定标准就一条：**函数的全部状态都在自己的栈帧里**——只读写参数和局部变量，不碰任何跨调用的共享状态。具体三条：

1. **不用静态变量、全局变量**（`static` 局部变量也算——它活在数据区不在栈上，两次进入共享同一份）；
2. **不调用不可重入的函数**（污染会传染）；
3. **不依赖单次初始化**（首次调用才能建好的内部缓冲、句柄）。

**printf/malloc 为什么不可重入**：
- `malloc/free` 管着**全局堆链表**（空闲块指针、bin 头）。ISR 里 malloc 到一半，主循环的 malloc 正在改同一条链表——链表指针写花，堆直接损坏，而且这种损坏在几百次分配之后才炸，极难查。
- `printf` 依赖**全局 stdio 缓冲区和内部锁**；嵌入式实现里还常常不可重入地使用临时缓冲。中断里调用，轻则输出交错，重则死等锁（锁被被打断的主循环持有）——这正是 Q-4246 说的 ISR 禁用清单的底层原因。

**锚点：状态全在栈上，才是可重入；碰了共享的堆和缓冲区，就不是。**

## 讲深一层

| 场景 | 表现 | 后果 |
| --- | --- | --- |
| ISR 调 malloc | 与任务态并发改堆链表 | 堆元数据损坏，延迟炸裂（最难查的一类 bug） |
| ISR 调 printf | 全局缓冲区重入 | 输出交错/丢字符，或死等内部锁 |
| 函数内 `static int cnt` 计数 | 两个执行流共享同一 cnt | 计数错乱；改成参数传入或局部变量即修复 |
| `strtok` 切字符串 | 内部 static 指针保存进度 | 两个流交替切同一串全局状态；用可重入版 `strtok_r` |

**可重入 vs 线程安全**（高频辨析）：
- 可重入⇒线程安全：状态全在栈上，多线程并发调用天然正确；
- 线程安全⇏可重入：用**互斥锁**保护全局状态的函数是线程安全的，但同一线程重入（ ISR 里再调）会**自己等自己的锁死锁**——锁不区分「谁」只区分「有没有」。
- 所以中断上下文的硬要求是可重入，比线程安全更强。

## 高频追问

1. **ISR 里想把数据交给日志线程，怎么做才安全？** —— 不在 ISR 里调 printf：ISR 只拷贝到预分配的环形缓冲（自己管理、无锁或关中断保护）+ 置标志/发队列，日志任务慢慢打（对应 Q-4205 串口环形缓冲做法）。
2. **volatile 和可重入有关系吗？** —— 没有。volatile 管「编译器别缓存到寄存器」（可见性），可重入管「共享状态不在栈上」（重入安全），两个维度；volatile 变量若是全局共享的，函数照样不可重入。
3. **怎么把不可重入函数改成可重入？** —— 共享状态改参数传入或局部变量；必须共享的用调用方传入的上下文结构体；实在不行调用方加临界区——但「函数自己关中断」只是让它临界区安全，不等于可重入。
4. **RTOS 的 API 哪些能在 ISR 里调？** —— 只带 `FromISR` 后缀的版本（xQueueSendFromISR 等）：普通版可能阻塞，FromISR 版不阻塞、用不同的锁语义；FreeRTOS 里普通版在 ISR 中调用会触发 configASSERT（Q-4246）。
5. **memcpy 可重入吗？** —— 只用参数和局部状态，可重入；但如果实现用了全局对齐缓冲/查表（某些 libc 优化版）就未必，所以跨平台 SDK 文档会标注。

## 易错点

- 把「线程安全」当「可重入」——mutex 保护的函数是线程安全但不可重入，重入死锁。
- 认为 `static` 局部变量没问题——它不在栈上，两次进入共享，是可重入的头号破坏者。
- 只背「ISR 不能调 printf」当咒语——追问「为什么」必须落到**全局堆链表/stdio 缓冲区被并发改写**。
- 修法答成「给 printf 加锁」——ISR 里加锁会死锁（等被自己打断的任务放锁），正解是 ISR 不调用、用队列/缓冲转交。
