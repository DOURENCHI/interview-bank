## 题目

**场景**：影石（全景相机）面试官问：摄像头 bring-up 流程是什么，如何移植或向后移植——影像设备公司的高频实战题。

**问**：一块新板 + 一颗新 sensor，从上电到出图怎么走？把老内核的 sensor 驱动迁到新内核要注意什么？

## 口述答案

> bring-up 的主线是**把「电 → 协议 → 图」一层层点亮**，按链路 sensor → MIPI CSI-2 → ISP/内存分六步：
> ①**硬件层确认**：三路供电（AVDD 模拟/DVDD 数字内核/DOVDD IO）电压时序对、MCLK 按手册给频、reset 上电时序满足 datasheet 的先后与脉宽；②**总线通**：I2C 能读到 chip ID——读不到 ID 别往下走，查上拉/地址 7 位 vs 8 位/上电时序；③**驱动**：sensor 驱动核心是寄存器初始化表（分辨率/帧率/RAW 位深模式）+ v4l2_subdev ops（s_stream 开关流）；④**DTS**：I2C 挂载地址、mclk 频率、CSI 端口 lane 数、link-frequency、数据类型对齐；⑤**点流**：v4l2-ctl --stream-mmap 抓帧，media-ctl 看管道拓扑，确认 lane 极性/数据类型没配反；⑥**验图**：raw 数据肉眼验（条纹=lane 问题、全绿/全粉=增益白平衡没配、斜纹=时序）。
>
> **移植/向后移植**：把旧内核驱动迁新内核（或反向），三类坑——**API 变化**（v4l2_subdev 接口、media controller 框架演进的签名改动）、**binding 变化**（DTS 属性改名/换节点结构，要对着新内核 Documentation 同步）、**子系统机制变化**（时钟/电源/复位框架的获取方式）。策略是**先跑最小链路**（I2C 通 + 能出一路 raw）再补 ISP 特性，别一上来全量搬。

## 讲深一层

| 阶段 | 检查物 | 典型翻车 |
|---|---|---|
| 供电时序 | 万用表/示波器 | DOVDD 先于 DVDD 上电锁死 |
| I2C 读 ID | i2cdetect | 7 位地址写了 8 位 |
| DTS | 编译+启动日志 | lane 数/link-freq 与驱动 mode 不符 |
| 出流 | v4l2-ctl 抓帧 | 数据类型 DT 配错收不到帧 |
| 图像质量 | raw 转图 | 条纹→lane、绿图→bayer 排列配错 |

**判断技巧**：答 bring-up 题按「层」不按「步骤名」——电、总线、驱动、设备树、流、图，每层报「验证物 + 翻车点」；只背「先配 DTS 再驱动」没有验证手段，一听就是没上手过。**记忆锚点**：「电通、ID 通、流通、图对，四关」。

## 高频追问

1. **I2C 读不到 ID 怎么排查？** —— 顺序：供电对不对（示波器看三路电）→ 时序满足没有 → 总线有没有响应（i2cdetect 扫地址）→ 上拉与速率 → 地址位宽；多数死在供电时序和地址位宽。
2. **MIPI 差异信号抓不到怎么定位？** —— 看 host 侧错误计数（CRC/ ECC）、确认 lane 顺序与 P/N 极性、用逻辑分析仪抓 LPDT 序列；阶段化：先 LP 能通再谈 HS。
3. **多 sensor 同一 CSI 口怎么处理？** —— I2C 地址错开 + DTS 端口复用/switch 配置，或走硬件 mux；软件上 media-ctl 拓扑要能把当前 sensor 路由到 ISP。
4. **向后移植最恶心的一类问题？** —— binding 不兼容：老 DTS 在新内核直接 probe 失败；改法是 binding 文本逐条对，补 deprecated 属性映射，别靠猜。

## 易错点

- 上电时序不当回事——sensor 锁死后怎么读都是无响应，先查电再看代码。
- 地址位宽混用——数据手册 8 位写法与 Linux 7 位地址差一位。
- 只配驱动不验拓扑——media-ctl 管道断链，抓帧永远超时。
- 移植直接全量搬——API/binding 变化叠加，出问题不知道哪层引入。
