## 题目

**问**：多核环境下多个执行单元访问同一个寄存器，怎么避免竞争？

## 口述答案

> 先分清是**内存**还是**外设寄存器**。
> 内存里的读-改-写（`x++`）不是原子操作，要用原子指令：ARM 的 LDREX/STREX、CAS，或编译器内建 `__atomic_fetch_add`；复杂临界区用自旋锁（spinlock）保护，持锁期间不能睡眠。
> 外设寄存器要注意：它映射成 Device 内存，不走 Cache，但多核同时写仍会互相覆盖。要么用 spinlock 串行化，要么用硬件信号量/专用寄存器（如 GPIO 的 BSRR 单次写、置位/复位分离）避免读-改-写。

## 讲深一层

```c
// 错误：非原子
GPIOA->ODR |= (1 << 5);
// 正确：用 BSRR，单次写完成置位，无需读改写
GPIOA->BSRR = (1 << 5);
```
| 场景 | 手段 |
|---|---|
| 内存计数 | `__atomic` / LDREX-STREX |
| 临界区 | spinlock + 关抢占 |
| 外设位操作 | BSRR/置位复位寄存器 |
| 跨核通知 | 硬件信号量 / IPI |

## 高频追问

1. **spinlock 能持有多久？** —— 越短越好，持锁睡眠会死锁。
2. **单核还需要锁吗？** —— 中断和主循环之间仍需要临界区（关中断）。
3. **volatile 够吗？** —— 不够，它只保证不被优化，不保证原子性。

## 易错点

- 用 `|=` 操作共享寄存器，两个核同时写丢位。
- 持 spinlock 调用可能睡眠的函数。
