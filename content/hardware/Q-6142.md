## 题目

**场景**：两份面经都考 DMA 细节：未注名公司问「DMA 半传输中断你了解吗」；拓竹科技（嵌入式软件岗）追问「DMA 半传输中断和传输完成中断的区别，为什么要有双缓冲」。这是 DMA 数据流设计的核心题。

**问**：半传输中断（HT）和传输完成中断（TC）分别在什么时机触发？怎么配合双缓冲实现不丢数据的高吞吐采集？

## 口述答案

> **DMA 一次搬 N 个数据时，搬完一半触发半传输中断（HT），全部搬完触发传输完成中断（TC）**——两个中断把缓冲区**天然切成前后两半**，这就是「乒乓」用法的硬件基础。
> **只开 TC 的痛点**：单缓冲必须等整段搬完才能处理，处理期间新数据继续覆盖缓冲区开头，要么丢数据、要么停 DMA 等处理——**吞吐和处理速度互相卡脖子**。
> **HT+TC 配合（伪双缓冲）**：开一个两倍大小的缓冲，DMA 从头写到尾循环搬运；**HT 来了处理前半段**（此时 DMA 正在写后半段），**TC 来了处理后半段**（此时 DMA 已回卷在写前半段）——处理和数据写入永远错开在不同的半区，**CPU 处理耗时只要不超过「半缓冲的填充时间」，数据就不丢也不停**。
> **真双缓冲（双地址寄存器）**：DMA 有 M0AR/M1AR 两个内存地址，硬件自动乒乓，写满一个自动切另一个并置位传输完成标志；处理当前缓冲时 DMA 写另一个，**连「算好半区边界」都不用管**，切换零开销。
> **ADC 循环采集的典型写法**：DMA 循环模式 + 半/全中断各处理半缓冲 + 数据序号校验；若还要往外发数据（如 DAC 波形），用双缓冲在 TC 里切换下一帧地址，波形输出无缝衔接。

## 讲深一层

```c
/* ADC 双缓冲采集骨架（HAL 风格） */
uint16_t adc_buf[2][BLOCK];              // 两块缓冲
volatile uint8_t ready;                   // 就绪块序号，由中断置位

void dma_ht_isr(void)  { ready = 0; }     // 半传输：前块就绪
void dma_tc_isr(void)  { ready = 1; }     // 传输完成：后块就绪

void process(void) {
    if (ready < 0) return;
    uint8_t idx = ready; ready = 0xFF;    // 取走就绪块
    do_fft(adc_buf[idx], BLOCK);          // 处理与 DMA 写另一块并行
}
```

| 方案 | 机制 | 风险 |
|---|---|---|
| 单缓冲+TC | 搬完才处理 | 处理期间丢新数据或停 DMA |
| 单缓冲+HT/TC | 前后半区错开 | 需自管边界，处理必须快于半区填充 |
| 真双缓冲 | 硬件自动切换 | 无，切换零开销 |

**判断技巧**：这题的本质是「**处理时间和搬运时间重叠**」——答出「HT/TC 把一块缓冲拆成两半轮流处理，处理时 DMA 写另一半」，再补真双缓冲的硬件自动切换，就完整了。**记忆锚点**：「半传输处理前半，传输完成处理后半；真双缓冲硬件自己换」。

## 高频追问

1. **处理太慢会怎样？** —— DMA 写进正在处理的半区，数据混叠；必须保证单块处理时间 < 半缓冲填充时间，超了就要加缓冲深度、提速或换真双缓冲+更快处理。
2. **中断里能直接处理数据吗？** —— 中断只做「置就绪标志/入队」，重处理放任务里——中断里做 FFT 会拖垮其他中断实时性。
3. **双缓冲和循环模式什么关系？** —— 循环模式是「搬到头自动回卷」；双缓冲在此基础上加了第二地址自动切换。两者可叠加：ADC 循环+内存双缓冲是采集标配。
4. **HT/TC 和 DMA 冲突（Q-4116 场景）怎么区分排查？** —— 先看中断是否如期到来、序号是否连续（丢数据的样式），再看总线仲裁和优先级配置（冲突破坏了传输本身）；现象不同，定位入口不同。

## 易错点

- 只开 TC 不用 HT——单缓冲吞吐卡死在「搬完才能处理」。
- 中断里做重处理——实时性被自己的 ISR 拖垮。
- 处理耗时超过半缓冲填充时间——数据混叠还不自知，靠序号校验才能发现。
- 真双缓冲忘了切换时 Cache/对齐问题——偶发旧数据。
