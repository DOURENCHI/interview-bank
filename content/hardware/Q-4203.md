## 题目

**题目**：上位机发来的指令是变长的（长度字段 + 命令字 + 数据 + 校验），用 `HAL_UART_Receive` 收固定长度总是不对。

**问**：单片机接收不定长串口数据，程序框架该怎么设计？

## 口述答案

> 标准方案是 **DMA + 空闲中断（IDLE）**：DMA 负责把字节搬进缓冲区，总线空闲时触发 IDLE 中断，此时"DMA 已传输计数"就是这一帧的长度。
> 这样 CPU 完全不参与逐字节接收，也不怕帧长变化。

## 讲深一层

```c
// 1. 启动 DMA 接收（长度给最大值）
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buf, sizeof(rx_buf));

// 2. 空闲回调（HAL 自动算长度）
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef* h, uint16_t size) {
    ring_write(&rb, rx_buf, size);        // 拷进环形缓冲
    HAL_UARTEx_ReceiveToIdle_DMA(h, rx_buf, sizeof(rx_buf));   // 重新武装
}

// 3. 主循环/任务里按协议解析
void task_comm(void* p) {
    for (;;) {
        parse_frames(&rb);                // 按长度字段切帧 + 校验
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

| 方案 | 帧边界判断 | CPU 占用 | 适合 |
|---|---|---|---|
| 逐字节中断 | 靠协议自己找 | 高 | 低速、简单 |
| **DMA + IDLE** | 总线空闲 | 极低 | **变长帧** |
| DMA + 定长 | 固定长度 | 极低 | 定长协议 |
| 空闲 + 定时器超时 | 超时 | 低 | 无 DMA 的芯片 |

**协议层面的三件事必须做**：
1. **长度字段**：从缓冲里读长度，够一帧才解析，不够就等；
2. **校验**（CRC/校验和）：丢包、粘包时能识别；
3. **超时丢弃**：半帧永远等不到后续字节时，要能超时清空缓冲。

**IDLE 中断的一个坑**：它只能告诉你"总线空闲了"，**不能保证一帧收完**（如果帧中间有停顿会被截断）。健壮做法是配合长度字段和超时。

## 高频追问

1. **DMA 缓冲区要多大？** —— 至少最大帧长的 2 倍（乒乓），或者用环形缓冲。
2. **没有 IDLE 中断怎么办？** —— 用定时器做"字节间超时"判断帧结束。
3. **能边收边解析吗？** —— 能，用状态机逐字节推进，适合流式协议。

## 易错点

- 用定长接收处理变长协议
- 不做校验，粘包时解析错乱
- IDLE 截断了一帧却当成完整帧处理
