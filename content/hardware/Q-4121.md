## 题目

**场景**：六个按键用同一份驱动，最初写成全局变量 `current_key`，结果两个任务同时读，互相覆盖。

**问**：多个任务共用一份驱动，为什么用句柄而不是全局变量？

## 口述答案

> 因为全局变量是**所有任务共享同一份状态**，多任务并发访问必然冲突；而句柄（handle）让**每个使用者拥有一份独立的实例**，状态互不干扰。
> 句柄的本质是"指向一个不透明结构体的指针"，调用方不需要知道内部结构，只需要传句柄。

## 讲深一层

```c
// ❌ 全局状态，多任务互相覆盖
int current_key;
void key_scan(void) { current_key = read_pin(); }

// ✅ 句柄，每人一份
typedef struct key_dev_s* key_handle_t;

key_handle_t key_create(GPIO_TypeDef* port, uint16_t pin) {
    key_handle_t h = pvPortMalloc(sizeof(struct key_dev_s));
    h->port = port; h->pin = pin; h->state = 0;
    return h;
}
void key_scan(key_handle_t h) { h->state = read(h->port, h->pin); }
```

| 方式 | 状态份数 | 多任务安全 | 可复用 |
|---|---|---|---|
| 全局变量 | 1 份 | ❌ | ❌ |
| 句柄 + 实例 | 每句柄 1 份 | ✅（各自独立） | ✅ |
| 加锁的全局 | 1 份 | ✅（串行） | ❌ |

**句柄的额外好处**：可以同时驱动 6 个同型号 LCD、2 路串口，代码只写一份——这就是"面向对象"在 C 里的表达方式。

**代价**：多一次指针间接访问，以及要管理句柄的生命周期（创建/销毁）。

## 高频追问

1. **句柄一定要 malloc 吗？** —— 不一定，静态数组池更常见（避免碎片）。
2. **句柄内部要不要加锁？** —— 如果多个任务会同时操作**同一个**句柄，需要；各自一个句柄就不需要。
3. **C++ 里对应什么？** —— 类的实例 + 成员函数。

## 易错点

- 多任务共用一个全局驱动状态
- 句柄 malloc 后忘了释放
- 句柄内部结构暴露在头文件里（失去封装意义）
