## 题目

**场景**：一块板子要同时做三件事——每 1 ms 采样一次 ADC、每 20 ms 扫一次按键、每 500 ms 刷一次屏幕。裸机 `while(1)` 里用 `HAL_Delay` 串起来，结果按键迟钝、采样丢点。

**问**：裸机主循环为什么"遇到不同周期就顾此失彼"？RTOS 是怎么解决的？

## 口述答案

> 因为裸机是**单线程顺序执行**，`HAL_Delay(1)` 期间 CPU 在空转等，什么都不能做。三个周期一旦不是整数倍关系，就只能取最小公约数不停地查，或者牺牲某个任务的响应。
> RTOS 用**时间片 + 阻塞唤醒**解决：每个任务写成一个死循环，用 `vTaskDelay` 让出 CPU，调度器按优先级和时间片切换。等待期间 CPU 去跑别的任务，不是空转。

## 讲深一层

```c
// 裸机：串行，总周期 = 各段之和
while (1) {
    adc_sample();  HAL_Delay(1);
    key_scan();    HAL_Delay(20);   // 这 20 ms 里 ADC 完全停摆
    lcd_refresh(); HAL_Delay(500);
}
```

```c
// RTOS：并行（看起来），各自按自己的周期阻塞
void task_adc(void* p) { for (;;) { adc_sample(); vTaskDelay(pdMS_TO_TICKS(1)); } }
void task_key(void* p) { for (;;) { key_scan();   vTaskDelay(pdMS_TO_TICKS(20)); } }
void task_lcd(void* p) { for (;;) { lcd_refresh();vTaskDelay(pdMS_TO_TICKS(500)); } }
```

| 维度 | 裸机超级循环 | RTOS |
|---|---|---|
| 并发 | 伪并发（轮流跑） | 真并发（抢占 + 阻塞） |
| 响应延迟 | 等于一轮循环时间 | 高优先级任务可随时抢占 |
| 代码结构 | 全部挤在 `main` | 一任务一文件 |
| 周期精度 | 受其他任务拖累 | 各自独立 |
| 资源开销 | 几乎为零 | RAM + 每个任务一份栈 |

**本质区别**：裸机的"等待"是**占用 CPU 等待**，RTOS 的"等待"是**让出 CPU 等待**。

## 高频追问

1. **RTOS 一定更快吗？** —— 不一定。任务切换有开销（几微秒），任务少、逻辑简单时裸机反而更快。
2. **什么时候不该上 RTOS？** —— 只有一个主循环、时序要求宽松、RAM 紧张（如 2 KB 的 MCU）。
3. **RTOS 的"并发"是真的并行吗？** —— 单核上是分时复用，看起来并行；多核才真并行。

## 易错点

- 认为 RTOS 让 CPU 变快（它只是让等待不占 CPU）
- 任务里用 `HAL_Delay` 而不是 `vTaskDelay`（前者空转，后者让出）
- 任务数开太多，RAM 不够
