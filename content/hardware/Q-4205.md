## 题目

**题目**：串口中断往缓冲区写、主循环从缓冲区读，偶尔读到半截数据。

**问**：串口环形缓冲区的读写指针该怎么设计？满和空怎么区分？

## 口述答案

> 用**两个单调递增的索引（不是取模指针）+ 掩码取模**：`head` 只由写方改、`tail` 只由读方改，这样**单生产者单消费者场景不需要加锁**。
> 满和空用"已用长度"判断：`used = head - tail`，`used == 0` 为空，`used == size` 为满。单调递增让"满"和"空"不会混淆（这是只用一个计数器的经典陷阱）。

## 讲深一层

```c
typedef struct {
    uint8_t buf[256];
    volatile uint16_t head, tail;    // 单调递增，用掩码取模
} ring_t;

static inline uint16_t used(ring_t* r) { return (uint16_t)(r->head - r->tail); }

// 写方（中断里）
bool ring_put(ring_t* r, uint8_t b) {
    if (used(r) >= sizeof(r->buf)) return false;    // 满
    r->buf[r->head & (sizeof(r->buf) - 1)] = b;
    ++r->head;                                       // 只有写方改 head
    return true;
}

// 读方（主循环）
bool ring_get(ring_t* r, uint8_t* b) {
    if (used(r) == 0) return false;                  // 空
    *b = r->buf[r->tail & (sizeof(r->buf) - 1)];
    ++r->tail;                                       // 只有读方改 tail
    return true;
}
```

| 设计 | 空/满判断 | 并发 |
|---|---|---|
| 单指针 + 计数 | 计数 0/满 | 需原子 |
| head/tail 取模 | 相等既空也满（歧义） | 需牺牲一格 |
| **单调 head/tail** | `head-tail` | **SPSC 无锁** |

**为什么要求缓冲区大小是 2 的幂**：`& (size-1)` 比 `% size` 快得多，在中断里很重要。

**为什么不需要锁**：写方只改 `head`、读方只改 `tail`，且都是单字节/单字对齐的原子写。**多生产者或多消费者就必须加锁**。

**`volatile` 必须加**：否则编译器可能把 `head`/`tail` 缓存在寄存器里，读到旧值。

## 高频追问

1. **能覆盖旧数据吗？** —— 看需求：丢新数据（返回 false）还是丢旧数据（推进 tail）。串口一般丢新。
2. **中断里能调用 `ring_put` 吗？** —— 能，这正是设计目标（SPSC 无锁）。
3. **缓冲区多大？** —— 至少"最大帧长 × 2"，或按"处理周期 × 波特率"估。

## 易错点

- 用取模指针，满和空都是 head==tail
- 读方也改 head（破坏无锁前提）
- 忘了 `volatile`，优化后死循环
