## 题目

**题目**：串口中断里只判断了 `RXNE`，结果偶尔进中断什么都没读到；定时器中断里也只判断了 `UIF`，偶尔卡死。

**问**：STM32 的中断服务函数为什么都要先判断标志位？

## 口述答案

> 因为**一个中断向量可能对应多个中断源**。USART1 的同一个向量里有 RXNE（收到数据）、TXE（发送空）、ORE（溢出）、IDLE（空闲）等；TIM 里有 UIF（更新）、CC1IF（比较）等。
> 不判断标志就处理，会在"别的事件触发"时执行错误逻辑；而如果**不清标志**，中断会立刻再次进入，形成死循环。

## 讲深一层

```c
void USART1_IRQHandler(void) {
    // HAL 里已经做了：判断 + 清标志 + 调回调
    HAL_UART_IRQHandler(&huart1);
}

// 寄存器版：必须自己判断
void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        uint8_t d = USART1->DR;          // 读 DR 会清 RXNE
        buf[i++] = d;
    }
    if (USART1->SR & USART_SR_ORE) {     // 溢出也要处理
        (void)USART1->DR;
    }
}
```

| 外设 | 常见中断源 | 标志位 |
|---|---|---|
| USART | 收到数据 / 发送空 / 溢出 / 空闲 | RXNE / TXE / ORE / IDLE |
| TIM | 更新 / 比较 / 捕获 | UIF / CCxIF |
| EXTI | 对应线的边沿 | PR 挂起位 |
| ADC | 转换完成 | EOC |

**"读 DR 清标志"的细节**：USART 的 RXNE 在"读 SR 再读 DR"后自动清除；有些标志必须**先读 SR 再写 0**（如 EXTI 的 PR），顺序错了清不掉。

**`ORE` 溢出标志最容易被忽略**：不清它，接收会一直卡住或反复进中断。

## 高频追问

1. **能只清关心的标志吗？** —— 能，但未清的其他标志会让中断反复进入。
2. **HAL 帮我清了吗？** —— 大部分是，所以用 HAL 时不要在回调里重复清。
3. **怎么确认标志清掉了？** —— 在 ISR 末尾读一次 SR 寄存器的值。

## 易错点

- ISR 里不判断标志，多源中断互相干扰
- 只清一个标志，其他标志导致反复进入
- 手动清标志和 HAL 重复操作
