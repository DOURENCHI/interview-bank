## 题目

**题目**：三种保护手段摆在面前：临界区、挂起调度器、互斥量。

**问**：三种保护手段怎么选？各自的边界在哪？

## 口述答案

> 按"**要保护什么**"和"**保护多久**"选：
> - **临界区**（关中断）：保护**几行代码**、涉及中断与任务共享的数据，开销最小；
> - **挂起调度器**：保护**稍长的操作**（如 `malloc`），不关中断所以中断仍能响应，但中断里不能调 API；
> - **互斥量**：保护**可能阻塞的较长临界区**，带优先级继承，但不能在中断里用。

## 讲深一层

| 维度 | 临界区 | 挂起调度器 | 互斥量 |
|---|---|---|---|
| 关中断 | ✅ | ❌ | ❌ |
| 禁止任务切换 | ✅ | ✅ | ❌（阻塞） |
| 中断里能用 | ✅（成对） | ❌ | ❌ |
| 可嵌套 | ✅（计数） | ✅（计数） | 需递归互斥量 |
| 优先级继承 | — | — | ✅ |
| 开销 | 极低 | 低 | 中（系统调用） |
| 适合时长 | 微秒级 | 几十微秒 | 毫秒级/可阻塞 |

```c
// 1. 临界区：最短
taskENTER_CRITICAL();
shared_flag = 1;
taskEXIT_CRITICAL();

// 2. 挂起调度器：稍长，不关中断
vTaskSuspendAll();
reorganize_list();       // 不能调用可能阻塞的 API
xTaskResumeAll();

// 3. 互斥量：可能阻塞
xSemaphoreTake(mtx, portMAX_DELAY);
write_flash();           // 慢操作
xSemaphoreGive(mtx);
```

**判断口诀**：**能在几行内做完 → 临界区；会阻塞或很长 → 互斥量；介于两者且要保中断响应 → 挂起调度器。**

**互斥量的优先级继承**：低优先级任务持锁时，会临时提升到等待者的优先级，避免被中间优先级任务插队——这是它相对二进制信号量的关键优势。

## 高频追问

1. **临界区能嵌套吗？** —— 能，内部有嵌套计数。
2. **`vTaskSuspendAll` 期间能收中断吗？** —— 能，但中断里不能调用 FreeRTOS API。
3. **互斥量能递归获取吗？** —— 普通互斥量不能（会死锁），要用递归互斥量。

## 易错点

- 用临界区保护耗时操作，中断响应变差
- 中断里用互斥量
- 用二进制信号量代替互斥量（无优先级继承）
