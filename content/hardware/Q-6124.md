## 题目

**场景**：沁恒微电子面经原题：同一块板既要支持 USB Host 又要支持 USB Device，软件架构和供电、连接检测策略应该怎样拆分——USB 芯片厂考察你对双角色设计的完整认识。

**问**：OTG 双模设备怎么实现 Host/Device 角色切换？VBUS 供电谁负责？连接检测在两个角色下分别怎么做？

## 口述答案

> 直答：**OTG = 同一个 USB 外设控制器 + 角色判定引脚 + 两套协议栈**。硬件上 mini/micro-AB 座多出 ID 引脚：**ID 接地 = A 设备（默认 Host），ID 悬空 = B 设备（默认 Device）**，插上线就知道默认谁当 Host。运行中还能换位：**SRP**（B 设备发数据线脉冲+VBUS 脉冲请求会话，提醒 A 给 VBUS 上电）和 **HNP**（总线挂起后 A 把 Host 角色让给 B），所以「相机直连打印机」这类 B 反串 Host 的连接也能成立。
> 理由：**供电责任跟着角色走**——A/Host 侧负责给 VBUS 供 5V 并带过流保护，掉电或过流事件要回收供电；B/Device 侧只检测 VBUS 有无来判断主机在不在。供电方向搞反，再对的上层协议也枚举不出来。
> **连接检测**：Device 模式靠 **VBUS 检测中断**——主机一上电先知道「有电了」，再拉起 D+ 上拉等复位；Host 模式靠 **线缆/DP-DM 线状态**——设备插入改变 D+/D- 电平触发检测，Host 再给 VBUS 上电、复位、枚举。软件架构上把 USB 拆成**角色无关核心层 + Host 栈 + Device 栈 + 角色管理层**（收 ID/VBUS 事件→互斥切换），类驱动写在两层之上复用，业务代码不感知角色。

## 讲深一层

| 机制 | 谁发起 | 硬件依据 | 作用 |
|---|---|---|---|
| ID 引脚 | 插线瞬间 | AB 座内 ID 接地/悬空 | 定默认角色 |
| SRP | B 设备 | 数据线脉冲+VBUS 脉冲 | 请求 A 建会话供电 |
| HNP | 协商后的 B | 总线挂起后移交 | B 反串 Host |
| VBUS 检测 | 双方 | VBUS 采样引脚 | Device 判主插入、Host 判掉电过流 |

（现代对应：Type-C 用 CC 引脚做方向与角色判定，DRP 双角色端口周期轮询，供电方向交给 PD 协商——机制同源，引脚换了。）

**判断技巧**：答 OTG 抓「谁供电谁说了算」——供电方是 A/Host，请求方是 B/Device；讲角色切换必点 SRP/HNP 两个缩写，再落到软件「先完整 deinit 再 init 的互斥切换」。**记忆锚点**：「ID 定角色，SRP 要电，HNP 换位，VBUS 管生死」。

## 高频追问

1. **为什么 ID 引脚能定角色？** —— AB 座的 ID 脚在座内接地，普通 Device 线缆不接 ID；Host 线一插 ID 被拉低，设备据此开 VBUS 当 Host，悬空就当 Device 等供电。
2. **A 设备 VBUS 供电要注意什么？** —— 必须对外供 5V，标准口按 100mA 单元负载起步、协商最高 500mA（USB 2.0），OTG 小电源场景 B 初始只允许取约 8mA 再协商扩展；同时要过流保护与掉电回收。
3. **双模软件最容易翻车在哪？** —— 角色切换的状态残留：旧栈中断没解绑、端点没复位就起新栈；必须设计成「完整 deinit → 互斥锁 → init」的切换流程。
4. **没有 ID 引脚的 Type-C 口怎么做双模？** —— CC 逻辑替代 ID：CC 上拉/下拉配对判 DFP/UFP，DRP 轮询切角色；软件同样收敛成角色事件，上层栈复用。

## 易错点

- 以为双模要两套控制器——多数 MCU 是同一个 USB 控制器换角色，靠 ID/VBUS 事件驱动。
- Host 忘了供 VBUS 或没做过流保护——设备插上永远枚举不出来。
- Device 侧只看 ID 不看 VBUS——VBUS 才是「主机在不在」的判据，掉了要拆栈。
- 角色切换直接叠初始化——残留状态让新角色偶发异常，最难复现。
