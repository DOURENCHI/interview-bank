## 题目

**题目**：串口收 1 MB 数据，CPU 一直在中断里搬运，别的活干不了。

**问**：DMA 是什么？没有它行不行？

## 口述答案

> DMA 是**直接内存访问**：外设和内存之间搬数据时**不经过 CPU**，CPU 只负责配置（源、目的、长度）和收完成中断。
> 没有它也能工作，但每搬一个字节都要一次中断或轮询，CPU 被彻底占住。有了 DMA，1 MB 数据只在结束时中断一次。

## 讲深一层

```c
// 串口 DMA 接收
HAL_UART_Receive_DMA(&huart1, buf, sizeof(buf));
// 传输完成后进 HAL_UART_RxCpltCallback
```
| 方式 | CPU 参与 | 适合 |
|---|---|---|
| 轮询 | 全程 | 极低速、简单 |
| 中断 | 每字节/每帧 | 中低速 |
| **DMA** | 仅配置和完成 | 高速、大批量 |
- DMA 要配**通道/请求源/优先级/传输宽度**，还要注意**缓存一致性**（有 Cache 的芯片要 `clean/invalidate`）。
- 常见坑：DMA 缓冲区放在 CCM RAM（DMA 访问不到）、传输中被改、忘记清标志。

## 高频追问

1. **DMA 传输期间 CPU 能访问同一块内存吗？** —— 能，但会产生竞争，需要软件协调（双缓冲）。
2. **DMA 完成怎么通知？** —— 传输完成中断 / 半满中断。

## 易错点

- 把 DMA 缓冲放在 DMA 访问不到的内存区
- 忽略 Cache 一致性（F7/H7 上必须处理）
