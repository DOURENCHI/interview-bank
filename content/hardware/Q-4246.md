## 题目

**场景**：你写了一个外部中断回调，里面直接 `printf` 打日志，又调了 `vTaskDelay` 等 10 ms 做按键去抖。

**问**：这段 ISR 有哪些问题？中断服务函数的设计原则是什么，哪些操作是禁止的？

## 口述答案

> ISR 的第一原则是**短**：只做"清标志、取数据、发通知"，把耗时处理丢给任务。
> 这段代码有三个硬伤：
> · `printf` 是**阻塞且不可重入**的，内部可能等 UART、动缓冲区，放在 ISR 里会拖长中断甚至死锁；
> · `vTaskDelay` 是任务级 API，在 ISR 里调用会直接触发断言；
> · 用延时去抖本身就把 CPU 占在中断里，应该改成时间戳判断或硬件滤波。
> 禁止清单：阻塞/延时、`malloc/free`、非 `FromISR` 版本的 FreeRTOS API、浮点运算（没开 FPU 上下文保存时）、长循环、不可重入的库函数。
> 正确姿势是 ISR 里 `xQueueSendFromISR` / `xTaskNotifyFromISR`，退出前 `portYIELD_FROM_ISR()` 触发切换。

## 讲深一层

```c
void HAL_GPIO_EXTI_Callback(uint16_t pin) {
    BaseType_t woken = pdFALSE;
    if (pin == KEY_PIN) {
        uint32_t t = HAL_GetTick();
        if (t - last_t > 20) {                 // 时间戳去抖，不阻塞
            last_t = t;
            xTaskNotifyFromISR(key_task, 1, eSetBits, &woken);
        }
    }
    portYIELD_FROM_ISR(woken);
}
```

| 能做 | 不能做 |
|---|---|
| 清中断标志、读写寄存器 | 延时、死等、阻塞 |
| 拷贝少量数据到缓冲区 | `malloc/free`、`printf` |
| 发队列/信号量/任务通知 | 非 `FromISR` 版 API |
| 置标志位 | 浮点运算（无 FPU 上下文保存时） |

## 高频追问

1. **清中断标志放在处理前还是处理后？** —— 多数外设要求先清再处理，否则处理期间的新事件会被吞；但清得太早也可能丢掉处理期间到来的边沿，要看外设手册，必要时用双缓冲或读-处理-再清。
2. **ISR 和任务共享变量要注意什么？** —— `volatile` 防优化，多字节数据要临界区或原子操作保护。
3. **中断嵌套要不要开？** —— 开嵌套能降低高优先级中断的延迟，但栈深度和临界区要重新核算，调试复杂度也上升。

## 易错点

- 在 ISR 里调 `HAL_Delay`，它依赖 SysTick，中断里会卡死。
- 忘了 `portYIELD_FROM_ISR`，通知发了但任务不立刻切换。
- ISR 里做浮点运算，没保存 FPU 上下文，任务数据被踩。
