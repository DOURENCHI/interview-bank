## 题目

**场景**：这个工具会被脚本调用。脚本怎么知道它成功了没有？

**问**：你怎么设计的退出码？为什么重要？

## 口述答案

**要点**

- **退出码是命令行工具的对外契约**。脚本里 `cmd && next` 或 `if cmd; then` 全靠它判断。
- 设计：`0` 成功；参数个数不对、时间格式非法、文件打不开等分别返回不同的非零值。
- 如果永远返回 0，脚本就无法区分「正常跑完」和「其实没读到文件」——自动化流程会静默出错。

## 讲深一层

退出码设计的通用原则：

| 码 | 含义 | 惯例 |
|---|---|---|
| 0 | 成功 | 所有工具统一 |
| 1 | 一般错误 | 通用兜底 |
| 2 | 用法错误 | 参数不对（grep/bash 都用 2） |
| 126/127 | 无法执行/命令不存在 | shell 保留 |
| 128+n | 被信号 n 终止 | shell 保留 |

自定义错误不要占用 126/127/128+ 这些 shell 保留值。

## 高频追问

1. **怎么在 C++ 里返回退出码？** —— `return code;` from `main`，或 `std::exit(code)`。
2. **和异常怎么配合？** —— `main` 里 catch 所有异常，转成对应退出码；不要在 catch 里直接 `return 0`。
3. **怎么测试退出码？** —— `./tool ...; echo $?`，或者写 shell 测试脚本断言。

## 易错点

- ❌ 所有错误都 `return 1` —— 脚本无法区分原因
- ❌ 出错后继续跑完再返回 0 —— 假成功，最危险
- ✅ 文档里列出每个退出码的含义
