## 题目

**场景**：两个类互相持有对方的 `shared_ptr`，对象销毁后内存没释放。

**问**：循环引用为什么会泄漏？`weak_ptr` 怎么破环？什么场景该用 `weak_ptr`？

## 口述答案

> 因为 `shared_ptr` 的释放条件是**引用计数归零**，而循环里 A 的计数被 B 持有、B 的计数被 A 持有，两者永远不归零，谁也不会析构。
> 把一个方向改成 `weak_ptr`：`weak_ptr` **不增加强引用计数**，只是"观察"，用的时候 `lock()` 提升成 `shared_ptr`（对象已销毁则返回空）。

## 讲深一层

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;      // ✅ 反向用 weak
};
```

| 指针 | 增加强计数 | 能访问对象 | 典型用途 |
|---|---|---|---|
| `shared_ptr` | ✅ | ✅ | 表达所有权 |
| `weak_ptr` | ❌ | 需 `lock()` | 打破环、观察者、缓存 |

```cpp
if (auto sp = wp.lock()) {        // 提升成功说明对象还活着
    sp->doSomething();
} else {
    // 对象已销毁
}
```

**破环规则**：在环上**任意一条边**改成 `weak_ptr` 即可。工程上常把"反向指针"（子指父）设为 `weak_ptr`，因为父拥有子的生命周期是自然的。

**其他用途**：缓存（条目可在别处被释放）、观察者模式（避免被观察者持有观察者）、`enable_shared_from_this` 内部实现。

## 高频追问

1. **`weak_ptr` 能直接解引用吗？** —— 不能，必须 `lock()`；否则并发下对象可能在使用中被销毁。
2. **`lock()` 是线程安全的吗？** —— 是，与同一控制块的 `shared_ptr` 操作线程安全。
3. **怎么发现循环引用？** —— 对象不析构但计数不为 0，或用 `valgrind` / 打印 `use_count()`。

## 易错点

- 双向关系两边都用 `shared_ptr`
- `weak_ptr` 直接 `*wp` 访问
- 用 `weak_ptr` 表达所有权（它不拥有对象）
