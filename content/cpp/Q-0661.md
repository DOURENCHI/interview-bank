## 题目

**场景**：STL 里容器名字一大堆，选错容器会让程序慢十倍。

**问**：顺序容器、容器适配器、关联容器、无序容器分别有哪些？按什么标准选？

## 口述答案

> 四类：**顺序容器**保持插入顺序（`vector`、`deque`、`list`、`array`）；**容器适配器**是对其他容器的接口包装（`stack`、`queue`、`priority_queue`）；**关联容器**有序、按 key 查找（`map`、`set`）；**无序容器**哈希实现（`unordered_map`、`unordered_set`）。
> 选择标准是三个问题：**要不要保持顺序、要不要按 key 查、插入删除集中在哪**。

## 讲深一层

| 容器 | 底层 | 随机访问 | 中间插入 | 查找 |
|---|---|---|---|---|
| `vector` | 连续数组 | ✅ O(1) | O(n) | O(n) |
| `deque` | 分段数组 | ✅ O(1) | O(n) | O(n) |
| `list` | 双向链表 | ❌ | O(1) | O(n) |
| `map` / `set` | 红黑树 | ❌ | O(log n) | O(log n) |
| `unordered_map` | 哈希表 | ❌ | 平均 O(1) | 平均 O(1) |
| `stack` / `queue` | 适配 `deque` | ❌ | — | — |

决策树：
1. 需要按 key 快速查 → `unordered_map`（不需要有序）或 `map`（需要有序/范围查询）；
2. 只在尾部增删 → `vector`（**默认选择**）；
3. 两头都要增删 → `deque`；
4. 频繁在中间插入且已持有迭代器 → `list`；
5. 数量固定 → `array`。

**实践结论**：`vector` 覆盖 90% 场景。链表"插入快"的优势常被"查找慢 + 缓存不友好"抵消。

## 高频追问

1. **`deque` 为什么两头插入都是 O(1)？** —— 分段连续存储，两端扩容只需新增一段。
2. **`map` 和 `unordered_map` 内存差多少？** —— 红黑树每节点有额外指针和颜色位，哈希表有桶数组和链表指针，通常 `unordered_map` 更省但不确定。
3. **`priority_queue` 底层是什么？** —— `vector` + 堆算法，默认大顶堆。

## 易错点

- 用 `list` 以为插入快，忽略查找成本
- 需要有序遍历却用 `unordered_map`
- 用 `vector<bool>` 当普通数组（它是位压缩的特化）
