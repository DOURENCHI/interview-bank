## 题目

**题目**：

```cpp
template <typename T> struct Base { T v; };
template <typename T> struct D : Base<T> { void f() { v = 1; } };   // 编译错误
```

**问**：为什么 `v` 找不到？类模板继承时，父类的模板参数怎么确定？

## 口述答案

> 因为 `Base<T>` 是**依赖基类**——`T` 还没确定，编译器不知道 `Base<T>` 里有什么，所以不会去里面查找 `v`。
> 解决办法有三种：写 `this->v`、写 `Base<T>::v`、或者 `using Base<T>::v;`。前两种是告诉编译器"这是个依赖名字，实例化后再找"。

## 讲深一层

```cpp
template <typename T> struct Base { T v; void g(); };

template <typename T> struct D : Base<T> {
    void f() {
        // v = 1;              // ❌ 找不到
        this->v = 1;           // ✅
        Base<T>::v = 1;        // ✅
        this->g();             // ✅
    }
    using Base<T>::v;          // ✅ 也可以先引入
};
```

| 写法 | 说明 |
|---|---|
| `this->v` | 声明这是成员访问 |
| `Base<T>::v` | 显式限定 |
| `using Base<T>::v;` | 引入名字到派生作用域 |
| `v` | 非依赖上下文才可用 |

**为什么这样设计**：C++ 是两阶段名字查找。模板定义时先做一次（非依赖名字），实例化时再做一次（依赖名字）。`Base<T>` 里的成员属于"依赖名字"，定义阶段不查，所以必须显式告诉编译器。

**同样的问题也出现在**：`typename T::value_type`（嵌套依赖类型必须加 `typename`）。

## 高频追问

1. **`typename` 什么时候必须写？** —— 访问依赖类型的嵌套类型时，如 `typename T::iterator`。
2. **`template` 关键字什么时候必须写？** —— 调用依赖模板的成员模板时，如 `t.template foo<int>()`。
3. **为什么要两阶段查找？** —— 让模板定义时就能发现明显的拼写错误。

## 易错点

- 在模板派生类里直接写 `v`
- 忘了嵌套依赖类型要加 `typename`
- 以为这只是编译器 bug
