## 题目

**题目**：

```cpp
struct A { A(){cout<<"A";} ~A(){cout<<"~A";} };
struct B {
    A a1, a2;
    B() { cout << "B"; }
    ~B() { cout << "~B"; }
};
```

**问**：输出是什么？如果初始化列表写成 `B() : a2(), a1() {}`，顺序会变吗？

## 口述答案

> 输出 `AAB~B~AA`。构造是 `a1`、`a2`、`B` 自身；析构完全逆序：`~B`、`~a2`、`~a1`。
> **初始化列表的书写顺序不影响构造顺序**，成员永远按**声明顺序**构造。上面写成 `a2(), a1()` 输出仍然是 `AAB`——编译器会按声明顺序执行，多数编译器还会给出 `-Wreorder` 警告。

## 讲深一层

```cpp
struct B {
    A a1, a2;
    B() : a2(), a1() {}     // 仍然先构造 a1！
};
```

| 对象 | 构造顺序 | 析构顺序 |
|---|---|---|
| 基类 | 1（最先） | 最后 |
| 成员 | 按**声明**顺序 | 逆序 |
| 自身构造函数体 | 最后 | 最先 |

**为什么这样规定**：析构顺序必须是构造的严格逆序，而构造顺序如果依赖初始化列表，就不可预测（不同构造函数可能写不同顺序）。按声明顺序才能保证"无论哪个构造函数，析构顺序都一样"。

**真正的坑**：初始化列表里 `a2(v)` 用到了 `a1` 的值，但 `a1` 还没构造——读到未初始化数据。

## 高频追问

1. **基类和成员的顺序？** —— 基类总是先于成员构造。
2. **虚基类呢？** —— 最派生类先构造虚基类，且只构造一次。
3. **能让成员晚构造吗？** —— 不能，成员总在构造函数体之前构造；需要延迟创建就用 `std::optional` 或指针。

## 易错点

- 以为初始化列表顺序决定构造顺序
- 在初始化列表里用未构造的成员
- 忘记成员按声明顺序析构
