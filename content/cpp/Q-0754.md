## 题目

**场景**：Linux 下写好的 socket 客户端代码（`socket()` + `recv()` 阻塞循环），想搬到 Qt 界面里，结果界面卡死。

**问**：为什么不能直接把原生 socket 代码搬进 GUI 线程？Qt 的正确做法是什么？

## 口述答案

> 因为**原生 `recv()` 是阻塞调用**，跑在 GUI 线程里会阻塞事件循环——界面不重绘、不响应点击，看起来就是卡死。
> Qt 的正确做法是用 **`QTcpSocket`**：它把 socket 集成到事件循环里，**非阻塞**，数据到达时发 `readyRead` 信号。或者把原生代码放到**独立线程**里。

## 讲深一层

```cpp
// ✅ Qt 方式：异步 + 信号
socket_ = new QTcpSocket(this);
connect(socket_, &QTcpSocket::connected,    this, &MainWindow::onConnected);
connect(socket_, &QTcpSocket::readyRead,    this, &MainWindow::onReadyRead);
connect(socket_, &QTcpSocket::disconnected, this, &MainWindow::onDisconnected);
socket_->connectToHost("127.0.0.1", 8080);

void MainWindow::onReadyRead() {
    QByteArray data = socket_->readAll();     // 不阻塞
}
```

| 方案 | 阻塞 | 集成事件循环 | 适合 |
|---|---|---|---|
| 原生 socket + `recv` | ✅ | ❌ | 独立线程/命令行程序 |
| `QTcpSocket` | ❌ | ✅ | **GUI 程序** |
| 原生 + `select`/`poll` | ❌ | 需自己接 | 高性能多路复用 |
| 原生 socket 放子线程 | ✅ | 子线程内 | 复用已有代码 |

**`readyRead` 的一个坑**：它表示"**有数据可读**"，不保证一次读到完整报文。TCP 是字节流，必须自己处理**粘包/半包**（定长、分隔符、或长度前缀）。

**`readAll()` 也可能只拿到部分数据**，不要在 `readyRead` 里假设一次就是一条完整消息。

## 高频追问

1. **怎么处理粘包？** —— 用长度前缀或分隔符，维护一个缓冲区累积到完整报文再解析。
2. **`QTcpSocket` 能在子线程用吗？** —— 能，但必须在那个线程创建和使用（见 Q-0766）。
3. **需要 UDP 呢？** —— 用 `QUdpSocket`，同样非阻塞。

## 易错点

- 在 GUI 线程调用阻塞 `recv()`，界面假死
- 在 `readyRead` 里假设一次读到完整报文
- 用 `waitForReadyRead()`（也是阻塞的）在 GUI 线程里
