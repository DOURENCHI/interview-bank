## 题目

**题目**：

```cpp
struct S {
    int a, b;
    S() : b(2), a(1) {}     // 先 b 后 a？
};
```

**问**：成员的初始化顺序由什么决定？为什么和初始化列表的书写顺序无关？

## 口述答案

> 由**声明顺序**决定，不是初始化列表顺序。所以 `a` 先初始化成 1，`b` 再初始化成 2，尽管列表里先写了 `b`。
> 这样规定是为了保证"**无论用哪个构造函数，析构顺序都一致**"——析构必须严格逆序，如果构造顺序可变，析构顺序就不确定了。

## 讲深一层

```cpp
struct S {
    int a, b;
    S() : b(2), a(1) {}   // 实际：a 先，b 后
    // GCC/Clang: warning: 'b' will be initialized after 'a'
};
```

| 阶段 | 顺序 |
|---|---|
| 虚基类 | 最先（只一次） |
| 非虚基类 | 按继承声明顺序 |
| 成员 | 按**声明顺序** |
| 构造函数体 | 最后 |

**真正的 bug 场景**：初始化列表里用另一个还没构造的成员。

```cpp
struct Bad {
    int x, y;
    Bad() : x(1), y(x + 1) {}    // ⚠️ 若 y 声明在前，y 读到未初始化的 x
};
```

**怎么避免**：开启 `-Wreorder`（`-Wall` 已包含），编译器会警告顺序不一致。

## 高频追问

1. **`-Wreorder` 会误报吗？** —— 不会，它只报列表顺序和声明顺序不一致的情况。
2. **基类和成员谁先？** —— 基类先；多个基类按声明顺序。
3. **成员能在构造函数体里再赋值吗？** —— 能，但那是赋值不是初始化，多一次构造+赋值开销。

## 易错点

- 依赖初始化列表顺序写逻辑
- 在初始化列表里用未构造的成员
- 内在类型成员忘了初始化（值不确定）
