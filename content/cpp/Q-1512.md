## 题目

**题目**：容器里的 Java 进程突然被杀了，`dmesg` 里有一行 `Killed process ... (java)`。

**问**：OOM killer 为什么杀进程？它是怎么打分的？

## 口述答案

> Linux 在**内存真的不够**（且无法回收）时会触发 OOM killer，选一个进程杀掉以保住系统。它按 `/proc/<pid>/oom_score` 打分：**占用内存越多、分越高、越容易被杀**。
> 分数还受 `oom_score_adj`（-1000~1000）调整：值越低越不容易被杀（-1000 表示禁用），这是保护关键进程的标准手段。

## 讲深一层

| 因素 | 对分数的影响 |
|---|---|
| RSS/总内存占比 | 越大越高 |
| `oom_score_adj` | 直接加减 |
| root 进程 | 略降权 |
| 已经 oom 过的 | 略升权 |
```bash
cat /proc/$(pgrep java)/oom_score
echo -500 > /proc/$(pgrep java)/oom_score_adj   # 降低被杀概率
```
- 触发前通常先经历**直接回收**（drop cache、swap），仍不够才 OOM。
- 容器里要区分：**cgroup 限额触发的 OOM**（杀容器内进程）和**宿主机 OOM**（可能杀别的容器）。
- 治本：限制堆大小（`-Xmx`）、加内存、修内存泄漏。

## 高频追问

1. **`echo -1000` 会怎样？** —— 该进程基本不会被 OOM killer 选中（但可能导致系统杀别的进程）。
2. **怎么确认是 OOM 而不是被 kill -9？** —— `dmesg -T | grep -i oom` 有记录。

## 易错点

- 以为 OOM 先杀 CPU 占用高的
- 在容器里看宿主机 `dmesg` 就下结论（要看 cgroup 的 memory.events）
