## 题目

**题目**：

```cpp
try { throw std::runtime_error("x"); }
catch (std::exception e) { }        // 按值
catch (const std::exception& e) { } // 按引用
```

**问**：异常对象存在哪？为什么 catch 要写引用？按值捕获会发生什么？

## 口述答案

> 异常对象由编译器分配在**特殊的异常存储区**（不是栈，因为栈要被展开），生命周期从抛出到最后一个 catch 结束。
> 按值捕获会**拷贝一份并发生切片**：`std::exception e = runtime_error(...)` 只保留基类部分，`what()` 返回基类信息，派生类数据全丢。按引用捕获不拷贝、不切片，虚调用正常。

## 讲深一层

```cpp
struct MyErr : std::runtime_error {
    int code;
    MyErr(int c) : std::runtime_error("my"), code(c) {}
};

try { throw MyErr(42); }
catch (std::exception e) {          // ❌ 切片，拿不到 code
    // e.what() 是基类信息
}
catch (const MyErr& e) {            // ✅ 保留全部信息
    cout << e.code;
}
```

| 捕获方式 | 拷贝 | 切片 | 动态类型 |
|---|---|---|---|
| `catch (E e)` | ✅ | ✅ | 丢失 |
| `catch (E& e)` | ❌ | ❌ | 保留 |
| `catch (const E& e)` | ❌ | ❌ | 保留（推荐） |
| `catch (...)` | — | — | 完全丢失 |

**为什么不能用 `catch (E&& e)` 通用**：能捕获，但异常对象是左值语义，`&&` 反而限制了能捕获的范围。

**顺序要求**：派生类在前、基类在后，否则派生分支永远不执行。

## 高频追问

1. **异常对象能被修改吗？** —— `catch (E& e)` 可以，但修改的是副本（异常对象本身的副本），影响不到抛出方。
2. **`throw;` 和 `throw e;` 区别？** —— 前者重新抛出原对象（保留类型），后者拷贝一份（可能切片）。
3. **异常对象的拷贝次数？** —— 标准允许实现省略，通常只有一次（构造异常对象时）。

## 易错点

- 按值捕获导致切片，`what()` 信息丢失
- `throw e;` 而不是 `throw;`，重新抛出时切片
- 基类 catch 写在前面
