## 题目

**现象**：`#include "c_lib.h"` 之后调用 `c_func()`，链接报 `undefined reference to 'c_func()'`，但 `nm` 明明能看到 `c_func`。

**问**：为什么 C++ 调不了 C 的函数？`extern "C"` 做了什么？

## 口述答案

> 因为 C++ 有**函数重载**，编译器会对函数名做**名字修饰**（name mangling），把参数类型编进符号名。C 不做修饰，符号就是 `c_func`。
> 所以 C++ 去链接时找的是 `_Z6c_funci` 这类名字，而 C 库里只有 `c_func`，自然找不到。`extern "C"` 的作用就是**告诉编译器这个符号按 C 的规则生成**，不做修饰。

## 讲深一层

```cpp
extern "C" {
    int c_func(int);          // 按 C 规则生成符号 c_func
}
```

标准写法（头文件同时支持 C 和 C++）：
```c
#ifdef __cplusplus
extern "C" {
#endif

int c_func(int);

#ifdef __cplusplus
}
#endif
```

| 语言 | `int f(int)` 的符号 |
|---|---|
| C | `f` |
| C++（g++） | `_Z1fi` |
| C++（MSVC） | `?f@@YAHH@Z` |

```bash
nm libc_lib.a | grep c_func        # 看到 c_func
nm myapp | grep c_func             # C++ 侧是 _Z6c_funci
c++filt _Z1fi                      # 还原成 f(int)
```

**反过来也成立**：C 调 C++ 函数必须给 C++ 函数加 `extern "C"`，否则 C 侧找不到符号。而且不能用重载（C 无法区分）。

## 高频追问

1. **`extern "C"` 能包类吗？** —— 不能，类、模板、重载函数都不行，只支持自由函数和变量。
2. **为什么 `nm` 看到的符号带下划线？** —— 不同平台的修饰规则不同，`c++filt` 可以还原。
3. **C++ 调 C 的库要不要改库？** —— 不用，只要在自己的头文件里用 `extern "C"` 声明。

## 易错点

- 只在函数声明前加 `extern "C"` 却忘了包住整段
- 试图 `extern "C"` 一个重载函数
- 头文件没写 `__cplusplus` 判断，C 编译器报错
