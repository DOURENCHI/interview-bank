## 题目

**现象**：`apt list --installed | grep opencv` 显示装了，`ls /usr/include/opencv4` 也有头文件，但 `find_package(OpenCV REQUIRED)` 报 `Could not find a package configuration file`。

**问**：CMake 找包靠什么？「装了但找不到」有哪几种原因？

## 口述答案

> CMake 找包有两条路：**Config 模式**（找 `OpenCVConfig.cmake`）、**Find 模块模式**（用 `FindOpenCV.cmake`）。报 `Could not find a package configuration file` 说明它在找 Config 文件但没找到。
> 常见原因：包装在非标准前缀（`/usr/local`、conda 环境、自编译目录）、没设 `CMAKE_PREFIX_PATH`、包只提供 `pkg-config` 文件而没有 Config、或者装的是运行时库没装开发包（`-dev`）。

## 讲深一层

```bash
# 让 CMake 知道去哪找
cmake -DCMAKE_PREFIX_PATH=/opt/opencv ..
cmake -DOpenCV_DIR=/opt/opencv/lib/cmake/opencv4 ..

# 看它找到的是哪个
cmake -B build && grep -i opencv build/CMakeCache.txt
```

```cmake
find_package(OpenCV REQUIRED)          # Config 或 Find 模块
message(STATUS "OpenCV: ${OpenCV_DIR} ${OpenCV_VERSION}")

# 找不到 Config 时，退回 pkg-config
find_package(PkgConfig REQUIRED)
pkg_check_modules(OCV REQUIRED opencv4)
target_include_directories(app PRIVATE ${OCV_INCLUDE_DIRS})
target_link_libraries(app PRIVATE ${OCV_LIBRARIES})
```

| 现象 | 原因 | 处理 |
|---|---|---|
| 找不到 Config 文件 | 装在非标准路径 | 设 `CMAKE_PREFIX_PATH` / `xxx_DIR` |
| 找到了但版本不符 | 系统里有旧版 | 用 `find_package(OpenCV 4.5 REQUIRED)` 指定 |
| 编译过但链接失败 | 只有 `.so` 没有 `.so` 符号链接（缺 dev 包） | 装 `-dev` 包 |
| 混用了两个版本 | 缓存里是旧路径 | 删 `build/CMakeCache.txt` 重新配 |

**最容易被忽略的一条**：`CMakeCache.txt` 会记住上次找到的路径。改了环境变量但没删缓存，它不会重新找。

## 高频追问

1. **`xxx_DIR` 和 `CMAKE_PREFIX_PATH` 什么区别？** —— 前者精确指定某个包的 Config 所在目录，后者是搜索根，CMake 会在其下按规则找。
2. **怎么让 CMake 重新找？** —— 删掉 `build/CMakeCache.txt`，或 `cmake --fresh`（3.24+）。
3. **`pkg-config` 和 CMake 谁优先？** —— 有 Config 就用 Config，没有才考虑 pkg-config。

## 易错点

- 只装运行时库，没装 `-dev`，头文件缺失
- 改了环境但没清缓存，始终用旧路径
- 全局污染 `CMAKE_PREFIX_PATH`，导致找错版本
