## 题目

**题目**：Qt 多线程有两种写法：`class W : public QThread { void run() override; }` 和 `moveToThread`。

**问**：两种写法差在哪？为什么官方现在推荐 `moveToThread`？

## 口述答案

> 关键区别是**哪些代码跑在新线程**：重写 `run()` 时只有 `run()` 函数体在新线程，`W` 的其他槽函数仍在**创建它的线程**执行——很容易误以为整个对象都在新线程。
> `moveToThread` 把**整个对象的槽函数**都搬到新线程执行，语义更清晰，也符合"QObject 属于某个线程"的模型。

## 讲深一层

```cpp
// 方式一：继承 QThread（只有 run 在新线程）
class Worker : public QThread {
    void run() override { /* 这里在新线程 */ }
    void onTimeout() { /* ⚠️ 这里在旧线程！ */ }
};

// 方式二：moveToThread（整个对象的槽都在新线程）
class Worker : public QObject {
    Q_OBJECT
public slots:
    void doWork() { /* 在新线程 */ }
};

auto* th = new QThread(this);
auto* w = new Worker();
w->moveToThread(th);
connect(th, &QThread::started, w, &Worker::doWork);
connect(w, &Worker::done, th, &QThread::quit);
th->start();
```

| 方式 | 新线程执行什么 | 适合 |
|---|---|---|
| 继承 `QThread` | 只有 `run()` | 纯计算循环，不需要事件循环 |
| `moveToThread` | 对象的**所有槽** | 需要信号槽、定时器、事件循环 |
| `QtConcurrent::run` | 一个函数 | 一次性任务 |
| 线程池 `QThreadPool` | 若干 `QRunnable` | 大量短任务 |

**判断标准**：需要在新线程里**收信号、用定时器**，就必须用 `moveToThread`（因为这些依赖事件循环，而 `QThread::run` 默认不跑事件循环）。

## 高频追问

1. **`moveToThread` 后原线程还能调它的方法吗？** —— 能，但那是直接调用（在新线程之外执行），要排队就用信号槽。
2. **对象能有多个线程吗？** —— 不能，`moveToThread` 是把整个对象搬过去。
3. **`run()` 里想用信号槽怎么办？** —— 在 `run()` 里调 `exec()` 启动事件循环。

## 易错点

- 继承 `QThread` 后把槽函数当"在子线程执行"
- `moveToThread` 后对象还有父对象（不允许跨线程有父）
- 忘了 `th->start()`，以为 move 完就跑了
