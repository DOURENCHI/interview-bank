## 题目

**场景**：龙芯中科面经题。新板 bring-up 必遇：内核像「死」了一样，串口一个字都没有——考的是有没有一套不瞎猜的排查顺序。

> 原题：Linux 内核早期串口没有输出时，你会检查哪些时钟、引脚、驱动和启动参数？

## 口述答案

> 直答：**按「物理层 → 启动参数 → 时钟/引脚 → 驱动」四层排查，用「内核解压前/解压后」这个分界先切一刀**。①**物理层先排除**：示波器看 TX 有没有波形——有波形是波特率/接线/终端设置问题，无波形才轮到「内核没打印」；②**启动参数第一位查**（改起来最快、错得最多）：`console=ttyS0,115200` 的设备名和波特率、`earlycon=uart8250,mmio32,<寄存器物理地址>,115200` 的地址/寄存器宽度（reg-shift、reg-io-width）是否与手册和设备树一致，再补 `loglevel=8 ignore_loglevel` 把打印全放开——bootargs 错一个字符就全哑；③**时钟与引脚**：设备树里 UART 节点的 clocks 是否引用正确、早期时钟门控有没有开（没时钟寄存器写不进），pinctrl 是否把 TX/RX 复用成 UART 功能而不是 GPIO；④**驱动**：UART 驱动和 CONSOLE/EARLYCON 支持必须编进内核（＝y 而不是 ＝m，早期 console 依赖内建驱动），console= 的设备名要和实际驱动对上（ttyS 与 ttyAMA 是不同驱动家族）。
>
> 还有一刀重要分界：**解压前有输出、解压后没有**——解压前是固件自己的串口驱动在打，解压后轮到内核，页表/设备树任一出错都死在打印之前。用 earlycon 能不能出字判断死在哪一段；看到乱码则是波特率除数错——UART 实际时钟源和你以为的不一致，回头查时钟树。

## 讲深一层

| 排查层 | 检查点 | 手段/证据 |
|---|---|---|
| 物理层 | TX 波形、电平、TX/RX 交叉、共地、终端波特率 | 示波器；换终端重试 |
| 启动参数 | console= / earlycon= / loglevel= | 对照手册与设备树逐字符核对；先加 ignore_loglevel |
| 时钟 | UART 源时钟是否使能、频率是否如预期 | 查时钟树与固件日志；乱码＝除数按错时钟算的 |
| 引脚复用 | pinctrl 是否把 TX/RX 复用为 UART | 设备树 pinctrl-0；对照引脚复用表 |
| 驱动 | UART 驱动＋console/earlycon 支持编入内核 | .config：串口 CONSOLE、EARLYCON 相关选 ＝y |
| 分界定位 | 解压前（固件）/解压后（内核）输出归属 | 看输出内容与固件 banner 是否同源 |

earlycon 与 console 的分工（追问高频）：earlycon 在驱动模型起来之前，按启动参数里写死的物理地址轮询写 UART——能用但需要手写地址和寄存器格式；console= 挂的是正式 tty 驱动，功能完整但要等驱动 probe 完成。**早期输出靠 earlycon，起来后自动切到 console**，两者参数不一致时会出现「前半段有字后半段没字」的典型现象。

**记忆锚点**：「**一看波形，二看 bootargs，三看时钟引脚，四看驱动编没编进内核**」。

## 高频追问

1. **earlycon 和 console= 的区别？** —— earlycon 按参数里的物理地址轮询直写 UART，不依赖驱动模型；console= 是正式 tty 设备，要等驱动 probe。排查早期问题用 earlycon，正常输出靠 console。
2. **loglevel 和 ignore_loglevel 什么关系？** —— console 只打印优先级不低于 loglevel 的消息，ignore_loglevel 全开；排查期第一步就是放开它，别让内核「其实在说话你听不见」。
3. **为什么解压前有输出解压后没有？** —— 解压前是固件的 UART 驱动；解压后轮到内核，页表/MMU/设备树出错会死在打印之前——用 earlycon 从第一句开始看它死在哪。
4. **乱码怎么快速定位是不是波特率问题？** —— 整段规律乱码但节奏对＝波特率/时钟源错；偶发丢字符＝中断/DMA/流控问题。用固件阶段已知正确的波特率反推内核 UART 的实际时钟。

## 易错点

- 没看波形就埋头改代码——接反、没共地、终端波特率配错这类物理层问题占大头。
- console= 设备名想当然（ttyS0 与 ttyAMA0 是两套驱动）——名字必须与实际驱动一致。
- UART 驱动编成模块——早期 console 依赖内建驱动，＝m 等于没有。
- 忽略 loglevel——内核其实在打印，全被过滤了。
