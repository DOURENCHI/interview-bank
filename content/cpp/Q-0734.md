## 题目

**追问**：类模板的成员函数写在 `.cpp` 里，链接报 `undefined reference`。

**问**：为什么类模板的成员函数必须写在头文件里？有没有例外？

## 口述答案

> 因为**只有实例化时才生成代码**，而编译器在编译某个 `.cpp` 时，如果只看到声明，不知道模板参数是什么，就无法生成成员函数的代码。
> 链接时其他 `.cpp` 调用 `Stack<int>::push`，但没有任何编译单元生成过它，于是 `undefined reference`。

## 讲深一层

```cpp
// stack.h
template <typename T>
class Stack {
    std::vector<T> v_;
public:
    void push(const T& x);      // 只有声明
};

// stack.cpp —— ❌ 没人告诉编译器 T 是什么，不会生成任何代码
template <typename T>
void Stack<T>::push(const T& x) { v_.push_back(x); }
```

三个解决方案：

| 方案 | 做法 | 适用 |
|---|---|---|
| 放头文件 | 定义写进 `.h` 或 `.hpp` | 通用 |
| 显式实例化 | `.cpp` 末尾写 `template class Stack<int>;` | 类型可枚举 |
| 分离 + 显式实例化声明 | 头里 `extern template class Stack<int>;` | 大项目加速编译 |

```cpp
// stack.cpp 末尾
template class Stack<int>;
template class Stack<double>;
```

**为什么标准库的头文件那么大**：`<vector>` 把所有成员函数的实现都写在头文件里，就是为了让每个使用点都能实例化。

## 高频追问

1. **`.hpp` 是什么？** —— 约定俗成的扩展名，表示"含实现的头文件"，编译器不区别对待。
2. **显式实例化能减小体积吗？** —— 能，避免每个编译单元各生成一份。
3. **模板能编译成动态库吗？** —— 能，但必须在库里显式实例化所有需要的类型。

## 易错点

- 模板成员函数放 `.cpp`，链接失败
- 显式实例化漏了某个类型
- 以为 `.hpp` 有特殊语法
