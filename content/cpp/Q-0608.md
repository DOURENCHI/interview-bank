## 题目

**场景**：`vector` 不断 `push_back`，观察 `capacity()` 的变化：1、2、4、8、16……不是 1、2、3、4。

**问**：为什么容量是倍增而不是每次加一？为什么不同实现的倍数还不一样（1.5× 和 2×）？

## 口述答案

> 倍增是为了让**均摊插入成本是 O(1)**。每次扩容要搬移全部元素，如果每次只加一个，容量增长是线性的，总搬移量是 1+2+…+n = O(n²)。
> 按倍数增长时，总搬移量是等比级数，收敛到 O(n)，均摊到每次插入就是 O(1)。
> 倍数的差异是工程折中：**2× 保证均摊 O(1) 但浪费最多一倍内存，1.5× 内存更省且能复用已释放的块**（MSVC 用 1.5，libstdc++ 用 2）。

## 讲深一层

| 实现 | 增长因子 | 说明 |
|---|---|---|
| libstdc++（GCC） | 2× | 简单，浪费多 |
| libc++（Clang） | 2× | 同上 |
| MSVC | 1.5× | 内存友好，且 1.5 倍序列可以复用之前的块 |

```cpp
std::vector<int> v;
for (int i = 0; i < 10; ++i) {
    v.push_back(i);
    std::cout << v.size() << "/" << v.capacity() << "\n";
}
// 1/1 2/2 3/4 4/4 5/8 6/8 7/8 8/8 9/16 10/16
```

**均摊分析的直觉**：n 次插入总搬移 ≈ n + n/2 + n/4 + … < 2n，所以每次插入平均搬移不到 2 个元素。

**扩容的代价不只是搬移**：所有指向元素的指针、引用、迭代器**全部失效**。这是 `vector` 最容易踩的坑——保存了 `&v[0]` 然后又 `push_back`。

## 高频追问

1. **扩容时旧内存怎么处理？** —— 分配新块 → 移动/拷贝元素 → 释放旧块。C++11 起元素可移动时用移动，否则拷贝。
2. **为什么 `vector` 不能像 `deque` 那样分段？** —— 分段就失去了连续内存，无法 `data()` 和指针算术，与"连续容器"的定位冲突。
3. **怎么完全避免扩容？** —— 已知规模就 `reserve`；或用 `std::array` / 固定容量容器。

## 易错点

- 认为"每次加一更省内存"，忽略 O(n²) 搬移
- 扩容后继续用旧指针/迭代器
- 把 `capacity()` 当 `size()` 用
