## 题目

**题目**：想全局拦截某个控件的鼠标点击，可以重写 `mousePressEvent`，也可以装 `eventFilter`。

**问**：Qt 的事件怎么派发？`event()` 和事件过滤器有什么区别？

## 口述答案

> 派发路径是：**事件循环取出事件 → `QCoreApplication::notify` → 目标对象的 `event()` → 分发给具体的 `mousePressEvent` 等处理函数**。
> 事件过滤器插在 `notify` 和目标 `event()` 之间——**比目标对象更早看到事件**，而且能拦截多个对象的事件。重写 `event()` 只能处理自己的事件。

## 讲深一层

```cpp
// 事件过滤器：能在目标之前拦截
target->installEventFilter(this);

bool MainWindow::eventFilter(QObject* obj, QEvent* e) {
    if (obj == target && e->type() == QEvent::MouseButtonPress) {
        // 处理或拦截
        return true;        // true = 已处理，不再往下传
    }
    return QMainWindow::eventFilter(obj, e);
}
```

| 手段 | 位置 | 范围 | 能否拦截别人的事件 |
|---|---|---|---|
| `eventFilter` | 目标 `event()` 之前 | 可监听多个对象 | ✅ |
| 重写 `event()` | 目标对象 | 只有自己 | ❌ |
| 重写 `mousePressEvent` | 最后 | 只有自己 | ❌ |
| `installEventFilter` 在 `qApp` 上 | 全局 | 所有对象 | ✅（慎用，性能） |

**`return true` 和 `return false` 的区别**：`true` 表示"事件已处理，别再传下去"；`false` 表示"我看过了，继续按正常流程走"。

**顺序**：多个过滤器按**安装的逆序**执行（后装的先看到），最后才到对象的 `event()`。

## 高频追问

1. **事件和信号槽什么关系？** —— 事件是"输入/系统通知"，信号是"对象状态变化"；Qt 内部有些信号由事件触发。
2. **`event()` 里要调基类吗？** —— 未处理的事件必须调 `QWidget::event(e)`，否则会丢失默认行为。
3. **能否阻止事件继续传递？** —— `e->accept()` / `ignore()` 控制，或在过滤器里 `return true`。

## 易错点

- 事件过滤器里 `return true` 但没处理，导致控件行为丢失
- 重写 `event()` 不调基类，默认行为全失效
- 在 `qApp` 上装过滤器监听所有事件，拖慢整个程序
