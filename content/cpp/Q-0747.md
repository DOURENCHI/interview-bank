## 题目

**场景**：Qt 程序点了按钮没反应，加了几个断点，但 `QApplication::exec()` 一进去就出不来，看不出问题。

**问**：Qt 程序调试时，断点下在哪里才有用？

## 口述答案

> **不要走在事件循环主线程的入口断点**，因为 `exec()` 是个死循环，停在那里什么都看不到。
> 有用的断点是：**槽函数的第一行**（确认信号有没有连上、有没有触发）、**`connect` 的返回值**（确认连接成功）、**事件处理函数 `event()` / `mousePressEvent`**（确认事件到了）、以及**出问题那个成员函数的数据入口**。

## 讲深一层

```cpp
// 1. 确认 connect 成功
bool ok = connect(btn, &QPushButton::clicked, this, &MainWindow::onClick);
Q_ASSERT(ok);                                  // 失败会在这里停住

// 2. 槽函数第一行断点
void MainWindow::onClick() {
    int x = 0;                                 // ← 断点放这里
    ...
}

// 3. 事件过滤器
bool MainWindow::eventFilter(QObject* o, QEvent* e) {
    if (e->type() == QEvent::MouseButtonPress) { /* 断点 */ }
    return QMainWindow::eventFilter(o, e);
}
```

| 现象 | 该在哪断 |
|---|---|
| 点了没反应 | 槽函数首行 + `connect` 返回值 |
| 界面卡死 | 所有可能阻塞的槽函数（看调用栈） |
| 数据不对 | 成员函数的入口和出口 |
| 事件不触发 | `event()` / `eventFilter` |
| 崩溃 | 用调试器捕获异常，看栈 |

**调试 Qt 的两个实用技巧**：
1. **`qDebug()` 比断点更适合事件循环**——不打断流程，能看到时序。
2. **`QT_LOGGING_RULES`** 可以打开 Qt 内部日志（如 `qt.qpa.*`），排查平台插件问题。

**卡死时怎么办**：附加调试器，暂停，看**主线程的调用栈**——99% 是槽函数里做了阻塞操作。

## 高频追问

1. **怎么知道信号连没连上？** —— 断在 `connect` 那行看返回值，或运行时看控制台有没有 `QObject::connect: No such slot` 警告。
2. **能断在事件循环里吗？** —— 能但要小心，`exec()` 里会反复停；用条件断点。
3. **`qDebug` 输出到哪？** —— Windows 下是调试器输出窗口，Linux 下是 stderr。

## 易错点

- 在 `exec()` 上打断点，程序"卡住"以为是 bug
- 不看 `connect` 返回值和运行时的 connect 警告
- 阻塞式操作写在槽函数里导致界面假死
