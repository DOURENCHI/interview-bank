## 题目

**场景**：小鹏嵌入式软件面经的文件 I/O 追问段：先问 Direct I/O 和普通文件 I/O 的区别、为什么有些场景要绕过 Page Cache，再压到「为什么用户 Buffer 的地址、长度、文件偏移有对齐要求」和「为什么普通 malloc 的 Buffer 不一定满足要求」。

**问**：Linux Direct I/O 为什么要求用户缓冲区地址、长度和文件偏移按块对齐？不对齐会怎样，工程上怎么解决？

## 口述答案

> **根本原因：O_DIRECT 绕过页缓存后，数据是按块在「用户缓冲区 ↔ 磁盘」之间直搬的**。普通 write 有页缓存当中转站，任意地址和长度都能先拷进缓存页、由内核整理后落盘；开 O_DIRECT 后这层缓冲没了，**磁盘 I/O 的最小单位是扇区/逻辑块**（512B 起步，文件系统通常按 4096 即一个内存页对齐），内核在提交 I/O 时直接校验——**地址、长度、偏移三者都要落在块边界上，任一不满足返回 EINVAL**。
>
> 三个对齐的具体含义：**地址**——缓冲区起始按逻辑块大小（保守取 4096）对齐；**长度**——本次读写的字节数是块大小的整数倍；**偏移**——文件内读写的起始位置同样按块对齐。malloc 只保证 16 字节对齐（满足最大基本类型），`new` 和栈上数组更不保证，所以**普通 malloc 的 Buffer 大概率不满足 O_DIRECT 要求**。
>
> 解法：`posix_memalign(&p, 4096, size)`（或 C++17 `std::aligned_alloc`）按块对齐分配，长度也向上取整到块大小。什么时候值得绕页缓存：**数据库、日志系统这类自带缓存的程序**——缓存自己管，再过一遍页缓存是双重缓存，白占内存还多一轮回写；O_DIRECT 省一次 CPU 拷贝、不污染页缓存、落盘节奏可控。代价：**失去预读、写合并、按需调页这些内核优化**，小块随机读通常变慢——普通应用老实用 Buffered I/O。

## 讲深一层

| 维度 | Buffered I/O | O_DIRECT |
|---|---|---|
| 拷贝次数 | 磁盘→页缓存→用户区（两次涉拷） | 磁盘↔用户区直搬（省一次拷贝） |
| 对齐要求 | 无 | 地址/长度/偏移按块对齐，否则 EINVAL |
| 内核优化 | 预读+合并+按需调页全有 | 全没有，缓存策略自己管 |
| 典型用户 | 绝大多数应用 | 数据库、日志、自带缓存的存储引擎 |

```c
#define BLK 4096
void *buf = NULL;                     // malloc 只保证 16B 对齐，直读会 EINVAL
posix_memalign(&buf, BLK, 4 * BLK);   // 按块对齐分配缓冲区
int fd = open("data.bin", O_RDWR | O_DIRECT);
pread(fd, buf, 4 * BLK, 0);           // 长度、偏移同样按 BLK 对齐
```

**判断技巧**：答 O_DIRECT 别停在「绕过缓存快」，要落到「DMA 按块直搬，所以三个参数都要块对齐」这一层。**记忆锚点**：「绕过页缓存 = 免了中转站，但搬运工只认块——地址、长度、偏移踩线就 EINVAL」。

## 高频追问

1. **对齐单位到底取多少？** —— 取文件系统逻辑块大小（ext4/xfs 常见 4096，statvfs 的 f_frsize 可程序化读取）；拿不准就按 4096 对齐，兼容性最好。
2. **为什么数据库都开 O_DIRECT？** —— DB 自带 buffer pool，页缓存那份是重复缓存，白占内存还让刷盘时机失控；绕过后内存预算和落盘节奏都归 DB 自己管。
3. **O_DIRECT 和 mmap 读大文件选哪个？** —— mmap 仍走页缓存、靠缺页调入，省的是拷贝；O_DIRECT 连缓存也不要。随机小 IO 用 mmap 缺页/TLB 开销可能更糟，自带缓存的引擎选 O_DIRECT。
4. **O_DIRECT 写的数据什么时候落盘？** —— 绕过页缓存不等于实时落盘，仍是异步 I/O；要掉电不丢照样得 fsync/fdatasync，只是不再等内核回写线程。

## 易错点

- 只对齐地址，忘了长度和文件偏移——三个条件缺一不可，任一不满足就是 EINVAL。
- 拿 malloc/new 的缓冲区直接 O_DIRECT——16 字节对齐不是块对齐。
- 把对齐单位说死成 512——不同文件系统逻辑块不同，保守按 4096。
- 只答「快」不答代价——失去预读和合并，小块随机读反而慢，普通应用别开。
