## 题目

**场景**：手写一个 `unique_ptr` 的简化版，写完发现 `p->method()` 编译不过。

**问**：`operator->` 和 `operator*` 分别返回什么？为什么 `operator->` 可以「递归调用」？

## 口述答案

> `operator*` 返回**对象的引用**（`T&`），所以 `*p` 可以直接用；`operator->` 返回**指针**（`T*`），所以 `p->method()` 等价于 `(p.operator->())->method()`。
> `operator->` 的特殊之处是**语言规定它会自动递归**：如果返回的又是一个重载了 `->` 的类，编译器会继续调用，直到拿到裸指针。这让智能指针、迭代器能无感地模拟指针语法。

## 讲深一层

```cpp
template <typename T>
class UniquePtr {
    T* p_ = nullptr;
public:
    ~UniquePtr() { delete p_; }
    T& operator*()  const { return *p_; }    // 返回引用
    T* operator->() const { return p_; }     // 返回裸指针
    explicit operator bool() const { return p_ != nullptr; }
};

UniquePtr<Foo> p(new Foo);
(*p).method();      // 解引用
p->method();        // 等价于 (p.operator->())->method()
```

| 运算符 | 返回类型 | 调用形式 |
|---|---|---|
| `operator*` | `T&` | `*p` |
| `operator->` | `T*`（或带 `->` 的类型） | `p->x` |
| `operator[]` | `T&` | `p[i]` |
| `operator bool` | `bool` | `if (p)` |

**递归的用途**：`std::vector<T>::iterator` 的 `operator->` 可能返回另一个代理对象，链式递归让 `it->field` 能一路解到真正的成员。

**注意**：`operator->` 必须返回指针或"有 `->` 的对象"，返回 `T&` 会编译错误。

## 高频追问

1. **为什么 `operator*` 返回引用而不是值？** —— 要支持 `*p = 1;` 这种写操作。
2. **`explicit operator bool` 有什么用？** —— 让 `if (p)` 可用，同时禁止 `int n = p;` 这种隐式转换。
3. **`operator->` 能带参数吗？** —— 不能，必须是零参数成员函数。

## 易错点

- `operator->` 返回 `T&`
- `operator*` 返回值，导致 `*p = 1` 改不到原对象
- 忘了 `operator bool` 加 `explicit`，产生意外隐式转换
