## 题目

**场景**：演示视频检索里，字幕搜索之外还要支持"按画面找"：用户输入"把杯子倒过来"，要在视频画面里定位对应片段。

**问**：换成按画面找，文字"把杯子倒过来"怎么和视频帧比较？图文对比学习在学什么？

## 口述答案

> 文字和像素没法直接比，先各自过编码器投到**同一个向量空间**再算相似度——这就是 CLIP 范式。
> 图文对比学习学的不是"重建画面"，而是**判别性对齐**：batch 内配对的图文对拉近、不配对的推远（InfoNCE）。学完后"把杯子倒过来"这句话的向量和"正在倒水"那一帧的向量自然靠近。
> 但这道题有个坑：**"倒过来"是动词，是状态变化，单帧只是姿态快照**——举着杯子斜了一下和真的在倒，单帧分不开。所以按画面找至少要拿**短时窗（多帧）**做嵌入，把运动信息包进来，这也直接引出下一问的滑窗设计。

## 讲深一层

对比目标（InfoNCE，温度 τ）：

```text
L = -log( exp(sim(text_i, img_i)/τ) / Σ_j exp(sim(text_i, img_j)/τ) )
```

分母就是 batch 内所有错配对——**负例越多，学到的对齐越判别**，所以 CLIP 类模型要大 batch。

| query 类型 | 单帧够不够 | 原因 |
|---|---|---|
| 静态属性（"红色杯子"） | 够 | 属性在画面里是稳态 |
| 动词/状态变化（"倒、盖、搅拌"） | 不够 | 需要帧间变化，即运动信息 |
| 否定/精确（"不漏水"） | 视觉难 | 视觉无否定，文本锚点更可靠 |

工程流程：视频按窗口抽帧 → 帧嵌入聚合（均值 / 注意力 / token 拼接过时序层）→ 窗口向量入库；查询文本过同一套文本塔 → 余弦相似度检索。

**记忆锚点**：对比学习学的是"谁和谁是一对"的判别边界，不是像素对应；名词看单帧，动词看窗口。

## 高频追问

1. **为什么对比学习要大 batch？** —— 分母负例数量 = batch−1，负例越足表示空间越判别；小 batch 靠队列/MoCo 式内存库补。
2. **和三元组损失什么区别？** —— Triplet 每次只拉一个正例推一个负例；InfoNCE 是"一个正例对全部负例"的 softmax 化，等价于多负例分类，梯度更稳。
3. **视频版怎么做帧聚合？** —— 便宜的均值池化；更好是把帧 token 拼起来过时序编码器，让"倒"这种跨帧模式自己浮出来。

## 易错点

- 拿文字和帧做像素级/逐词对应比较——两边根本不在一个空间
- 以为对比学习在"重建配对"，它学的是判别性对齐
- 用单帧表达动词类 query，动作漏检还以为是模型不行
