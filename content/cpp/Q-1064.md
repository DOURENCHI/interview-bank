## 题目

**场景**：读大日志文件、进程间传大块数据、加载 ELF，都会被建议「用 mmap」。很多人只会背「零拷贝」，一到「为什么快」「怎么共享」就断了。

**问**：mmap 是什么？和 read/write 相比什么时候用？两个进程怎么通过 mmap 共享内存？

## 口述答案

> **mmap 把文件（或匿名内存）映射进进程虚拟地址空间**：建立「虚拟地址 ↔ 页缓存/物理页」的映射，之后指针访问直接命中页缓存，不经过 read 那条「磁盘 → 页缓存 → 用户缓冲区」的拷贝链。**它不是把文件读进内存，是把内存对到文件**——分配的只是虚拟地址，真正占物理页发生在第一次触碰（缺页）时。
>
> 和 read/write 的取舍：**大文件 + 随机访问**用 mmap 赢——省一次 CPU 拷贝、按需调页不占多余内存、多进程映射同一文件还天然共享同一份页缓存；**小文件或一次顺序读**用 read 赢——mmap 建映射 + 缺页中断的开销摊不回来，还可能被 TLB 刷频繁干扰。
>
> 共享内存两条路：①**MAP_SHARED 映射同一个文件**（或 posix_shm_open 的对象），两个进程的虚拟地址各自不同，但落到同一批物理页，一方写另一方立即可见；②**fork 前 MAP_SHARED 的匿名映射**，子进程继承映射关系。要互斥就配进程间信号量/文件锁。一句话：**共享的本质是「不同虚拟地址映射到同一批物理页」，而不是「传数据」**。

## 讲深一层

| 维度 | read/write | mmap |
|---|---|---|
| 数据路径 | 磁盘→页缓存→用户区（两次涉拷） | 用户指针直连页缓存（零次拷贝） |
| 随机访问 | 反复 lseek+read | 指针随意跳，按页调入 |
| 小文件 | 简单直接 | 建映射+缺页开销不划算 |
| 进程间共享 | 要经管道/socket 拷贝 | MAP_SHARED 同物理页 |
| 崩溃风险 | 读到多少算多少 | 文件被截断后访问映射区收 **SIGBUS** |

```c
int fd = open("data.bin", O_RDWR);
char *p = mmap(NULL, len, PROT_READ | PROT_WRITE,
               MAP_SHARED, fd, 0);        // offset 需页对齐
p[0] = 'A';                               // 触发缺页 → 调入 → 变脏页
msync(p, len, MS_SYNC);                   // 需要落盘时序点才调，否则等内核回写
munmap(p, len);
```

**判断技巧**：面试说 mmap 快，下一句一定被问「为什么快」——答「省了内核到用户缓冲区那次拷贝 + 按需调页」，再补「但小文件不划算」展示有代价意识。**记忆锚点**：「mmap 不是读进内存，是把内存对到文件；共享 = 同物理页不同虚拟地址」。

## 高频追问

1. **为什么文件被截断后 mmap 访问会 SIGBUS 而不是段错误？** —— 缺页处理时发现虚拟地址落在文件范围外（无对应页），内核判定为总线错误；这也提醒映射长度要跟着文件大小走。
2. **mmap 写的数据什么时候落盘？** —— 脏页由内核回写线程异步刷；要「掉电不丢」的时点必须显式 msync；普通删除语义下 munmap 不等于同步点。
3. **匿名映射和 malloc 什么关系？** —— glibc 对 ≥128KB 的请求直接 mmap 匿名块，free 即归还 OS；小块走 brk/arena，这就是「申请大块再释放内存还回去、小块不还」的原因。
4. **MAP_PRIVATE 有什么用？** —— 写时复制：改的是私有副本，适合「读文件 + 临时改」；调试器、ELF 加载的数据段重定位都用它。

## 易错点

- 把 mmap 说成「把文件读进内存」——方向反了，是建立映射、按需调页。
- 只答「零拷贝」不答代价——缺页开销、TLB 压力、SIGBUS 风险一个不提。
- 共享内存答成「shmget 就够了」却讲不清为什么共享——面试官要的是物理页级解释。
- offset 忘了页对齐（4KB），直接 EINVAL。
