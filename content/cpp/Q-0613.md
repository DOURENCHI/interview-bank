## 题目

**场景**：同一个矩阵运算程序，Debug 构建跑 800 ms，Release 构建跑 45 ms。

**问**：从 `-O0` 到 `-O2` 为什么能有这么大的差别？为什么用 Debug 版测性能没有意义？

## 口述答案

> 因为 `-O0` 关掉了所有优化：**内联没了、循环不展开、临时对象不消除、寄存器分配最差**。对 C++ 这种大量使用模板和 RAII 的语言，这意味着每个 `operator+`、每个 `shared_ptr` 拷贝、每个迭代器自增都变成真实函数调用。
> 我们的项目里就踩过这个：`colcon build` 默认没指定构建类型，推理节点慢了一倍，模型和参数全查过才发现是构建配置。
> **Debug 版测性能没有意义**，因为它的性能特征和发布版完全不同，优化的方向可能都是错的。

## 讲深一层

| 优化级别 | 主要效果 | 典型差距 |
|---|---|---|
| `-O0` | 不优化，变量都在栈上 | 基准 |
| `-O1` | 基本优化，编译快 | 2–5× |
| `-O2` | 内联、循环优化、向量化（部分） | 5–20× |
| `-O3` | 更激进的向量化和展开 | 比 O2 再快 10–30%，代码更大 |
| `-Os` | 优化体积 | 接近 O2，略慢 |

```bash
# CMake 项目
cmake -DCMAKE_BUILD_TYPE=Release ..
# colcon
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release
# 手写 g++
g++ -O2 -DNDEBUG main.cpp
```

**`-DNDEBUG` 也很关键**：它关掉 `assert`。Debug 版里大量 `assert` 在热循环中会显著拖慢。

**怎么验证**：`objdump -d` 看关键函数里有没有意外的 `call`；或者用 `perf stat` 对比指令数。

## 高频追问

1. **为什么 `-O3` 不一定更快？** —— 可能因代码膨胀导致指令缓存命中率下降，必须实测。
2. **`RelWithDebInfo` 能测性能吗？** —— 能，它和 `-O2` 等价，只是多带调试符号。
3. **优化会让 bug 消失或出现吗？** —— 会。未定义行为（越界、数据竞争）在 `-O0` 下可能"看起来正常"，开优化后表现不同。

## 易错点

- 用 Debug 版做性能测试并据此优化
- 只改 `-O2` 忘了 `-DNDEBUG`
- 认为 `-O3` 一定比 `-O2` 快
