## 题目

**题目**：和硬件寄存器/网络协议结构体对接时，`sizeof` 多了几个填充字节，数据对不上。

**问**：不想让编译器做字节对齐，该怎么办？

## 口述答案

> 三种手段：**`#pragma pack(1)`**（配合 push/pop 恢复）、**`__attribute__((packed))`**（GCC/Clang）、**MSVC 的 `#pragma pack` 同样有效**。
> C++11 起还能用 `alignas` 反向提高对齐，但没有"降低到 1"的标准语法——降低只能靠编译器扩展。

## 讲深一层

```c
#pragma pack(push, 1)
typedef struct { uint8_t a; uint32_t b; } Pkt;   // sizeof = 5
#pragma pack(pop)
```
```c
typedef struct __attribute__((packed)) { uint8_t a; uint32_t b; } Pkt;
```
- 代价：**非对齐访问变慢**，某些架构（老 ARM）直接触发异常；编译器会生成逐字节拼装的代码。
- 更稳的做法：协议解析时**手工按偏移取值**（`memcpy` + `ntohl`），不依赖结构体布局。
- 收尾一定要 `pop`，否则污染后面所有结构体。

## 高频追问

1. **`packed` 结构体能取成员地址吗？** —— 能，但得到的指针是非对齐的，解引用可能崩。
2. **`alignas(1)` 能取消对齐吗？** —— 不能，标准不允许降低到比自然对齐更小。

## 易错点

- 忘了 `pop`，后续结构体全被压紧
- 在对齐敏感的架构上直接解引用 packed 成员
