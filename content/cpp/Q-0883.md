## 题目

**背景**：百度推荐算法面里的 LLM 生成控制题。大模型落地都要「输出结构化」：要么产出合法 JSON 给下游解析，要么受词表/业务约束不生成敏感词。约束解码（constrained decoding）是这类需求的标准解法，考的是解码器底层机制——logit 处理层面的干预原理，而不是提示词层面的软约束。
**问**：约束解码的原理是什么？

## 口述答案

> 约束解码的核心原理一句话：在自回归解码的每一步，模型输出的是整个词表上的概率分布，约束解码在取样之前直接干预这个分布——把违反约束的 token 的 logit 置成负无穷（概率归零），再从剩余合法 token 里采样。这样生成的每一步都必然满足约束，是硬保证，不是「引导模型尽量输出 JSON」这种提示词软约束。
> 具体机制分三步。第一步：正常前向计算得到全词表的 logits，这一步和普通生成完全一样。第二步：规则引擎判断当前已生成的前缀下，哪些 token 会导致违规——比如目标是合法 JSON，就用一个 JSON 文法解析器（通常是有限状态机或下推自动机）跟踪当前前缀的语法状态：处于期待 key 的状态时，只有引号、字母等能开启 key 的 token 合法；处于期待冒号的状态，只有冒号合法。第三步：把所有非法 token 的 logit 加上负无穷掩码，softmax 后它们的概率严格为零，从合法集合里采样（贪心或 top-p 都行），token 拼进前缀，状态机推进，进入下一步。
> 关键洞察是：约束是「前缀敏感」的动态过程，不是静态黑名单。同一个 token 在不同语法状态下合法性不同——引号在字符串内部是内容，在 key 位置是结构符。所以实现上都维护一个与生成同步推进的状态机，outlines、xgrammar、llama.cpp 的 GBNF 这类库本质都是「文法编译成状态机 + 每步做掩码」。
> 性能上有个重要优化：状态机的状态转移和对应合法 token 集合是可以预计算的——把「状态 → 合法 token 掩码」编译成查找表，解码时查表做掩码，开销从每步跑一遍文法解析降到一次位运算。vLLM 里的 xgrammar 集成走的就是预编译路线，吞吐损失能压到个位数百分比。
> 约束的来源不止 JSON 文法：可以是正则表达式（电话号、日期格式）、EBNF 文法、给定字符集（只允许中文）、禁用词表，甚至 Enum 枚举值——只要约束可以表达为「合法前缀的后续合法集合」，都能套进这个框架。

## 讲深一层

- 与采样参数的关系：temperature/top_p 是在合法集合内部再调节分布形状，掩码在它们之前生效——先掩码后采样，两者正交不冲突；但掩码后合法集合很小时，高温也无济于事，合法集只有一个 token 时温度失去意义。
- 局限性是高频追问点：硬约束保证语法合法，不保证语义正确——模型可以被约束「必须吐 JSON」，但字段值仍可能幻觉（乱编日期）；强约束还会扭曲分布，模型本来想说的词被禁掉，被逼选次优 token，长文本里约束越严质量下降越明显，所以要尽量把约束设计得宽松（如允许自由文本字段）。
- 与训练侧方法的关系：结构化输出也可以靠微调（SFT 大量合法样本）或强化学习奖励约束满足度实现，那是概率性改善；约束解码是推理时硬保证。生产上两者常组合：微调让模型默认输出格式对，推理掩码兜底语法错。
- beam search 与约束兼容：掩码作用于每个 beam 的 logits，束搜索下约束同样成立；但掩码可能让部分 beam 提前死亡（合法路径枯竭），需要实现层处理空集情况——合法集合为空说明文法与前缀不一致，通常是文法定义有 bug。

## 高频追问

1. 约束解码和 function call 有什么关系？——Function call 是「模型训练时就学过按 schema 输出工具参数」，推理时配合 JSON schema 约束解码兜底，两者配合才稳；只靠训练不掩码，长 schema 下仍会偶发格式错
2. 掩码会不会破坏校准的概率分布？——会。被禁 token 的概率质量被重新归一化到合法集合，模型内部「真实意图」被扭曲；对分类枚举类小约束影响小，对长文强约束影响大，这也是生产上建议约束尽量局部化的原因
3. 为什么不直接解析失败就重试？——可以，但不稳定也不高效：长输出重试一次要完整重生成，成本翻倍且不保证下次合法；约束解码一次生成必合法，延迟和成本都可控，重试只该当兜底

## 易错点

- 说成「提示词里写『请输出 JSON』」——那是软约束，失败率高；约束解码是 logit 层硬掩码，概率严格归零，答不出「干预分布」这一层就是没理解原理
- 忽略前缀敏感性——把约束讲成静态词表过滤，讲不出状态机随生成推进，暴露只在博客上看过名词
- 只答「保证合法」不谈代价——分布扭曲、语义不受保证、性能开销三个代价一个不说，面试官会认为你没用过（没用过的人才会觉得它是免费的）
