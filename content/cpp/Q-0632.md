## 题目

**追问**：很多人说"指针就是地址"，那 `sizeof(ptr)` 为什么依赖平台？`ptr+1` 为什么不是加 1？

**问**：「指针就是地址」这个说法哪里不完整？指针到底带了哪些信息？

## 口述答案

> 指针除了地址还带**类型**。类型决定了三件事：解引用时读几个字节、`+1` 走多远（按 `sizeof(T)` 步进）、以及怎么解释那块内存。
> 所以 `int*` 和 `char*` 存同一个地址，`+1` 的结果完全不同。类型信息在编译期起作用，运行时指针变量里确实只有一个地址。

## 讲深一层

```cpp
int a[3] = {1,2,3};
int* p = a;
char* c = reinterpret_cast<char*>(a);

p + 1;              // 地址 + 4（sizeof(int)）
c + 1;              // 地址 + 1
sizeof(p);          // 8（64 位平台）
```

| 说法 | 是否准确 |
|---|---|
| 指针就是地址 | ❌ 缺类型，无法解释算术和 sizeof |
| 指针是"地址 + 类型" | ✅ |
| 指针是"地址 + 类型 + 有效范围" | ✅ 更完整（越界指针仍是未定义行为） |

**为什么类型必须在**：`*(p+1)` 要知道从哪读到哪；没有类型，编译器无法生成正确的加载指令。

**一个延伸**：`void*` 是没有类型信息的指针，所以不能解引用、不能做算术（GCC 扩展允许按字节加，但不是标准）。

## 高频追问

1. **`sizeof(指针)` 为什么都是 8？** —— 64 位平台地址宽度是 64 位；和指向的类型无关。
2. **函数指针也是 8 字节吗？** —— 通常同宽，但标准不保证；某些架构上代码指针和数据指针宽度不同。
3. **`reinterpret_cast` 安全吗？** —— 不安全，绕过类型系统，除非你确切知道内存布局。

## 易错点

- 说"指针就是整数"，忽略类型和算术规则
- 以为 `ptr+1` 一定加 1 字节
- 用 `void*` 做算术（非标准）
