## 题目

**场景**：调试一个边界条件，怀疑某个变量取某个值时会走错分支。想直接在调试器里改掉它，看后面会怎样。

**问**：GDB 里怎么改变量值？这么做有什么风险？

## 口述答案

> 用 `set var 变量 = 值`（或 `set 变量 = 值`）。立即生效，后续执行就用新值。
> 风险有三：**优化后变量可能不存在**（被优化进寄存器或直接常量折叠，GDB 显示 `<optimized out>`）；**改变量绕过了真实逻辑**，你验证的是"如果我这样写会怎样"，不是"程序为什么这样"；**可能掩盖内存越界**——改了值不崩了，但根因还在。

## 讲深一层

```gdb
(gdb) p counter
$1 = 3
(gdb) set var counter = 10
(gdb) p counter
$2 = 10
(gdb) next            # 继续执行，用的是 10

# 改内存（危险）
(gdb) set {int}0x7fffffffe00 = 42
```

| 现象 | 原因 |
|---|---|
| `<optimized out>` | 变量被优化掉，用 `-O0` 重编或看寄存器 |
| 改了没生效 | 断点位置在赋值之后 |
| 改了导致崩溃 | 破坏了不变量，后续逻辑假设不成立 |

**正确的用法**：把改变量当成**假设验证工具**——"如果这个值正常，程序是否继续正常？"用来缩小问题范围，而不是当修复手段。

## 高频追问

1. **优化版怎么改变量？** —— 改寄存器或内存地址：`set $eax = 10`、`set {int}&var = 10`，但要知道自己在做什么。
2. **能改函数的返回值吗？** —— 能，在 `return` 处断点后 `set $rax = 0`（x86-64）。
3. **怎么做条件断点？** —— `break file.cpp:42 if counter > 10`，比手动改值更贴近真实场景。

## 易错点

- 在 `-O2` 版本上改变量，发现改不动
- 改完不崩就认为问题解决了
- 用改变量代替分析根因
