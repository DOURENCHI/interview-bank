## 题目

**题目**：多线程里每个线程要有独立的错误码/随机数引擎，用全局变量不行。

**问**：thread_local 的作用是什么？

## 口述答案

> `thread_local` 让变量**每个线程各有一份独立副本**，生命周期跟随线程——线程创建时构造，线程结束时析构。
> 它解决的正是"看起来是全局、实际要按线程隔离"的需求：`errno`、随机数引擎、线程本地缓存、调试上下文。

## 讲深一层

```cpp
thread_local int t_counter = 0;          // 每线程独立
thread_local std::mt19937 rng(std::random_device{}());

void worker() { ++t_counter; }           // 不会互相干扰
```
- 可以是 `static thread_local`（文件内可见 + 每线程一份）。
- 析构时机：线程正常退出时；`detach` 的线程退出时也会析构。
- 实现上靠 TLS（线程本地存储），访问比普通全局稍慢（一次间接寻址）。
- 陷阱：动态库里的 `thread_local` 在 `dlclose` 后可能悬垂；大量线程 × 大对象会吃内存。

## 高频追问

1. **`thread_local` 变量能跨线程传值吗？** —— 不能，它就是隔离的。
2. **和 `__thread` 有什么区别？** —— GNU 扩展 `__thread` 更快但不支持非平凡类型；`thread_local` 支持构造析构。

## 易错点

- 用它存"需要共享"的数据
- 在大批量短线程里放大的 thread_local 对象
