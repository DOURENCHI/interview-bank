## 题目

**题目**：`cout << a << b << c;` 能连着写，而 `a + b + c` 也能连着写。

**问**：`<<` 为什么能链式调用？它返回的是什么？这和「运算符重载」有什么关系？

## 口述答案

> `operator<<` 被重载成返回 `std::ostream&`（流的引用），所以 `(cout << a)` 的结果还是 `cout`，可以继续 `<< b`。
> 左结合性让 `cout << a << b` 解析成 `(cout << a) << b`，配合返回引用就形成了链。

## 讲深一层

```cpp
// 标准库里的声明（简化）
std::ostream& operator<<(std::ostream& os, int v);
std::ostream& operator<<(std::ostream& os, const std::string& v);

// 自定义类型
struct Point { int x, y; };
std::ostream& operator<<(std::ostream& os, const Point& p) {
    return os << "(" << p.x << ", " << p.y << ")";
}
```

| 要点 | 说明 |
|---|---|
| 返回类型 | `ostream&`，不是 `ostream`（否则每次拷贝流） |
| 参数 | 流按引用传，且不能是 `const`（会改状态） |
| 位置 | **非成员函数**（左操作数是流，不是你的类） |
| 左结合 | `<<` 是左结合，所以能自然串联 |

**为什么不能写成成员函数**：成员函数的左操作数必须是本类对象，而这里左操作数是 `cout`。所以要么写自由函数，要么写 `friend`。

**`endl` 的代价**：它不只是换行，还会 flush；大量输出时用 `'\n'` 能快一个数量级。

## 高频追问

1. **`operator>>` 也是同理吗？** —— 是，返回 `istream&`，左操作数是输入流。
2. **为什么参数用 `const T&`？** —— 避免拷贝，且不修改被输出的对象。
3. **能重载 `<<` 用于自己的类但写成成员吗？** —— 语法上不能表达"流在左边"，只能用非成员或友元。

## 易错点

- 返回 `ostream` 而不是 `ostream&`，产生拷贝
- 写成成员函数，编译不过
- 输出时用 `endl` 导致性能问题
