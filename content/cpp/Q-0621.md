## 题目

**场景**：接一个第三方库，`find_package` 成功，`target_link_libraries` 也写了，但编译报"找不到头文件"，或者链接报一堆 `undefined reference`。

**问**：用 CMake 找第三方库，最常踩的三个坑是什么？

## 口述答案

> 三个：**只链了库没加头文件路径**、**库名写错**（`libxxx.so` 要写 `xxx`，`ImGui` 和 `imgui` 大小写也敏感）、**Debug/Release 混用**（MSVC 的调试版和发布版 CRT 不兼容，链到一起直接崩）。
> 这三个的共同点是：错误信息都不指向真正的原因。

## 讲深一层

```cmake
# ✅ 完整写法：用 target_* 把用法要求和库绑在一起
find_package(OpenCV REQUIRED)
add_executable(app main.cpp)
target_include_directories(app PRIVATE ${OpenCV_INCLUDE_DIRS})
target_link_libraries(app PRIVATE ${OpenCV_LIBS})
```

| 坑 | 症状 | 修法 |
|---|---|---|
| 缺 include 路径 | `fatal error: xxx.h: No such file` | `target_include_directories` |
| 库名错 | `cannot find -lxxx` | 去掉 `lib` 前缀和 `.so` 后缀 |
| Debug/Release 混用 | MSVC 下 `_ITERATOR_DEBUG_LEVEL` 不匹配 | 统一构建类型，或用 `debug`/`optimized` 关键字 |
| 静态库顺序错 | `undefined reference` | 被依赖的放后面 |
| 缺间接依赖 | 链接时报第三方符号 | 用 `target_link_libraries` 的传递性，或显式补 |

```cmake
# 同时支持两种构建类型
target_link_libraries(app PRIVATE
    debug   mylibd
    optimized mylib)
```

**一个判断技巧**：`undefined reference` 提到的是**你调用但没定义**的符号 → 查库路径；提到的是**第三方库内部**的符号 → 查它的依赖（比如 OpenCV 依赖的 `libjpeg`）。

## 高频追问

1. **`find_package` 之后为什么要用变量而不是写死路径？** —— 变量由 CMake 根据实际安装位置生成，写死路径换机器就挂。
2. **静态库顺序为什么反直觉？** —— 链接器从左到右扫描，遇到未解析符号才去后面的库里找，所以被依赖的要放后面。
3. **`PUBLIC` / `PRIVATE` 在这里怎么用？** —— 头文件里出现的依赖用 `PUBLIC`，只在 `.cpp` 里用的用 `PRIVATE`。

## 易错点

- 只加 `target_link_libraries` 不加 include 路径
- 库名带 `lib` 前缀或 `.so` 后缀
- 混用 Debug 和 Release 的预编译库
