## 题目

**场景**：有人用 `v.reserve(1000)` 之后直接 `v[0] = 1`，程序行为异常。

**问**：`reserve` 到底改变了什么、没改变什么？`reserve` 和 `resize` 该怎么选？

## 口述答案

> `reserve` 只改**容量**（`capacity`），不改**大小**（`size`）。预留之后 `size()` 仍然是 0，`v[0]` 访问的是未构造的内存，是未定义行为。
> `resize` 才改 `size`，并且会真正构造（或析构）元素。
> 选法很简单：**只是为了避免扩容用 `reserve`；需要真的有 N 个元素用 `resize`。**

## 讲深一层

```cpp
std::vector<int> v;
v.reserve(1000);
v.size();        // 0
v.capacity();    // >= 1000
v[0] = 1;        // ❌ UB：元素不存在

v.resize(1000);  // ✅ 现在有 1000 个值初始化的 int
v[0] = 1;        // 合法
```

| 操作 | `size` | `capacity` | 构造元素 | 影响已有元素 |
|---|---|---|---|---|
| `reserve(n)` | 不变 | ≥ n | 否 | 可能搬移（使迭代器失效） |
| `resize(n)` | 变 n | 可能增 | 是 | 缩小会析构尾部 |
| `shrink_to_fit()` | 不变 | 降到 size | 否 | 可能搬移，非强制 |

**一个反直觉的点**：`reserve` 也可能让迭代器失效——如果它触发了重新分配（`n` 大于当前 `capacity`）。所以"reserve 是安全的"这个说法不成立。

**什么时候 `reserve` 收益最大**：已知元素个数时。比如从数组构造、或者循环里要 `push_back` 一万次，`reserve` 能省掉十几次扩容和几万次搬移。

## 高频追问

1. **`reserve` 能减少内存占用吗？** —— 不能，它只会增加。减少要用 `shrink_to_fit` 或 `swap` 技巧。
2. **`resize` 对 `vector<string>` 会怎样？** —— 新增的元素是默认构造的空串，不是"未初始化"。
3. **`reserve` 对 `map` / `list` 有效吗？** —— 无效，它们没有 `reserve` 成员（节点式容器不需要连续空间）。

## 易错点

- `reserve` 后直接用下标访问
- 以为 `reserve` 一定不改动已有元素
- 对 `list` / `map` 调 `reserve`（编译不过）
