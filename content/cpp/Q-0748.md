## 题目

**题目**：`connect(sender, &Sender::sig, receiver, &Receiver::slot, Qt::QueuedConnection);` 第五个参数是什么？

**问**：信号槽的底层原理是什么？`connect` 的第五个参数有什么作用？

## 口述答案

> 底层是**元对象系统（moc）**：`Q_OBJECT` 宏让 moc 生成元数据，`connect` 把"信号索引 → 接收者/槽索引"记录到发送者的连接表里。信号触发时执行 moc 生成的代码，按连接类型**直接调用或投递事件**。
> 第五个参数是**连接类型**，决定槽在哪个线程、同步还是异步执行——这是 Qt 多线程最容易搞错的地方。

## 讲深一层

| 连接类型 | 行为 | 线程 |
|---|---|---|
| `AutoConnection`（默认） | 同线程直接调用，跨线程排队 | 自动判断 |
| `DirectConnection` | 立即调用，等价于函数调用 | **发送者线程** |
| `QueuedConnection` | 投递事件，稍后处理 | **接收者线程** |
| `BlockingQueuedConnection` | 排队并阻塞等待 | 接收者线程（同线程会死锁） |
| `UniqueConnection` | 避免重复连接（可 `|` 组合） | — |

```cpp
// 跨线程：自动变成 Queued
connect(worker, &Worker::progress, this, &MainWindow::onProgress);

// 强制排队，即使同线程
connect(a, &A::sig, b, &B::slot, Qt::QueuedConnection);
```

**`QueuedConnection` 的前提**：参数类型必须能被 Qt 元系统识别（基本类型、`QString` 等已注册；自定义类型要 `qRegisterMetaType`）。否则运行时报
`Cannot queue arguments of type 'MyStruct'`。

**`AutoConnection` 的判断依据**：比较 `QThread::currentThread()` 和接收者对象的线程归属，不是"声明在哪个类"。

## 高频追问

1. **`BlockingQueuedConnection` 什么时候用？** —— 需要等对方处理完再继续，且不在同一线程；同线程会立刻死锁。
2. **信号能返回值吗？** —— 不能，信号没有返回值（要结果就用回调或 `QFuture`）。
3. **连接能断开吗？** —— `disconnect(sender, signal, receiver, slot)`，或 `sender->disconnect()`。

## 易错点

- 跨线程用 `DirectConnection`，槽在错误线程操作 UI 导致崩溃
- 自定义结构体没注册元类型就用队列连接
- `BlockingQueuedConnection` 用在同线程，死锁
