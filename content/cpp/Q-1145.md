## 题目

**问**：**内存映射的方式有哪几种？分别都用在哪里？**

## 口述答案

> 按"映射什么、共享谁"分四类：
> 1. **文件映射 + MAP_SHARED**：把文件映射进内存，多进程映射同一文件时写回可见——最常用的"用内存读写代替文件 IO"，也用于跨进程共享文件数据；
> 2. **文件映射 + MAP_PRIVATE**：写时复制（COW），修改只发生在自己的私有副本上，不写回文件——动态库代码段就是这么加载的，还可用于"改了后悔"的场景；
> 3. **匿名映射 + MAP_SHARED**：不带 fd，`MAP_ANONYMOUS|MAP_SHARED`，父子进程 fork 后共享这块内存——简易版共享内存；
> 4. **匿名映射 + MAP_PRIVATE**：malloc 大块内存（glibc 对 ≥128KB 的请求）底层就是这么干的，内容全零、进程私有。

## 讲深一层

```c
/* 父子进程共享匿名映射 */
char *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_SHARED|MAP_ANONYMOUS, -1, 0);

/* 文件只读映射 */
int fd = open("data.bin", O_RDONLY);
char *m = mmap(NULL, sz, PROT_READ, MAP_SHARED, fd, 0);
```

判断口诀：要不要"给别人看到"→ SHARED；要不要"基于文件"→ 有 fd。

## 高频追问

1. **共享内存和文件映射什么关系？** —— POSIX `shm_open` 就是在 /dev/shm 下开个文件再 MAP_SHARED，本质是同一条路。
2. **mmap 比 read 快吗？** —— 大文件随机访问/多次访问快（省一次拷贝 + 页缓存直接访问）；顺序读一遍差别不大，还多一次缺页。

## 易错点

- 说 MAP_PRIVATE 能把修改写回文件——错，COW 只改私有副本
- 忽略匿名映射，答不出 malloc 大内存的实现
