## 题目

**题目**：

```cpp
void f() {
    std::thread t([]{ doWork(); });
}   // 程序直接 terminate
```

**问**：为什么 `std::thread` 析构时必须已经 `join` 或 `detach`？两种选择各适合什么场景？

## 口述答案

> 因为 `std::thread` 析构时如果线程**仍可 join**（还在运行且没 detach），标准要求调用 `std::terminate`——这是刻意设计的：**不允许静默丢弃一个还在跑的线程**。
> `join` 是等待它结束（同步），`detach` 是放任它自己跑（分离）。要么明确等，要么明确放手，不允许含糊。

## 讲深一层

```cpp
// ✅ join
void f() {
    std::thread t([]{ doWork(); });
    t.join();                 // 等它结束
}

// ✅ detach（谨慎）
void g() {
    std::thread t([]{ doWork(); });
    t.detach();               // 放任，注意它不能访问局部变量
}

// ✅ C++20 jthread：析构自动 join
void h() {
    std::jthread t([]{ doWork(); });
}   // 自动 join
```

| 方式 | 析构行为 | 适合 |
|---|---|---|
| `join` | 阻塞等待 | 需要结果、需要保证完成 |
| `detach` | 放任运行 | 后台常驻任务（但生命周期难管） |
| `jthread` | 自动 join + 可请求停止 | **C++20 推荐** |

**为什么 `detach` 危险**：分离后的线程无法被等待，程序退出时它可能还在访问已销毁的对象；而且没有任何机制能确认它结束了。

**`jthread` 的好处**：析构自动 `join`，还带 `stop_token` 协作式取消，能避免"忘了 join"这类崩溃。

## 高频追问

1. **`join` 能调用两次吗？** —— 不能，第二次会抛 `std::system_error`；先 `joinable()` 判断。
2. **`detach` 后还能 join 吗？** —— 不能，`joinable()` 返回 false。
3. **异常安全怎么写？** —— 用 `jthread`，或自己包一个 RAII 类在析构里 `join`。

## 易错点

- 创建线程后忘了 `join`/`detach`，析构 terminate
- `detach` 的线程访问局部变量
- 在析构函数里 `join` 但线程又需要访问该对象
