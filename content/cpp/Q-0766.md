## 题目

**题目**：在 A 线程创建 `QTcpSocket`，B 线程调 `write()`，程序崩溃或报
`QObject: Cannot create children for a parent in a different thread`。

**问**：`QTcpSocket` 为什么不能跨线程使用？正确的跨线程网络编程该怎么做？

## 口述答案

> 因为 `QObject` **属于创建它的线程**，它的内部定时器、事件通知、`QSocketNotifier` 都绑定在那个线程的事件循环上。在别的线程调用，等于在没有事件循环的线程里操作一个依赖事件循环的对象——行为未定义。
> 正确做法：**在哪个线程创建就在哪个线程用**。要让网络跑在子线程，就把整个 socket 一起 `moveToThread`，或者干脆在网络线程里创建。

## 讲深一层

```cpp
// ✅ 方案一：socket 在网络线程创建
class NetWorker : public QObject {
    Q_OBJECT
    QTcpSocket* sock_ = nullptr;
public slots:
    void start() {
        sock_ = new QTcpSocket(this);       // 在所属线程创建
        connect(sock_, &QTcpSocket::readyRead, this, &NetWorker::onReady);
        sock_->connectToHost(host_, port_);
    }
};

auto* th = new QThread;
auto* w = new NetWorker;
w->moveToThread(th);
th->start();
QMetaObject::invokeMethod(w, "start", Qt::QueuedConnection);   // 在子线程执行
```

| 做法 | 是否可行 |
|---|---|
| A 线程创建、B 线程调用方法 | ❌ |
| `moveToThread` 把 socket 搬到 B 线程 | ✅（但要在 B 线程启动前） |
| 在 B 线程创建并使用 | ✅ **推荐** |
| 主线程用 `QTcpSocket` 异步接口 | ✅（不需要子线程） |

**关键认识**：`QTcpSocket` 本身**已经是异步非阻塞**的，多数场景根本不需要单独开线程——除非解析逻辑很重。

**要跨线程传数据**：用信号槽（队列连接），把 `QByteArray` 传回主线程或业务线程。

## 高频追问

1. **怎么判断对象在哪个线程？** —— `sock->thread()` 与 `QThread::currentThread()` 比较。
2. **`moveToThread` 有前提吗？** —— 对象不能有父对象，且必须在原线程调用。
3. **崩溃为什么是偶发的？** —— 取决于事件循环是否恰好处理到，典型的竞争型 bug。

## 易错点

- 跨线程直接调用 socket 方法
- sql/网络对象在主线程创建、子线程使用
- 以为"加个 mutex 就安全了"（这是线程归属问题，不是数据竞争）
