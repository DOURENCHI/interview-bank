## 题目

**场景**：龙芯中科面经题。设备树是驱动工程师每天要写的东西，面试官想确认你是「照抄参考设计」还是「对着手册逐项翻译」。

> 原题：设备树中的 reg、interrupts、clocks 和 compatible 属性分别怎样与硬件手册对应？

## 口述答案

> 直答：**这四个属性是驱动和硬件手册之间的四座桥，各对一类资源**。①**reg**：寄存器/内存空间的物理地址和长度，来自手册的「内存映射/寄存器空间」章节；用几个 cell 表示地址和长度由父节点的 `#address-cells`/`#size-cells` 决定（64 位平台地址常是 2 个 cell）。②**interrupts**：中断号＋触发方式，来自手册的中断章节；cell 数量由中断控制器的 `#interrupt-cells` 决定，还要有 `interrupt-parent` 指向控制器。③**clocks**：时钟引用，用 phandle 指向时钟树里的节点，配 `clock-names` 给驱动按名字取；引用哪个时钟由手册的时钟树决定。④**compatible**：字符串用来匹配驱动，不是抄手册——按「厂商,型号」惯例命名，内核拿它去匹配驱动的 of_match_table。写 DTS 的过程就是「对着手册把每类资源翻译成属性」。
>
> 驱动侧**属性→API 一一对应**：compatible 匹配到 probe 后，reg 用 `platform_get_resource`/`devm_platform_ioremap_resource`（或 of_iomap）拿映射；中断用 `platform_get_irq`/of_irq_get 拿号再 request_irq；时钟用 `devm_clk_get(&pdev->dev, 名字)` 按 clock-names 取，再 clk_prepare_enable；GPIO 用 of_get_named_gpio 或 gpiod_get。把这张对照表背下来，面试就赢了一半。

## 讲深一层

属性↔手册↔API 对照表：

| DTS 属性 | 手册出处 | 驱动侧 API | 常见坑 |
|---|---|---|---|
| reg ＋ reg-names | 内存映射表（基址/长度） | devm_platform_ioremap_resource / of_iomap | 地址没和固件桥片窗口对上；缺 reg-names 只能按索引取 |
| interrupts | 中断章节（号＋触发类型） | platform_get_irq → request_irq | #interrupt-cells 不一致导致解析错位；触发方式与手册不符 |
| clocks ＋ clock-names | 时钟树 | devm_clk_get → clk_prepare_enable / clk_get_rate | 忘开时钟读寄存器全 0；clk_get 返回 ERR_PTR 没检查 |
| compatible | —（驱动自定义） | of_match_table 匹配 → probe | 节点列表要按精确→通用排列，写错匹配到旧驱动 |

DTS 骨架示意（地址/中断号一律以实际芯片手册为准）：

```dts
uart1: serial@1FE00000 {              /* ← 基址仅示意，以手册内存映射表为准 */
    compatible = "vendor,uart1";      /* 与驱动 of_match_table 严格一致 */
    reg = <0x0 0x1FE00000 0x0 0x100>; /* cells 数由 #address-cells/#size-cells 决定 */
    interrupt-parent = <&intc>;
    interrupts = <16 IRQ_TYPE_LEVEL_HIGH>;  /* 中断号＋触发方式，cells 数由 #interrupt-cells 决定 */
    clocks = <&clk_apb>, <&clk_uart>; /* phandle 引用 */
    clock-names = "apb", "baud";      /* 与驱动 clk_get 的名字对齐 */
};
```

compatible 匹配顺序：设备节点的 compatible 列表按**精确→通用**排列（自家精确型号在前，家族通用串在后兜底）；内核按列表顺序尝试匹配驱动表，先命中者生效——新芯片写自己的精确串，保证未来同家族芯片还能复用通用驱动。

**记忆锚点**：「**reg 找手册要地址，interrupts 找手册要号，clocks 找时钟树要引用，compatible 找驱动要匹配**」。

## 高频追问

1. **#address-cells / #size-cells 是干什么的？** —— 决定子节点 reg 每个条目用几个 u32 表示地址/长度；解析时按这个数切分，配错会把地址和长度读串位。
2. **中断触发方式写错了会怎样？** —— 电平/边沿与手册不符：要么中断风暴，要么永远收不到中断；必须按手册中断章节与中断控制器的能力写。
3. **compatible 匹配顺序谁说了算？** —— 节点 compatible 列表按「精确→通用」排列，内核按列表顺序逐个尝试驱动表；精确型号放最前，通用串兜底。
4. **时钟为什么经常「读寄存器全 0/全 1」？** —— 最常见是时钟门控没开：clk_prepare_enable 漏调或 clk_get 失败没检查返回值；先确认时钟拿到且使能，再谈寄存器。

## 易错点

- reg 地址照抄别的板子——必须逐字段对硬件手册与固件桥片窗口。
- interrupt-parent/#interrupt-cells 漏配——中断号解析错位，挂到别的设备上。
- clocks 引用了不存在的 phandle——编译可能不报错，运行时 clk_get 失败。
- compatible 与驱动字符串差一个字符——probe 不执行，还很难一眼看出。
