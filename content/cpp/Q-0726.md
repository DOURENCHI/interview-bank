## 题目

**背景**：字节抖音电商 AI Agent 开发一面的工程编码题。真实场景就是 Agent 配置合并：默认配置 + 用户配置 + 会话级覆盖多层叠加，同 key 类型冲突时怎么处理。考点三段：递归合并的正确写法、类型冲突的策略决策、边界清单的完备性。手撕时最容易翻车的是「两边类型不同还硬递归」和「数组合并策略说不清」。
**问**：两个多层 JSON 怎么深度合并？类型冲突怎么办？

## 口述答案

> 先定递归规则，两行说完：两边都是 dict（对象）→ 逐 key 递归合并；其余任何情况 → 按合并策略处理，默认后者覆盖前者。这两行就是深度合并的全部骨架，剩下的都是策略和边界。
> 类型冲突指同一 key 下两侧类型不一致：一边 dict 一边标量/数组、或两边都不是 dict。此时绝不能硬递归——把标量当 dict 遍历直接崩。处理是个策略问题，要主动给面试官选项：默认「后者赢」（用户配置覆盖默认值，符合直觉）；可配置的两种例外——一是白名单整体替换，像 `retries`、`model_name` 这种原子配置不许被深合并改内部字段，整块换；二是数组的显式策略：覆盖、拼接去重、还是按 id 合并，Agent 配置里工具列表通常是「拼接去重」，而 prompt 模板是「覆盖」。
> Python 手撕骨架（不可变版本，不改入参）：
> ```python
> def deep_merge(a, b):
> if isinstance(a, dict) and isinstance(b, dict):
> out = dict(a)
> for k, v in b.items():
> if k in a and isinstance(a[k], dict) and isinstance(v, dict):
> out[k] = deep_merge(a[k], v)
> else:
> out[k] = v          # 冲突与新增：后者赢
> return out
> return b
> ```
> 边界清单是区分度所在，至少说全这六条：①b 有 a 没有 → 新增；②a 有 b 没有 → 保留不删（合并不等于替换）；③两边都 None → 结果 None，别把 None 当 dict 递归；④数组内嵌 dict → 默认整块覆盖，要按 id 合并是显式策略；⑤循环引用 → JSON 文本本身不可能有环，但已解析的 Python dict 可以（自引用 dict），严谨实现用 id() 集合检测防死循环，或声明只接受合法 JSON 输入；⑥极深嵌套 → 递归深度限制或改显式栈迭代，防止爆栈。
> 设计语义要口头补一句：合并顺序即优先级，a 是默认配置、b 是用户配置，b 赢——这个约定要说出口，让面试官知道你不是默写而是理解。

## 讲深一层

- 可变合并 vs 不可变合并：直接在 a 上改省内存但污染调用方的数据，配置系统里一律新建对象——函数式写法还顺带解决了「合并中途失败留下半残配置」的问题。
- 与深拷贝的同构：深度合并和深拷贝都是「递归遍历对象图 + 叶子处理」，克隆图/随机链表复制（Q-1877-algo/Q-1852-algo）里防死循环的 visited 集合，对应这里的循环引用检测。
- 生态参照：JS 的 Object.assign 与展开符是浅合并（一层），lodash.merge 才是深合并；Python 有 deepmerge / pydantic 的配置叠加——说出「我知道现成库，但手撕考的是边界处理」就很稳。
- 三层配置的真实工程：默认值 → 全局配置 → 用户配置逐层 deep merge，同 key 用「后者赢」，再用 schema 校验最终结果——合并完不做 schema 校验的配置系统迟早被脏数据打挂。

## 高频追问

1. 数组怎么合并？——默认整块覆盖；显式策略可选拼接去重或按 id/唯一键合并，Agent 工具列表常用后者
2. 怎么处理循环引用？——严格 JSON 输入不会有环；对象图输入用 id() 集合检测，或直接拒绝非法输入
3. 合并结果怎么验证？——合并后过一次 schema 校验（必填字段/类型/枚举），脏配置在入口拦截
4. 性能上有什么要注意的？——O(总节点数)，配置体量小不是瓶颈；高频调用时注意不可变合并的分配开销，可改原地合并+写时复制

## 易错点

- 两边类型不同还递归进去——「一边 dict 一边标量」直接崩，类型检查是深度合并的第一道闸
- 数组合并策略默认「拼接」而不说明——覆盖才是更安全的默认（用户少一半工具时是想要替换），策略要显式声明
- 忘了「a 有 b 没有 → 保留」——写成 b 全量替换就变成浅合并了，合并语义直接错
- 只写函数不讲语义——合并顺序的优先级约定、不可变性、冲突策略是设计题的另一半，光有代码只有一半分
