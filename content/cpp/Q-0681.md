## 题目

**题目**：把一段 `int` 数组复制到另一个数组，用 `std::copy` 还是 `memcpy`？

**问**：两者有什么区别？什么情况下不能互换？为什么非平凡类型只能用 `std::copy`？

## 口述答案

> `std::copy` 是**类型安全的元素级复制**，对每个元素调用拷贝赋值/拷贝构造；`memcpy` 是**按字节复制**，完全不管类型。
> 对 `int`、`double` 这类**平凡可复制（trivially copyable）**类型，两者等价（`memcpy` 可能更快）；对 `std::string`、`vector`、含虚函数的类，`memcpy` 会复制指针而不复制内容，导致双重释放或悬垂。

## 讲深一层

```cpp
int a[10], b[10];
std::copy(a, a + 10, b);          // ✅
memcpy(b, a, sizeof(a));          // ✅ 对 int 也安全

std::string s1[3] = {"a","b","c"}, s2[3];
// memcpy(s2, s1, sizeof(s1));    // ❌ 复制了内部指针，析构时双重释放
std::copy(s1, s1 + 3, s2);        // ✅ 调用 string 的拷贝赋值
```

| 类型 | `memcpy` 安全 | 原因 |
|---|---|---|
| `int` / `double` / POD | ✅ | 平凡可复制 |
| `std::string` | ❌ | 内部有堆指针 |
| `std::vector` | ❌ | 同上 |
| 含虚函数的类 | ❌ | vptr 复制后可能错乱 |
| `std::shared_ptr` | ❌ | 引用计数不增加 |

**判断标准**：`std::is_trivially_copyable_v<T>` 为真才能用 `memcpy`。

**性能**：对平凡类型，现代编译器的 `std::copy` 会特化调用 `memmove`，和手写 `memcpy` 一样快；所以"`memcpy` 更快"这个说法在平凡类型上基本不成立。

## 高频追问

1. **`memcpy` 和 `memmove` 区别？** —— 后者处理内存重叠，前者重叠时未定义。
2. **`std::copy` 能处理重叠区间吗？** —— 不能保证，重叠要用 `std::copy_backward` 或 `memmove`。
3. **`std::uninitialized_copy` 什么时候用？** —— 目标内存是原始未构造内存时（如自己实现容器）。

## 易错点

- 对 `std::string` 数组用 `memcpy`
- 用 `memcpy` 复制含虚函数的对象
- 区间重叠时用 `memcpy`
