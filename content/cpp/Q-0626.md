## 题目

**场景**：本地用 C++17 写的代码，拷到另一台机器上编译报"`std::optional` 不是 `std` 的成员"。

**问**：`-std=c++17` 和 `-o` 分别做什么？怎么确认编译器实际用的是哪个标准？

## 口述答案

> `-std=c++17` 指定**语言标准**，决定哪些语法和库可用；`-o` 指定**输出文件名**，跟标准无关。
> 确认标准用 `__cplusplus` 宏，或者在 g++ 里查默认值。C++17 对应 `201703L`，C++14 是 `201402L`，`201103L` 是 C++11。**注意 MSVC 默认不更新这个宏**，要用 `_MSVC_LANG`。

## 讲深一层

```bash
g++ -std=c++17 main.cpp -o main     # -std 语言标准，-o 输出文件名
g++ -dM -E -x c++ /dev/null | grep __cplusplus   # 看默认标准
```

```cpp
#include <cstdio>
int main() {
    printf("%ld\n", __cplusplus);   // 201703 = C++17
}
```

| 标准 | `__cplusplus` 值 |
|---|---|
| C++11 | 201103L |
| C++14 | 201402L |
| C++17 | 201703L |
| C++20 | 202002L |

**为什么"本地能编、别处编不过"**：常见原因是 GCC 默认标准随版本变化（GCC 11 起默认 `gnu++17`），老版本默认 `gnu++14`。所以项目里必须显式指定，别依赖默认值。

**`-std=c++17` 和 `-std=gnu++17` 的区别**：后者额外开启 GNU 扩展（如变长数组、`typeof`）。跨平台项目建议用 `c++17` + `CMAKE_CXX_EXTENSIONS OFF`。

## 高频追问

1. **怎么让 CMake 指定标准？** —— `set(CMAKE_CXX_STANDARD 17)` + `CMAKE_CXX_STANDARD_REQUIRED ON`。
2. **`-o` 写错会怎样？** —— 输出到意外的文件名，或者覆盖已有文件；`-o` 后面跟的是完整路径。
3. **C++20 的 `std::format` 编不过？** —— 需要 `-std=c++20`，且 GCC 13 起才完整支持。

## 易错点

- 依赖编译器默认标准，换机器就炸
- 把 `-o` 当成"开启优化"（那是 `-O`，大写且无参数区别）
- 用 `__cplusplus` 判断 MSVC 的版本
