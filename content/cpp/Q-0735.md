## 题目

**场景**：一个函数要接收 `Stack<int>` 参数，`void f(Stack<int> s)`、`void f(Stack<int>& s)`、`template<typename T> void f(Stack<T>& s)` 三种写法都能用。

**问**：类模板作为函数参数有哪几种写法？各适合什么场景？

## 口述答案

> 三种：**具体类型**（`Stack<int>`，只接受一种）、**模板参数化容器**（`Stack<T>`，接受任意 `Stack`）、**模板参数化元素**（`template<typename T> void f(T& c)`，接受任意容器）。
> 选择依据是"**需要多通用**"：只服务一种类型就用具体类型（编译快、错误信息清楚）；需要泛化才上模板。

## 讲深一层

```cpp
// 1. 具体类型
void f1(Stack<int>& s);

// 2. 容器模板化（只接受 Stack）
template <typename T>
void f2(Stack<T>& s);

// 3. 元素模板化（接受任何支持 push/pop 的容器）
template <typename Container>
void f3(Container& c);

// 4. C++20 concepts 约束
template <typename C>
requires requires(C c) { c.push(1); }
void f4(C& c);
```

| 写法 | 通用性 | 编译速度 | 错误信息 |
|---|---|---|---|
| `Stack<int>` | 最低 | 最快 | 最清晰 |
| `Stack<T>` | 中 | 中 | 中 |
| `template<typename C>` | 最高 | 慢 | 最难读 |
| concepts | 高（有约束） | 中 | 较好 |

**经验**：**从最具体的写法开始**，等真的需要泛化再抽象。过早模板化会让编译变慢、错误信息变成天书。

## 高频追问

1. **为什么错误信息那么长？** —— 模板实例化链条完整打印，一层套一层。
2. **concepts 解决了什么？** —— 把"要求什么能力"写在签名里，错误在调用点就报清楚。
3. **传值还是传引用？** —— 容器一般传 `const&`，避免拷贝。

## 易错点

- 一上来就用最泛化的模板
- 传值导致整个容器拷贝
- 没用 concepts，错误信息难以定位
