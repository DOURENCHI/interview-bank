## 题目

**场景**：函数参数写 `void f(BigStruct s)`，每次调用都拷贝几百字节；改成 `const BigStruct& s` 后快了。

**问**：`const T&` 到底避免了哪两次开销？什么情况下反而不该用引用？

## 口述答案

> 避免的是**一次拷贝构造 + 一次析构**（如果按值传，实参拷贝进形参，函数结束再析构）。对 `std::string`、`vector`、大结构体，这个成本可能包含堆分配。
> 但**小类型（`int`、`double`、指针）不该用 `const T&`**：引用底层是指针，多一次间接寻址，反而不如直接按值传（寄存器传递）。

## 讲深一层

| 参数类型 | 拷贝成本 | 建议 |
|---|---|---|
| `int` / `double` / 指针 | 极小 | **按值** |
| `std::string_view` | 极小 | 按值 |
| `std::string` / `vector` | 大（可能堆分配） | `const T&` |
| 大结构体 | 大 | `const T&` |
| 需要修改 | — | `T&` |
| 需要"可空" | — | `T*` 或 `std::optional` |
| 需要转移所有权 | — | 按值 + `std::move` |

```cpp
void f(const std::string& s);   // 大对象：避免拷贝
void g(int x);                  // 小对象：按值更快
void h(std::string s);          // 要存下来：按值 + 移动
```

**`const T&` 还能绑定临时量**：`f("hello")` 会构造临时 `string` 并延长生命周期，这是它相对 `T&` 的关键优势。

**C++17 的补充**：只读字符串参数优先 `std::string_view`，避免"从 `const char*` 构造 `string`"的那次分配。

## 高频追问

1. **`const T&` 一定不拷贝吗？** —— 传 `const char*` 给 `const string&` 会构造临时对象，仍有一次分配。
2. **返回值也该用引用吗？** —— 返回成员或静态对象可以，返回局部变量不行（悬垂）。
3. **`T&&` 什么时候用？** —— 完美转发（模板里 `T&&` + `std::forward`）或明确要移动语义时。

## 易错点

- 对 `int` 参数也用 `const&`，白白多一层间接
- 返回局部变量的 `const&`
- 以为 `const T&` 万能，不知道它会构造临时对象
