## 题目

**题目**：

```cpp
struct T { T(){} T(const T&){} T(T&&){} };
T a;                // (1)
T b = a;            // (2)
T c = std::move(a); // (3)
T d = T();          // (4)
```

**问**：四种构造分别在什么时候被调用？默认构造、拷贝构造、移动构造怎么区分？

## 口述答案

> (1) 默认构造；(2) 拷贝构造（`a` 是左值）；(3) 移动构造（`std::move` 产生右值）；(4) C++17 起**零构造**（复制省略，直接构造 `d`）。
> 区分依据只有一条：**实参是左值还是右值**。左值走拷贝，右值走移动；没有移动构造时右值也退化成拷贝。

## 讲深一层

| 场景 | 调用的构造 |
|---|---|
| `T a;` | 默认构造 |
| `T b = a;` / `T b(a);` | 拷贝构造 |
| `T c = std::move(a);` | 移动构造 |
| `T d = T();` | C++17 起省略，直接默认构造 |
| `f(T x)` 传左值 | 拷贝构造 |
| `f(T x)` 传 `std::move(a)` | 移动构造 |
| `return local;` | 通常 NRVO（零构造） |
| `v.push_back(a)` | 拷贝构造 |
| `v.push_back(std::move(a))` | 移动构造 |

**一个高频陷阱**：`T b = a;` 里 `=` 不是赋值运算符，是**初始化**，所以调拷贝构造而不是拷贝赋值。只有对**已存在对象**赋值才调 `operator=`。

## 高频追问

1. **拷贝构造和拷贝赋值的区别？** —— 前者创建新对象，后者修改已有对象；后者要处理自赋值和释放旧资源。
2. **不写移动构造会怎样？** —— 右值也会走拷贝构造（如果拷贝构造可用）。
3. **`= default` 和手写的区别？** —— `= default` 由编译器生成，通常更优；手写会抑制其他特殊成员的隐式生成。

## 易错点

- 把 `T b = a;` 当成赋值
- 以为右值一定走移动构造（可能退化成拷贝）
- 手写一个特殊成员，导致其他成员不再自动生成
