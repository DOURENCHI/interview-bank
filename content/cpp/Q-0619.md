## 题目

**场景**：`g++ main.cpp -o main` 一条命令就出结果了，但面试官问"这条命令内部做了什么"。

**问**：把「编译链接」拆开看，实质是哪几件事？每步的产物是什么？

## 口述答案

> 四步：**预处理**（展开宏和 `#include`，产物 `.i`）→ **编译**（转成汇编，产物 `.s`）→ **汇编**（转成机器码，产物 `.o`）→ **链接**（合并 `.o` 和库，产物可执行文件）。
> 我们常说的"编译"其实涵盖了前三步，第四步是独立的"链接"。很多报错类型是能靠这一步区分出来的：`error:` 是编译期，`undefined reference` 是链接期。

## 讲深一层

```bash
g++ -E main.cpp -o main.i      # 预处理：展开头文件和宏
g++ -S main.i  -o main.s       # 编译：生成汇编
g++ -c main.s  -o main.o       # 汇编：生成目标文件
g++ main.o -o main             # 链接：合并符号
# 等价于
g++ main.cpp -o main
```

| 阶段 | 输入 | 输出 | 典型错误 |
|---|---|---|---|
| 预处理 | `.cpp` | `.i` | 找不到头文件 |
| 编译 | `.i` | `.s` | 语法错误、类型错误 |
| 汇编 | `.s` | `.o` | 汇编器错误（少见） |
| 链接 | `.o` + 库 | 可执行文件 | `undefined reference`、`multiple definition` |

**为什么这个区分有用**：看到 `undefined reference to 'foo'`，就知道语法和类型都没问题，问题在"符号没找到"——查库路径、库顺序、`extern "C"`，而不是去改代码逻辑。

## 高频追问

1. **`-c` 是什么意思？** —— 只编译不链接，产出 `.o`。
2. **头文件在哪个阶段处理？** —— 预处理，`#include` 就是文本插入。
3. **链接顺序为什么重要？** —— 静态库按命令行顺序解析，被依赖的库要放在依赖它的后面。

## 易错点

- 把 `undefined reference` 当成语法错误去改代码
- 不知道 `-c` 只编译不链接
- 头文件路径写错，报的是"找不到文件"而不是"函数未定义"
