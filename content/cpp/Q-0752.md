## 题目

**追问**：信号槽和事件都能"通知"，为什么 Qt 要两套机制？

**问**：信号槽和事件机制有什么区别？各自适合什么场景？

## 口述答案

> **事件是"从外到内"的输入**：由 Qt 或操作系统产生（鼠标、键盘、重绘、定时器），按事件循环派发，有明确的接收者。**信号是"从内到外"的通知**：由对象自己的状态变化产生，一对多广播，接收者是谁由 `connect` 决定。
> 一句话区分：**事件是"别人告诉我发生了什么"，信号是"我告诉别人我变了"**。

## 讲深一层

| 维度 | 事件 | 信号槽 |
|---|---|---|
| 来源 | 系统/Qt 内部 | 对象自身状态变化 |
| 方向 | 从外到内（派发） | 从内到外（广播） |
| 接收者 | 明确（目标对象） | 由 connect 决定，可多个 |
| 同步性 | 事件循环驱动 | 可同步可异步 |
| 能否拦截 | ✅（过滤器） | ❌ |
| 典型用途 | 鼠标、键盘、重绘、窗口 | 按钮点击、数据就绪、状态变更 |

```cpp
// 事件：重写处理函数
void MyWidget::mousePressEvent(QMouseEvent* e) { /* ... */ }

// 信号：定义并发射
signals:
    void dataReady(const QByteArray& buf);
void onData() { emit dataReady(buf_); }
```

**它们会互相转化**：`QPushButton` 收到 `mouseReleaseEvent`（事件），判断在按钮区域内后 `emit clicked()`（信号）。这是 Qt 控件的典型结构。

**选型建议**：需要拦截/改变默认行为用事件；需要解耦"谁关心我"用信号。

## 高频追问

1. **信号能被拦截吗？** —— 不能直接拦，但可以不连；要拦截就用事件。
2. **事件能跨线程吗？** —— `postEvent` 可以投递到目标线程的事件队列。
3. **什么时候该自定义信号？** —— 内部逻辑需要通知外部，但不想暴露实现细节时。

## 易错点

- 用信号实现"拦截鼠标"（做不到，该用事件过滤器）
- 用事件实现一对多通知（该用信号）
- 以为信号一定异步（同线程是同步直接调用）
