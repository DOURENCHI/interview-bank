## 题目

**场景**：C++ 项目要解析 XML，选库时发现 TinyXML2、pugixml、libxml2、RapidXML 各有拥趸，装了一个发现 API 完全不一样。

**问**：为什么"装了哪个库"会成为问题？选型该看什么？

## 口述答案

> 因为 C++ **没有标准 XML 库**，每个库的 API、内存模型、许可证、依赖都不同——不像 Python 有 `xml.etree`。
> 选型要看四点：**API 风格**（DOM 还是 SAX）、**依赖**（是否要 expat/iconv）、**许可证**（商用是否友好）、**维护状态**。

## 讲深一层

| 库 | 风格 | 依赖 | 许可证 | 特点 |
|---|---|---|---|---|
| pugixml | DOM | 无（单文件） | MIT | 轻量、快、API 简洁 |
| TinyXML2 | DOM | 无 | zlib | 极小，功能够用 |
| RapidXML | DOM | 无 | MIT/Boost | 极快，但会修改输入缓冲 |
| libxml2 | DOM + SAX | 有 | MIT | 功能全，体积大 |
| Boost.PropertyTree | DOM | Boost | Boost | 通用（XML/JSON/INI），性能一般 |

```cpp
// pugixml
pugi::xml_document doc;
doc.load_file("cfg.xml");
for (auto node : doc.child("root").children("item"))
    std::cout << node.attribute("id").as_int();
```

**C++ 生态的普遍问题**：标准库覆盖窄，选库时要额外考虑 ABI 稳定性、是否 header-only、能否静态链接进 SDK。

**面试里能加分的一句**：如果只是读配置，优先 JSON（有 nlohmann/json 这种 header-only 的成熟方案）；XML 只在对接已有系统时才用。

## 高频追问

1. **DOM 和 SAX 怎么选？** —— 文件小、要随机访问用 DOM；文件大（几百 MB）用 SAX 流式解析。
2. **header-only 有什么好处？** —— 不用处理链接和 ABI，直接拷进项目。
3. **解析安全要注意什么？** —— XXE（外部实体注入）和实体展开炸弹，要禁用 DTD。

## 易错点

- 引入重量级库只为了读一个配置
- 忽略许可证（GPL 库进商业 SDK）
- 不处理 XXE，解析外部输入有安全风险
