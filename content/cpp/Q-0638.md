## 题目

**场景**：`#define SQUARE(x) x*x`，调用 `SQUARE(1+2)` 得到 5 而不是 9。

**问**：宏和 inline 函数有什么区别？为什么宏容易出问题？

## 口述答案

> 宏是**预处理期的文本替换**，没有类型检查、没有作用域、参数会被重复求值；`inline` 函数是**真正的函数**，有类型检查、参数只求值一次，只是建议编译器内联展开。
> `SQUARE(1+2)` 展开成 `1+2*1+2 = 5`，因为宏只是文本粘贴，没有括号保护。

## 讲深一层

```cpp
#define SQUARE(x) x*x
SQUARE(1+2)        // → 1+2*1+2 = 5  ❌

#define SQUARE2(x) ((x)*(x))
SQUARE2(i++)       // → ((i++)*(i++))  i 被加两次 ❌

inline int square(int x) { return x * x; }   // ✅ 类型安全，求值一次
```

| 维度 | 宏 | inline 函数 |
|---|---|---|
| 处理阶段 | 预处理（文本替换） | 编译 |
| 类型检查 | 无 | 有 |
| 参数求值 | 可能多次 | 一次 |
| 调试 | 看不到符号 | 可断点 |
| 作用域 | 无（文件级） | 遵循作用域 |
| 副作用 | 可能重复求值 | 无 |

**宏仍然有用的场景**：条件编译（`#ifdef`）、字符串化（`#x`）、拼接（`a##b`）、头文件保护——这些是函数做不到的。

**现代替代**：常量用 `constexpr`，函数用 `inline` 或模板，只有"需要看源码结构"的场景才用宏。

## 高频追问

1. **`inline` 一定内联吗？** —— 不一定，只是建议；现代编译器会自己决定，`inline` 更像"允许在头文件里定义"的标记。
2. **`constexpr` 函数比宏好在哪？** —— 类型安全、可调试、可用于模板参数。
3. **宏能调试吗？** —— 不能设断点，只能看预处理后的 `.i` 文件（`g++ -E`）。

## 易错点

- 宏参数不加括号
- 把有副作用的表达式传给宏
- 用宏定义常量（应该 `constexpr`）
