## 题目

**题目**：`ps` 里出现一堆 `<defunct>` 进程，占着 PID 但不释放。

**问**：僵尸进程、孤儿进程、守护进程分别是什么？

## 口述答案

> **僵尸进程**：子进程已退出，但父进程**没调用 `wait()` 回收**，留下一个只占 PID 和退出状态的空壳。
> **孤儿进程**：父进程先死了，子进程被 `init`（PID 1）或 subreaper 收养，不会变成僵尸。
> **守护进程**：主动脱离终端的后台进程（`setsid` 两次 fork），用于常驻服务。
> 三者的关系是：**孤儿会被收养所以不僵尸；僵尸的根源是父进程没回收**。

## 讲深一层

```c
// 避免僵尸：忽略 SIGCHLD，或显式 wait
signal(SIGCHLD, SIG_IGN);         // 子进程退出自动回收
// 或
while (waitpid(-1, NULL, WNOHANG) > 0) { }
```
| 类型 | 状态 | 处理 |
|---|---|---|
| 僵尸 | 已退出未回收 | 父进程 `wait`，或杀掉父进程 |
| 孤儿 | 运行中，父已死 | 被 init 收养，一般无需处理 |
| 守护 | 常驻后台 | 双 fork + setsid + 重定向 stdio |
- 僵尸不能被 `kill -9` 杀掉（它已经死了），只能让父进程回收。

## 高频追问

1. **僵尸进程占资源吗？** —— 不占内存/CPU，但占 PID，太多会耗尽 PID 表。
2. **怎么检测僵尸？** —— `ps aux | grep Z`，`STAT` 列为 `Z`。

## 易错点

- 试图 `kill` 僵尸进程
- 以为孤儿进程会变僵尸
