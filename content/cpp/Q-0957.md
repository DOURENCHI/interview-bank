## 题目

**问**：把**堆内存、栈内存、静态存储区**的申请情况都讲一讲。

## 口述答案

> 三个区域，分配方式和生命周期完全不同：
> - **栈**：函数调用自动分配，存局部变量、参数、返回地址。从高地址向低地址生长，分配就是移动栈指针，几乎零成本；生命周期到函数返回，Linux 默认每线程 8MB。
> - **堆**：`malloc/new` 手动申请，`free/delete` 释放。向高地址生长，由 ptmalloc/jemalloc 管理 brk/mmap 出来的内存池；大小受虚拟内存限制，生命周期由程序员控制。
> - **静态/全局存储区**：编译期确定，程序加载时就分好，整个进程生命周期存在；分 `.data`（已初始化）和 `.bss`（未初始化，加载时清零）。

## 讲深一层

```c
int g_init = 1;          /* .data   */
int g_zero;              /* .bss    */
static int s_cnt;        /* .bss    */
int main(void) {
    int stack_v = 0;                       /* 栈 */
    static int s_in_func = 0;              /* 静态区（函数内 static 也在 .bss/.data） */
    int *heap_v = malloc(100);             /* 堆：指针在栈，内存在堆 */
    free(heap_v);
}
```

为什么栈快：只需 `sub rsp, N`，不用找内存管理器；但也因此大小受限，大数组放栈上直接栈溢出。

## 高频追问

1. **函数内 `static` 变量存在哪？** —— 静态存储区，不是栈；且初始化在首次执行时保证（C++11 线程安全）。
2. **栈溢出怎么排查？** —— 深递归/超大局部数组；`ulimit -s` 查大小，段错误落在栈边界附近。

## 易错点

- 把"指针变量"和"指针指向的内容"混在一起——指针本身在栈，指向的内存在堆
- 说堆一定比栈慢——首次 mmap 有系统调用开销，但热路径上 ptmalloc 有缓存，差距没想象大
