## 题目

**题目**：

```cpp
const int& r = 42;              // 合法
int& r2 = 42;                   // 编译错误
void f(const std::string& s);
f("hello");                     // 合法，构造临时 string
```

**问**：`const T&` 到底特殊在哪？它为什么能绑定临时量，生命周期又是怎么延长的？

## 口述答案

> `const T&` 能绑定**临时对象**（右值），普通 `T&` 不能。绑定之后，临时对象的生命周期被**延长到引用的作用域结束**，所以 `const int& r = 42;` 之后 `r` 一直有效。
> 这个特性让 `const T&` 成为最通用的只读参数类型：既能接受左值，也能接受临时量，还能避免拷贝。

## 讲深一层

```cpp
const std::string& s = std::string("hi");   // 生命周期延长
// 等价于：临时对象存活到 s 的作用域结束

struct S { const std::string& ref; };
S s{ std::string("x") };    // ⚠️ 不延长！成员引用的临时量在构造语句后销毁
```

| 绑定 | `T&` | `const T&` | `T&&` |
|---|---|---|---|
| 左值 | ✅ | ✅ | ❌ |
| 临时量（右值） | ❌ | ✅（延长） | ✅（延长） |
| `const` 左值 | ❌ | ✅ | ❌ |

**生命周期延长的边界**（很容易踩）：
1. **只对"直接绑定"生效**，通过函数返回值绑定不延长；
2. **成员引用不延长** → 悬垂；
3. **绑定到 `return` 的临时量**不延长。

**实用结论**：函数参数用 `const T&` 是安全的（调用期间临时量一直活着）；但**不要把 `const T&` 存成成员**。

## 高频追问

1. **`T&&` 也能延长吗？** —— 能，规则同理。
2. **延长多久？** —— 到引用本身的生命周期结束（作用域结束）。
3. **`const T&` 和 `T` 参数哪个好？** —— 大对象用 `const&`（省拷贝），小对象（`int`）按值更好。

## 易错点

- 把 `const T&` 存成成员，临时量早销毁
- 以为延长规则对返回值也生效
- 对小类型也用 `const&`
