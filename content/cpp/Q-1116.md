## 题目

**问**：传统三段式权限（属主/组/其他）不够用时怎么办？

## 口述答案

> 用 **ACL**（访问控制列表），可以给特定用户或组单独授权，不受「一个文件只能有一个属主一个属组」的限制。
> 比如「让 bob 对这份日志有读权限，但其他人都没有」，三段式做不到，ACL 一条命令就行。
> 另外还有**特殊权限**：SUID（执行时以属主身份）、SGID（以属组身份 / 目录里新建文件继承组）、
> Sticky（目录里只能删自己的文件）。

## 讲深一层

```bash
setfacl -m u:bob:r-- file     # 给 bob 读权限
getfacl file                   # 查看
setfacl -x u:bob file          # 移除
chmod u+s file                 # SUID
chmod g+s dir                  # SGID（目录）
chmod +t dir                   # Sticky
```

| 特殊位 | 作用 | 典型场景 |
|---|---|---|
| SUID | 以文件属主身份执行 | `passwd` |
| SGID | 以属组身份执行 / 继承组 | 共享目录 |
| Sticky | 只能删自己的 | `/tmp` |

## 高频追问

1. **SUID 有什么安全风险？** —— 提权漏洞的常见入口，生产环境要审计。
2. **ACL 和 SELinux 什么关系？** —— ACL 是权限扩展，SELinux 是强制访问控制（MAC），层次不同。
3. **怎么查文件有没有 ACL？** —— `ls -l` 权限位末尾会出现 `+`。

## 易错点

- ❌ 以为 ACL 能替代 SELinux
- ❌ SGID 用在文件上和目录上含义不同（执行身份 vs 继承组）
- ✅ 说清「三段式不够 → ACL 补」
