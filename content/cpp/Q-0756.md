## 题目

**面试官问**：你用 Qt 写过网络程序，踩过哪些坑？

**问**：Qt 网络编程最常见的三个坑是什么？各自怎么解决？

## 口述答案

> 三个最常见的：**粘包/半包**（`readyRead` 不等于一条完整报文）、**在 GUI 线程用阻塞 API**（`waitForReadyRead` 让界面假死）、**socket 跨线程使用**（在 A 线程创建、B 线程调用，崩溃或警告）。
> 前两个是使用方式问题，第三个是 Qt 对象线程归属的硬约束。

## 讲深一层

| 坑 | 现象 | 解决 |
|---|---|---|
| 粘包/半包 | 解析出错、消息错位 | 长度前缀 / 分隔符 + 缓冲累积 |
| 阻塞 API | 界面假死 | 只用信号槽异步接口 |
| 跨线程使用 | 崩溃、`QObject: Cannot create children for a parent in a different thread` | 在所属线程创建和使用 |
| 没处理错误 | 连接失败无感知 | 连 `errorOccurred` |
| 缓冲区无限增长 | 内存涨 | 设上限，超限断开 |

```cpp
// 长度前缀协议的最小实现
void onReadyRead() {
    buf_ += socket_->readAll();
    while (buf_.size() >= 4) {
        quint32 len;
        memcpy(&len, buf_.constData(), 4);
        if ((int)buf_.size() < 4 + (int)len) break;      // 半包，等更多
        QByteArray msg = buf_.mid(4, len);
        buf_.remove(0, 4 + len);
        handle(msg);
    }
    if (buf_.size() > kMaxBuf) socket_->abort();          // 防内存爆炸
}
```

**`QObject` 线程归属规则**：对象属于创建它的线程，`delete`、`start timer`、socket 操作都必须在那个线程。跨线程只能通过信号槽（队列连接）投递。

## 高频追问

1. **怎么判断是否跨线程？** —— `obj->thread() != QThread::currentThread()`。
2. **缓冲区上限设多少？** —— 按协议最大报文来，比如 4 MB；超了直接断开。
3. **UDP 也有粘包吗？** —— 没有（保留消息边界），但可能丢包、乱序、重复。

## 易错点

- 假设 `readyRead` 一次给一条完整消息
- GUI 线程调用 `waitForReadyRead()`
- 在子线程操作主线程创建的 socket
