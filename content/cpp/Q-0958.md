## 题目

**追问**：**栈的大小是多少？堆内存最大能申请多少？以 x86-64 为例。**

## 口述答案

> - **栈**：Linux 默认每线程 **8MB**（`ulimit -s` 可查可改）；线程创建时可用 `pthread_attr_setstacksize` 单独指定。Windows 默认 1MB。
> - **堆**：理论上限是**进程可用虚拟地址空间**。x86-64 用户态实际用到 **48 位虚拟地址（约 256TB）**，再扣掉共享库映射、代码段等，可分配几十 TB 量级；实际受物理内存 + swap 的 overcommit 策略约束。

## 讲深一层

```bash
ulimit -s            # 8192 (KB)，栈
cat /proc/sys/vm/overcommit_memory   # 0 启发式 / 1 总是 / 2 严格
```

malloc 细节（glibc ptmalloc）：请求 < 128KB 从 brk 扩展的主 arena 切块；**≥ 128KB 直接 mmap 单独映射**，free 时立刻归还 OS——这就是"申请 1GB 再 free，top 里 RSS 立刻下降"的原因。

64 位下"最大能申请多少"的正确回答框架：虚拟地址够大 → 看 overcommit → 看物理内存+swap → 看是否被 cgroup/ulimit 限制。

## 高频追问

1. **栈 8MB 溢出了怎么调？** —— `ulimit -s unlimited` 或改线程属性；但根本解法是别在栈上放大对象。
2. **overcommit=2 时能申请多少？** —— `swap + RAM×vm.overcommit_ratio`，超了 malloc 直接返回 NULL。

## 易错点

- 答"堆最大 4GB"——那是 32 位；64 位用户态是几十 TB 量级
- 忽略 128KB 的 mmap 阈值，解释不了"free 后内存还给 OS"的现象
