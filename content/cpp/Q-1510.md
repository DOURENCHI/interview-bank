## 题目

**题目**：每来一个请求就 `pthread_create`，并发一高就崩。

**问**：线程池是怎么设计出来的？关键参数有哪些？

## 口述答案

> 线程池的核心是**预先创建固定数量的工作线程 + 一个任务队列**：主线程只负责入队，工作线程循环取任务执行。这样避免了频繁创建销毁线程的开销，也能限制并发上限。
> 关键参数：**线程数**、**队列容量**、**拒绝策略**、**空闲回收时间**。

## 讲深一层

| 参数 | 怎么定 |
|---|---|
| 线程数 | CPU 密集≈核数；I/O 密集可放大 |
| 队列容量 | **必须有界**（否则内存爆） |
| 拒绝策略 | 拒绝 / 调用方执行 / 丢最旧 |
| 空闲超时 | 长期空闲的线程回收 |
```cpp
// C++ 版骨架
for (int i = 0; i < n; ++i)
    workers.emplace_back([this]{
        for (;;) {
            Task t;
            { std::unique_lock lk(m_); cv_.wait(lk, [&]{ return stop_ || !q_.empty(); });
              if (stop_ && q_.empty()) return;
              t = std::move(q_.front()); q_.pop(); }
            t();
        }
    });
```
- 队列无界 = 把过载变成 OOM（这与我们题库里"线程池为什么必须有界"是同一个结论）。
- 线程数不是越多越好：超过核数后只是增加切换开销。

## 高频追问

1. **线程池能保证任务顺序吗？** —— 多线程不保证；要保序就用单线程或按 key 分片。
2. **怎么优雅关闭？** —— 设 `stop_` 标志 + 唤醒所有线程 + `join`。

## 易错点

- 无界队列
- 线程数开到几百
