## 题目

**场景**：写了 `virtual void f();`，派生类也写了同名函数，但通过基类指针调用还是走基类版本。

**问**：动态多态必须同时满足哪三个条件？漏掉一个会怎样？

## 口述答案

> 三个条件：**通过基类指针或引用调用**、**函数在基类声明为 `virtual`**、**派生类签名完全一致**（同名、同参数、同 const）。
> 漏掉任何一个都会退化成静态绑定，编译期就决定调用基类版本。最常见的漏法是**签名不一致**——比如派生类漏了 `const`，那就变成了一个新函数而不是覆写。

## 讲深一层

```cpp
struct Base {
    virtual void f();              // 1. 基类 virtual
    virtual void g() const;
};
struct D : Base {
    void f() override;             // 2. 签名一致 ✅
    void g();                      // ❌ 漏了 const，不是覆写
};

Base* p = new D;
p->f();      // 走 D::f（动态绑定）
p->g();      // 走 Base::g（D::g 是另一个函数）
```

| 漏掉的条件 | 后果 |
|---|---|
| 基类没 `virtual` | 静态绑定，永远走基类版本 |
| 用对象而非指针/引用 | 对象切片，静态绑定 |
| 签名不一致 | 变成新函数，原虚函数未被覆写 |
| 基类函数是 private | 仍可覆写，但外部不能通过基类调用 |

**`override` 关键字的价值**：让编译器检查"确实覆写了某个虚函数"，签名写错立刻报错。**`final`** 则禁止进一步覆写。

**对象切片**：`Base b = d;` 只拷贝基类部分，`b.f()` 走基类版本——这是"用对象而非引用"的典型后果。

## 高频追问

1. **构造函数能是虚函数吗？** —— 不能，构造时对象类型还没确定；但析构函数应该是虚的。
2. **静态函数能是虚函数吗？** —— 不能，虚函数依赖对象。
3. **`override` 会改变行为吗？** —— 不会，只是编译期检查；但能防住大量 bug。

## 易错点

- 派生类漏 `const`，以为覆写了其实没有
- 用对象赋值导致切片
- 不写 `override`，签名错了也不报错
