## 题目

**场景**：`template<typename T> T max(T a, T b);` 调用 `max(1, 2.5)` 编译失败。

**问**：函数模板的类型推导规则是什么？为什么模板定义必须放头文件？

## 口述答案

> 推导规则是**从实参推出 `T`**：两个参数都要求同一个 `T`，但 `1` 是 `int`、`2.5` 是 `double`，推导冲突就失败。解决办法是显式指定 `max<double>(1, 2.5)` 或写两个类型参数。
> 模板定义放头文件，是因为**编译器需要在实例化点看到完整定义**才能生成代码；只看到声明无法实例化，链接时就会找不到符号。

## 讲深一层

```cpp
template <typename T>
const T& max(const T& a, const T& b) { return a < b ? b : a; }

max(1, 2);            // T = int ✅
max(1, 2.5);          // ❌ 推导冲突
max<double>(1, 2.5);  // ✅ 显式指定，1 转成 double
```

| 写法 | 推导结果 |
|---|---|
| `max(1, 2)` | `T = int` |
| `max(1.0, 2.0)` | `T = double` |
| `max(1, 2.5)` | 冲突，编译失败 |
| `max<double>(1, 2.5)` | `T = double`，`1` 隐式转换 |
| `max<int>(1, 2.5)` | `T = int`，`2.5` 被截断 ⚠️ |

**推导时会做的调整**：数组→指针、函数→函数指针、去掉顶层 `const`。但**不会**做隐式类型转换（除了显式指定的情况）。

**为什么放头文件**：模板不是"代码"，是"生成代码的配方"。编译器在每个使用点都要看到完整配方才能生成对应的函数。

## 高频追问

1. **能不能把模板定义放 `.cpp`？** —— 能，如果在该 `.cpp` 里**显式实例化**已知的所有类型（`template int max<int>(...)`）。
2. **`typename` 和 `class` 有区别吗？** —— 在模板参数列表里等价；但嵌套依赖类型必须用 `typename`。
3. **`auto` 返回类型会影响推导吗？** —— 会，`auto` 按值推导会丢掉引用和 `const`。

## 易错点

- `max(1, 2.5)` 报错时不知道是推导冲突
- 以为模板定义可以只放声明
- `max<int>(1, 2.5)` 悄悄截断
