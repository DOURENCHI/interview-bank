## 题目

**问**：systemd 是什么？为什么它取代了 init 脚本？

## 口述答案

> systemd 是现代 Linux 的 **init 系统和服务管理器**，负责开机时按依赖关系启动服务、管理服务生命周期、收集日志。
> 相比传统 SysV init 的串行启动，它用**依赖声明 + 并行启动**，开机更快；
> 还统一了日志（journald）、定时任务（timer）、挂载（mount）等。
> 核心概念是 **unit**（服务是 service unit，还有 target、timer、mount 等类型）。

## 讲深一层

```bash
systemctl start/stop/restart nginx
systemctl enable/disable nginx      # 开机自启
systemctl status nginx
journalctl -u nginx -f              # 看日志
systemctl list-units --type=service
```

| 概念 | 说明 |
|---|---|
| unit | 配置单元，`.service` / `.target` / `.timer` |
| target | 一组 unit 的集合，类似运行级别 |
| 依赖 | `After=` `Requires=` `Wants=` |

**`Wants` 和 `Requires` 的区别**：`Requires` 是强依赖（对方挂了我也挂），`Wants` 是弱依赖（对方失败我照跑）。

## 高频追问

1. **写一个 service 需要什么？** —— `[Unit]` 描述、`[Service]` 的 `ExecStart`、`[Install]` 的 `WantedBy`。
2. **`Type=simple` 和 `forking` 区别？** —— simple 前台运行，forking 自己 daemon 化。
3. **为什么不推荐自己写 daemon 化？** —— 交给 systemd 管更可靠，重启、日志、依赖都由它处理。

## 易错点

- ❌ 服务里自己 double-fork —— 和 systemd 的进程管理冲突
- ❌ 用 `Requires` 做所有依赖 —— 一个失败全挂
- ✅ 记住「unit + 依赖 + 并行启动」
