## 题目

**背景**：基础数据结构对比题，面试官想看候选人能否结合实际场景做选择。

**问**：`vector` 和链表 `list` 有什么区别？实际工程里怎么选？

## 口述答案

> 结论：**默认用 vector，除非有明确的中间插入删除需求且元素很大**。vector 是连续内存：随机访问 O(1)、尾插摊还 O(1)、遍历 cache 友好；代价是中间插删 O(n) 移动，扩容按 1.5~2 倍重新分配并拷贝，扩容后迭代器、指针、引用全部失效。list 是双向链表：已知位置插删 O(1)，但随机访问 O(n)，每个节点多两个指针，节点分散导致 cache miss 严重。实测小数据量下 vector 常胜出。

## 讲深一层

| | vector | list |
|---|---|---|
| 随机访问 | O(1) | O(n) |
| 尾插 | 摊还 O(1) | O(1) |
| 中间插删 | O(n) | O(1) |
| 内存开销 | 3 指针 + 容量冗余 | 每节点 2 指针 |
| 缓存友好 | 好 | 差 |
| 迭代器失效 | 扩容全失效 | 仅被删节点 |

Stroustrup 的实验：随机插入 10 万个整数后排序遍历，vector 仍快于 list。

## 高频追问

1. **什么时候真的该用 list？** —— 元素很大（拷贝贵）、需要在遍历中安全删除、或用 `splice` 拼接（O(1)）。
2. **vector 扩容为什么是 2 倍或 1.5 倍？** —— 保证摊还 O(1)；1.5 倍更易复用已释放的块，2 倍摊还常数更小。
3. **有中间插入需求怎么办？** —— 用 `std::deque`（分段连续），或 `vector` + 批量重建；LRU 用 `list` + `unordered_map` 存迭代器。

## 易错点

- 说"list 插入删除一定比 vector 快"，忽略查找定位的 O(n)
- 忽略 vector 扩容导致的历史迭代器/指针失效
- 用 vector 存大对象并频繁拷贝，忘记 `emplace_back` 与移动语义
