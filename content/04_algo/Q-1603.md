## 题目

**现象**：本地跑样例全对，提交后通过率 30%。把输入输出打印出来逐字符比对，发现 `6` 和 `6 ` 被判成不同。

**问**：输出格式错会掉多少分？有哪些必须自查的点？

## 口述答案

> **可能直接掉到 0**。判题机做的是文本比对，多一个空格、少一个换行都算错，它不"理解"你的答案对不对。
> 必须自查四处：**行末有没有多余空格**、**最后一行有没有换行**、**大小写是否一致**、**浮点数保留几位**。这四项能覆盖绝大多数格式性失分。

## 讲深一层

```cpp
// ❌ 行末多空格：最后一项后面也打了空格
for (int i = 0; i < n; ++i) cout << a[i] << ' ';

// ✅ 用分隔符打在前面
for (int i = 0; i < n; ++i) cout << (i ? " " : "") << a[i];
cout << '\n';

// ✅ 浮点数：必须 fixed + setprecision 一起用
cout << fixed << setprecision(2) << ans << '\n';
```

| 自查项 | 错误写法 | 正确写法 |
|---|---|---|
| 行末空格 | 每项后都打空格 | 分隔符前置，或判断 `i < n-1` |
| 末尾换行 | 最后不换行 | 统一 `'\n'` |
| 浮点位数 | `setprecision(2)` 单独用 | `fixed << setprecision(2)` |
| 大小写 | `Yes` / `YES` 混用 | 照抄样例 |

**`setprecision` 单独用是「有效数字」，不是「小数位数」**：`setprecision(2)` 输出 `3.1` 而不是 `3.14`，必须配 `fixed`。

自查土办法：把输出重定向到文件，用 `cat -A` 看行尾有没有 `^M` 和多出来的空格。

## 高频追问

1. **判题机忽略行末空格吗？** —— 有些平台忽略，有些严格。**一律按严格处理**，成本很低。
2. **PE 是什么？** —— Presentation Error，格式错。有的平台单独计，有的直接算 WA。
3. **怎么本地复现判题？** —— `./a.out < in.txt > out.txt` 然后 `diff -B out.txt ans.txt`，`-B` 会忽略空行差异，能暴露其他问题。

## 易错点

- 认为"多点空格应该没事"
- `setprecision` 不配 `fixed`
- 最后一行没换行，被判定输出不完整
