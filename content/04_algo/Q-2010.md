## 题目

**背景**：一道经典外排序题，考察在内存远小于数据量时，如何用有限内存完成全量排序。

**问**：只有 200MB 可用内存，要对硬盘上 2GB 的 int32 数据排序，有哪两种解法？各自复杂度如何？

## 口述答案

> 结论：两种主流解法是**外部归并排序**和**范围/基数分桶**。外部归并分两阶段：每次装约 50MB（约 1250 万个数）在内存快排后写成有序 run，2GB 约产生 40 个；再用最小堆做 40 路归并，每路只常驻一个缓冲页。分桶先按数值高位散到 256 个桶文件，保证每桶能整体装进内存，再逐桶读入排序后追加——省掉归并堆，但要求分布均匀，否则单桶倾斜。

## 讲深一层

```
2GB / 4B = 5.12 亿个数
200MB 留 1/4 给输入输出缓冲，保守每次排 50MB → 1250 万
run 数 = 512M / 12.5M ≈ 41
归并趟数 = ceil(log_k N)，k=41 时一趟即可
```
| | 归并 | 分桶 |
|---|---|---|
| I/O 趟数 | 2~3 | 2 |
| 额外空间 | run + 堆 | 桶缓冲 |
| 风险 | 归并随机读 | 数据倾斜 |
| 稳定性 | 稳定 | 稳定 |

## 高频追问

1. **为什么归并路数不能无限大？** —— 每路要一个读缓冲，路数受文件句柄数（`ulimit -n`）和缓冲内存限制；可用多趟归并。
2. **能一趟完成吗？** —— 可以，若桶划分保证每桶 ≤ 内存，即"桶排序 + 桶内排序"，但需要先采样确定分位点。
3. **怎么优化 I/O？** —— 顺序读写、大块缓冲（1MB 以上）、`O_DIRECT` 或 mmap，避免小随机写。

## 易错点

- 忽略"内存要给输入输出缓冲留余量"，按满 200MB 算导致 OOM
- 归并时每次 `read` 一行，系统调用开销吃掉全部收益
- 分桶不做采样，遇到有序或集中分布直接退化成单桶
