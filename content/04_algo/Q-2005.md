## 题目

**题目**：给 100 万个 0–99999 的整数排序，要求 O(n)。

**问**：基数排序的原理是什么？为什么它不比较元素？

## 口述答案

> 基数排序是**按位分配-收集**：从最低位到最高位，每一轮按当前位的值把元素放进 10 个桶，再按顺序收回。做 d 轮（d = 最大位数）就排好了。
> 它**不做元素间比较**，靠"位"的信息直接定位桶，所以能突破比较排序的 O(n log n) 下界，复杂度 **O(d(n+k))**，k 是桶数。

## 讲深一层

```c
void radix_sort(int a[], int n) {
    int tmp[n], cnt[10];
    for (int exp = 1; exp <= max_val; exp *= 10) {
        memset(cnt, 0, sizeof cnt);
        for (int i = 0; i < n; ++i) cnt[(a[i]/exp) % 10]++;
        for (int i = 1; i < 10; ++i) cnt[i] += cnt[i-1];     // 前缀和定位置
        for (int i = n-1; i >= 0; --i) tmp[--cnt[(a[i]/exp)%10]] = a[i];  // 倒序保证稳定
        memcpy(a, tmp, n*sizeof(int));
    }
}
```
| 排序 | 比较 | 时间 | 稳定 |
|---|---|---|---|
| 比较排序（快/归/堆） | ✅ | ≥ O(n log n) | 部分 |
| 计数排序 | ❌ | O(n+k) | ✅ |
| 基数排序 | ❌ | O(d(n+k)) | ✅ |
- 必须**稳定**才能逐位排序（所以收集时要倒序遍历）。
- 数据范围大且稀疏时不适合（桶太浪费）。

## 高频追问

1. **为什么收集要倒序？** —— 保证相同位的元素保持上一轮的顺序（稳定性）。
2. **什么情况比快排慢？** —— 位数多、数据量小，常数开销占主导。

## 易错点

- 收集时正序遍历（破坏稳定性，结果错）
- 对浮点数直接用（要先转成可比较的整数形式）
