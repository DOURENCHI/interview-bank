## 题目

**题目**：LRU 你写过，但面试官问"工程级实现里 RAII、引用计数、splice 分别解决什么"。

**问**：LRU 的工程级实现要注意什么？

## 口述答案

> 四个工程细节：
> 1. **用 `std::list` + `splice`**：`splice` 把节点从链表任意位置**剪切**到头部，O(1) 且**迭代器不失效**，比手动删了再插干净得多；
> 2. **哈希表存迭代器**（`unordered_map<K, list<pair<K,V>>::iterator>`），才能 O(1) 定位；
> 3. **RAII/智能指针**：缓存值可能是大对象或需要释放的资源，用 `unique_ptr`/`shared_ptr` 管理；
> 4. **引用计数**：如果返回给调用方的值可能被外部持有，要保证淘汰时不悬垂（返回 `shared_ptr` 或拷贝）。

## 讲深一层

```cpp
class LRUCache {
    using Item = std::pair<int, int>;
    std::list<Item> lst_;                                  // 头部最新
    std::unordered_map<int, std::list<Item>::iterator> pos_;
    size_t cap_;
public:
    int get(int k) {
        auto it = pos_.find(k);
        if (it == pos_.end()) return -1;
        lst_.splice(lst_.begin(), lst_, it->second);       // O(1) 提到头部
        return it->second->second;
    }
    void put(int k, int v) {
        auto it = pos_.find(k);
        if (it != pos_.end()) { it->second->second = v; lst_.splice(lst_.begin(), lst_, it->second); return; }
        if (lst_.size() == cap_) { pos_.erase(lst_.back().first); lst_.pop_back(); }
        lst_.emplace_front(k, v);
        pos_[k] = lst_.begin();
    }
};
```
| 要点 | 为什么 |
|---|---|
| `splice` 而非 erase+insert | 迭代器不失效，哈希表不用改 |
| 哨兵节点 | 省掉头尾特殊判断 |
| 淘汰与哈希同步 | 否则哈希表留野迭代器 |
- `splice` 的三个重载里，`splice(pos, other, it)` 是"把 other 里的 it 剪到 pos 前"——正好是 LRU 的"提到头部"。
- 多线程下要加锁，或者做分段 LRU。

## 高频追问

1. **`splice` 会让迭代器失效吗？** —— 不会，只是重新链接，被剪的迭代器仍指向原节点。
2. **为什么不用 `std::map` 存访问时间？** —— 每次访问要更新时间戳（O(log n)），比链表慢。

## 易错点

- 手动 erase + push_front（多一次分配，迭代器失效）
- 淘汰时只删链表不删哈希
