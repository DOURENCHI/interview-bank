## 题目

**题目**（华为机考 AI 方向，150 分大模拟）：LLM 推理系统按 KV Cache 容量调度请求。N 个请求，第 i 个请求三个属性：到达时刻 arrive_i（时间步从 0 编号）、还需生成的 Token 数 tokens_i、处理期间占用的显存 mem_i（不随进度变化）。系统显存总容量 M。规则：
1. **并行**：每个时间步，把显存分给若干「已到达且未完成」的请求，各生成 1 个 Token；同请求同时间步最多 1 个 Token。
2. **释放**：请求累计处理满 tokens_i 步即完成，立刻释放显存，但**释放的显存下一个时间步才能分给其他请求**。
3. **接纳**：每个时间步，在「已到达、未完成、尚未占住显存」的请求中，按 mem_i 从小到大（相同则到达早者优先）依次尝试：已占用显存 + mem_i ≤ M 就接纳，装不下继续等；已接纳的请求一直处理到完成。
4. **清空**：允许主动清空某未完成请求的缓存（保留已生成数、释放显存、回到等待），但它重新开始要重占显存且已花掉的计算时间作废。题面明示：最优做法是**不清空任何请求**。
输出：全部请求处理完毕时的总时间步数。
**问**：给出求解算法与代码。

## 口述答案

> 直接按题面**逐时间步模拟**，因为规则就是确定性的贪心。每个时间步做三件事：① 接纳——从"已到达、未完成、未占用"的请求里按 (mem 升序，arrive 升序) 排序，依次尝试装入：当前已占用显存之和 + mem_i ≤ M 就接纳；② 生成——所有已占用的请求（含本步刚接纳的）各生成 1 个 Token，生成满 tokens_i 的请求在本步末移出占用（天然实现"释放的显存下一步才可用"，因为接纳发生在每步开头）；③ 计数——时间步加一。终止条件是全部完成。第 4 条清空规则按题面结论直接忽略——模拟器里根本不实现清空逻辑，这就是答案的一部分。复杂度：每步 O(K log K)（K 为候选数，排序），总步数 T 有限，整体 O(T·K log K)，N 和 tokens 不大时轻松通过。

## 讲深一层

```cpp
struct Req { long long arrive, tokens, mem, done = 0; bool occ = false; };
int main() {
    long long n, M; cin >> n >> M;
    vector<Req> rs(n);
    for (auto &r : rs) cin >> r.arrive >> r.tokens >> r.mem;
    long long t = 0, finished = 0, used = 0;
    while (finished < n) {
        // ① 接纳：候选 = 到达且未完成且未占用，按 (mem, arrive) 排序
        vector<Req*> cand;
        for (auto &r : rs)
            if (r.arrive <= t && r.done < r.tokens && !r.occ) cand.push_back(&r);
        sort(cand.begin(), cand.end(), [](auto a, auto b){
            return a->mem != b->mem ? a->mem < b->mem : a->arrive < b->arrive; });
        for (auto r : cand)
            if (used + r->mem <= M) { r->occ = true; used += r->mem; }
        // ② 生成：已占用的各推进 1 个 Token，满则本步末释放
        for (auto &r : rs)
            if (r.occ && ++r.done == r.tokens) { r.occ = false; used -= r.mem; ++finished; }
        ++t;   // ③ 计数
    }
    cout << t << endl;
}
```
自构小例（演示规则，数值以原题为准）：M=6；请求 A(arrive 0, tokens 2, mem 4)、B(arrive 0, tokens 2, mem 2)。t=0：mem 升序先接纳 B（2≤6），再接纳 A（2+4=6≤6），两者并行生成；t=1：都完成 → 输出 2。若再有一个 C(arrive 0, tokens 1, mem 1)：t=0 时 6+1>6 等待，t=1 时 A、B 已完成释放，C 接纳并完成 → 输出 2。

## 高频追问

1. 为什么"清空缓存"永远不优？——清空只作废已付出的计算时间，显存占用规则不变，纯亏
2. 如果 N 很大怎么优化？——每步的候选集用堆（mem, arrive）维护，免去重复排序
3. 完成释放"下步才可用"怎么保证？——接纳在步首、释放在步尾，顺序天然隔离

## 易错点

- 接纳时用"剩余显存"和"总显存"算错——判断条件是已占用和 + mem ≤ M
- 新接纳的请求本步就要生成 Token（原帖样例明确如此），漏掉整体时间少 1
- 实现"清空"逻辑——题面已说最优不清空，写了反而引入 bug
