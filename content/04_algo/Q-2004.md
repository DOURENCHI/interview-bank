## 题目

**题目**：要排一个 100 万条记录的日志，且要求相同时间戳的记录保持原顺序。

**问**：归并排序怎么实现？为什么它适合链表？

## 口述答案

> 归并是**分治**：把数组对半切、分别排序、再合并两个有序段。合并只要一次线性扫描，所以总复杂度 **O(n log n)**，且**稳定**。
> 它天然适合链表，因为合并阶段只需**改指针**，不需要额外数组（数组版要 O(n) 临时空间，链表版可以做到 O(1)）。

## 讲深一层

```c
void merge(int a[], int lo, int mid, int hi, int tmp[]) {
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];
    for (i = lo; i <= hi; ++i) a[i] = tmp[i];
}
```
| 场景 | 更适合 |
|---|---|
| 要求稳定 | 归并 |
| 数据在链表上 | 归并 |
| 外部排序（内存放不下） | 归并 |
| 内存紧张 | 快排/堆排 |
- `std::stable_sort` 通常就是归并（或归并+插入混合）。
- 外排序：分块排好写临时文件，再多路归并。

## 高频追问

1. **归并的空间能省吗？** —— 数组版可以原地归并但很慢；链表版可以 O(1)。
2. **为什么外部排序都用归并？** —— 只需顺序读写，适合磁盘。

## 易错点

- 说归并是原地排序
- 合并时用 `<` 而不是 `<=`（会破坏稳定性）
