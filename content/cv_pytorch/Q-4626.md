## 题目

**背景**：讨论多 Agent 协作时，面试官关心主 Agent 把任务交给子 Agent 时上下文怎么传。

**问**：上下文从主 Agent 传到子 Agent，怎么保证关键信息不丢？

## 口述答案

> 不靠"把对话历史整段丢过去"，靠结构化契约。1. 定义显式的 Context 对象：任务目标、已确认约束、可用工具、截止条件，序列化后作为子 Agent 的输入，而不是让它自己从历史里翻。2. 关键字段做 schema 校验，缺了直接失败，不要静默降级。3. 子 Agent 返回时回传它实际消费了哪些字段，便于核对。4. 长材料只传摘要加原文 ID，需要时再取。

## 讲深一层

```json
{
  "task": "为订单 12345 生成退款方案",
  "constraints": ["金额不得超过原单", "7 天内"],
  "tools": ["query_order", "calc_refund"],
  "refs": {"order_doc": "doc://order/12345"},
  "deadline_steps": 5
}
```
三类丢失：截断（超 token 被裁）、摘要（细节被压掉）、模型忽略（在上下文里但没被引用）。前两类靠结构化解，第三类只能靠返回时回执核对。

## 高频追问

1. **子 Agent 需要原始对话怎么办？** —— 给引用 ID 加按需取回工具，而不是预加载全文，避免上下文污染。
2. **怎么发现"传了但没用"？** —— 要求返回 used_fields，和传入字段做差集，差集过大说明契约设计有问题。
3. **多级传递会不会失真？** —— 会，每级都可能重写；关键字段应只读透传，不允许中间层改写。

## 易错点

- 直接拼接对话历史，长度不可控且噪声大
- 用自然语言描述约束（"尽量别超金额"），模型会自行放宽
- 没有 schema 校验，字段丢了到下游才炸
