## 题目

**背景**：快手大模型算法岗一面，MoE 结构题。考的是 MoE 挂在 Transformer 的哪个位置、以及「训练和推理两个视角下 MoE 各得到什么」——这是 MoE 面试的标准两问，能不能分开答决定深度。
**问**：MoE 一般加在 Transformer 的哪个位置？从训练和推理的角度看，MoE 有什么好处？

## 口述答案

> 位置：加在 Transformer block 的 FFN 层，也就是把原来的单个 MLP 换成「路由器+一组专家 FFN」——每个 token 过完 attention 后，由路由器（一个小线性层）打分，选 top-k 个专家处理这个 token，加权合并输出。Attention 层保持 dense 不动，因为注意力的参数量小、换稀疏收益不大，而 FFN 通常占模型参数的三分之二，是稀疏化的主战场。DeepSeek 系的做法是细粒度专家（把专家切小、top-k 调大，组合更灵活）加共享专家（所有 token 必经，承载通用知识）。
> 训练视角的好处：同等计算量下模型容量大幅提升。每个 token 只激活 top-k 个专家，FLOPs 由 k 决定而不是专家总数 N 决定——参数翻 10 倍计算量不变，等于「白拿」容量，模型可以装更多知识。Mixtral 8×7B 激活 13B 参数达到 70B dense 的水准，就是这个逻辑。代价是训练难：路由是离散选择不可导，靠 softmax 的软分配近似；早期训练容易路由崩塌（所有 token 挤到少数专家），要加负载均衡辅助损失逼着专家雨露均沾。
> 推理视角的好处：激活参数少，单 token 前向的 FLOPs 是 dense 同容量模型的零头，延迟和算力成本占优。但有个关键代价必须主动说：显存要装下全部专家参数——MoE 是「拿显存换算力」，专家全要驻留显存（或做 offload 换延迟），所以 MoE 部署通常配专家并行（EP），把专家切到多卡上，而 all-to-all 通信成为新的开销点。总结成一句话：训练收益是容量，推理收益是算力，两个视角共同的代价是显存和系统复杂度。

## 讲深一层

- 「白拿容量」的直觉：dense 模型每个 token 激活全部参数，参数即算力；MoE 把「参数量」和「计算量」解耦，路由器决定每 token 用哪一小部分——这是理解所有 MoE 问题的根模型，负载均衡、专家分化、EP 全都能从这里推出来。
- 细粒度专家的动机：粗粒度（8 个大专家选 2）组合数有限、路由错误代价大；切细后（DeepSeek-V3 256 个选 8）等效组合爆炸，专家分工更精细，还配了共享专家兜底通用能力、无损压缩专家冗余。
- 推理系统视角的难点是 all-to-all：EP 下 token 要被送到专家所在卡，一轮 forward 内做两次全局 all-to-all 通信，通信和计算的重叠调度是 MoE serving 框架（DeepSeek 开源 DeepEP）的核心工程题——这层是推理岗的加分答案。

## 高频追问

1. 负载均衡损失怎么设计？——对每个专家的「被选频率」做辅助惩罚，逼均分；但过强会损害专家专业化，DeepSeek 用 device-level 限制替代 token 级均衡减小干扰
2. MoE 的 KV Cache 有变化吗？——没有，attention 是 dense 的，MoE 稀疏的是 FFN，KV Cache 优化是另一条线（GQA/MLA），两者正交可叠加
3. 专家会学出什么样的分工？——可解释性研究显示与 token 语义相关（标点/代码/领域词），但没有清晰主题边界，专家分化更接近「路由便利性」而非人类可读的分类

## 易错点

- 只答「参数多效果好」不讲位置和机制——「挂在 FFN 替换 MLP」是第一问的送分点，答不出位置直接暴露没读过结构图
- 推理好处只说「快」不说显存代价——MoE 的全部参数都要驻留显存，「拿显存换算力」这个 trade-off 说不出来，会被追问「那部署不就更难了吗」
- 忽略路由不可导——离散选择怎么训练（softmax 软化+负载均衡辅助损失）是 MoE 能训起来的前提，没提这个等于没理解训练过程
