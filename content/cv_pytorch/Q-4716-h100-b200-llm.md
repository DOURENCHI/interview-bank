## 题目

**背景**：小鹏深度学习平台岗被问的硬件题：H100 和 B200 有什么区别？LLM 推理瓶颈在哪？
**问**：请比较两代 GPU 并说清 Prefill/Decode 两个阶段的瓶颈差异。

## 口述答案

> 代际上：H100 是 Hopper 架构，B200 是 Blackwell，最关键的变化有三点——B200 用双 die 封装，晶圆利用率和高密度堆叠更好；HBM 换成 HBM3e，带宽到约 8TB/s 量级（H100 是 HBM3 约 3.35TB/s）；原生支持 FP4/FP6 低精度，吞吐有质变，但要评估精度折损。推理瓶颈必须分阶段说：**Prefill（处理整段输入 prompt）是计算密集**——整段并行做大 GEMM，算术强度高，瓶颈在算力；**Decode（逐 token 生成）是带宽密集**——每生成一个 token 都要把全部权重和 KV Cache 从显存读一遍，算术强度极低，瓶颈在显存带宽。所以优化方向也不同：Prefill 靠并行与好 kernel，Decode 靠 KV Cache 量化、大 batch 摊薄权重读取、投机解码。

## 讲深一层

| 阶段 | 每步做什么 | 算术强度 | 瓶颈 | 优化 |
|---|---|---|---|---|
| Prefill | N 个 token 并行 GEMM | 高 | 算力 | 更大 batch、好 kernel |
| Decode | 1 token，全量读权重+KV | 低 | 显存带宽 | KV 量化、批处理、投机解码 |
- B200 原生 FP4：吞吐翻倍级，精度敏感任务仍用 FP8

## 高频追问

1. 为什么 Decode 算术强度低？——每步只算 1 token，读的数据量不变
2. Prefill 和 Decode 能不能分开调度？——可以，vLLM 的 chunked prefill 就是干这个

## 易错点

- 笼统说"瓶颈在 GPU"——必须分阶段
- 只背参数（带宽数字）不解释 Decode 为什么吃带宽
