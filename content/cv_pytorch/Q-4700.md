## 题目

**背景**：拼多多一面的 Agent 架构题，问法开放——不给场景先问部署位置，考的是有没有一套「按什么维度做架构决策」的方法论，而不是背「后端更好」。
**问**：Agent 是跑在浏览器里，还是部署在后端服务器上？

## 口述答案

> 我不会直接二选一，先给判断三轴：要碰什么资源、要什么延迟、怕什么风险。要调私有工具、查内部数据库、跑长任务、需要统一权限管控和审计的，Agent 编排放后端——企业场景默认形态，浏览器只做交互壳；代价是所有数据都要过服务器，隐私、带宽、合规都是成本项。数据不能出本地（隐私/合规敏感）、要吃本地上下文（页面 DOM、本地文件）、要求离线可用和低延迟交互的，能力放端侧/浏览器；代价是算力受限跑不了大任务、模型更新和策略下发难、端上代码易被逆向，安全边界更难守。实际生产主流是混合：编排和重工具在后端，端侧做轻量预处理、缓存和敏感数据脱敏，模型按场景决定——小模型端侧做意图/摘要，大模型云端。回答时再补一句演进视角：端侧模型能力随 NPU 和量化技术在涨，边界在动态变化，架构决策要留迁移余地。

## 讲深一层

- 传输通道随位置变化：后端编排常用 SSE/WebSocket 流式（配合中断与续传），端侧编排则是进程内调用，通道复杂度差一个量级。
- 会话状态归属：后端编排把多轮上下文放服务端（Redis/DB），换设备可续聊；端侧编排状态在本机，隐私好但无法跨端。
- 审计与合规是后端的核心论点：企业要留存「Agent 做了什么」的完整审计链，端侧执行天然难以审计。
- 端侧的算力现实：量化到 int4 的 3B 级模型可用，长上下文的 KV 显存是硬约束，复杂工具编排基本放不下。
- 安全模型差异：后端怕的是注入打进内网工具，端侧怕的是宿主环境被逆向、凭据泄露。

## 高频追问

1. 浏览器插件型 Agent 有什么特殊风险？——页面内容是不可信输入（间接注入）、凭据在客户端可被提取、更新机制易被劫持
2. 后端 Agent 的会话怎么做隔离？——会话 ID+用户鉴权绑定，上下文按会话分键存储，工具调用带上会话级权限快照
3. 什么信号提示该把能力从端侧挪到云端？——任务复杂度超端侧算力、需要调云端私有数据、隐私约束放松或数据已脱敏

## 易错点

- 张口就「肯定后端」——没有决策维度，面试官会追「那隐私敏感场景呢」
- 混淆「模型部署位置」和「编排执行位置」——小模型端侧+编排后端是很常见的组合，两者不是绑死的
- 忘了混合架构——现实生产几乎都是分层的，单选答案说明没做过实际系统
