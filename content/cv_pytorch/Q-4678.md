## 题目

**背景**：Agent 要真正替用户操作外部系统，面试官问权限边界怎么划，考的是安全意识而不是功能实现。

**问**：Agent 的权限管理怎样设计？

## 口述答案

> 分五层。身份：调用方和被代理用户都要有明确身份，Agent 不能拿一个超级账号跑所有事。授权：最小权限，工具级加参数级 scope，比如只允许读指定日历、只能建不超过两小时的会，用 OAuth scope 或 RBAC 加 ABAC 表达业务条件。执行：策略判断放在执行侧的策略引擎里，模型输出只当"申请"，能不能做由引擎决定，不能靠提示词约束模型。高危操作加人工确认，比如支付、删除、对外发消息。审计：每次调用记清谁、以谁的身份、调了什么、参数是什么、结果如何。凭据用短期 token，不落进 prompt 和日志。还要防间接注入，工具返回内容一律当不可信输入。

## 讲深一层

| 层 | 手段 | 常见失败模式 |
| --- | --- | --- |
| 身份 | 用户 token 透传或委托 | 所有请求共用一个高权账号 |
| 授权 | scope + ABAC 条件 | 只做工具级，粒度太粗 |
| 执行 | 策略引擎 + 沙箱 | 靠 prompt 说"不要越权" |
| 确认 | human-in-the-loop | 高危操作静默执行 |
| 审计 | 全量调用日志 | 只记结果不记参数 |

## 高频追问

1. **间接注入怎么防** —— 工具返回内容不参与权限判断，只作为数据；关键动作要求二次确认或参数白名单
2. **多 Agent 委托怎么传权限** —— 委托只能收窄不能放大，子 Agent 的 scope 必须是父集合的子集
3. **权限怎么测** —— 红队用例集，每个高危工具都要有"应该被拒"的反向用例

## 易错点

- 用提示词当权限边界 —— 提示可被注入绕过，边界必须在执行侧
- 只做工具级权限 —— 同一个工具不同参数风险差异巨大，参数级才够
- 不记参数只记调用 —— 出了事无法判断实际影响了什么
