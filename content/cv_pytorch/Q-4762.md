## 题目

**场景**：基座模型几十亿参数，全参微调的显存和存储都不可行，需要讲清 LoRA 用什么代价换来了省。

**问**：介绍 LoRA 的原理，如何理解其中的「低秩」？

## 口述答案

> LoRA 的做法：**冻结原权重 W，旁边挂一对小矩阵**，前向变成 `h = Wx + (α/r)·B·A·x`。A 是 r×k、B 是 d×r，r 远小于 d 和 k，训练只更新 A、B，参数从 d×k 降到 **r×(d+k)**。
> 「低秩」指一个假设：**微调引起的权重变化量 ΔW 秩很低**。预训练模型已经过参数化，适配一个下游任务只需要在一个低维子空间里改方向，所以用秩不超过 r 的 BA 去近似满秩的 ΔW 就够用。
> 附带工程福利：推理时 BA 可以直接**合并进 W**，零额外延迟；每个任务只存一对 A、B（MB 级），多任务切换不用换整个模型。

## 讲深一层

```
W: d×k（冻结）  A: r×k（高斯初始化）  B: d×r（零初始化）
h = Wx + (α/r)·B·A·x
t=0 时 B=0 → BA=0 → 起点严格等于原模型
参数量: d·k → r·(d+k)，r=8、d=k=4096 时约为原来的 1/256
```

| | 全参微调 | LoRA |
|---|---|---|
| 可训参数 | d×k | r×(d+k) |
| 每任务存储 | 整个模型 | 仅 A、B（MB 级） |
| 推理延迟 | 基线 | 合并后无增加 |

**记忆锚点**：低秩不是说「模型简单」，而是「从预训练到任务所需的**改动方向少**」——r 就是这个改动子空间的维数；B 零初始化保证训练从原模型无损出发。

## 高频追问

1. **r 怎么选？** —— 常用 4~64，任务越复杂、数据越多取越大，收益随 r 增大递减。
2. **α 是干嘛的？** —— 对 BA 做缩放，等效放大学习率；常固定 α，改 r 不用重调学习率。
3. **只调 q_proj 够吗？** —— 结论是调全部线性层（attention + FFN）效果更好。

## 易错点

- 写成 W+AB——维度对不上，是 W + B·A
- 把「低秩」只解释成参数少，丢了对 ΔW 秩的假设
- 忘了 B 零初始化的作用（起点严格等于原模型）
