## 题目

**背景**：Agent 架构的追问，面试官把两个常被混用的概念摆在一起，看能否说清边界。

**问**：AI Agent 的上下文工程和记忆管理是什么关系？

## 口述答案

> 上下文工程管"这一次调用往窗口里放什么"，记忆管理管"跨多次调用该记住什么、存哪里、何时取回"。前者是编排问题：system prompt、工具描述、检索文档、历史摘要、当前任务状态怎么在 token 预算内排布，关注顺序、位置、冗余和噪声。后者是存储与生命周期问题：哪些事实值得持久化（用户偏好、已确认结论），存向量库、KV 还是结构化表，怎么去重、衰减、召回。关系是记忆管理提供原料，上下文工程决定这一刻取哪些、以什么形式喂进去。没有记忆管理，每次都得从零拼；没有上下文工程，召回了也塞不进去，还会挤掉关键指令。

## 讲深一层

| 维度 | 上下文工程 | 记忆管理 |
|---|---|---|
| 时间尺度 | 单次调用 | 跨会话 |
| 核心问题 | 放什么、怎么排 | 存什么、怎么取 |
| 失败模式 | 噪声淹没指令、超窗 | 召回不准、陈旧事实 |
| 载体 | prompt 拼装 | 向量库/KV/图 |

一个经验比例：固定指令和工具描述占 20%–30%，检索与记忆占 40%–50%，剩余留给对话和输出预算。

## 高频追问

1. **记忆一定要用向量库吗？** —— 不一定，结构化事实（偏好、配置）用 KV 更准更便宜，向量适合模糊语义召回，常常两者混用
2. **记忆冲突怎么办？** —— 带时间戳和来源，新的覆盖旧的，但"用户明确否定过的"要标记为负例而不是简单删除
3. **上下文超了先丢什么？** —— 先丢低相关检索片段和早期寒暄，任务状态和约束最后丢，因为它们决定正确性

## 易错点

- 把两者当同义词——一个是编排，一个是存储，混着答说明没做过长会话 Agent
- 只讲"压缩历史"——压缩只是上下文工程的一个手段，不涉及记忆的持久化和召回
- 记忆只增不删——陈旧事实会污染后续所有对话，必须有衰减和覆盖策略
