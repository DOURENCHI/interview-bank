## 题目

**背景**：RAG 评测要建金标准集，面试官问你怎么保证评测可信。

**问**：Golden Set 怎样构建？忠实度评测的稳定性怎样检查？

## 口述答案

> Golden set：从真实 query 日志分层采样（意图、难度、长度、长尾），标注标准答案和 gold passages，双人标注加仲裁，规模几百到几千，版本化管理并定期换血防污染，留一部分完全 held-out。
> 忠实度稳定性：同一输入在 temperature>0 下多次采样，看判定一致率；换 judge、换 prompt 交叉验证；抽子集人工复核算 Cohen's kappa；固定 judge 版本与 prompt 版本；报置信区间而不是单点。

## 讲深一层

| 稳定性来源 | 检查方式 | 目标 |
|---|---|---|
| 采样随机 | 同输入跑 5 次 | 一致率 > 90% |
| judge 偏差 | 两个不同家族模型 | 结论同向 |
| 人工对齐 | 抽 100–200 条双盲 | kappa > 0.6 |
| 样本波动 | bootstrap | 报 95% CI |

忠实度本身建议拆成原子断言逐条判定，比整体打 1–10 分稳定得多。

## 高频追问

1. **golden set 能让人工全标吗？** —— 大规模不现实，通常是人工标核心集 + 强模型预标 + 人工抽检。
2. **评测集用久了会失效吗？** —— 会，模型和 prompt 都可能间接见过，指标虚高，要定期换血并保留历史版本对比。
3. **一致率多少算合格？** —— 看业务容错，一般 90% 以上才敢用于验收，低于 80% 说明判定标准本身模糊。

## 易错点

- 用模型生成的问题和答案当 golden，等于自己评自己。
- 只跑一次判定就下结论，把采样噪声当效果变化。
- 换了 judge 版本还和旧分数直接比。
