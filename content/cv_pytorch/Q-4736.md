## 题目

**背景**：面试官在问 Agent 的工程实现，先从"模型怎么调工具"切进来。

**问**：模型和工具之间具体怎么交互？工具报错时应该怎么处理？

## 口述答案

> 链路是：把工具 schema（JSON Schema）注入 prompt → 模型输出 tool_call(name, args) → 编排层校验参数 → 执行 → 把结构化结果作为 tool 消息回灌 → 模型决定继续调还是收敛。
> 报错分四类：参数错回灌给模型让它改；超时/限流退避重试；5xx 或连续失败切备用；业务空结果当正常返回，但明确告诉模型"无数据"。
> 关键是写操作必须带幂等键、重试有上限（2–3 次）、错误只回灌摘要而不是整段 stack trace、不可恢复就降级或转人工。

## 讲深一层

| 错误类型 | 处理 | 是否重试 |
|---|---|---|
| 参数校验失败 | 回灌错误字段 | 让模型改，不计入失败预算 |
| 429/超时 | 指数退避 + jitter | 是，≤3 次 |
| 5xx | 切备用实例/模型 | 是 |
| 权限/404 | 直接失败 | 否，重试无意义 |

超时要分层设：单工具 3–10s、单轮总计 30s、整个任务 2–5min，任一层超限都要有确定的收尾动作。

## 高频追问

1. **模型反复调同一个工具怎么办？** —— 用 (tool, args) 哈希去重，连续重复两次就把"已调用过、结果如下"回灌并强制收敛。
2. **错误信息要不要全量给模型？** —— 不要，长 stack trace 会挤占上下文并诱导模型瞎猜，给错误码、原因和可行动建议即可。
3. **工具返回超大结果怎么处理？** —— 先摘要或分页，保留结构化字段，完整结果落到外部存储按 id 引用。

## 易错点

- 无限重试，把一次参数错误放大成几十次调用。
- 写操作不带幂等键，超时重试造成重复下单。
- 把内部异常原文直接展示给用户，泄露实现细节。
