## 题目

**背景**：多 Agent 协作时，面试官关心不同 Agent 的上下文会不会互相污染。

**问**：多 Agent 之间上下文怎么隔离？

## 口述答案

> 原则是默认不共享、按需授权。1. 每个子 Agent 有独立上下文窗口，只拿自己任务的输入，不继承主 Agent 的完整历史。2. 需要共享的状态放外部存储，通过显式读写接口访问，带命名空间和权限。3. 敏感字段引用化，只传 ID 不传明文，需要时再换。4. 存储 key 加 tenant_id 和 session_id 前缀，防串号。5. 日志按 Agent 分开记，便于归因。

## 讲深一层

| 隔离级别 | 手段 | 防的问题 |
|---|---|---|
| 上下文窗口 | 独立 messages | 指令互相干扰 |
| 存储 | 命名空间前缀 | 跨租户串数据 |
| 权限 | 每 Agent 独立凭证 | 越权调工具 |
| 生命周期 | 子 Agent 结束即销毁 | 残留状态泄漏 |

注意：子 Agent 的中间推理不要回灌主上下文，只回传结论和证据，否则主窗口很快被撑爆。

## 高频追问

1. **子 Agent 之间要协作怎么办？** —— 通过共享黑板（显式 KV）交换，而不是互相塞上下文；写入要带来源和版本。
2. **隔离太严会不会导致重复劳动？** —— 会，所以公共检索结果可放只读共享区，写操作仍隔离。
3. **怎么验证没串？** —— 造多租户并发用例，断言 A 的会话查不到 B 的实体。

## 易错点

- 所有子 Agent 共用一份全局 messages，越跑越乱
- 用同一个服务账号调工具，权限无法收敛
- 只做逻辑隔离不做存储隔离，前缀忘了加就串
