## 题目

**背景**：面试官要求挑一个具体任务，把 Agent 从收到输入到产出结果的完整链路讲一遍，考的是有没有真正跑通过端到端，而不是只会说概念。

**问**：选取一个真实问题单，完整描述从 Agent 接收输入、走完全流程、到产出最终结果的整条链路。

## 口述答案

> 我按七段讲。接入层做鉴权和会话绑定，拿到 session_id；输入处理把多模态转成统一文本，做语言识别和敏感内容过滤；上下文组装拼 system prompt、结构化任务状态、检索到的知识和最近几轮原文；规划阶段判断要不要调工具、拆成几步，产出可执行计划；执行阶段逐个调工具，每次调用前做参数 schema 校验和权限检查，带超时和幂等键，结果写回状态；终止判断看目标是否达成、预算是否耗尽；最后结果校验，检查字段完整性和事实一致性，再输出并把副作用落库。全程一个 trace_id，每步的输入输出和耗时都埋点，失败能按 trace 回放。

## 讲深一层

| 阶段 | 关键动作 | 失败时 |
| --- | --- | --- |
| 接入 | 鉴权、限流、session 绑定 | 401/429 快速失败 |
| 上下文 | 状态 + 检索 + 近轮原文 | 超限走压缩 |
| 规划 | 在有界候选集内选工具、拆步 | 降级为单步 |
| 执行 | schema 校验、超时、幂等键 | 重试或标记 missing |
| 校验 | schema + 事实核对 | 转人工或部分返回 |

## 高频追问

1. **trace 必须记什么** —— prompt 版本、模型版本、工具入参出参、token 数、每步耗时；缺任一项就无法复现
2. **在哪一层重试** —— 只在工具执行层重试且仅限幂等调用；规划失败应该重新规划，而不是重放同一个错误计划
3. **怎么防无限循环** —— 总步数、总 token、墙钟三个预算同时卡，任一超限即终止

## 易错点

- 只讲"调模型→调工具→再调模型" —— 缺校验、埋点、终止条件，这是 demo 不是生产链路
- 把规划说成模型自由发挥 —— 生产上必须有候选工具集和步数上限
- 不提副作用落库 —— 工具成功但状态没持久化，重启就丢
