## 题目

**背景**：阿里一面的概念题，表面问「为什么生成不能并行」，实际考你有没有分清「训练的并行」和「推理的串行」到底是机制差异还是工程差异。
**问**：自回归语言模型训练时可以并行计算，为什么生成答案通常还要逐 token 进行？

## 口述答案

> 核心是输入的来源不同。训练时用 teacher forcing：完整序列是给定的训练数据，目标是对每个位置预测下一个 token，位置 i 的输入是数据里的真值前缀，所有位置的输入 simultaneously 已知，互相不依赖，所以一次前向加上因果 mask 就能对全部位置并行算 loss——并行来自「位置间无数据依赖」，不是工程优化。生成时第 t 步的输入里包含第 t-1 步自己采样出来的 token，这个值在上一步结束前根本不存在，是算法层面的串行依赖：没有输入就没法算，只能一步步来。一句话总结：训练是「已知全部输入，并行预测各位置的下一步」；推理是「输入要靠自己的输出喂回来，只能串行」。工程上的 KV Cache 正是对这个串行过程的补偿——每步只算新 token，避免前缀重算；而 speculative decoding 则是打破串行的尝试：小模型先草拟 k 个 token，大模型一次前向并行验证这 k 个，接受的部分直接白拿，把「逐 token 串行」变成「逐块串行」。

## 讲深一层

- 因果 mask 的双重作用：训练时既保证位置 i 只看 ≤i（不偷看答案），又让全部位置共享同一次前向成为合法。
- exposure bias：训练永远喂真值、推理喂自己的采样，误差会累积——这是两模式差异带来的经典副作用。
- prefill/decode 两阶段：prompt 部分输入已知，所以 prefill 能整段并行；逐 token 串行的只是 decode 阶段，首 token 延迟和每 token 延迟要分开谈。
- 并行化的三条路线：speculative decoding（草稿+验证）、非自回归/半自回归生成（牺牲质量换速度）、多路 beam 并行（广度换质量，时间上仍串行）。

## 高频追问

1. teacher forcing 是什么？为什么推理时不用？——训练直接喂真值加速收敛；推理时没有真值可喂，只能用自己上一步的输出
2. 采样是不是必须串行？——采样本身一次只要微秒级，贵的是整次前向；但「下一步输入依赖上一步输出」这个链条决定了必须逐步
3. speculative decoding 为什么能并行验证？——验证 k 个草稿 token 时它们暂时当作已知输入，一次前向并行算 k 个位置的预测，拒绝的回退重试

## 易错点

- 答「训练数据多所以能并行」——并行来自位置间无依赖，跟数据量没关系
- 说「推理慢是因为模型大」——模型大决定每步耗时，串行依赖决定步数，两个维度混为一谈
- 忘了 prefill 是并行的——张口就说「推理全程逐 token」，首 token 延迟那部分直接答错
