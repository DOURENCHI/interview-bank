## 题目

**题目**（华为 AI 笔试）：量化如何与推理实现配合，下面哪一句最准确？
A. INT4 权重量化主要压权重、降显存缩加载时间；部分 GPU 有 INT4 张量核心，但累加精度和生态受限，部署时常先把权重反量化成 FP16/BF16 再算
B. 反量化必须单独一个 kernel，不能和矩阵乘写在一起
C. KV Cache 做低比特后单请求解码不会变快，因为解码算力紧带宽不紧
D. 激活量化到 INT8 主要为省显存；只量化激活也能直接用低精度乘加

## 口述答案

> 选 A。三个干扰项各错一个关键点：B 恰恰说反了——把反量化（dequant）融合进矩阵乘 kernel 是主流做法（如 Marlin/AWQ 的 fused kernel），单独跑一遍 dequant 反而多一次全量访存；C 错在瓶颈判断——Decode 阶段每生成一个 token 都要把权重和 KV Cache 完整读一遍，是**带宽密集**，KV Cache 降到低比特直接省访存，单请求解码也会变快；D 错在目的与条件——激活量化到 INT8 主要为配合权重走低精度乘加管线，只量化激活、权重还是 FP16 的话计算前还得转回高精度，加速落空。A 的表述最贴工程现实：INT4 先救显存与加载，计算侧视硬件支持反量化到 BF16/FP16。

## 讲深一层

| 量化对象 | 收益 | 代价 |
|---|---|---|
| 权重 INT4 | 显存/加载 | 需反量化或专用核 |
| KV Cache INT8/FP8 | Decode 带宽，长上下文收益大 | 精度需校准 |
| 激活 INT8 | 配合 W8A8 走整数管线 | 需校准 + 反量化 |

## 高频追问

1. W4A16 是什么？——权重 4bit 存储、计算时反量化到 16bit
2. 为什么 Decode 是带宽密集？——每 token 都全量读权重/KV，算术强度低

## 易错点

- 被选项 C 带偏：Decode 恰恰是带宽敏感，KV 低比特直接受益
- 认为反量化必须独立 kernel——融合才是主流
