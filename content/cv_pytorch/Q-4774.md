## 题目

**背景**：快手 Agent 岗的解码层工程题（该帖实为专栏引流帖，题目本身完整成立）。考点是把「约束解码」从名词落到机制：怎么在每一步采样时把输出空间焊死到合法片段 ID 上，以及清醒认识约束能消除哪类幻觉、消除不了哪类——能分清「合法性」和「正确性」两层的才是真懂。
**问**：让模型只能从返回过的片段 ID 中挑一个，约束解码怎么做到？这样能消除引用幻觉吗？

## 口述答案

> 先讲机制。生成是逐 token 的：模型每步输出一个词表上的概率分布，采样一个 token。「约束」就是在每步 softmax 之前，把 logits 里不属于合法 token 的位置置成负无穷再归一化——非法 token 概率恒为零，任何解码策略（greedy/采样/beam）都逃不出去。实现上最贴这个场景的是 trie 约束：把所有合法片段 ID 拼成一颗前缀树，生成到 ID 的第 i 个字符时，只放行 trie 当前节点的子边对应的字符，ID 生成完自然闭合。另一条路线是 FSM 约束（outlines、guidance 这类库）：把「必须输出 cite[<id>]」这类输出格式编译成状态机，状态机当前状态决定每步合法 token 集；JSON schema 约束（GBNF 语法）同源，都是把「输出语法」形式化后逐 token 放行。
> 再说能消除什么。能消除的是「引用非法」这一类：编造不存在的 ID、引用了没返回的片段、格式坏掉——因为非法 token 在解码层根本出不来，这是硬保证。消除不了的是「选错引用」：模型仍然可能从合法集合里挑一个语义不对应的片段——字幕说杯子的片段被安到画面演示上，张冠李戴照样合法通过。约束只管合法性，不管正确性。
> 所以完整方案是软硬结合：解码期约束格式与 ID 合法性（硬保证），生成后做引用一致性校验兜底——把被引片段回填、用 NLI 或相似度打分验证「引用是否支持正文这句话」，不通过就重试或降级为不引用。引用幻觉的另一半还得靠检索质量本身：检索都引错了，解码层怎么约束都救不回来。

## 讲深一层

- 掩码的位置：在 softmax 之前作用到 logits，所以 temperature、top-p 只在合法集合内部起作用——「先约束后采样」的顺序是机制层的关键认知。
- trie 约束的开销：每步查 trie 是 O(1)~O(串长)，几十上百个候选 ID 完全无感；工程上真正要小心的是约束过强导致分布变形——模型想输出「无引用」却被逼着硬挑一个，正文质量反而下降，所以合法集里要留 EOS/「不引用」分支。
- 与 tool calling 的 JSON schema 约束同源：结构化输出保证的是「语法可解析」，字段取值正确性依然要运行时校验——两层分开是所有结构化 LLM 输出的通用设计。
- 评测衔接：引用命中率（引用的片段是否支持该句）+ 引用覆盖率（该引的是否都引了），对照本帖 Q-0694 的检索评估指标，把「检索对不对」和「引用对不对」拆开测。

## 高频追问

1. 约束解码和 temperature 谁先谁后？——先掩码后采样，温度只在合法 token 内部分布上起作用
2. 模型就是不想引用怎么办？——合法集里留「不引用」分支（trie 加终止边），别逼它硬选
3. 引用 ID 对但内容不支持正文怎么办？——约束管不到，生成后 NLI/相似度校验 + 重试，或把片段内容直接内联进 prompt 减少间接引用
4. trie 和 FSM 约束什么关系？——FSM 是通用框架（正则/上下文无关语法都能编译成状态机），trie 是「有限字符串集合」这个特例的高效实现

## 易错点

- 答「prompt 里写清楚要求就行」——prompt 是软约束，模型照样编 ID；解码层掩码才是硬保证
- 答「约束解码消除幻觉」——只消除非法引用，「合法但选错」它管不了，两层必须分开答
- 说不出任何实现载体（trie/FSM/GBNF）——只停留在「限制输出」这个动词层，等于没答
