## 口述答案

这题先给结论：四大开源 VLA 没有全能架构，只有匹配任务。π0.5 走「预训练离散 token + 后训流匹配」的分层路线，GR00T N1.7 走双系统松耦合，WALL-OSS 走 MoT 全 token 联合注意力的紧耦合，LingBot-VLA 走 MoE 动作专家加双蒸馏——四种思路正好铺开一张 2026 年的开源 VLA 地图。

π0.5（Physical Intelligence，2025-09）：2.6B 的 Gemma 加 SigLIP 视觉，再加 0.3B Action Expert；预训练阶段用离散 token、不挂动作 expert 所以快，后训再挂 flow matching，high/low-level 分层，机械臂经典任务最稳。GR00T N1.7（英伟达，2026-02）：双系统——System2 的 VLM 每次观测只推一次、取中间层特征，经 cross-attention 松耦合喂给 System1 的 1.09B DiT 做 4 步去噪出动作；四家里推理最快；动作用相对末端位置表示，人手数据和机器人数据共用一套表示。

WALL-OSS 0.5（自变量，2026-05，4.16B）：MoT 架构，VL 专家 2.78B 和动作专家 0.4B 各有 FFN/QKV，但全 token 联合注意力，紧耦合所以最慢、也最「懂」；三个损失一起上——RVQ 离散动作 token 交叉熵当智商桥、多模态交叉熵当泛化锚、flow matching 出动作；官方只支持末端位姿，控关节要自己做 URDF 正运动学转换。LingBot-VLA 2.0（蚂蚁灵波，2026-07，6B）：千问3-VL 4B 当理解专家，动作专家是 MoE——1 个共享专家加 32 路由选 4，为的是覆盖 20 多种本体；动作统一成 55 维向量；双蒸馏用 LingBot-Depth 深度特征 L1 加视频表征特征 MSE，当前帧对齐深度、未来帧对齐视频特征；6B 最慢，要量化或 torch.compile。

选型按本体和任务对号：人形优先 GR00T，人形数据最厚——数据金字塔是 2500h 人类视频、1700h 仿真合成（几十条演示扩成 54 万条）、8376h 真机，另有 2 万小时 EgoDex 人手视频，无标签部分用隐动作模型编伪本体；双臂加底盘看 WALL-OSS；要覆盖多本体选 LingBot-VLA；机械臂经典任务选 π0.5。

**松耦合赢在快，紧耦合赢在懂——没有全能架构，只有匹配任务。**

## 讲深一层

| 维度 | 要点 | 展开 |
|---|---|---|
| π0.5-构成 | 2.6B Gemma + SigLIP + 0.3B Action Expert | Physical Intelligence，2025-09 |
| π0.5-训练 | 预训练离散 token（不挂 expert，快）→ 后训挂 flow matching | high/low-level 分层 |
| π0.5-适配 | 机械臂经典任务稳 | 选型默认项 |
| GR00T-架构 | System2 VLM 每观测只推一次，中间层特征 cross-attention 松耦合 | System1 DiT 1.09B、4 步去噪 |
| GR00T-速度 | 四模型推理最快 | 松耦合的直接红利 |
| GR00T-动作 | 相对末端位置 | 人手/机器人数据共用表示 |
| GR00T-数据 | 2500h 人类视频 / 1700h 仿真合成 / 8376h 真机 | 几十条演示 → 54 万条合成 |
| GR00T-伪本体 | 无标签人手视频用隐动作模型编伪本体 | EgoDex 2 万 h 人手视频 |
| WALL-架构 | MoT：VL 专家 2.78B + 动作专家 0.4B，各有 FFN/QKV | 全 token 联合注意力，紧耦合、最慢 |
| WALL-损失 | RVQ 离散动作 token CE + 多模态 CE + flow matching | 智商桥 + 泛化锚 + 动作头 |
| WALL-接口 | 官方只支持末端位姿 | 控关节需 URDF 正运动学转换 |
| LingBot-构成 | 千问3-VL 4B 理解专家 + 动作专家 MoE | 蚂蚁灵波，2026-07，6B |
| LingBot-MoE | 1 共享 + 32 路由选 4 | 为覆盖 20+ 本体 |
| LingBot-动作 | 统一 55 维动作向量 | 跨本体统一接口 |
| LingBot-蒸馏 | LingBot-Depth 深度特征 L1 + 视频表征特征 MSE | 当前帧对齐深度、未来帧对齐视频特征（JEPA） |
| LingBot-部署 | 6B 最慢 | 需量化 / torch.compile |
| 选型口诀 | 人形 GR00T、双臂+底盘 WALL-OSS、多本体 LingBot、机械臂经典任务 π0.5 | 按本体与任务对号 |
| 时间线 | 2025-09 → 2026-02 → 2026-05 → 2026-07 | π0.5 → GR00T N1.7 → WALL-OSS 0.5 → LingBot-VLA 2.0 |
| 参数量 | 2.6B+0.3B / 1.09B / 4.16B / 6B | π0.5 / GR00T System1 / WALL / LingBot |
| 耦合谱系 | 松 ↔ 紧 | GR00T cross-attention 松耦合 ↔ WALL 全 token 联合注意力紧耦合 |
| 速度序 | GR00T 最快 | WALL 紧耦合最慢；LingBot 6B 需量化/torch.compile |

**耦合谱系**：GR00T 松耦合赢在快，WALL-OSS 紧耦合赢在懂——快和「懂任务」是一对权衡；π0.5、LingBot 在谱系中间各取所需。

**面试速记**：π0.5 = 2.6B+0.3B 分层；GR00T = 双系统+4 步去噪+最快；WALL = 全 token 联合+三损失；LingBot = MoE 32 选 4+55 维+双蒸馏。

**时间线记忆**：π0.5（2025-09）→ GR00T N1.7（2026-02）→ WALL-OSS 0.5（2026-05）→ LingBot-VLA 2.0（2026-07），开源 VLA 半年一代。

**GR00T 数据金字塔**：2500h 人类视频 + 1700h 仿真合成（几十条演示扩到 54 万条）+ 8376h 真机，另有 EgoDex 2 万 h 人手视频托底——人形选它的根本原因。

**WALL 三损失的分工**：RVQ 离散动作 token CE 让 VL 主干「懂动作」（智商桥），多模态 CE 锚住泛化，flow matching 出连续动作——三个头各管一件事。

**LingBot 双蒸馏的两个对齐**：当前帧对齐 LingBot-Depth 深度特征（L1）、未来帧对齐视频表征特征（MSE）——预测特征不预测画面，JEPA 思想。

**面试口径**：报架构带「发布方+时间+参数量」，报选型带「本体+任务」，两组信息交叉才显得真懂。

## 高频追问

1. **双系统为什么 System2 可以只推一次？** —— System2 管「看懂」：场景语义在一次观测内变化慢，不必每个动作步重算；它把中间层特征交给 cross-attention，System1 的 DiT 在执行期连续去噪出动作——理解慢速更新、执行高频输出，各司其职所以整体最快。
2. **MoE 动作专家为什么要 32 路由？** —— LingBot-VLA 要同时服务 20 多种本体，各本体动作分布差异大；1 个共享专家保通用能力，32 路由选 4 让不同本体激活不同专家子集，路由容量吃下本体差异。
3. **「预测特征不预测画面」省在哪？** —— 双蒸馏对齐的是深度特征与视频表征特征（当前帧对深度、未来帧对视频特征），不重建像素；特征空间比像素空间紧凑，监督直指「懂场景、会预判」——JEPA 的核心思想。
4. **WALL-OSS 只支持末端位姿是硬伤吗？** —— 末端位姿覆盖多数抓放任务；要控关节就自己做 URDF 正运动学转换，多一步工程，不是不能用。
5. **GR00T 为什么敢用相对末端位置做动作表示？** —— 这个表示让人手数据与机器人数据共用一套接口，2 万小时 EgoDex 人手视频才能直接进训练，配上隐动作模型给无标签视频编伪本体，数据金字塔才做得厚。

## 易错点

- **用参数量排座次**：6B 的 LingBot-VLA 最慢要量化、4.16B 的 WALL-OSS 紧耦合最慢——先看推理速度与任务匹配，再看参数量。
- **把 GR00T 的快当全能**：松耦合赢在快，理解深度不如紧耦合，选它主要为人形数据生态。
- **忽略动作表示差异**：GR00T 相对末端位置、WALL-OSS 官方仅末端位姿、LingBot 55 维统一向量——接硬件前先对表示。
- **把 WALL-OSS 当开箱即用**：控关节要自己加 URDF 正运动学转换，官方只给末端位姿。
