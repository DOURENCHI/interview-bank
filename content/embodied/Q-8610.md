## 口述答案

先建立概念：VLA 每次推理输出的不是单步动作，而是一个动作块——未来 N 步。默认有两种跑法：要么执行完一整块再推理下一块（同步部署，成功率 53%），要么推理和执行异步、新块算完直接拼上去（默认衔接，76%）。

抖动出在第二种：异步之下新旧两块各算各的，新块的起点不等于旧块的终点，接缝处位置跳变、速度不连续，机械臂就「咯噔」一下——病灶在衔接，不在模型。

解法是 RTC（实时动作分块）：执行旧块剩余步的同时提前请求新块，并且让新块的生成以旧块的未来若干步为条件——新块从旧块的延续处自然长出来，接缝在生成时就被消化，衔接 20 步时成功率 93%，对照同步 53%、直接拼接 76%。

块长也是工程变量：π0.5 默认动作块 50 步，博主实测改成 20 步更顺——块越长越省推理次数但计划越僵，块越短越灵活但推理越频繁、接缝越多。

**抖动不是模型不行，是两段轨迹没对齐——让新块看见旧块的未来，它就知道怎么接。**

## 讲深一层

|---|---|---|
| 动作块 | 一次推理输出未来 N 步 | VLA 的执行单位是块，不是单步 |
| 部署-同步 | 执行完一块再推理下一块 | 53%，执行在等推理 |
| 部署-拼接 | 异步推理、新块直接拼接 | 76%，接缝处轨迹跳变 |
| 抖动根因 | 新块起点 ≠ 旧块终点 | 速度不连续，表现为动作抖动 |
| RTC-调度 | 执行旧块剩余步时提前请求新块 | 推理与执行重叠，消灭空窗 |
| RTC-条件 | 新块生成以旧块未来若干步为条件 | 生成即衔接，无需事后平滑 |
| RTC-效果 | 衔接 20 步 → 93% | 同步 53% / 拼接 76% 同口径对照 |
| 块长默认 | π0.5 默认动作块 50 步 | 博主实测改 20 步更顺 |
| 块长权衡 | 长=省推理，短=灵活 | 越长计划越僵，越短推理越频、接缝越多 |
| 调参入口 | 衔接步数 | 20 步是实测甜点 |
| 问题定性 | 工程问题非模型问题 | 换更强模型不解决轨迹跳变 |
| 与微调的关系 | 部署与权重各自独立加分 | 同素材 Q-8609：微调提上限，RTC 提衔接 |
| 三档对照 | 同步 53% / 默认衔接 76% / 衔接 20 步 93% | 差距全在衔接质量 |
| 术语 | RTC = 实时动作分块 | 部署侧推理调度技术 |
| 适用范围 | 动作块类 VLA 通用 | 不绑定 π0.5 一家 |
| 评测口径 | 每设置真机 40 次 | 与 Q-8609 同一实验体系 |
| 部署演进 | 干等 → 硬接 → 先看后接 | 同步/拼接/RTC 的递进关系 |
| 名词拆解 | 动作块与衔接步数 | 块=一次推理的未来 N 步；衔接步数=新块条件里的旧块未来步数 |
| 对比记忆 | 三档约 40 点差距 | 53% → 76% → 93%，逐档抬升 |

**机制一句话**：同步是「干等」，拼接是「硬接」，RTC 是「先看后接」——旧块的未来进了新块的生成条件，接缝在生成阶段就被消化。

**排查顺序**：先录关节轨迹，看跳变是否集中在动作块边界——集中在边界是衔接问题，上 RTC；全程随机抖先查控制与标定。

**三档递进**：同步 53%（执行等推理）→ 拼接 76%（去掉空窗、留下接缝）→ RTC 93%（生成时对齐接缝）——每一步解决上一档的一个病灶。

**为什么拼接有 76%**：异步让推理和执行重叠，多数时间新旧块偏差不大，所以比同步高；但接缝跳变仍在，到不了 93%。

**块长二次权衡**：50 步块推理少、计划僵；20 步块推理频繁但贴合实时状态——博主实测 20 步更顺，默认值不是最优。

**面试口径**：先讲根因（新块起点≠旧块终点、速度不连续），再讲机制（以旧块未来步为条件），最后报三档数字。

**记忆锚点**：**推理别等、拼接别硬、新块要看旧块的未来。**

## 高频追问

1. **为什么「以旧块未来步为条件」能消除跳变？** —— 跳变的本质是新旧轨迹在接缝处位置和速度不连续；把旧块的未来若干步放进新块的生成条件后，新块的起点与速度剖面天然从旧块延续，接缝在生成时对齐，不需要事后滤波。
2. **动作块长短怎么权衡？** —— 块长省推理次数但计划僵、环境变了反应慢；块短灵活但推理频繁、接缝更多；π0.5 默认 50 步实测不如 20 步顺，默认值不是最优。
3. **同步部署 53% 差在哪？** —— 每块之间有一段「执行等推理」的空窗，动作流断续、动态时机也错过；异步拼接去掉空窗到 76%，RTC 再把接缝做顺到 93%。
4. **上 RTC 要改模型权重吗？** —— 不用，改的是推理调度和条件构造：新块推理时把旧块未来步拼进条件序列，属于纯部署侧工程。
5. **怎么定位抖动是不是接缝问题？** —— 看跳变点的位置分布：集中在动作块边界=衔接问题，上 RTC；全程随机抖=先查控制、标定与机械问题。

## 易错点

- **把抖动归咎于模型**：根因多是异步新旧块轨迹跳变，先查衔接再怀疑权重。
- **以为异步就万事大吉**：直接拼接只有 76%，接缝跳变还在，条件化衔接才有 93%。
- **迷信默认块长**：π0.5 默认 50 步不是最优，实测 20 步更顺。
- **用事后滤波硬抹抖动**：平滑引入滞后，RTC 在生成时对齐才是正解。
