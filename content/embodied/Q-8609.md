## 口述答案

这题的底座是 Dream Machines 在双臂插执行器任务上做的系统消融：21 小时真机数据，每个设置都在真机跑 40 次，把 VLA 微调里「想当然」的经验逐条验证，得到六条反直觉铁律。面试先报实验规模——结论的分量全在「每设置 40 次真机」这条纪律上。

第一条讲起点：只用 Gemma 语言骨干直接微调，成功率 0%——必须从 π0.5 权重出发，不能从语言骨干冷启，具身能力的大头在预训练里已经长好。第二条讲训练方式：全参微调 76%，LoRA 只有 52.5%，掉 23~43 个点——和 LLM 生态「LoRA 就够」的直觉相反，具身必须全参。

第三条讲何时停：3 万步基本到顶；更要命的是验证集 loss 与真机成功率完全无关，loss 好看的 checkpoint 未必能干活。第四条讲超参：学习率 5e-5、batch 256 都不敏感，超参不是瓶颈，预算该花在数据上。

第五、六条讲数据：场景多样性大于数据量，4 小时单场景 33%，换 5 个场景 63%；纯堆时长边际递减，4h/10h/21h 对应 63%/64%/76%；但在 21h 之上再加 1 小时「慢而稳」的高质量数据直接到 90%，换成 1 小时数据加 240 次人工干预（快出错时人接管）到 88%，都远超 21 小时被动采集的 76%。

**验证集 loss 会骗人，真机不会——挑 checkpoint 的唯一办法是让它多插几次。**

| 训练方式 | 必须全参 | 全参 76% vs LoRA 52.5%，掉 23~43 个点，与传统 LLM 相反 |
| 训练步数 | 3 万步到顶 | 继续训练收益趋零，按固定预算训完即可 |

| 干预价值 | 接管聚焦「快出错」状态 | 失败边缘样本是被动采集最缺的一类 |

**数据账**：4h 63% → 10h 64% → 21h 76%，纯堆时长越来越不值钱；同样加 1 小时，「慢而稳」到 90%、人工干预到 88%——数据的「质」和「覆盖失败边缘」比「量」值钱。

**和 LLM 的对照**：LLM 微调面对的是 token 分布的小偏移，LoRA 低秩适配够用；VLA 要重塑「感知→连续动作」整条映射，低秩扰动撑不住，「具身必须全参」是实测不是玄学。

**铁律清单**：①不能从语言骨干冷启（0%）；②具身必须全参（76% vs 52.5%）；③3 万步到顶、loss 挑不了 checkpoint；④lr 5e-5、batch 256 不敏感；⑤场景多样性>数据量；⑥1h「慢而稳」或人工干预胜过被动堆时长。

**递减曲线**：4h 63% → 10h 64% → 21h 76%，被动采集越往后越贵；对照 1h 慢而稳 +14 点、1h 干预 +12 点。

**部署三档**：同步 53% / 默认衔接 76% / RTC 衔接 20 步 93%——同一权重的差距全在衔接，机制见 Q-8610。

**实验纪律**：双臂插执行器、21h 数据、每设置真机跑 40 次——引用数字时把这套条件一起报，可信度才立得住。

**复习钩子**：0% → 52.5% → 76% → 88% → 90%，五个数字串起「权重、训练方式、数据量、干预、质量」五级阶梯。

## 高频追问

1. **为什么 LLM 的 LoRA 经验搬到具身会失效？** —— LLM 下游任务与预训练同为 token 分布的小偏移，低秩适配够用；VLA 要改的是连续动作输出的整条映射，实测 LoRA 52.5% 对全参 76%，掉 23~43 个点，必须全参。
2. **「慢而稳」数据好在哪？** —— 同样 1 小时，慢速、稳定、少失败的轨迹正样本密度高、毛刺少，叠在 21h 上把 76% 拉到 90%，比再堆 11 小时被动采集管用。
3. **人工干预数据为什么这么值钱？** —— 接管恰好发生在「快出错」的状态上，正是被动采集里最稀缺的失败边缘分布；1h 数据加 240 次干预到 88%，超过 21h 被动采集的 76%。
4. **loss 不可信，训练过程还怎么监控？** —— loss 只确认「在学」，不挑「哪个最好」；3 万步到顶后把候选 checkpoint 全部上真机，每设置 40 次再选。
5. **超参不敏感，微调的发力点在哪？** —— 三处：初始权重（必须 π0.5）、数据构成（场景多样性、慢而稳、人工干预）、部署衔接（RTC 动作分块），每一处都是十几个点的差距。

## 易错点

- **上 LoRA 省显存**：LLM 的好经验在具身是坑，52.5% 对 76%，掉 23~43 个点，微调必须全参。
- **盯验证集 loss 挑 checkpoint**：loss 与真机成功率完全无关，唯一办法是真机多跑几次。
- **只堆单场景时长**：4h 单场景 33% 不如 5 场景 63%，先扩场景再加时长。
- **忽视部署衔接**：同一模型同步部署只有 53%，RTC 衔接 20 步到 93%，部署不是「能跑就行」。
