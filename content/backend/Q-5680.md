## 题目

**场景**：滴滴一面注解链的收口题（题单第 21 题，OCR 提取残缺，题面按原图核对复原）。紧跟「注入注解、最常用注解」之后，考 Spring MVC 最日常的注解选择，答完要能接住「返回字符串为什么不需要 @ResponseBody」的追问。

**问**：@Controller 和 @RestController 有什么区别？

## 口述答案

> 一句话：**@RestController = @Controller + @ResponseBody**——源码上它就是被这两个注解元标注的组合注解。
>
> 行为差异在**返回值的解释方式**：@Controller 的方法返回值默认被 **ViewResolver 解析为视图名**（跳转 JSP/Thymeleaf 页面），要返回 JSON 得在方法上额外加 @ResponseBody；@RestController 把 @ResponseBody 提到类级，**所有方法的返回值一律走 HttpMessageConverter 序列化**（Jackson 转 JSON），直接写进响应体。所以前后端分离项目统一用 @RestController，传统服务端渲染页面才用 @Controller。
>
> 两个注解都能被组件扫描发现（都元标注了 @Component），注册成 Bean、接收请求的能力完全一样——差别只在返回值处理，不影响「是不是 Controller」这个身份。还有一个常见角落：@RestController 下某方法偏偏要返回视图/做重定向，用 `ModelAndView` 或 `RedirectView` 返回类型即可绕开统一序列化。

## 讲深一层

```java
// Spring 源码：组合注解的真相
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Controller          // ← 身份：可被扫描注册
@ResponseBody        // ← 行为：返回值写响应体
public @interface RestController { ... }
```

| 维度 | @Controller | @RestController |
|---|---|---|
| 注册为 Bean | ✓ | ✓（元标注 @Component） |
| 默认返回值语义 | 视图名 → ViewResolver | JSON/文本 → MessageConverter |
| 返回 JSON | 方法上加 @ResponseBody | 开箱即用 |
| 典型场景 | 服务端渲染、页面跳转 | 前后端分离 API |

**判断技巧**：组合注解题的万能答法「A = B + C，行为差异在 C」——同类还有 @Configuration vs @Component、@Service vs @Component，都是「元标注 + 增强语义」的结构。**记忆锚点**：「@RestController 是 @Controller 的『全 JSON 模式』开关」。

## 高频追问

1. **@Controller 方法想返回 JSON 怎么办？** —— 方法级加 @ResponseBody；两者可共存——页面方法返回 String，数据方法带 @ResponseBody 返回对象。
2. **@RestController 怎么统一异常格式？** —— @RestControllerAdvice + @ExceptionHandler 全局拦截，把异常转成统一 Response 结构；它是 @ControllerAdvice + @ResponseBody 的组合。
3. **自定义注解能这样组合吗？** —— 可以：元标注 @Component + 自定义语义即可被扫描；Spring 的条件注解、事务注解都支持元标注传递（AnnotatedElementUtils 处理）。

## 易错点

- 说「@RestController 更高级所以都用它」——服务端渲染场景它会把视图名直接当字符串吐出去，选型要跟架构走。
- 不知道它是组合注解——答不出「= @Controller + @ResponseBody」就等于没看过源码层。
- 混淆 @ResponseBody 和 @RestControllerAdvice——前者管单个方法返回体，后者是全局异常/增强切面。
