## 题目

**背景**：面试官从向量检索转到关键词检索，问一个基础概念，考的是能不能把数据结构讲清楚而不是背名词。

**问**：倒排索引为什么叫倒排索引？你了解过它的原理吗？

## 口述答案

> 正向索引是"文档到词"，给你一个 doc_id，能查到它包含哪些词；倒排把关系翻过来，变成"词到文档"，一个词对应一串包含它的文档，这串就叫 posting list。叫"倒排"就是相对正向映射的反向。posting list 里不只有 doc_id，还存词频和位置，位置用于短语查询和邻近查询。工程上 doc_id 按升序存，用 delta 编码加 varint 压缩，再叠跳跃表或 Roaring Bitmap 加速多词求交。查 "A and B" 就是拿两个 posting list 归并求交，代价和较短的那个长度相关，不是扫全库。

## 讲深一层

```
"搜索" -> [(doc3, tf=2, pos=[5,18]), (doc17, tf=1, pos=[42]), ...]
doc_id 序列 3,17,42  delta 编码后是 3,14,25
```

| 优化 | 作用 |
| --- | --- |
| delta + varint | 压缩 doc_id 间距，通常能省一半以上 |
| skip list | 求交时跳跃前进，避免逐条比对 |
| Roaring Bitmap | 交并差用位运算，适合稠密集合 |
| 位置索引 | 支持短语、邻近查询 |

## 高频追问

1. **为什么不用哈希表** —— 哈希只能精确匹配单词，做不了前缀、范围、短语和多词求交
2. **前缀查询怎么支持** —— 词典本身用 FST 或有序结构存，先找前缀对应的 term 集合，再合并 posting list
3. **ES 的 segment 不可变和这个有什么关系** —— 倒排一旦建成改造成本高，所以 Lucene 用不可变 segment 加合并，删除只是标记

## 易错点

- 只说"倒过来存" —— 要讲清正向是什么、倒排存了什么，否则等于循环解释
- 认为 posting list 只有 doc_id —— 缺词频和位置就做不了打分和短语查询
- 把倒排和向量索引混为一谈 —— 一个是词项精确匹配，一个是语义近似
