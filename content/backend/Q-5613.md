## 题目

**背景**：线上告警说队列积压，面试官问你的排查顺序。

**问**：消息积压了，你先看什么？

## 口述答案

> 先判断是生产变多还是消费变慢，这决定后面往哪查。看三个指标：生产速率和消费速率的差值、lag 曲线是突增还是缓慢爬升、单条处理耗时和错误率。突增多半是上游流量上涨或重复投递；缓慢爬升通常是消费端变慢，比如下游 RT 升高、锁竞争、GC。再看分区数够不够、有没有单分区热点。别一上来就加机器，先定位瓶颈在哪一段。

## 讲深一层

追赶时间估算：`T ≈ lag / (消费速率 − 生产速率)`，若消费速率 ≤ 生产速率则永远追不上，必须先限流或扩容。

```bash
kafka-consumer-groups.sh --bootstrap-server x:9092 \
  --describe --group order-group   # 看 LAG / CONSUMER-ID
```

## 高频追问

1. **lag 突增怎么查？** —— 对比上游 QPS 曲线和重试日志，确认是流量还是重复投递。
2. **消费慢怎么定位？** —— 看单条耗时分布、下游依赖 RT、线程池队列长度和 GC 时间。
3. **临时扩容有效吗？** —— 只有分区数 ≥ 消费者数时加机器才有用，否则新实例分不到分区。

## 易错点

- 直接扩容不看瓶颈，消费端慢的时候加机器无效
- 只看总 lag 不看分区分布，掩盖单分区热点
- 忽略重复投递，误判为业务量上涨
