## 题目

**背景**：面试官从技术选型转到落地细节，问 Python + FastAPI 这套栈里数据库怎么接、表结构谁负责，考的是工程分工和基本功。

**问**：项目使用 Python + FastAPI，数据库层如何接入？数据库表是否由你设计？

## 口述答案

> 接入用 SQLAlchemy 2.0 的 async 引擎配 asyncpg，会话通过依赖注入提供，请求结束自动关闭；连接池设 pool_size 和 max_overflow，开 pool_pre_ping 防止拿到已断开的连接；迁移用 Alembic，每次 schema 变更生成版本脚本而不是手改库。模型分两层：ORM 管持久化，Pydantic schema 管出入参，不混用，避免把库字段直接暴露成 API。表设计我负责过核心表，包括主键选型、唯一约束、索引和软删字段；多人协作时我做的是评审和定规范，具体某张表可能由业务同学落。设计上我坚持唯一约束放数据库而不是只靠应用层判断，时间统一存 UTC。

## 讲深一层

| 关注点 | 做法 | 代价 |
| --- | --- | --- |
| 连接池 | pool_size≈并发/worker 数，开 pre_ping | 过大会打爆 DB 的 max_connections |
| N+1 | selectinload 或 joinedload | joinedload 一对多会行膨胀 |
| 迁移 | Alembic autogenerate + 人工复核 | autogenerate 会漏类型变更 |
| 索引 | 按查询模式建复合索引，守最左前缀 | 每个索引都带来写放大 |

## 高频追问

1. **异步下事务怎么写** —— `async with session.begin()`；不要在事务里做 HTTP 调用，长事务会长期占用连接
2. **深分页怎么做** —— 用游标（keyset）而不是大 offset，offset 大了等于全表扫
3. **表结构变更怎么上线** —— 先加可空或带默认值的列，回填后再加约束，避免长时间锁表

## 易错点

- 说"表全是我一个人设计的" —— 追问细节就露馅，讲清职责边界更可信
- 只提 ORM 不提迁移 —— 生产上没有 Alembic 就是事故源头
- pool_size 拍个大数 —— 连接数是 DB 侧硬限制，要按 max_connections 反推
