## 题目

**背景**：字节抖音电商 AI Agent 开发一面的第二问，与上一问的三级架构直接衔接。考点是跨 Agent 边界的信息交接设计——「摘要丢字段」这半问与库内 Q-0839（单 Agent 对话压缩丢哪三类信息）衔接，但本题的重心在「主子 Agent 之间传什么、怎么传、丢了怎么兜底」，是系统设计题不是记忆题。
**问**：主子 Agent 的上下文怎么交接？摘要丢字段怎么办？

## 口述答案

> 交接的核心原则一句话：传「任务契约」，不传「聊天记录」。主 Agent 派发子任务时，给子 Agent 的应该是一份结构化任务单：目标（做什么）、输入事实（已知条件和数据引用）、约束（格式、权限、边界）、完成标准（怎么算做完）。子 Agent 回传的也是结构化结果：结论、依据、未决事项、消耗的预算。两边都是 schema 可校验的对象，不是一段自由文本。
> 为什么不传全文历史：子 Agent 的上下文窗口有限，主 Agent 的全部历史里与该子任务相关的可能不到 10%，剩下的全是稀释注意力的噪音；而且权限隔离要求子 Agent 不该看到其他任务的中间信息。让子 Agent「理解来龙去脉」的代价是精确性和安全性双输。
> 摘要丢字段怎么办，分两层答。先说丢什么：摘要模型天然丢三类信息——精确值（时间、数量、ID 会被模糊化成「大概下午」）、否定与例外（「别用邮件」「周四不行」这类约束最容易被弱化掉）、指代锚点（「第二个」「照旧」被指代的对象被压掉后，后文全部悬空）。再说怎么办：治本的思路是关键信息不走自然语言摘要——执行必需的字段（数值、ID、约束、未决事项）提取成结构化字段随任务单传递，摘要只负责「为什么这么做」的推理脉络；数值、约束、未决事项这三类永远进字段不进摘要。
> 兜底机制：交接接口做 schema 校验，必填字段缺失直接拒绝并要求主 Agent 重发，绝不让子 Agent 带着残缺上下文往下跑；关键值双写（字段里一份、摘要里一份）便于人工审计比对；交接后让子 Agent 先回读任务单确认理解（一句「我的任务是 X，约束是 Y，有误请纠正」），把交接错误拦在执行之前。

## 讲深一层

- 摘要在主 Agent 侧的另一个用途：子任务完成后主 Agent 不收全文结果，只收结论 + 摘要，防止子 Agent 的长输出撑爆主 Agent 的窗口——「进摘要出结构化」是双向的。
- 状态与摘要的分工：对话历史是过程记录、结构化状态是当前事实（Q-0839 的结论），跨 Agent 交接时状态字段的更新必须由明确的工具调用或确认事件触发，防止「消息里改了、状态没改」的撕裂。
- 为什么不用 RAG 式检索代替交接：检索适合「按需查细节」，交接契约适合「定义执行边界」——子 Agent 的任务边界必须显式声明，靠检索隐式发现会导致同任务不同跑法。
- 分布式类比：这就是微服务间传 DTO 而不是传数据库快照——接口窄化、职责隔离、schema 演进，Agent 系统里全部成立。

## 高频追问

1. 子 Agent 中途失败，主 Agent 怎么知道它做到哪了？——要求子 Agent 按检查点上报结构化进度（完成步骤/未决事项），而不是事后靠摘要猜
2. 摘要谁来做？——主 Agent 在派发前自己做（可控、可校验），不要让子 Agent 替你总结任务；结果侧的摘要由子 Agent 出但主 Agent 校验字段完整性
3. 任务单怎么设计才不会被子 Agent 误解？——目标动词明确（生成/检索/判断）、完成标准可判定、约束显式列出否定式；最好带一个最小示例
4. 多个子 Agent 的结果冲突怎么办？——主 Agent 是唯一合并点，冲突时回到任务单的优先级声明，或升级为新的裁决子任务而不是主 Agent 自己拍板

## 易错点

- 把「摘要丢字段」只答成「摘要模型不好」——丢什么（三类信息）和怎么防（结构化字段+schema 校验）才是考点，泛泛说「用更强的模型」是空话
- 主子 Agent 互传全文历史——既爆上下文又泄权限，出现这个设计直接暴露没做过多 Agent 系统
- 漏掉兜底——交接失败要「拒绝并重发」而不是「带着残缺继续」，这半句是生产意识的标志
- 和 Q-0839 的单 Agent 压缩混淆——单 Agent 是「一个窗口内省 token」，跨 Agent 是「跨边界的任务契约」，机制和目的都不同
