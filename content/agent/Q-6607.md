## 题目

**场景**：Agent（含检索、工具调用、生成）迭代频繁，每次换模型、改 prompt、调检索参数，都需要知道"效果是变好还是变坏"。

**问**：怎么量化评估模型回答的效果？

## 口述答案

> 核心思想：**分层评 + 固定基准 + 全自动可回归**。回答质量不是一个分数，是三个层面各管一段：
> ①**检索层**：召回命中率、MRR/nDCG——用标注好的"query→应命中文档"评测集测，检索坏了生成再好也没用；
> ②**生成层**：忠实度（答案是否忠于检索到的证据，有没有编）、相关性、完整性——这三样用 **LLM-as-judge**：给 judge 模型一份明确的评分 rubric（每个分数档的判据写清楚），对回答打分；
> ③**任务层**：端到端任务成功率（Agent 场景=任务是否真的完成，可程序化判定）+ 人工抽检兜底。
>
> 工程闭环三件套：**固定评测集**（真实 query 采样 + 边界 case 人工补充，版本化入库）、**judge 校准**（judge 打分与人工标注的对齐率要定期测，不一致就修 rubric）、**回归门禁**（每次改动跑一遍，关键指标跌了就拦）。
>
> 没有这套，"优化"就是玄学：改了 prompt 觉得变好，换个 query 集又觉得变差。

## 讲深一层

LLM-as-judge 的三个已知偏差与对策：

| 偏差 | 表现 | 对策 |
|---|---|---|
| 位置偏差 | 偏爱先出现的回答 | 成对比较时 A/B 换序各评一次 |
| 长度偏差 | 偏爱长回答 | rubric 明确"长度不加分" |
| 自我偏好 | judge 偏爱同家族模型的输出 | judge 与被评模型异源 |

评测集构造：**从生产真实 query 分层采样**（高频/长尾/失败 case 各占一定比例），标准答案写成"要点清单"而非范文（judge 按要点覆盖打分，避免风格偏好）。边界 case（约束冲突、检索为空、恶意输入）单列一档，回归时必过。

**判断技巧**：面试官在探"你有没有被 LLM 评测的不确定性坑过"——主动讲 judge 校准和偏差，比报一堆指标名更能证明做过。

**记忆锚点**：「**检索、生成、任务三层各打各的分；judge 也要考试（与人工对齐）**」。

## 高频追问

1. **没有标注预算怎么办？** —— 生产 query 抽样 + judge 全量初筛 + 人工只复核 judge 打的低分和分歧样本（主动学习思路），标注量降一个数量级。
2. **judge 和被评模型同源有什么风险？** —— 自我偏好 + 同样的知识盲区：judge 看不出被评模型编的错。用异源模型，且抽检比例不设为零。
3. **线上怎么持续评估？** —— 在线指标（用户点踩率/采纳率/重试率/会话中断率）+ 采样回流评测集，形成"线上发现→离线复现→修复→回归"的环。

## 易错点

- 只评生成不评检索：检索层退化时生成层的分数波动会误导归因。
- judge 无 rubric 直接问"这个回答好不好"：打分随机性大，版本间不可比。
- 评测集一成不变：逐渐被迭代"过拟合"，要定期注入新的真实 query。
