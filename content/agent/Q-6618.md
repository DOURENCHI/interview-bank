## 题目

**背景**：字节火山引擎后端一面的 eino 深入题，紧跟「讲讲 eino 框架」而来。Chain 与 Graph 是 eino 两种编排范式的对照，考的是控制流表达力这个编译器级别的直觉：线性管道 vs 有向图（可分支可循环）。它同时是通用考点——这个分野在 Python 生态同样存在（LangChain 的 LCEL chain vs LangGraph），答好一题等于证明你理解所有 LLM 编排框架的骨架。
**问**：chain 和 graph 范式的区别？你们用的是什么？

## 口述答案

> 先把范式定位讲清：Chain 和 Graph 的区别本质是**控制流的表达力**。Chain 是线性管道——A→B→C 固定顺序执行，一次输入从头流到尾，没有分支没有回头路；Graph 是有向图——节点间连线可以带条件分支（根据上一步输出走不同边）、可以成环（流程回到之前的节点重复执行），控制流在运行时由数据决定。
> 对应到适用场景，用一句话概括：**流程确定用 Chain，流程需要模型决策用 Graph**。典型 Chain 场景：标准 RAG 链（检索→组装模板→生成→解析），步骤固定、无决策点，Chain 代码直白、类型好推、调试容易；典型 Graph 场景：ReAct 型 Agent（模型→工具调用→观察→回到模型，直到模型决定结束），这个「回到」就是环——Chain 表达不了循环，硬写只能外层手写 for 循环，把编排逻辑漏到框架外面，失去类型检查与统一回调埋点。
> Graph 的两个关键机制要点出来：条件分支（branch，edge 上挂判断函数按输出选下一跳）和状态传递（跨节点的共享状态，循环多轮时累积上下文）。代价是复杂度——图比链难调试、难画、并发路径要做状态合并，所以工程上的选型原则是**能 Chain 不 Graph**：先问「流程里有没有模型决定的分叉/循环」，没有就别上图。
> 「你们用的是什么」收尾给判断过程：我们的主流程是标准 RAG 问答，用 Chain；Agent 式的多工具协作子流程用 Graph 建环；两者在 eino 里可以互相嵌套（Graph 的一个节点内部是一条 Chain）。补一句通用性：这个分野不是 eino 独有，LangGraph 相对 LangChain 的出现就是为了补循环与分支——说明这是 LLM 编排的共性问题。

## 讲深一层

- 为什么 Agent 必须要环：ReAct 的终止条件是**模型运行时决定**的（「我认为信息够了，直接回答」），静态管道没有退出点；环+条件边让「再想一轮还是结束」成为图的一部分，编排框架才能统一管到终止、超时与预算（与库内 Q-6615 约束实施呼应）。
- Chain 的隐藏优势是**静态可分析**：整条链拓扑编译期固定，可以推导每段的输入输出类型、做端到端耗时预估、失败重试粒度清晰；Graph 运行时才确定路径，观测要靠 trace 还原实际走的边——这是「能 Chain 不 Graph」的工程学依据。
- 嵌套是真实项目的常态：Graph 节点可以是子图/子链，RAG 问答（链）作为 Agent（图）的一个工具节点——不要把范式选择讲成二选一。
- 并发与合并：Graph 里多分支并行执行时，状态合并策略（覆盖/追加/自定义 reducer）是框架必须回答的问题，LangGraph 与 eino 都提供 reducer 机制；能主动提「并行分支怎么合状态」是做过图的强信号。
- 调试友好度差异：Chain 打日志按段就能看；Graph 要靠 callback + trace 把「实际走过的路径」可视化出来——生产排障时图的可观测成本更高，也要讲。

## 高频追问

1. 什么时候必须用 Graph？——控制流由模型输出决定时：工具循环（ReAct）、多方案路由（按意图走不同专家）、带反思的重试（生成→评审→不达标回炉）；全是确定性步骤就别用
2. Graph 的条件分支怎么实现？——边上挂 branch 判断函数，读当前节点输出/状态返回下一跳；具体 API 以 eino 文档为准，概念上等价于 switch 路由
3. 循环怎么防止死循环？——三道闸：最大迭代次数、整体预算（token/时长）、终止条件节点（模型输出结构化的 finish 信号）；框架层兜底+业务层语义终止双保险
4. Chain 能做并行吗？——单条 Chain 是串行的；并行要么用 Graph 的分支，要么在应用层起多个 Chain 并发再合并（eino/Go 的 goroutine 并发做 fan-out 很自然）
5. 这两种范式跟工作流引擎（如 Temporal）的区别？——工作流引擎编排的是**人的业务步骤**（长周期、持久化、补偿），LLM 编排框架编排的是**模型调用链**（秒级、内存态为主）；粒度与生命周期完全不同，大型系统里可能两层并存

## 易错点

- 把区别答成「一个简单一个复杂」——没说到点上；核心是控制流表达力（分支/循环/运行时路由），复杂度只是代价
- 说「我们全用 Graph」——过度设计信号；图的可调试性成本高，确定性流程上链是正确选型，面试官在钓你会不会「能简不繁」
- 不知道 Graph 能嵌 Chain——真实项目全是嵌套的，二选一的回答暴露没做过整合
- 只谈 eino 不谈共性——这个分野在 LangChain/LangGraph 同样成立，能横向类比说明理解的是范式不是某个框架的 API
