## 题目

**背景**：平台要跑用户提交的不可信代码，需要限制它不能吃满宿主机资源。

**问**：用 Docker 做资源隔离和限制时，具体用哪些命令或参数来约束用户代码的 CPU、内存、进程数和权限？

## 口述答案

> 结论：**隔离靠 namespace，限制靠 cgroup，落到 `docker run` 参数**。CPU 用 `--cpus=1.5` 设配额，`--cpu-shares` 是相对权重（只在争抢时生效），`--cpuset-cpus` 绑核。内存用 `--memory=512m` + `--memory-swap=512m` 禁 swap（默认是 2 倍），`--memory-reservation` 软限。进程用 `--pids-limit=128` 防 fork bomb。权限：`--ulimit nofile`、`--read-only` + `--tmpfs`、`--network none`、`--cap-drop ALL`、`--user` 非 root。

## 讲深一层

```bash
docker run --rm \
  --memory=512m --memory-swap=512m --memory-reservation=384m \
  --cpus=1.5 --cpuset-cpus=0-1 \
  --pids-limit=128 --ulimit nofile=256:256 \
  --read-only --tmpfs /tmp:rw,size=64m \
  --network none --cap-drop=ALL \
  --security-opt no-new-privileges --user 1000:1000 \
  runner:latest
```
| 维度 | namespace | cgroup |
|---|---|---|
| 进程/网络/挂载 | pid/net/mnt/uts/ipc | — |
| CPU/内存/IO | — | cpu.max、memory.max、io.max |

## 高频追问

1. **`--cpus` 和 `--cpu-shares` 区别？** —— 前者是硬配额（CFS quota，超了被 throttle），后者是权重，空闲时不限制。
2. **JVM 在容器里内存怎么设？** —— 老版本读不到 cgroup 限制；用 `-XX:MaxRAMPercentage=75` 或升级到容器感知版本。
3. **怎么防容器逃逸？** —— 非 root、drop 全部 capability、seccomp/AppArmor、只读根文件系统、禁 `--privileged`。

## 易错点

- 只设 `--memory` 不设 `--memory-swap`，容器仍可用 2 倍 swap
- 用 `--cpu-shares` 当硬限制，空闲时根本限不住
- 忘了 `--pids-limit`，一个 fork bomb 拖垮整台机器
