## 题目

**背景**：产品同时有端上小模型和云端大模型，面试官问怎么分工。

**问**：端云协同怎么划分职责？什么情况下应该走云端？

## 口述答案

> 结论：按**延迟敏感度、隐私、复杂度、成本**四个维度分。端上负责首 token 快、离线可用、隐私数据不出端，以及简单任务：意图分类、改写、纠错、固定格式抽取、短问答。云端负责长上下文、复杂推理、知识密集问答、工具调用、多模态。路由依据 query 复杂度分类器 + 端上置信度 + 设备状态（电量、温度、网络）+ 用户套餐。常见形态是级联：端上先出，置信度低再升级；或两端竞速。必须有云端失败回退端上的降级路径。

## 讲深一层

| 维度 | 端 | 云 |
|---|---|---|
| 首 token | 10~50ms | 200~800ms |
| 上下文 | 2K~8K | 32K+ |
| 隐私 | 数据不出端 | 需合规 |
| 成本 | 一次性 | 按 token 计费 |
| 离线 | 可用 | 不可用 |

## 高频追问

1. **复杂度分类器怎么做？** —— 轻量模型（小 BERT / 规则 + 长度 + 工具意图），输出"端上可解"的概率，阈值按业务调。
2. **级联会不会重复计费？** —— 会，需要 request_id 贯穿两端，云端命中缓存不重复计费。
3. **怎么评估分工是否合理？** —— 看端上承接率、升级率、端到端 P99、单请求成本，四个指标一起调。

## 易错点

- 把所有请求都送云端，延迟和成本双高
- 端上硬扛长上下文，频繁 OOM
- 没有降级路径，云端一抖全不可用
