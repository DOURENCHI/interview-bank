## 题目

**背景**：线上出现"回答变笨了"的投诉，面试官看排查思路是否有层次。

**问**：用户投诉"回答变笨了"，你怎么定位原因？

## 口述答案

> 结论：**先确认事实，再按"输入—模型—输出"分层归因，最后才怀疑模型本身**。1. 确认范围：全量还是某机型/地域/版本，对比模型 hash、配置版本、prompt 模板版本；2. 看输入：日志里实际的 prompt，上下文是否被截断、RAG 是否召回为空、system prompt 是否被裁剪；3. 看输出：拒答率、平均长度、重复率、工具成功率、首 token 延迟；4. 取 badcase 与旧版本同 prompt 双跑；5. 常见真因是检索退化、上下文被截、安全策略误拦、参数被改。

## 讲深一层

| 层 | 检查项 |
|---|---|
| 输入 | 实际 prompt、token 数、检索命中 |
| 模型 | 版本 hash、量化方式、温度 |
| 输出 | 拒答率、长度、重复率 |
| 人群 | 新老用户、机型、地域 |

```text
时间线对齐：把指标突变点与发版/配置变更/流量活动对齐
```

## 高频追问

1. **怎么快速判断是不是检索的问题？** —— 看检索为空的比例、top-k 相似度分布；把检索结果拼进 prompt 人工看能否回答。
2. **只有新用户投诉怎么解释？** —— 新用户历史短、冷启动特征缺失，个性化退化；分组对比新老用户指标。
3. **怎么避免下次再发生？** —— golden set 回归 + 上线前双跑对比 + 关键指标按小时监控告警。

## 易错点

- 一上来就换模型/重训，掩盖真实原因
- 只看聚合指标，忽略分机型/分人群的差异
- 复现时改了温度或 prompt，对比不成立
