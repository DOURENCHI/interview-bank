## 题目

**场景**：龙芯中科（国产 CPU）Linux 驱动岗面经题。国产化替代背景下，「ARM 上写的代码怎么搬到 LoongArch」考的是工程化迁移与版本管理能力，不是背指令集。

> 原题：LoongArch 平台从 ARM Linux 迁移应用或驱动时，首先要核对哪些架构差异？
> 原题：LoongArch 交叉编译工具链、sysroot、内核头文件和用户态库怎样固定版本？

## 口述答案

> 直答：**先核对「指令集/ABI → 内核 → 工具链」三层差异，再动手搬代码**。①**指令集与 ABI**：LoongArch 是从零设计的指令集，不是 ARM 变体——内联汇编、屏障、原子操作的写法都要换；应用态 ABI 分 lp64d/lp64f/lp64s（双精度/单精度/软浮点），全项目必须统一，浮点 ABI 配错会连不上预编译库；内存模型是弱一致，ARM 上的无锁代码不能想当然平移。②**内核版本与驱动 API**：国产平台内核是厂商维护分支，版本可能落后主线，驱动要按「那个版本」的 API 写，先确认内核版本再定移植策略。③**字节序与数据布局**：LoongArch 为小端，与主流 ARM64 一致，但依赖端序的代码（位段/联合体/网络序转换）要专项过一遍。
>
> 版本固定：**用「一份清单锁死三件套」**——交叉 gcc（用官方发布包＋sha256 校验，不从源码现编）、sysroot（目标根文件系统的头文件＋库，独立打包归档）、内核头文件（`make ARCH=loongarch headers_install` 从内核源码导出，与内核源码 commit 绑定）。三者版本写进一个 manifest（repo manifest/Buildroot 外部树/Yocto layer 均可），CI 从清单拉取构建。**复现性的标准是：同样的清单在任何机器上必然产出同样的产物**——面试官要听的是这个意识，而不是「装个新版」。

## 讲深一层

| 设计点 | 决策 | 为什么 |
|---|---|---|
| 指令集差异 | 先盘点内联汇编/屏障/原子操作清单 | ISA 从零设计，ARM 的屏障与独占访问语义不能平移 |
| ABI 选择 | 全项目统一 lp64d（无特殊约束时） | 混 ABI 的 .so 无法链接；发行版默认也按此分发 |
| 字节序 | 小端，与主流 ARM64 一致 | 依赖端序的代码（位段/联合体/网络序）要专项审 |
| 内核 API | 以厂商内核分支为准写驱动 | 按主线新 API 写，厂商老内核上编不过 |
| 交叉 gcc | 官方发布包＋sha256 校验 | 自编工具链引入不可控差异，还难复现 |
| sysroot | 独立打包、随项目归档 | 直接指向主机 /usr 会混入主机架构的库 |

工具链自检三步（通用命令，路径按项目替换）：

```bash
# 1. 编译目标与 ABI 是否正确
loongarch64-linux-gnu-gcc -print-multi-lib     # 列出 lp64d/lp64s 等 multilib
# 2. sysroot 里库的架构与 ABI 是否对得上
readelf -h "$SYSROOT"/lib/libc.so.6 | grep -E 'Machine|Flags'
# 3. 内核头文件与内核源码同源导出
make ARCH=loongarch headers_install INSTALL_HDR_PATH="$SYSROOT"/usr
```

**记忆锚点**：「**架构查 ABI，内核查版本，工具链查三件套；版本不靠口头约定，靠清单锁死**」。

## 高频追问

1. **ARM 的内联汇编怎么迁？** —— 优先替换成标准原语（内核 smp_mb/atomic、编译器 __atomic 内建），让编译器按架构生成指令；确需手写的才对照 LoongArch 指令逐条翻译，并收进架构隔离层，别散落在业务代码里。
2. **sysroot 从哪来？** —— 两条路：从现成目标板整包拷贝 /usr（快但版本失控）；用 Buildroot/Yocto 自建一套最小根文件系统当 sysroot（推荐，版本可控可归档）。
3. **为什么不能拿内核源码里的 include 直接当用户态头文件？** —— 用户态要的是 headers_install 导出的稳定 ABI 头；源码 include/ 混着内核私有定义，编用户态程序会引入不可移植依赖。
4. **怎么验证迁完是「干净」的？** —— file 看 Machine 与 interpreter、readelf -d 看动态库依赖是否全落在 sysroot、扫一遍内联汇编清单、跑内存序/原子性专项单测。

## 易错点

- 把 LoongArch 当「另一款 ARM」——指令集与内存序语义从零设计，汇编层要重写重验。
- 只改 --host 不换 sysroot——链到主机库，编译过、运行时炸。
- ABI 随手指定——lp64d/lp64s 混用直接链接失败或浮点参数错位。
- 版本「能跑就行」——换机器重编产物不同，问题再也复现不出来。
