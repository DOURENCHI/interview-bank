## 题目

**背景**：端上模型动辄上 G，面试官关心更新包的大小与下发可靠性。

**问**：端上模型更新怎么下发？包大概多大，怎么做增量与回滚？

## 口述答案

> 结论：包 = **量化权重 + 配置 + tokenizer + 版本清单**，1B 参数 INT4 约 0.6GB，3B 约 1.8GB，端上通常控制在 0.5~2GB。下发用 CDN 分片 + 断点续传 + sha256 校验 + 签名验签；增量用 bsdiff/xdelta 或按 tensor 分片只传变更层，通常压到全量 5%~20%。策略：仅 WiFi + 充电 + 闲时下载；A/B 双分区写完原子切换，校验失败自动回滚；按机型地域灰度，服务端保留停推开关。存储预留约 3 倍空间。

## 讲深一层

| 方式 | 体积 | 适用 |
|---|---|---|
| 全量 | 100% | 首次安装 |
| bsdiff | 5~20% | 小改版本 |
| 分片增量 | 按层 | 只换部分权重 |
| 热更新配置 | KB 级 | 参数/开关 |

```text
下载 → 校验 sha256 → 验签 → 解压到 B 分区
     → 自检推理 → 切换指针 → 保留 A 分区待回滚
```

## 高频追问

1. **差分包为什么有时比全量还大？** —— 权重重量化后二进制差异巨大，bsdiff 失效；此时直接发全量更划算。
2. **下载中断怎么办？** —— 分片级断点续传，已完成分片不重下；整体超时后清理临时目录。
3. **怎么保证切换安全？** —— 切换前跑自检向量，输出偏差超阈值就不切；切换后保留旧版本至少一个周期。

## 易错点

- 只校验 md5 不验签，包可被替换
- 边下边覆盖当前模型，中断后无法使用
- 不预留解压空间，更新时磁盘满导致 App 崩溃
