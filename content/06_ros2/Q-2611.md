## 题目

**场景**：一台笔记本跑导航，一台工控机跑感知，网线直连。两边节点各自都能跑，但互相看不到对方的话题。

**问**：ROS2 两台机器要怎么才能通信？有哪些必查项？

## 口述答案

> 前提是**同一个 ROS_DOMAIN_ID、同一网段、多播可达、DDS 实现一致**。
> ROS2 靠 DDS 自动发现，默认走多播。所以第一步查 `ROS_DOMAIN_ID` 是否相同，第二步查两台能不能 ping 通、多播有没有被防火墙或交换机挡住，第三步看 `ROS_LOCALHOST_ONLY` 是不是被设成了 1——设了 1 就只在本机通信。

## 讲深一层

```bash
# 1. 域一致（默认 0）
echo $ROS_DOMAIN_ID

# 2. 是否只在本机
echo $ROS_LOCALHOST_ONLY      # 1 = 只本机，跨机必须为 0 或不设

# 3. 网络可达
ping <另一台IP>

# 4. 多播是否通（关键）
ros2 multicast send      # 另一台执行 ros2 multicast receive

# 5. DDS 实现一致
echo $RMW_IMPLEMENTATION
```

多播不通时的兜底：
```bash
export ROS_STATIC_PEERS="192.168.1.11;192.168.1.12"
# 或起 discovery server
fastdds discovery -i 0 -l 192.168.1.11 -p 11811
export ROS_DISCOVERY_SERVER=192.168.1.11:11811
```

根因排序：`ROS_LOCALHOST_ONLY=1` > `ROS_DOMAIN_ID` 不同 > 防火墙拦多播 > 双网卡走错路由 > DDS 实现混用。

多网卡很容易被忽略：机器同时连 WiFi 和有线时，多播可能从 WiFi 出去，导致发现失败。

## 高频追问

1. **为什么 `ros2 topic list` 一台有一台没有？** —— 发现单向成功的典型表现，查两边的多播路由和防火墙。
2. **domain id 有什么用？** —— 隔离逻辑网络，同一网段多套系统互不干扰；取值范围 0–232。
3. **大消息跨机传不动怎么办？** —— 调 DDS 的 fragment size 或共享内存配置，或改用压缩话题。

## 易错点

- 只 ping 通就认为能通信（多播可能仍然不通）
- 忘了 `ROS_DOMAIN_ID` 必须一致
- 双网卡环境不看多播走哪张网卡
