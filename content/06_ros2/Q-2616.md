## 题目

**场景**：调试时 `ros2 run tf2_tools view_frames` 出来一张树，上面有 `map → odom → base_link → laser` 这样一串。

**问**：TF 到底是什么？为什么不能直接把激光点从 `laser` 换到 `map`，非要经过中间几层？

## 口述答案

> TF 是一棵**坐标系变换树**，每个节点是一个坐标系，每条边是一个带时间戳的位姿（平移加四元数）。它回答的问题是：**在某一时刻，A 坐标系里的点，在 B 坐标系里是多少**。
> 必须经过中间层是因为 TF 的约束：**每个坐标系只能有一个父节点**，查询时只能沿树走。所以树的形状不是设计选择，是数据结构决定的。分层的好处是每段变换各管一件事，改一段不影响其他。

## 讲深一层

```bash
ros2 run tf2_ros tf2_echo map base_link     # 实时打印变换
ros2 run tf2_tools view_frames              # 生成树状图 PDF
ros2 topic echo /tf_static                  # 静态变换
```

```cpp
geometry_msgs::msg::TransformStamped t;
t.header.stamp = node->now();
t.header.frame_id = "base_link";     // 父
t.child_frame_id  = "laser";         // 子
t.transform.translation.x = 0.12;
t.transform.rotation.w = 1.0;
tf_broadcaster_->sendTransform(t);
```

| 层 | 谁发布 | 含义 |
|---|---|---|
| map → odom | SLAM / 定位 | 全局校正量 |
| odom → base_link | 里程计 | 连续但会漂 |
| base_link → laser | static_transform_publisher | 机械安装，固定不变 |

两个必须知道的点：

1. **时间戳**：`lookupTransform` 要指定时刻，TF 会在缓存里做插值。查一个还没收到的未来时刻会抛 `ExtrapolationException`。
2. **静态变换用 `/tf_static`**：`static_transform_publisher` 只发一次并加 latch，不占带宽；用 `/tf` 发固定变换是浪费。

## 高频追问

1. **为什么每个 frame 只能有一个父？** —— 保证任意两个坐标系之间的路径唯一，否则同一点会有多个答案，变换不唯一。
2. **TF 断了会怎样？** —— 查询抛异常，依赖它的节点直接报错停机。所以 launch 里要保证静态变换先起来。
3. **`map` 和 `odom` 为什么必须分开？** —— odom 连续但漂移，map 全局但会跳变；分开才能既保证局部平滑又允许全局纠正。

## 易错点

- 把 TF 说成「一个矩阵」，漏掉时间维度和树结构
- 用 `/tf` 发静态变换，浪费带宽还容易丢
- 忽略时间戳，用「最新变换」硬查，导致外推异常
