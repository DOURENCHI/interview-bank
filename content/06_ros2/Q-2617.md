## 题目

**场景**：写 TF 监听时看到示例代码是这样的两行：

```cpp
tf2_ros::Buffer buffer(clock);
tf2_ros::TransformListener listener(buffer);
```

**问**：为什么需要两个对象？Buffer 里到底存了什么，Listener 又做了什么？

## 口述答案

> 因为这是**存储**和**采集**分离的设计。`Buffer` 是一个带时间戳的变换缓存，负责存和查；`TransformListener` 是一个订阅者，负责从 `/tf` 和 `/tf_static` 收数据并往 Buffer 里填。
> 所以监听的一方只跟 Buffer 打交道：`buffer.lookupTransform(...)`。Listener 的生命周期必须比 Buffer 短或同时结束，否则它会往一个已销毁的 Buffer 里写。

## 讲深一层

```cpp
tf2_ros::Buffer buffer(node->get_clock());
tf2_ros::TransformListener listener(buffer);   // 构造即开始订阅

try {
  auto t = buffer.lookupTransform("map", "base_link",
                                  tf2::TimePointZero,              // 最新
                                  std::chrono::milliseconds(100)); // 最多等 100 ms
} catch (const tf2::TransformException &e) {
  RCLCPP_WARN(node->get_logger(), "%s", e.what());
}
```

Buffer 内部做了三件事：

| 职责 | 说明 |
|---|---|
| 按 frame 对建索引 | 每个 (父, 子) 一条时间序列 |
| 时间插值 | 查询时刻落在两条记录之间就线性插值（旋转用 slerp） |
| 超时等待 | 数据还没到时阻塞等一小会儿，避免瞬时缺失 |

**为什么要缓存历史**：点云时间戳是 100 ms 前的，你必须在「那个时刻」的坐标系下变换它，用最新变换会让运动中的点云错位。这就是 Buffer 存在的根本原因。

`tf2::TimePointZero` 表示「取最新可用」，不是「取此刻」——这个区别在传感器数据处理里很关键。

## 高频追问

1. **Buffer 缓存多久？** —— 默认 10 秒，可在构造时指定。缓存太长吃内存，太短会让回放 rosbag 时查不到历史。
2. **为什么查不到会抛异常而不是返回单位阵？** —— 返回单位阵会静默产生错误结果，抛异常强制你处理。
3. **静态变换也进 Buffer 吗？** —— 进，来自 `/tf_static`，且不受时间约束。

## 易错点

- 以为 Listener 本身能查询，直接调它的方法
- 用「最新变换」处理带时间戳的传感器数据，运动时错位
- Listener 先于 Buffer 销毁，出现野指针
