## 题目

**场景**：同一份代码要在三台不同配置的机器人上跑，相机型号、最大速度、控制频率都不一样。改代码显然不现实。

**问**：ROS2 的参数机制怎么用？哪些操作是必须会的？

## 口述答案

> 参数是**运行时可变、可通过 YAML 批量注入**的配置。四个动作必须会：**声明**（`declare_parameter`，带默认值）、**读取**（`get_parameter`）、**监听变化**（参数回调）、**外部设置**（`ros2 param set` 或 `--params-file`）。
> 一个纪律：参数必须先声明再访问，否则运行时会抛异常——这是 ROS2 和很多框架不一样的地方。

## 讲深一层

```cpp
// 声明（带默认值，可加范围约束）
rcl_interfaces::msg::ParameterDescriptor d;
d.description = "最大线速度 m/s";
d.floating_point_range.resize(1);
d.floating_point_range[0].from_value = 0.0;
d.floating_point_range[0].to_value = 3.0;
node->declare_parameter("max_speed", 1.0, d);

// 读取
double v = node->get_parameter("max_speed").as_double();

// 监听变化（参数被 set 时会进这里）
node->add_on_set_parameters_callback(
  [](const std::vector<rclcpp::Parameter> &ps) {
    for (auto &p : ps) RCLCPP_INFO(rclcpp::get_logger("p"), "%s changed", p.get_name().c_str());
    return rcl_interfaces::msg::SetParametersResult{true, ""};
  });
```

YAML 注入：
```yaml
/my_node:
  ros__parameters:
    max_speed: 1.2
    control_rate: 50
```
```bash
ros2 run my_pkg my_node --ros-args --params-file cfg/robot.yaml
```

| 命令 | 用途 |
|---|---|
| `ros2 param list` | 看有哪些参数 |
| `ros2 param get / set` | 读、改单个参数 |
| `ros2 param dump` | 导出当前全部参数为 YAML |
| `ros2 param load` | 从 YAML 批量载入 |

调试时最有用的是 `param dump`：把现场调好的参数导出来，直接当默认配置用。

## 高频追问

1. **参数和话题有什么区别？** —— 参数是低频配置（改一次生效很久），话题是高频数据流。用话题传配置会浪费带宽。
2. **为什么必须先 declare？** —— 强制显式声明，避免拼错名字静默失效；这也是参数能列出、能被 dump 的前提。
3. **参数改了要不要重启？** —— 只有实现了参数回调才会实时生效，否则只改内存值、逻辑里读的是缓存。

## 易错点

- 不声明直接 `get_parameter`，运行时抛异常
- 参数名拼错，静默使用默认值，行为「莫名其妙」
- 以为 `ros2 param set` 会持久化（重启就丢，要 dump 出来）
