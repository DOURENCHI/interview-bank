## 题目

**场景**：`colcon build` 编译完，跑起来发现推理节点比预期慢一倍。模型和参数都查过没问题，最后发现是构建类型的问题。

**问**：默认的 `colcon build` 和发布版差在哪？应该加什么参数？

## 口述答案

> 默认 `colcon build` 走的是 CMake 的默认构建类型，而不少包在 CMakeLists 里显式写了 `-O0 -g`，结果就是**带调试符号的未优化代码**，跑起来可能慢好几倍。
> 发布版要显式指定：
> ```
> colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release
> ```
> 再加 `--symlink-install`，改 Python 和 launch 文件就不用重新编译。

## 讲深一层

```bash
# 开发期：保留符号，方便 gdb
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo

# 性能测试 / 发布：一定用 Release
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release

# 只编某个包，改一个包别全量编
colcon build --packages-select my_infer_node --cmake-args -DCMAKE_BUILD_TYPE=Release
```

**为什么差别能到几倍**：`-O0` 下 Eigen 的表达式模板、STL 的 inline、循环展开全部失效，矩阵运算可能慢 5–20 倍。这类「慢」在日志里看不出来，只有对比构建类型才能发现。

验证办法：`objdump -d` 看关键函数里是不是 call 满天飞；或者代码里打点计时，两种构建各跑一遍。

## 高频追问

1. **RelWithDebInfo 和 Release 差什么？** —— 都是 `-O2/-O3`，前者多带调试符号，性能基本一致、体积更大。性能测试用哪个都行，关键是别用 `-O0`。
2. **为什么改了代码没生效？** —— 忘了 `source install/setup.bash`，或者跑的是系统里的旧版本。用 `ros2 pkg prefix <包名>` 确认实际加载路径。
3. **`--symlink-install` 有什么用？** —— Python 和 launch 文件走软链接，改完直接生效；C++ 仍需重新编译。

## 易错点

- 用默认参数做性能测试，得出「ROS2 很慢」的结论
- 只改一个包却全量编译，白等几分钟
- 编译完忘记 source，测的还是旧二进制
