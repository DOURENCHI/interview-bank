## 题目

CI 静态扫描的输出是什么？改完怎么确认修复正确、不引入新 bug？

## 口述答案

> 静态扫描（clang-tidy/cppcheck/SonarQube）的输出通常是**规则 ID + 文件:行号 + 严重级别 + 描述**。处理流程：
> 1. 先分级：Error/阻断级必修，Warning 评估，Style 可批量忽略；
> 2. 逐条改，改完**重跑同一份规则集**，确认该条消失且没有新增（对比两次报告 diff）；
> 3. 回归测试 + 单测覆盖改动点；
> 4. 把误报加进 baseline/抑制文件，避免噪音掩盖真问题。
> 关键：扫描报告要进 CI 留档，按"新增问题数"设门禁（如新增 Error 为 0 才允许合入）。

## 讲深一层

```bash
clang-tidy src/*.cpp -- -Iinclude > before.txt
# 修复后
clang-tidy src/*.cpp -- -Iinclude > after.txt
diff <(sort before.txt) <(sort after.txt)   # 只应减少
```

## 高频追问

1. **误报太多怎么办？** —— 收敛规则集（先只开 bugprone/security），逐条基线化，别一下全开。
2. **怎么证明没引入新 bug？** —— 单测 + 集成测试 + 关键路径人工 review，扫描只是辅助。

## 易错点

- 改完不看 diff，可能修一个引入两个
- 把"扫描通过"当成质量保证，忽略测试
