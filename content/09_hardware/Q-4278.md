## 题目

**问**：CAN 总线上两个节点同时发，谁先发？为什么 ID 越小优先级越高？

## 口述答案

> CAN 是**显性位（0）覆盖隐性位（1）**的线与总线：节点每发一位都同时读回总线，如果自己发的是隐性却读到显性，说明有更高优先级的节点在发，它就**退出仲裁**转为接收，赢家继续发、不被打断——这叫非破坏性仲裁。
> ID 从高位开始逐位比较，前导 0 越多越早把别人"压下去"，所以**数值越小优先级越高**。标准帧 11 位 ID，扩展帧 29 位，IDE 位也参与仲裁，因此标准帧优先于同数值的扩展帧。
> 仲裁失败不是错误，节点会在总线空闲后自动重发。

## 讲深一层

```
节点A ID=0x100 : 1 0000 0001 00
节点B ID=0x101 : 1 0000 0001 01
                          ↑ 最后一位：A 发 0（显性），B 发 1（隐性）
                            B 读到显性 → 退出仲裁
```

| 要点 | 说明 |
|---|---|
| 显性/隐性 | 0 显性，1 隐性，总线做"与" |
| 仲裁范围 | 到仲裁段结束为止 |
| 失败处理 | 转接收，空闲后重发 |
| 前提 | 所有节点同一波特率 |

## 高频追问

1. **仲裁期间会丢数据吗？** —— 不会，赢家继续发，输家重发。
2. **CAN FD 为什么数据段能提速？** —— 仲裁段仍需全网同步，进入数据段后才切高速。
3. **ID 越小越好吗？** —— 优先级高，但所有节点抢同一条总线，要按实时性分配。

## 易错点

- 把 ID 当成节点地址（它其实是报文标识/优先级）。
- 忽略所有节点波特率必须一致这个前提。
