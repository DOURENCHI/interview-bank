## 题目

**题目**：ADC 转换完成中断里把采样值发到队列，写了 `xQueueSend(q, &v, 0)`，编译过了但偶尔丢数据。

**问**：中断里往队列发数据，为什么必须用 FromISR 版本？还会遇到什么问题？

## 口述答案

> 普通 `xQueueSend` 在队列满时可能阻塞，而中断**不能阻塞**；FromISR 版本不阻塞，并且能通过 `pxHigherPriorityTaskWoken` 告知是否需要立即切换。
> 偶尔丢数据的真正原因通常是：**队列满了**（`xQueueSendFromISR` 返回 `errQUEUE_FULL` 被忽略），或者**发送频率高于消费速度**。

## 讲深一层

```c
void ADC_IRQHandler(void) {
    BaseType_t woken = pdFALSE;
    uint16_t v = ADC1->DR;

    if (xQueueSendFromISR(adc_q, &v, &woken) != pdPASS) {
        ++drop_count;                     // 记录丢弃，别静默
    }
    portYIELD_FROM_ISR(woken);
}
```

| 问题 | 原因 | 修法 |
|---|---|---|
| 丢数据 | 队列满 | 加长队列 / 提高消费优先级 / 记丢弃计数 |
| 数据错乱 | 没清中断标志，重复入队 | 中断里清标志 |
| HardFault | 中断优先级过高 | 降到 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 之下 |
| 延迟大 | 忘了 `portYIELD_FROM_ISR` | 补上 |

**设计建议**：队列长度按"中断频率 × 最长处理时间"估。1 kHz 采样、任务 10 ms 处理一次，至少要 10 个槽位。

**更高频的做法**：用**流缓冲区（stream buffer）**或 DMA + 半满/全满中断，一次搬一批，减少中断次数。

## 高频追问

1. **能发到队列后立刻处理吗？** —— 不能，中断里只能发信号，处理留给任务。
2. **中断里能 `malloc` 吗？** —— 不能，任何堆分配都不行。
3. **丢数据怎么统计？** —— 全局计数器，任务里定期打印。

## 易错点

- 中断里用 `xQueueSend` 并传超时
- 忽略 `xQueueSendFromISR` 的返回值
- 中断优先级配太高，调用 API 直接崩
