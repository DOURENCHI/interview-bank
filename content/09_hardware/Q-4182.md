## 题目

**题目**：串口每 1 ms 收一个字节，轮询版和中断版都能工作，想知道差别有多大。

**问**：轮询版和中断版串口程序，CPU 占用差多少？

## 口述答案

> 粗算：115200 波特率下 1 字节（10 位）约 87 μs。**轮询版**如果死等，这 87 μs 里 CPU 100% 空转；**中断版**只在数据到达时占用几微秒处理，其余时间 CPU 完全空闲。
> 也就是说，轮询版为了收 1 字节浪费约 87 μs，中断版只花约 2–5 μs——**差 20 倍以上**。

## 讲深一层

| 方式 | 每字节 CPU 时间 | 1 KB 数据的 CPU 占用 |
|---|---|---|
| 死等轮询 | ~87 μs（全浪费） | ~89 ms |
| 带超时轮询 | 取决于轮询间隔 | 取决于实现 |
| 中断（逐字节） | ~3 μs | ~3 ms + 中断开销 |
| DMA + 空闲中断 | ~0 | ~0（CPU 完全不参与） |

```c
// 中断版：CPU 只在回调里干活
void HAL_UART_RxCpltCallback(UART_HandleTypeDef* h) {
    ring_put(&rb, rx_byte);
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);     // 重新武装
}

// DMA + IDLE：一次收一整帧
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, buf, sizeof(buf));
```

**为什么还会有"中断开销"**：每次中断有压栈/出栈约 24 周期，加上 ISR 入口，1 KB 数据就是 1024 次中断，累计几毫秒。**高频小数据用 DMA 才彻底解放 CPU**。

**结论**：轮询适合"初始化/调试"；中断适合"偶发事件"；DMA 适合"持续大数据流"。

## 高频追问

1. **DMA 怎么知道收完了？** —— 空闲中断（IDLE）或半满/全满中断。
2. **中断版会丢数据吗？** —— 处理慢了会溢出（ORE），要看溢出标志。
3. **轮询真的没有优点吗？** —— 简单、无并发问题，适合极简场景。

## 易错点

- 主循环里用 `HAL_UART_Receive`（阻塞）收数据
- 逐字节中断收大数据流，CPU 全在中断里
- 不看 ORE 溢出标志
