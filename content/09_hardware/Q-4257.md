## 题目

**问**：程序偶尔死机、现场又不容易复现，你一般怎么处理？

## 口述答案

> 先**保住现场**，再谈复现。
> 1. 装 HardFault/看门狗复位钩子：把 PC、LR、PSP/MSP、CFSR、HFSR、MMFAR、BFAR 写进 noinit RAM 或专用 Flash 区，重启后读出来用 `addr2line` 对 map 文件定位；
> 2. 加环形日志（放 RAM，定期落 Flash），记录关键状态机和最后几条命令；
> 3. 打开栈水位检查、堆哨兵、MPU 越界保护，把"偶发"变成"必现"；
> 4. 加压复现：高温/低压、满负载、通信错误注入、长时间老化；
> 5. 分析方向通常是野指针、栈溢出、中断与主循环竞态、堆碎片、看门狗误喂。

## 讲深一层

```c
void HardFault_Handler(void) {
    __asm volatile("mrs r0, psp \n mrs r1, msp \n b crash_save");
}
// crash_save 里读 SCB->CFSR/HFSR/MMFAR/BFAR + 栈帧 PC/LR
// 存到 __attribute__((section(".noinit"))) 的结构体
```
| 手段 | 抓什么 |
|---|---|
| HardFault 钩子 | 崩溃现场、调用栈 |
| 环形日志 | 崩溃前最后状态 |
| 栈水位 | 栈溢出风险 |
| MPU/哨兵 | 越界写 |
| 错误注入 | 把偶发变必现 |

## 高频追问

1. **为什么放 noinit？** —— 复位不清零，能把现场带到下一次启动。
2. **没有调试器怎么定位？** —— 存 PC 后反查 map/反汇编，或回传日志到上位机。
3. **看门狗复位后怎么知道是它？** —— 读 RCC 的复位标志寄存器。

## 易错点

- 一上来就加 printf，改变时序后问题消失。
- 只看复位后变量，没保存崩溃现场。
