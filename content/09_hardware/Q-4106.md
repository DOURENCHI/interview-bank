## 题目

**题目**：看 FreeRTOS 的启动代码，发现它打开了 SVC、PendSV、SysTick 三个异常。分别干什么？

**问**：FreeRTOS 内核用到哪几个中断？各自的作用是什么？

## 口述答案

> 三个各司其职：**SVC** 用于启动第一个任务（从特权态切到任务上下文）；**PendSV** 负责**上下文切换**（保存/恢复寄存器）；**SysTick** 提供**系统节拍**（tick），驱动延时和时间片。
> 关键设计是 **PendSV 的优先级设成最低**：这样上下文切换会等所有其他中断处理完再执行，避免在中断中间切换导致状态错乱。

## 讲深一层

| 异常 | 作用 | 优先级 |
|---|---|---|
| SVC | 启动调度器、任务首次运行 | 高 |
| PendSV | 上下文切换（保存/恢复 R0-R15） | **最低** |
| SysTick | 系统节拍（tick 计数、延时、时间片） | 通常低于 SVC |

```c
// port.c 里的典型配置（Cortex-M）
#define configKERNEL_INTERRUPT_PRIORITY      255        // PendSV/SysTick 最低
#define configMAX_SYSCALL_INTERRUPT_PRIORITY 191        // 可调 API 的最高优先级
```

**为什么 PendSV 必须最低**：切上下文要保存完整寄存器组，如果在中断嵌套中间切换，返回时恢复的上下文可能是错的。放到最低优先级，保证"所有中断都处理完了再切"。

**SysTick 可以被替换**：用 `configSYSTICK_CLOCK_HZ` 改时钟源，或改用其他定时器提供 tick（见 Q-4112）。

## 高频追问

1. **能改 PendSV 优先级吗？** —— 能配，但不能高于"可调 API 的最高优先级"，否则会破坏临界区保护。
2. **上下文切换保存了什么？** —— R4–R11、R14 等（R0–R3、R12、LR、PC、xPSR 由硬件自动压栈）。
3. **tick 中断里做了什么？** —— `xTaskIncrementTick()`，判断是否需要切换，需要就挂起 PendSV。

## 易错点

- 把 PendSV 优先级设高，导致切换在中断中间发生
- 以为 SysTick 是唯一 tick 来源
- 在中断里调用非 FromISR 版本 API
