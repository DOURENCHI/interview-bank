## 题目

**题目**：标准库工程里中断处理写在 `stm32f10x_it.c`，HAL 工程里却只有一行 `HAL_UART_IRQHandler(&huart1)`。

**问**：标准库和 HAL 库的中断处理方式有什么不同？为什么 HAL 要包一层？

## 口述答案

> 标准库是**在 ISR 里直接处理**：判断标志、读数据、清标志，全写在 `xxx_IRQHandler` 里。
> HAL 把 ISR 拆成两层：`HAL_xxx_IRQHandler` 负责**判断标志、清标志、调用回调**；用户只实现 `HAL_xxx_Callback`。好处是生成代码和你写的代码分离，CubeMX 重新生成不会覆盖你的逻辑。

## 讲深一层

```c
// 标准库：全在 ISR 里
void USART1_IRQHandler(void) {
    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        uint8_t d = USART_ReceiveData(USART1);
        buf[i++] = d;
        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}

// HAL：ISR 只有一行，逻辑在回调里
void USART1_IRQHandler(void) { HAL_UART_IRQHandler(&huart1); }

void HAL_UART_RxCpltCallback(UART_HandleTypeDef* h) {
    buf[i++] = rx_byte;
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);     // 重新武装
}
```

| 维度 | 标准库 | HAL |
|---|---|---|
| 中断处理位置 | ISR 里 | 回调里 |
| 标志位管理 | 手动 | 由 `HAL_xxx_IRQHandler` 处理 |
| 代码生成兼容 | 冲突（同文件） | 分离 |
| 灵活性 | 高 | 中（想看细节要读 HAL 源） |
| 代码体积 | 小 | 大 |

**HAL 的坑**：`HAL_UART_Receive_IT` 是**单次**的，回调里必须重新调用才能继续接收，否则只收到一个字节就停了。

## 高频追问

1. **回调在什么上下文？** —— 中断上下文，所以必须短。
2. **能同时用标准和 HAL 吗？** —— 不建议，中断向量会冲突。
3. **HAL 的回调能拿到哪个外设吗？** —— 参数是 `UART_HandleTypeDef*`，可以判断是哪个串口。

## 易错点

- 在 HAL 回调里做耗时操作
- 忘了重新调用 `HAL_UART_Receive_IT`
- 手动清标志和 HAL 重复操作
