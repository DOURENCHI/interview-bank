## 题目

**题目**：`configUSE_PREEMPTION`、`configUSE_TIME_SLICING` 两个宏，四个组合。

**问**：FreeRTOS 支持哪几种调度策略？抢占式和协作式区别在哪？

## 口述答案

> FreeRTOS 本质是**基于优先级的调度**，两个宏控制两种行为：
> - `configUSE_PREEMPTION=1`：**抢占式**，高优先级任务就绪立刻抢占低优先级；
> - `configUSE_TIME_SLICING=1`：**同优先级任务按时间片轮转**（tick 到了就换）。
> 关掉抢占（=0）就是**协作式**：任务必须主动让出（`vTaskDelay`、等信号量、`taskYIELD`）才会切换。

## 讲深一层

| 组合 | 行为 | 适用 |
|---|---|---|
| 抢占 + 时间片 | 默认，响应最好 | 大多数场景 |
| 抢占 + 无时间片 | 高优先级抢占；同优先级先进先出直到阻塞 | 想减少切换开销 |
| 协作 + 时间片 | 只在主动让出时切换 | 几乎不用 |
| 协作 + 无时间片 | 纯协作 | 老式系统/极简场景 |

```c
// FreeRTOSConfig.h
#define configUSE_PREEMPTION    1
#define configUSE_TIME_SLICING  1
#define configUSE_TICKLESS_IDLE 0
```

**协作式的风险**：一个任务写死循环不阻塞，**所有低优先级任务永远得不到执行**，看门狗都跑不了。

**优先级数字越大越高**（和某些 RTOS 相反），范围 0 到 `configMAX_PRIORITIES-1`；空闲任务固定优先级 0。

## 高频追问

1. **时间片多长？** —— 一个 tick（`1/configTICK_RATE_HZ`），1000 Hz 时是 1 ms。
2. **同优先级任务怎么排队？** —— 就绪链表按优先级分桶，同桶内轮转。
3. **优先级反转怎么解决？** —— 用互斥量（带优先级继承），不要用二值信号量做互斥。

## 易错点

- 以为 FreeRTOS 默认是协作式
- 认为优先级数字越小越高
- 协作式下写死循环，低优先级任务饿死
