## 题目

项目中遇到深浅拷贝问题，举个实际案例？怎么避免复发？

## 口述答案

> 实际案例：一个配置结构体里有 `char*` 成员，按值拷贝结构体后两个对象指向同一块堆内存，一个释放后另一个变野指针，偶发崩溃。
> 根因是**默认拷贝是浅拷贝**（逐字节复制指针值）。避免复发：①类里管资源就遵循三/五法则，或直接用 `std::string/vector/智能指针`；②禁用拷贝（`= delete`）或写显式深拷贝；③代码规范要求"持有裸指针的类必须审查拷贝语义"；④静态扫描 + code review checklist；⑤单测里加 ASAN。

## 讲深一层

```cpp
struct Bad { char* p; ~Bad(){ delete[] p; } };   // 默认拷贝 = 双 free
struct Good { std::vector<char> p; };            // 值语义，天然深拷贝
```

## 高频追问

1. **移动语义能解决吗？** —— 能避免多余拷贝，但被 move 后的对象仍要保证有效可析构。
2. **怎么在 CI 里防？** —— ASAN/UBSAN + clang-tidy 的 `cppcoreguidelines-owning-memory`。

## 易错点

- 只答"用深拷贝"，说不出怎么在流程上防复发
- 忽略返回值优化/移动后对象状态
