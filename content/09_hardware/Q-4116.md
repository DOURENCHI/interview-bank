## 题目

**问**：DMA 搬运数据的时候，CPU 同时访问那块内存会不会冲突？冲突了怎么办？有 Cache 的芯片还要注意什么？

## 口述答案

> 结论：会争总线，但不会丢数据，靠总线仲裁解决，代价是 CPU 被 stall。分点：1. 单端口 SRAM 上 CPU 和 DMA 是主设备竞争，仲裁器按固定或轮转优先级让一个先走，另一个插等待周期；2. 减小冲突窗口用双缓冲/乒乓，或把 DMA buffer 放到独立 SRAM 块；3. 提高 DMA 突发长度（burst）减少占用次数；4. Cortex-M7/A 核还有 Cache 一致性：DMA 绕过 Cache 直接写内存，CPU 可能读到旧值。

## 讲深一层

STM32F4 用多层 AHB 总线矩阵，DMA 走 AHB，冲突时按流优先级（DMA_SxCR 的 PL[1:0]：低/中/高/超高）仲裁。M7 上处理：发送前 SCB_CleanDCache_by_Addr 把脏行写回，接收后 SCB_InvalidateDCache_by_Addr 作废，buffer 必须按 32 字节 cache line 对齐且长度为整数倍，否则会误伤相邻变量。

## 高频追问

1. **双缓冲怎么防撕裂？** —— DMA 写 B 区时 CPU 处理 A 区，半满/全满中断里交换角色，读 CT 位判断当前目标区。
2. **冲突会导致数据错吗？** —— 不会，只会变慢；真正丢数据是外设侧 overrun（如 UART ORE、ADC overrun），要单独处理。
3. **DMA buffer 能放栈上吗？** —— 不建议，栈地址不保证对齐到 cache line，且函数返回后失效。

## 易错点

- 认为 DMA 是"独立通道"完全不占总线带宽
- 忽略 D-Cache，CPU 读到 DMA 更新前的旧数据
- buffer 未按 cache line 对齐，invalidate 把邻居的脏数据丢了
