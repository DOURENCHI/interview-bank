## 题目

**场景**：面试官在黑板上写了两行声明，问你它们是不是一回事。

```c
void f(int a[10]);
void g(int *a);
```

**问**：这两个声明有区别吗？数组作为实参传进去时到底发生了什么？函数里还能不能算出数组长度？

## 口述答案

> 没有区别，编译器都会把它们当成 `int *`。数组名作为实参时会**退化成指向首元素的指针**，函数拿到的只是一个地址，长度信息在形参这一层就丢了。
> 所以：
> · 函数里 `sizeof(a)` 得到的是**指针大小**（32 位 4 字节、64 位 8 字节），不是数组大小；
> · 想遍历必须**额外传长度**，或者约定结束符（`'\0'`）、或者把数组包进结构体一起传。
> 还要分清一件事：数组名本身不是指针。在定义它的作用域里，`sizeof(arr)` 仍然是整个数组的大小，`&arr` 的类型是 `int (*)[N]`，只是传参这一刻退化掉了。

## 讲深一层

| 写法 | 形参实际类型 | 函数内 sizeof |
|---|---|---|
| `void f(int a[10])` | `int *` | 4 / 8 |
| `void f(int a[])` | `int *` | 4 / 8 |
| `void f(int (*a)[10])` | 指向数组的指针 | 4 / 8，但 `(*a)[i]` 可定长访问 |
| `void f(int (&a)[10])`（C++） | 数组引用 | **整个数组 40** |

二维数组更容易踩坑：`int a[3][4]` 传参后退化成 `int (*)[4]`，**第二维不能省**，否则 `a[i][j]` 的步长会算错。

```c
void f(int a[][4], int rows);   // 正确
void f(int **a);                // 错：和 int[3][4] 不兼容
```

想改调用方的指针本身，要传二级指针 `int **`；C++ 里也可以写 `int *&`。

## 高频追问

1. **为什么 `sizeof` 在函数里就不灵了？** —— `sizeof` 是编译期按类型算大小，形参类型已经是指针，编译器只知道指针多大。
2. **把数组包进结构体行不行？** —— 行，`struct { int n; int a[10]; }` 按值传会整体拷贝，长度不会丢，但大数组的拷贝开销要算进去。
3. **`a` 和 `&a` 有什么区别？** —— 值相同、类型不同：`a` 退化成 `int*`，`&a` 是 `int(*)[10]`，`&a + 1` 跳过整个数组。

## 易错点

- 说"数组传参是引用传递"——C 里全是值传递，传的是指针的值。
- 在函数里写 `sizeof(a)/sizeof(a[0])` 求长度，64 位下结果恒为 2。
- 二维数组形参写成 `int **`，编译能过但运行时地址算错。
