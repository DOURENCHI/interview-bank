## 题目

**题目**：把主频从 8 MHz 超到 72 MHz，程序跑飞；查出来 `FLASH->ACR` 的 LATENCY 没改。

**问**：Flash 等待周期为什么必须设置？怎么算？

## 口述答案

> 因为 **Flash 的读取速度跟不上 CPU 主频**。72 MHz 下 Flash 需要多个等待周期才能稳定输出数据，不设就会读到错误指令或数据，表现为随机跑飞、HardFault。
> F103 的规则：`0 < SYSCLK ≤ 24 MHz` 用 0 等待，`24 < ≤ 48` 用 1，`48 < ≤ 72` 用 2。

## 讲深一层

```c
// 在提高主频之前就要设置好等待周期
__HAL_FLASH_SET_LATENCY(FLASH_LATENCY_2);      // 72 MHz → 2 个等待周期
__HAL_FLASH_PREFETCH_BUFFER_ENABLE();           // 同时开预取，抵消等待开销
```

| SYSCLK | 等待周期（F103） |
|---|---|
| ≤ 24 MHz | 0 |
| 24–48 MHz | 1 |
| 48–72 MHz | 2 |

**顺序很关键**：**先把等待周期设大，再升主频**。反过来会在升频的瞬间用错误的等待周期执行代码，立刻跑飞。

**预取缓冲（Prefetch）**：顺序执行时能提前取下一条指令，把等待周期的影响降到接近 0；但跳转频繁时代码收益变小。

**F4/H7 更复杂**：有多条 AXI/APB 总线、指令/数据 Cache、ART Accelerator，等待周期和 Cache 配置要一起考虑。

## 高频追问

1. **开了预取就不用设等待周期吗？** —— 不能，预取是优化，等待周期是硬要求。
2. **设多了会怎样？** —— 变慢，但不会错。
3. **怎么验证？** —— 跑一个纯计算循环对比耗时，或看是否稳定不复位。

## 易错点

- 先升频后设等待周期
- 忘记 F103 在 72 MHz 需要 2 个等待周期
- 只设 LATENCY 不开预取，性能差一截
