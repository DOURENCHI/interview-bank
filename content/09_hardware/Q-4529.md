## 题目

**题目**：一个设备有 5 个状态、8 种事件，代码里 switch 套 switch 越来越乱。

**问**：什么是状态机编程？为什么嵌入式常用它？

## 口述答案

> 状态机 = **有限个状态 + 事件驱动的迁移规则**。任一时刻只处于一个状态，收到事件后按规则迁移到下一个状态并执行动作。
> 嵌入式常用它，是因为控制逻辑天然是"状态 + 事件"：按键消抖、协议解析、电机启停、UI 流程都能用同一套结构表达，比嵌套 if 清晰得多。

## 讲深一层

```c
switch (state) {
case IDLE:
    if (ev == EV_START) { motor_on(); state = RUNNING; }
    break;
case RUNNING:
    if (ev == EV_STOP)  { motor_off(); state = IDLE; }
    else if (ev == EV_FAULT) { state = FAULT; }
    break;
}
```
| 实现方式 | 特点 |
|---|---|
| switch-case | 直观，适合状态少 |
| 状态表（函数指针数组） | 易扩展，`table[state][event]` |
| 层次状态机 | 支持嵌套/继承，复杂度高 |
- 关键纪律：**所有状态迁移集中在一处**，别在别处直接改状态变量。
- 状态机 + 超时 = 更健壮（如"等待响应超过 100 ms 就回 IDLE"）。

## 高频追问

1. **状态多了怎么组织？** —— 用表驱动（行是状态、列是事件），加状态只加一行。
2. **怎么处理超时？** —— 每个状态带一个进入时间戳，定期检查。

## 易错点

- 在多个地方直接改状态变量
- 状态迁移没有默认分支（漏事件导致卡死）
