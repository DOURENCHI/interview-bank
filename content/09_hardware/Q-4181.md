## 题目

**题目**：EXTI0 中断里先清标志再判断，或者判断完在 if 外面统一清，都出现过丢事件。

**问**：EXTI 的挂起寄存器为什么必须在 if 里清？清早了或清晚了各有什么问题？

## 口述答案

> 因为 `EXTI->PR` 是**所有线共用的一个寄存器**，每位对应一条线。如果在 `if` 外面无条件写 1 清所有位，会把**同时到来的其他线**的挂起标志一起清掉——那些事件就丢了。
> 正确做法是：**判断是哪条线 → 处理 → 只清那一位**。

## 讲深一层

```c
void EXTI0_IRQHandler(void) {
    if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_0) != RESET) {
        handle_key();                                  // 先处理
        __HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0);          // 只清这一位
    }
    // 若 EXTI1 也走这个向量（不会，向量是分开的），就再判断
}
```

| 写法 | 后果 |
|---|---|
| `if` 里判断 + `if` 里清 | ✅ 正确 |
| `if` 外无条件清全部 | ❌ 丢掉同时到达的其他线 |
| 先清再处理 | ⚠️ 处理期间新事件可再次置位（可能正常，也可能丢一次） |
| 忘记清 | ❌ 退出后立刻再次进入 |

**"写 1 清零"（write-1-to-clear）**：EXTI 的 PR 寄存器是这种语义——写 1 清除对应位，写 0 无影响。这和很多寄存器相反，容易写错。

**HAL 的封装**：`HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_x)` 内部就是"判断 + 清 + 调回调"，用 HAL 时不要在回调里再清一次。

## 高频追问

1. **为什么是写 1 清零？** —— 避免读-改-写影响其他位，是硬件常用的设计。
2. **清早了会怎样？** —— 处理期间同一条线再来一次边沿，会被漏掉（因为标志已被清、处理中不再响应）。
3. **能一次清多位吗？** —— 能，写对应位掩码，但要确认那些事件确实不需要了。

## 易错点

- 在 if 外清全部挂起位
- 先清后处理，处理期间的新事件丢失
- 用 `&= ~` 方式清（对 W1C 寄存器无效）
