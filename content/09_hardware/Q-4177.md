## 题目

**题目**：`void USART1_IRQHandler(void)` 这个名字必须一字不差，否则中断不触发。

**问**：中断服务函数名是固定的吗？从哪来？写错了为什么编译不报错？

## 口述答案

> 是**固定的**，来自**启动文件里的中断向量表**（`startup_stm32f103xb.s`）。表里每一项是一个弱符号，名字就是 CMSIS 规定的 `USART1_IRQHandler`。
> 你写同名函数就"覆盖"了这个弱符号；名字写错则变成一个新函数，向量表里仍是默认的无限循环（`Default_Handler`），所以编译通过、中断不响应。

## 讲深一层

```asm
; startup_stm32f103xb.s 片段
.word  USART1_IRQHandler      ; 向量表第 37 项
.weak  USART1_IRQHandler
.thumb_set USART1_IRQHandler, Default_Handler   ; 默认死循环
```

```c
// 正确：名字与向量表一致
void USART1_IRQHandler(void) { HAL_UART_IRQHandler(&huart1); }

// 错误：名字拼错 → 进了 Default_Handler（死循环），中断不工作
void USART_IRQHandler(void) { ... }
```

| 现象 | 原因 |
|---|---|
| 中断不触发 | 函数名拼错，走了 Default_Handler |
| 编译报重复定义 | 两个文件都定义了同名 ISR |
| 中断进一次就卡住 | 在 Default_Handler 的死循环里 |

**怎么确认**：在 ISR 里点灯或置标志；或者调试时在 ISR 打断点——打不上说明没进。

**CubeMX 生成的 `stm32f1xx_it.c`** 已经写好了所有 ISR 的空壳，只调 `HAL_xxx_IRQHandler`，所以一般不用自己起名。

## 高频追问

1. **能改 ISR 名字吗？** —— 不能，除非改向量表（不推荐）。
2. **`Default_Handler` 是什么？** —— 弱定义的无限循环，用于捕获未实现的中断。
3. **同一个 ISR 能写在两个文件里吗？** —— 不能，链接报重复定义。

## 易错点

- 名字拼错（`USART1_IRQhandler` 大小写错）
- 自己写了 ISR 又调了 CubeMX 生成的同名函数
- 以为编译通过就说明配置对了
