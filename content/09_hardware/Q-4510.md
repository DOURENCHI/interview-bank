## 题目

**题目**：协议里有个 3 位的字段，想省内存，用位域还是位操作？

**问**：C 语言的位域是什么？有什么坑？

## 口述答案

> 位域在结构体里指定成员占几个 **bit**：`struct { unsigned a:3; unsigned b:5; }`，编译器把它们打包进同一个存储单元，省内存。
> 坑有三：**布局依赖编译器和字节序**（不可跨平台）、**不能取地址**（没有独立地址）、**访问要读-改-写**（非原子，多线程/中断危险）。

## 讲深一层

```c
struct Flags {
    unsigned ready  : 1;
    unsigned mode   : 3;
    unsigned err    : 4;
};   // 共 1 字节（vs 三个 int 的 12 字节）
```
| 优点 | 缺点 |
|---|---|
| 省内存 | 布局不可移植 |
| 语义清晰（硬件寄存器映射） | 不能 `&flag.ready` |
| 便于解析协议 | 读写非原子 |
- 位域的类型建议用 `unsigned`（有符号位域的行为依赖实现）。
- 跨平台协议解析还是手工移位更可靠：`(v >> 3) & 0x7`。

## 高频追问

1. **位域能跨字节吗？** —— 取决于编译器，可能跨也可能不跨。
2. **为什么不能取地址？** —— 位不占用独立字节地址，最小的可寻址单位是字节。

## 易错点

- 用位域做跨平台通信协议
- 在多任务下读写同一位域字段
