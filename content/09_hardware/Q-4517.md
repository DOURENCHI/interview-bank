## 题目

**题目**：CPU 主频 3 GHz，内存访问要 100 ns，为什么程序没慢成那样？

**问**：Cache 是什么？为什么它能提速？

## 口述答案

> Cache 是 CPU 和内存之间的**小容量高速缓冲**，存最近用过的数据和指令。因为程序有**时间局部性**（刚用过的还会用）和**空间局部性**（用了 a[i] 很快会用 a[i+1]），命中率通常 90%+，平均访问时间大幅下降。
> 访问顺序是 **寄存器 → L1 → L2 → L3 → 内存**，越靠后越慢越大。

## 讲深一层

| 层级 | 典型容量 | 延迟 |
|---|---|---|
| 寄存器 | 几百字节 | < 1 ns |
| L1 | 32–64 KB | ~1 ns |
| L2 | 256 KB–1 MB | ~4 ns |
| L3 | 几 MB–几十 MB | ~15 ns |
| 内存 | GB | ~100 ns |
- Cache 按**行**（64 B）加载，所以顺序访问比随机访问快得多。
- 这解释了为什么"链表遍历比数组慢"——每次节点跳转都可能 cache miss。
- 缓存一致性（多核）：MESI 协议维护各核 Cache 的一致性。

## 高频追问

1. **Cache 命中率怎么提高？** —— 顺序访问、数据紧凑、避免大跨度跳转。
2. **什么是伪共享？** —— 两个核改同一缓存行里的不同变量，导致反复失效。

## 易错点

- 以为 Cache 由程序员显式管理（CPU 自动的）
- 忽略缓存行对齐对多线程性能的影响
