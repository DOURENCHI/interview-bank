## 题目

**题目**：要在 STM32 + 4G 模块上把传感器数据发到云平台，选 MQTT。

**问**：MQTT 的报文格式和连接流程是什么？在单片机上实现要注意什么？

## 口述答案

> 报文分三段：**固定头（1 字节类型 + 1–4 字节剩余长度）+ 可变头（按类型）+ 载荷**。连接流程是 `CONNECT → CONNACK → (SUBSCRIBE/SUBACK) → PUBLISH → PINGREQ/PINGRESP → DISCONNECT`。
> 单片机实现的关键是**内存受限**：不能像 PC 那样一次性构造完整报文，要**边算边发**，剩余长度用变长编码。

## 讲深一层

```
固定头：| Type(4bit) | Flags(4bit) | Remaining Length(1-4 字节变长) |
```

| 报文 | 方向 | 作用 |
|---|---|---|
| CONNECT / CONNACK | C→S / S→C | 建立会话、鉴权 |
| PUBLISH | 双向 | 发布消息（QoS 0/1/2） |
| SUBSCRIBE / SUBACK | C→S / S→C | 订阅主题 |
| PINGREQ / PINGRESP | C→S / S→C | 心跳保活 |
| DISCONNECT | C→S | 正常断开 |

```c
// 剩余长度是变长编码：每字节 7 位，最高位表示"还有后续"
// 127 → 0x7F；128 → 0x80 0x01；16383 → 0xFF 0x7F
```

**单片机上的四个注意点**：

1. **心跳**：`keepalive` 内必须发 PINGREQ，否则服务器断开（4G 网络下尤其容易掉）；
2. **QoS 选择**：QoS 1/2 需要本地存消息做重传，RAM 紧张时用 QoS 0；
3. **重连**：4G 断线是常态，要有退避重连（1s/2s/4s…）；
4. **TLS**：MQTTS 需要 TLS 握手，RAM 和 Flash 开销大，用硬件加密或轻量库（如 mbedTLS 裁剪版）。

**能加分的说法**：MQTT 是"轻量"协议，但轻量指的是**报文头小**，不是"实现简单"——状态机和重连逻辑才是工作量。

## 高频追问

1. **QoS 0/1/2 区别？** —— 最多一次 / 至少一次 / 恰好一次；代价依次增大。
2. **遗嘱消息是什么？** —— CONNECT 时声明，客户端异常断开时服务器代发。
3. **主题设计要注意什么？** —— 层级用 `/` 分隔，避免 `#` `+` 通配符出现在发布端。

## 易错点

- keepalive 内不发心跳，被服务器踢掉
- QoS 1 却没做本地重传存储
- 断线后一直重试不退避，把流量打满
