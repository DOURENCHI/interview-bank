## 题目

**现象**：串口接收到一个字节后，程序卡在中断里出不来，主循环完全不执行。

**问**：串口接收不清 RXNE 标志，为什么会反复进中断？

## 口述答案

> 因为 RXNE 是**"接收寄存器非空"**标志，只要数据没被读走它就一直是 1。中断退出后 NVIC 发现该中断线仍处于挂起状态，立刻再次进入 ISR——形成死循环。
> 清除它的方法是**读 SR 再读 DR**（读 DR 把数据取走，硬件自动清标志）。

## 讲深一层

```c
// ❌ 只读 SR 不读 DR，标志不清
if (USART1->SR & USART_SR_RXNE) {
    uint8_t d = USART1->SR;        // 读错了寄存器
}

// ✅ 读 DR
if (USART1->SR & USART_SR_RXNE) {
    uint8_t d = USART1->DR;        // 顺带清 RXNE
    handle(d);
}
```

| 标志 | 清除方式 |
|---|---|
| RXNE | 读 SR 后读 DR |
| TXE | 写 DR |
| ORE（溢出） | 读 SR 后读 DR |
| IDLE | 读 SR 后读 DR |
| TC（发送完成） | 读 SR 后写 DR 或写 0 |

**`ORE` 溢出最容易漏**：接收太快来不及读，新数据覆盖旧数据并置 ORE。如果只处理 RXNE 不管 ORE，可能一直卡住。健壮的 ISR 要同时检查。

**HAL 的处理**：`HAL_UART_IRQHandler` 内部会读 DR 清标志，所以用 HAL 一般不会踩这个坑——但如果你在回调里又手动读 SR 判断，可能干扰。

## 高频追问

1. **怎么确认卡在中断里？** —— 调试器暂停，看 PC 是否在 ISR 里。
2. **`HAL_UART_Receive_IT` 只收一个字节？** —— 是单次的，回调里要重新调用。
3. **ORE 会导致什么？** —— 数据丢失 + 可能卡死，必须处理。

## 易错点

- 只读 SR 不读 DR
- 不管 ORE 溢出标志
- 在 HAL 回调里重复清标志
