## 题目

**题目**：板子有两块 RAM：内部 SRAM（20 KB）+ 外部 SRAM（512 KB）。`heap_4` 只能用一块，怎么办？

**问**：`heap_4` 和 `heap_5` 有什么区别？什么时候必须用 `heap_5`？

## 口述答案

> 区别在**内存区域数量**：`heap_4` 只用一块连续内存（`ucHeap[]` 数组），`heap_5` 支持**多块不连续区域**，需要显式初始化告诉它有哪些段。
> 所以内存分散在多块（内部 + 外部、CCM + 普通 SRAM）时必须用 `heap_5`。

## 讲深一层

```c
// heap_5：先声明区域，再初始化
static uint8_t ucHeap1[10 * 1024];                    // 内部 SRAM
static uint8_t ucHeap2[512 * 1024] __attribute__((section(".ext_sram")));

HeapRegion_t regions[] = {
    { ucHeap1, sizeof(ucHeap1) },
    { ucHeap2, sizeof(ucHeap2) },
    { NULL, 0 }                                       // 结束标记
};

int main(void) {
    vPortDefineHeapRegions(regions);                  // 必须在创建任何对象前调用
    xTaskCreate(...);
    vTaskStartScheduler();
}
```

| 方案 | 区域数 | 初始化 | 适用 |
|---|---|---|---|
| `heap_4` | 1 | 自动 | 单块 RAM |
| `heap_5` | 多 | `vPortDefineHeapRegions` | 内外部 RAM 混合 |

**顺序很重要**：`vPortDefineHeapRegions` 必须在**创建任务/队列/定时器之前**调用，否则那些对象会分配到未初始化的堆上。

**STM32 的常见场景**：F4/F7 有 CCM RAM（内核专用，DMA 访问不到），H7 有 DTCM + AXI SRAM 多块——这些场合 `heap_5` 几乎是唯一选择。

## 高频追问

1. **能只用外部 SRAM 吗？** —— 能，但外部 SRAM 慢（要配 FMC），高频访问的任务栈放里面会拖慢。
2. **`heap_5` 会合并跨区域的空闲块吗？** —— 不会，不同区域之间不能合并。
3. **DMA 缓冲区能放 CCM 吗？** —— 不能，CCM 不被 DMA 访问。

## 易错点

- 忘了 `vPortDefineHeapRegions` 就创建任务
- 把 DMA 缓冲分配到 CCM RAM
- 区域数组没有 `{NULL, 0}` 结束标记
