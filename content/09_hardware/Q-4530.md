## 题目

**题目**：设备和云端约定用 JSON 通信，但单片机 RAM 只有 20 KB。

**问**：JSON 格式的数据长什么样？嵌入式里怎么解析？

## 口述答案

> JSON 是**键值对 + 数组 + 嵌套**的文本格式：`{"temp": 25.3, "ok": true, "tags": ["a","b"]}`。类型只有对象、数组、字符串、数字、布尔、null。
> 嵌入式里用**流式解析器**（cJSON、jsmn、jansson 的裁剪版），不要用"先构建整棵树"的方式——树结构会把 RAM 吃光。

## 讲深一层

| 库 | 方式 | 内存 |
|---|---|---|
| cJSON | 构建 DOM 树 | 较高（要 malloc） |
| jsmn | 只切 token，不分配 | 极低（推荐） |
| 手写 | 按固定 schema 定位字段 | 最低，但脆弱 |
- 固定 schema 时可以只做"字符串查找 + 数值转换"，甚至不用库。
- 注意：浮点解析（`strtod`）会拉进一大坨库，Flash 紧张时用定点。
- 发送方注意转义（引号、反斜杠、控制字符）。

## 高频追问

1. **JSON 和二进制协议怎么选？** —— JSON 可读、易调试；二进制省带宽和省解析开销。
2. **JSON 有长度限制吗？** —— 没有，但嵌入式必须自己设上限防内存爆。

## 易错点

- 在小 RAM 上构建完整 DOM
- 不限制报文长度
