## 题目

**题目**：`xEventGroupWaitBits(eg, bits, xClearOnExit, xWaitForAllBits, timeout)` 里倒数第二个参数是什么意思？

**问**：「或」等待与「与」等待有什么区别？各自适合什么场景？

## 口述答案

> `xWaitForAllBits = pdTRUE` 是**与**等待：指定的位**全部**置位才唤醒；`pdFALSE` 是**或**等待：**任意一个**置位就唤醒。
> - **与**：适合"多个前置条件都满足才能继续"（网络 + 传感器 + 配置都就绪）；
> - **或**：适合"多个事件任一来就处理"（按键、串口、定时器任一触发）。

## 讲深一层

```c
// 与：三个都就绪
xEventGroupWaitBits(eg, BIT_A | BIT_B | BIT_C,
                    pdTRUE, pdTRUE, portMAX_DELAY);

// 或：任一个就绪，返回值告诉你是哪个
EventBits_t got = xEventGroupWaitBits(eg, BIT_A | BIT_B | BIT_C,
                                      pdTRUE, pdFALSE, portMAX_DELAY);
if (got & BIT_A) handle_a();
if (got & BIT_B) handle_b();
```

| 参数 | 值 | 含义 |
|---|---|---|
| `xClearOnExit` | `pdTRUE` | 返回前清除**满足条件的那些位** |
| `xWaitForAllBits` | `pdTRUE` | 全部置位才唤醒 |
| | `pdFALSE` | 任一置位就唤醒 |
| `xTicksToWait` | 0 / n / `portMAX_DELAY` | 立即返回 / 等 n tick / 永等 |
| **返回值** | `EventBits_t` | 唤醒时的位状态（含未等待的位） |

**返回值要注意**：它返回的是**当时的全部位状态**，不只是你等的那几位，所以判断时要用 `&` 掩码。

**超时的处理**：超时返回时位可能部分满足，必须检查返回值是否符合预期，不能只看"函数返回了"。

## 高频追问

1. **`xClearOnExit` 清哪些位？** —— 只清你等待的那些位中已置位的。
2. **超时后位会保留吗？** —— 会，除非设了 `xClearOnExit`。
3. **能在中断里等待吗？** —— 不能，中断里只能 set，不能 wait。

## 易错点

- 与/或参数搞反，条件永远不满足
- 不检查返回值，超时也当成功
- 忘了 `xClearOnExit`，位粘住
