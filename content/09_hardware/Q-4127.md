## 题目

**题目**：串口中断里收到一帧数据，要通知任务处理。写了 `xSemaphoreGive(sem)` 编译不过。

**问**：在中断里发信号为什么要用 FromISR 版本？三步曲是什么？

## 口述答案

> 因为中断上下文**不能阻塞**，而普通版本内部可能会阻塞（等锁、触发调度）。FromISR 版本不阻塞，并且需要知道"是否唤醒了更高优先级任务"。
> 三步曲：**用 FromISR 版本 → 接收 `xHigherPriorityTaskWoken` → 用 `portYIELD_FROM_ISR` 决定是否立即切换**。

## 讲深一层

```c
void USART1_IRQHandler(void) {
    BaseType_t woken = pdFALSE;

    // 1. FromISR 版本
    xSemaphoreGiveFromISR(uart_sem, &woken);

    // 2. 清中断标志（别忘了）
    __HAL_UART_CLEAR_OREFLAG(&huart1);

    // 3. 按需切换
    portYIELD_FROM_ISR(woken);
}
```

| API | 任务中 | 中断中 |
|---|---|---|
| 给信号量 | `xSemaphoreGive` | `xSemaphoreGiveFromISR` |
| 发队列 | `xQueueSend` | `xQueueSendFromISR` |
| 置事件位 | `xEventGroupSetBits` | `xEventGroupSetBitsFromISR` |
| 延时 | `vTaskDelay` | ❌ 不可用 |

**`xHigherPriorityTaskWoken` 的作用**：如果被唤醒的任务优先级高于当前被打断的任务，就应该在中断退出时立刻切换过去，而不是等下一个 tick——这能显著降低延迟。

**`portYIELD_FROM_ISR` 的写法**：老版本是 `portEND_SWITCHING_ISR(woken)`；新版也可以直接 `portYIELD_FROM_ISR(woken)`，内部会判断。

## 高频追问

1. **忘了 `portYIELD_FROM_ISR` 会怎样？** —— 不会错，只是延迟变高（要等下一个 tick 才切换）。
2. **能在中断里调用 `vTaskDelay` 吗？** —— 不能，中断没有任务上下文。
3. **中断优先级有什么限制？** —— 优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`，否则不能调 API。

## 易错点

- 中断里调用非 FromISR 版本
- 忘了传 `&woken` 或忘了 `portYIELD_FROM_ISR`
- 中断优先级配得过高，调用 API 直接 HardFault
