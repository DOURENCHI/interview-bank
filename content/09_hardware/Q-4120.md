## 题目

**追问**：按键任务里 `vTaskDelay(10)` 既能消抖，又刚好够用。为什么不能改成 100 ms？

**问**：延时长短各有什么代价？怎么选？

## 口述答案

> 延时就是**扫描周期**：太长会漏掉快速点按（按下 50 ms 就松开，100 ms 扫一次可能完全没看到）；太短则任务频繁唤醒，白耗 CPU。
> 10–20 ms 是折中：**大于机械抖动时间（5–20 ms，天然消抖），小于人的最快点按（约 50–100 ms）**。

## 讲深一层

| 扫描周期 | 漏按风险 | CPU 开销 | 消抖效果 |
|---|---|---|---|
| 1 ms | 无 | 高（每秒 1000 次唤醒） | 需要软件消抖 |
| 10 ms | 极低 | 低 | 天然消抖 |
| 20 ms | 低 | 更低 | 天然消抖 |
| 100 ms | **高**（快速点按丢失） | 最低 | 过长，响应迟钝 |

```c
// 更好的做法：中断唤醒 + 任务处理，兼顾省电和响应
void EXTI_IRQHandler(void) {
    BaseType_t woken = pdFALSE;
    xSemaphoreGiveFromISR(key_sem, &woken);
    portYIELD_FROM_ISR(woken);
}

void task_key(void* p) {
    for (;;) {
        xSemaphoreTake(key_sem, portMAX_DELAY);   // 睡到按键按下
        vTaskDelay(pdMS_TO_TICKS(20));            // 消抖
        if (still_pressed()) handle_press();
    }
}
```

**`vTaskDelay` 的实际时长**：至少 n 个 tick，可能多一个（取决于调用时刻在 tick 周期的位置），所以"10 ms"实际是 10–11 ms。

## 高频追问

1. **为什么不用定时器中断做消抖？** —— 会引入更多中断，反而不如轮询简单。
2. **多按键能共用一个任务吗？** —— 能，一次扫全部，10 ms 够用。
3. **低功耗怎么兼顾？** —— 用 EXTI 唤醒，空闲时进 STOP 模式。

## 易错点

- 扫描周期设 100 ms，快速点按丢失
- 周期设 1 ms 却不做消抖，一次按下触发多次
- 以为 `vTaskDelay(10)` 精确等于 10 ms
