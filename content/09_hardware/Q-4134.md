## 题目

**题目**：定时器回调里读了一个 I2C 传感器（约 5 ms），结果其他定时器全部延迟。

**问**：回调函数为什么绝对不能阻塞？正确做法是什么？

## 口述答案

> 因为**所有软件定时器的回调都在同一个守护任务里串行执行**。一个回调阻塞 5 ms，后面所有到期定时器就都晚 5 ms——定时精度被最慢的回调决定。
> 正确做法：回调里只做**极轻的标记动作**（置标志、发信号量、发队列），耗时操作交给普通任务。

## 讲深一层

```c
// ❌ 回调里做耗时操作
void cb_slow(TimerHandle_t t) {
    i2c_read_sensor();      // 5 ms，阻塞所有定时器
}

// ✅ 回调只发通知
void cb_fast(TimerHandle_t t) {
    BaseType_t woken = pdFALSE;
    xSemaphoreGiveFromISR(sensor_sem, &woken);   // 或 xTaskNotifyGive
    portYIELD_FROM_ISR(woken);
}

void task_sensor(void* p) {
    for (;;) {
        xSemaphoreTake(sensor_sem, portMAX_DELAY);
        i2c_read_sensor();           // 耗时操作在任务里
    }
}
```

| 回调里禁止 | 原因 |
|---|---|
| `vTaskDelay` | 阻塞守护任务 |
| 等信号量/队列 | 同上 |
| `malloc` | 不确定耗时 |
| 长 `printf` | 慢且可能阻塞 |
| 大量浮点运算 | 占满守护任务 |

**同样的规则适用于中断**：ISR 也必须是"标记 + 退出"，耗时逻辑交给任务。这是 RTOS 设计的通用原则——**中断和回调只负责"通知"，任务负责"干活"**。

## 高频追问

1. **回调里能调用 `xTimerStop` 吗？** —— 能，它是非阻塞的命令投递。
2. **`xTaskNotifyGive` 和信号量哪个好？** —— 通知更轻（不占额外内存），但要配对使用。
3. **守护任务栈要开多大？** —— 按回调里最深的调用链估，用 `printf` 时要 512 字以上。

## 易错点

- 回调里做 I/O 或 `vTaskDelay`
- 回调里 `malloc`
- 守护任务栈开太小
