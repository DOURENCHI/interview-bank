## 题目

**题目**：驱动层要在数据到达时通知上层，但驱动不该知道上层是谁。

**问**：什么是回调函数？它在嵌入式里怎么用？

## 口述答案

> 回调是**把函数指针注册给底层，底层在合适时机反过来调用它**——这样底层不需要知道上层的具体实现，实现了解耦。
> 嵌入式里到处都是：HAL 的中断回调、`qsort` 的比较函数、RTOS 定时器回调、事件注册表。

## 讲深一层

```c
typedef void (*on_data_t)(const uint8_t* buf, uint16_t len);

void uart_register_callback(on_data_t cb);   // 上层注册
// 驱动收到数据时：
if (cb) cb(buf, len);
```
| 要点 | 说明 |
|---|---|
| 判空 | 必须先判 `cb != NULL` |
| 上下文 | 中断里回调 → 回调必须极短 |
| 生命周期 | 回调里别引用已销毁的对象 |
| 可重入 | 多任务/中断下要保证线程安全 |
- C++ 里可以用 `std::function` + lambda，但会引入动态分配，嵌入式慎用。
- 更轻的替代：**任务通知**或**事件标志**，省一次函数调用和栈开销。

## 高频追问

1. **回调在中断里执行要注意什么？** —— 不能阻塞、不能调用非 FromISR 的 API。
2. **回调能带上下文参数吗？** —— 加一个 `void* user_data` 参数（注册时一起传）。

## 易错点

- 回调指针不判空
- 在中断回调里做耗时操作
