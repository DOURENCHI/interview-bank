## 题目

**题目**：`xTaskCreate` 和 `xTaskCreateStatic` 该怎么选？

**问**：FreeRTOS 创建任务有几种方式？动态和静态差在哪？

## 口述答案

> 两种：**`xTaskCreate`**（动态，从 FreeRTOS 堆里 `malloc` 出 TCB 和栈）和 **`xTaskCreateStatic`**（静态，你自己提供 TCB 和栈的内存）。
> 动态方便但会产生**堆碎片**、可能在运行时失败；静态**在编译期就确定内存**，不占堆、不会失败，适合安全关键或长期运行的系统。

## 讲深一层

```c
// 静态创建：内存自己给
StaticTask_t tcb;
StackType_t  stack[128];
xTaskCreateStatic(task_fn, "t", 128, NULL, 2, stack, &tcb);
```
| 维度 | 动态 | 静态 |
|---|---|---|
| 内存来源 | FreeRTOS 堆 | 用户提供数组 |
| 会失败吗 | 会（堆不够） | 不会 |
| 碎片 | 可能有 | 无 |
| 配置要求 | `configSUPPORT_DYNAMIC_ALLOCATION` | `configSUPPORT_STATIC_ALLOCATION` |
- 静态创建还要提供空闲任务和定时器任务的内存（`vApplicationGetIdleTaskMemory` 等回调）。
- 量产项目倾向静态分配，把所有内存开销在 map 文件里看清楚。

## 高频追问

1. **静态创建需要额外实现什么？** —— 空闲任务/定时器任务的内存回调。
2. **动态创建失败怎么发现？** —— 检查返回值 `pdPASS`，或实现 `vApplicationMallocFailedHook`。

## 易错点

- 动态创建不检查返回值
- 开了静态支持却没实现内存回调（链接失败）
