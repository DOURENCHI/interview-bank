## 题目

**问**：字符设备驱动从 open 到 read，大概会走哪些流程？

## 口述答案

> **注册阶段**：`alloc_chrdev_region` 申请设备号 → `cdev_init` + `cdev_add` 挂到 cdev_map → `class_create` + `device_create` 生成 `/dev` 节点。
> **open**：用户态 `open()` → VFS `do_sys_open` → `path_openat` 找到 inode → `vfs_open` 调用 `file->f_op->open`，字符设备会先通过设备号在 cdev_map 找到 cdev，把 `f_op` 换成驱动的 ops。
> **read**：`vfs_read` → `file->f_op->read`（或 `read_iter`）→ 驱动里取数据 → `copy_to_user` 把内核缓冲拷回用户态。

## 讲深一层

```
open:  sys_open → do_sys_open → vfs_open → chrdev_open → fops->open
read:  sys_read → vfs_read → fops->read → copy_to_user
```
| 结构 | 作用 |
|---|---|
| `file_operations` | open/read/write/ioctl/release |
| `cdev` | 设备号 → ops 的映射 |
| `inode` | 代表设备节点 |
| `file` | 每次打开一个实例 |

## 高频追问

1. **主设备号和次设备号各是什么？** —— 主设备号对应驱动，次设备号对应具体设备实例。
2. **`copy_to_user` 能睡眠吗？** —— 可能睡眠（缺页），不能在原子上下文调用。
3. **misc 设备是什么？** —— 主设备号固定 10，简化注册的一类字符设备。

## 易错点

- 直接解引用用户态指针，必须走 copy_from/to_user。
- 忘记在 release 里释放资源。
