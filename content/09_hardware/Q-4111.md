## 题目

**题目**：`configMAX_SYSCALL_INTERRUPT_PRIORITY` 写成 `5 << 4`，为什么不是直接写 5？

**问**：为什么 FreeRTOS 的中断优先级要左移 4 位？不左移会怎样？

## 口述答案

> 因为 Cortex-M 的 NVIC 优先级寄存器是 **8 位字段**，但芯片只实现了**高位的那几位**（常见 4 位）。硬件规定：**优先级值必须放在高 4 位**，低 4 位无效。
> 所以 4 位优先级 `5`（二进制 0101）写进寄存器要变成 `0101 0000` = `0x50` = `5<<4`。直接写 5 会被硬件当成"最高优先级"（因为低 4 位被忽略，高 4 位是 0）。

## 讲深一层

```
NVIC IPR 寄存器（8 位），芯片实现 4 位：
  位: 7 6 5 4 | 3 2 1 0
      ↑ 有效   ↑ 读回为 0
  优先级 5 → 0101 0000 = 0x50
  直接写 5 → 0000 0101 → 硬件读到高 4 位 0000 = 最高优先级！
```

| 写法 | 实际优先级 | 后果 |
|---|---|---|
| `5 << 4` = 0x50 | 5 | ✅ 正确 |
| `5` = 0x05 | 0（最高） | ❌ 变成最高优先级，可能破坏临界区 |
| `15 << 4` = 0xF0 | 15（最低） | ✅ |

```c
#define configKERNEL_INTERRUPT_PRIORITY      (15 << 4)   // PendSV/SysTick 最低
#define configMAX_SYSCALL_INTERRUPT_PRIORITY (5 << 4)    // 高于它（数值更小）的中断不能调 API
```

**为什么这么严格**：FreeRTOS 的临界区通过 `BASEPRI` 屏蔽中断，只屏蔽"优先级数值 ≥ 阈值"的中断。如果某个中断优先级配错成 0，它不会被屏蔽，在里面调用 `xQueueSend` 就会破坏内核数据结构。

**CMSIS 有现成宏**：`NVIC_SetPriority(IRQn, pri)` 内部会做移位，但 FreeRTOSConfig.h 里的宏是直接写寄存器值，所以要自己移。

## 高频追问

1. **怎么知道芯片实现了几位优先级？** —— 读 `NVIC->IPR` 写 0xFF 再读回，看低几位被清零。
2. **8 位全实现的芯片要移吗？** —— 不用，但为可移植性一般仍按 4 位写。
3. **`configPRIO_BITS` 是什么？** —— FreeRTOS 用它表示实现的优先级位数，通常在移植文件里定义。

## 易错点

- 直接写 `5` 而不是 `5 << 4`
- 以为优先级数值越大越高
- 在高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断里调用 FreeRTOS API
