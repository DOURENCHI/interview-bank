## 题目

**题目**：优先级寄存器有 4 个有效位，但配置时分成"抢占优先级"和"子优先级"两部分。

**问**：4 个比特位怎么分出「抢占」和「子」？分组怎么影响行为？

## 口述答案

> 4 位可以被**分组**切分：GROUP_4 是 4 位抢占 + 0 位子；GROUP_2 是 2+2；GROUP_0 是 0+4。
> - **抢占优先级**决定"能不能打断正在执行的 ISR"；
> - **子优先级**只在"同时挂起"时决定谁先执行，**不能打断**。

## 讲深一层

| 分组 | 抢占位 | 子位 | 可抢占级数 | 同抢占时的排序 |
|---|---|---|---|---|
| GROUP_0 | 0 | 4 | 0（不能抢占） | 16 级 |
| GROUP_1 | 1 | 3 | 2 | 8 |
| GROUP_2 | 2 | 2 | 4 | 4 |
| GROUP_3 | 3 | 1 | 8 | 2 |
| GROUP_4 | 4 | 0 | 16 | 无（同抢占=同优先级） |

```c
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);
HAL_NVIC_SetPriority(TIM2_IRQn, 2, 0);     // 抢占 2，子 0
HAL_NVIC_SetPriority(EXTI0_IRQn, 1, 0);    // 抢占 1 → 可打断 TIM2
```

**选择建议**：
- **不需要嵌套** → GROUP_4（HAL 默认），一个数字就是一个优先级，最不容易错；
- **需要"同抢占级内排序"** → GROUP_2 或 3。

**一个实际陷阱**：如果两个中断配了相同抢占优先级，它们**不能互相打断**，但可以互相"排队"。有人误以为子优先级高的能打断低的——不能。

## 高频追问

1. **中途改分组会怎样？** —— 已配置的优先级被重新解释，行为全乱。
2. **优先级 0 最高还是最低？** —— 0 最高。
3. **和 FreeRTOS 冲突吗？** —— 会，RTOS 要求可调 API 的中断优先级数值 ≥ 某阈值。

## 易错点

- 以为子优先级能抢占
- 中途改分组
- 与 RTOS 混用时优先级越界
