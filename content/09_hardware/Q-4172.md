## 题目

**题目**：SPI 只有 MOSI 和 MISO 两根数据线，为什么叫"全双工"？

**问**：SPI 为什么必须「发一个才能收一个」？全双工体现在哪？

## 口述答案

> 因为 SPI 是**两个移位寄存器首尾相连**：主机和从机各有一个 8 位移位寄存器，时钟每打一拍，主机移出一位到从机、从机移出一位到主机，**同时进行**。
> 所以"收"和"发"是同一个动作的两面——你想收 1 字节，就必须发 1 字节（内容无所谓，常发 0xFF）。

## 讲深一层

```
主机 SR ──MOSI──▶ 从机 SR
主机 SR ◀──MISO── 从机 SR
        （同一个时钟，同时移位）
```

```c
// 读一个字节 = 写一个字节
uint8_t spi_transfer(uint8_t out) {
    HAL_SPI_TransmitReceive(&hspi1, &out, &in, 1, 100);
    return in;
}
```

| 模式 | 数据线 | 能否同时收发 | 速度 |
|---|---|---|---|
| SPI | MOSI + MISO | ✅ 全双工 | 高（几十 MHz） |
| I2C | SDA 一根 | ❌ 半双工 | 中（100k–3.4M） |
| UART | TX + RX | ✅ 全双工 | 中 |

**推论**：
1. **只读不写是不可能的**——必须发 dummy 字节来产生时钟；
2. **主机发得慢，从机也收得慢**——速度由主机时钟决定；
3. **CS 决定和谁通信**，一主多从靠片选切换。

**常见误解**：以为"读的时候不用发"。实际读传感器时，主机发的 dummy 字节通常被从机忽略，但时钟是必须的。

## 高频追问

1. **发 0xFF 还是 0x00 有区别吗？** —— 对多数从机无所谓，但有些芯片要求特定值，查手册。
2. **SPI 有应答机制吗？** —— 没有，全靠 CS 和时序，所以更容易出问题。
3. **DMA 能加速吗？** —— 能，一次搬一整块，减少中断次数。
