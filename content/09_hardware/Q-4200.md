## 题目

**题目**：重定向 `printf` 到串口后，接调试器时能打印，拔掉调试器程序卡死。

**问**：`printf` 重定向到串口的原理是什么？为什么要关掉半主机模式？

## 口述答案

> 原理是**重写底层字符输出函数**：`printf` 内部最终调用 `fputc`（或 `_write`），你把它改成往串口发一个字节即可。
> **半主机（semihosting）** 是 ARM 的调试机制：`printf` 通过 `BKPT` 指令请求调试器帮忙输出。**没有调试器时这个断点没人响应，程序就停在那里死等**——所以必须禁用半主机，改用真正的串口输出。

## 讲深一层

```c
// 方式一：重写 fputc（Keil / newlib 常用）
int fputc(int ch, FILE* f) {
    HAL_UART_Transmit(&huart1, (uint8_t*)&ch, 1, 10);
    return ch;
}

// 方式二：重写 _write（GCC newlib）
int _write(int fd, char* ptr, int len) {
    HAL_UART_Transmit(&huart1, (uint8_t*)ptr, len, 100);
    return len;
}
```

```c
// 禁用半主机（GCC）
#pragma import(__use_no_semihosting)
// 或用 microlib / --specs=nosys.specs
```

| 方式 | 依赖 | 无调试器时 |
|---|---|---|
| 半主机 | 调试器 | ❌ 卡死 |
| 重写 fputc/_write | 串口 | ✅ 正常 |
| ITM/SWO | 调试器（SWO 线） | ❌ |

**调试器能打印的原因**：半主机请求被调试器接住了，所以"看起来正常"——这就是最迷惑的地方，只有脱机运行才暴露。

**另一个坑**：`printf` 吃栈（几百字节）且不是线程安全的，RTOS 里要加锁或改用 `snprintf`。

## 高频追问

1. **怎么确认用了半主机？** —— 反汇编能看到 `BKPT 0xAB` 指令。
2. **microlib 有什么代价？** —— 不支持某些 C 库特性（如 `locale`），但体积小。
3. **能不用 printf 吗？** —— 能，用 `snprintf` 到缓冲再 `HAL_UART_Transmit`，可控且线程安全。

## 易错点

- 只测调试器环境，没测脱机
- 忘了禁半主机，独立运行卡死
- RTOS 里多任务 `printf` 输出交错
