## 题目

**问**：`fork` 做了什么？为什么紧接着通常要 `exec`？

## 口述答案

> `fork` 创建一个子进程，**复制父进程的地址空间**（写时复制，不是立刻全拷）、文件描述符表、信号处理等，
> 返回值在父进程里是子进程 PID，在子进程里是 0。
> 但 fork 出来的子进程跑的还是父进程的代码，所以要执行新程序必须 `exec`——
> `exec` 用新程序**替换**当前进程的代码段和数据段，PID 不变。
> 这就是 shell 执行外部命令的两步：fork 出子进程，子进程里 exec。

## 讲深一层

```c
pid_t pid = fork();
if (pid == 0) {
    execl("/bin/ls", "ls", "-l", NULL);
    _exit(127);                 // exec 失败才走到这
} else if (pid > 0) {
    int st; waitpid(pid, &st, 0);   // 父进程等子进程
} else {
    perror("fork");
}
```

| 调用 | 作用 | PID |
|---|---|---|
| fork | 复制出新进程 | 新 PID |
| exec | 替换程序映像 | 不变 |
| wait/waitpid | 回收子进程 | — |

**写时复制（COW）**：fork 后父子共享物理页，谁写谁拷贝，所以 fork 本身很快。

## 高频追问

1. **不 wait 会怎样？** —— 子进程变僵尸（占着进程表项）。
2. **`vfork` 和 `fork` 区别？** —— vfork 共享地址空间且阻塞父进程，只为 exec 用。
3. **`posix_spawn` 呢？** —— 封装 fork+exec，某些场景更快。

## 易错点

- ❌ 忘了 wait —— 僵尸进程
- ❌ 以为 fork 立刻全量拷贝内存
- ✅ 说清「fork 复制、exec 替换、wait 回收」
