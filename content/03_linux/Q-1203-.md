## 题目

**背景**：面试官在纸上写了 `struct { char a; int b; char c; }`，让你算 sizeof，再问能不能改成员顺序让它更小。
**问**：结构体大小怎么算？怎么调整成员排布更省内存？

## 口述答案

> 两条对齐规则：每个成员的偏移量必须是"自身对齐数"（默认为自身大小，可被 pack 修改）的整数倍；整个结构体大小必须是最大成员对齐数的整数倍。上面那个结构体：a 占 0，b 要对齐到 4，跳 3 字节占 4–7，c 占 8，再补齐到 4 的倍数 → 12 字节。省内存的办法是按对齐数从大到小排成员：`int b; char a; char c;` 变成 8 字节。本质是让填充洞集中在尾部而不是散在中间。

## 讲深一层

```c
struct A { char a; int b; char c; };  // 1+3(洞)+4+1+3(尾) = 12
struct B { int b; char a; char c; };  // 4+1+1+2(尾)    = 8
```
- `#pragma pack(1)` 可以关对齐，但成员可能跨缓存行/总线，ARM 上非对齐访问可能直接异常，网络协议解析除外一般别用
- 缓存行（64B）视角：热成员放前 64 字节，读写频繁的成员分开放避免伪共享

## 高频追问

1. 为什么需要内存对齐？——CPU 按字长访问，非对齐要么多次访问要么硬件不支持
2. `sizeof(struct)` 和各成员 sizeof 之和为什么不相等？

## 易错点

- 只背"4 的倍数"不区分成员各自的对齐数；long 在 64 位 Linux 是 8 字节
- 忘了整体也要对齐到最大成员的倍数
