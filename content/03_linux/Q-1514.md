## 题目

**题目**：程序在客户现场出问题，没有 IDE，只有 SSH。

**问**：常用的调试方法有哪些？各自适合什么场景？

## 口述答案

> 按"问题类型"选：**崩溃/内存问题**用 core dump + gdb、ASan、valgrind；**逻辑问题**用打日志、gdb 断点；**性能问题**用 `perf`、`gprof`、`strace`；**死锁/卡住**用 `pstack`、`gdb -p` 看线程栈；**系统调用层**用 `strace`。
> 一句话原则：**先缩小范围（日志/监控），再上重武器（调试器/分析器）**。

## 讲深一层

| 场景 | 工具 |
|---|---|
| 段错误 | `ulimit -c unlimited` + `gdb ./app core` |
| 内存越界 | ASan、valgrind |
| CPU 高 | `perf top`、`gprof` |
| 卡住/死锁 | `gdb -p <pid>` + `thread apply all bt` |
| 系统调用异常 | `strace -f -T` |
| 网络问题 | `tcpdump`、`ss` |
- 现场排查三件套：`dmesg`（内核日志）、`top`（资源）、`ss`（连接）。
- `gdb` 的 `bt`、`info threads`、`thread apply all bt` 是诊断卡死的第一选择。

## 高频追问

1. **没有 core dump 怎么办？** —— 先开 `ulimit -c`，或让程序装 `SIGSEGV` 处理器打印栈。
2. **`strace` 影响性能吗？** —— 显著影响（每次系统调用都要停），只适合短时诊断。

## 易错点

- 只会 `printf` 打日志
- 现场直接跑 valgrind（慢到不可用）
