## 题目

**题目**：UDP 说"无连接"，那它通信前到底要不要做什么？

**问**：TCP 和 UDP 有什么区别？各自的连接流程是什么？

## 口述答案

> TCP 是**面向连接、可靠、有序、有流控**的字节流；UDP 是**无连接、不可靠、保留消息边界**的数据报。
> 流程上：TCP 要先三次握手建连、传完四次挥手；UDP 只 `sendto/recvfrom`，**没有建连过程**（`connect` 只是绑定默认对端，不产生网络报文）。

## 讲深一层

| 维度 | TCP | UDP |
|---|---|---|
| 连接 | 三次握手 | 无 |
| 可靠性 | 确认重传 | 不保证 |
| 顺序 | 保证 | 不保证 |
| 边界 | 字节流（会粘包） | 保留边界 |
| 开销 | 20+ 字节头 + 状态机 | 8 字节头 |
| 适用 | 文件、HTTP、SSH | 音视频、DNS、游戏、广播 |
- TCP 的可靠性靠：序号 + 确认 + 超时重传 + 校验和 + 流控 + 拥塞控制。
- UDP 要可靠就得自己在应用层做（QUIC 就是这么干的）。

## 高频追问

1. **UDP 会丢包吗？** —— 会，链路拥塞、缓冲满都会丢，应用自己处理。
2. **TCP 会粘包，UDP 会吗？** —— 不会，UDP 保留消息边界。

## 易错点

- 说 UDP 的 `connect` 会发报文（不会）
- 以为 TCP 一定比 UDP 快/慢（取决于场景）
