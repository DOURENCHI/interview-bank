## 题目

**问**：**如何让一个线程绑定在一个 CPU 核心上，让它一直在那个核运行？**

## 口述答案

> Linux 下三种常用入口：
> ```c
> /* ① 线程级（最常用） */
> #define _GNU_SOURCE
> #include <pthread.h>
> cpu_set_t set; CPU_ZERO(&set); CPU_SET(4, &set);
> pthread_setaffinity_np(pthread_self(), sizeof(set), &set);
> /* ② 进程级 */
> sched_setaffinity(0, sizeof(set), &set);
> /* ③ 命令行（不改代码） */
> /* taskset -c 4 ./app   或   taskset -pc 4 <pid> */
> ```
> "一直运行"的准确理解：亲和性只保证**只在这个核上被调度**，不保证独占——想让核不被别人抢，还要把其他任务/中断迁走（isolcpus 内核参数 + irqbalance 排除），构成"独占核"方案，低延迟交易/DPDK 就是这么干的。

## 讲深一层

容器环境注意：cgroup cpuset 已经限制了可用核集合，再 setaffinity 取交集；`nproc` 看到的可能不是物理核数。线程池类框架（如 OpenMP）用环境变量 `GOMP_CPU_AFFINITY` / OMP_PROC_BIND 设置更方便。

## 高频追问

1. **绑核后缓存一定更好吗？** —— 同核被 SMT 兄弟线程抢执行单元也会抖；严格独占要关 SMT 或隔离兄弟核。
2. **怎么验证绑定了？** —— `top` 按 H 看 CPU 列，或 perf 里看迁移次数（migrations）归零。

## 易错点

- 混淆 `pthread_setaffinity_np` 与 `sched_setaffinity` 的对象（线程 vs 进程）
- 以为绑核等于独占——还要隔离中断和其他任务
