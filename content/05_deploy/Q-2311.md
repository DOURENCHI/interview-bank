## 题目

**背景**：量化方案设计时要在对称和非对称之间选，面试官追问判断依据。

**问**：对称量化和非对称量化分别是什么？实际项目里你怎么选？

## 口述答案

> 结论：**看分布是否零均值对称，以及硬件 kernel 支持哪种**。对称量化令 `zero_point = 0`，范围 `[-127, 127]`，`scale = max(|min|,|max|)/127`；权重近似零均值正态，用对称最合适，zp 为 0 时还能省掉零点修正项。非对称范围 `[0,255]`，`scale = (max-min)/255`，`zp = round(-min/scale)`，适合 ReLU 后的激活和全为正的特征。实际：权重对称逐通道，激活偏斜用非对称；但很多 NPU 只支持对称。

## 讲深一层

```
对称:   q = clamp(round(x / s), -127, 127),  s = max(|x|)/127
非对称: q = clamp(round(x / s) + zp, 0, 255)
        s = (max-min)/255,  zp = round(-min/s)
反量化: x̂ = s * (q - zp)
```
| | 对称 | 非对称 |
|---|---|---|
| 码点利用 | 偏斜分布浪费 | 充分利用 |
| 计算开销 | 无 zp 修正 | 多一项 |
| 硬件支持 | 广泛 | 部分不支持 |

## 高频追问

1. **per-tensor 和 per-channel 怎么选？** —— 权重必须 per-channel，否则通道间动态范围差异会毁掉小通道；激活一般 per-tensor。
2. **离群值怎么处理？** —— 用 percentile 截断（99.99%）而非 max，或做 clipping 搜索；LLM 里可用 AWQ/SmoothQuant 把难度转移到权重。
3. **zp 为什么常取整数？** —— 便于用整数指令做零点修正；实现里 zp 也可量化成 int8。

## 易错点

- 所有权重都用 per-tensor 对称，小通道精度崩塌
- 非对称量化后忘了反量化时减 zp
- 认为非对称一定更准，忽略硬件不支持带来的回退开销
