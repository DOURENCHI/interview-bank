## 题目

**背景**：团队把模型从 INT8 压到 INT4，理论上更省，实测却更慢，面试官要原因。

**问**：为什么换成 INT4 之后反而更慢了？怎么定位和解决？

## 口述答案

> 结论：**多数硬件没有真正的 INT4 算力，你只省了带宽，却多付了反量化开销**。W4A16 要把 4bit 权重解包、乘 scale 还原成 fp16 再进 GEMM，unpack 指令数可能超过矩阵乘本身；没有 int4 tensor core，只能回退 fp16/int8 通路；group size 与 tile 不对齐还会产生冗余访存。另外小 batch、短序列本来就是 memory-bound，一旦变成 compute-bound，解包开销直接体现为变慢。对策是用融合 kernel（Marlin/GPTQ fused）并对齐 group size。

## 讲深一层

| 场景 | INT4 预期 |
|---|---|
| 大 batch、长序列、memory-bound | 变快 |
| 小 batch、短序列、compute-bound | 可能变慢 |
| 无 int4 指令的 NPU | 通常变慢 |

```bash
ncu --set full ...   # 看 DRAM throughput vs SM busy
```
判断瓶颈：算 arithmetic intensity 对 roofline，或直接看 profiler 的 DRAM 利用率与 SM 占用率。

## 高频追问

1. **怎么判断是 memory-bound 还是 compute-bound？** —— 看 profiler 的 DRAM 利用率与 SM 占用；两者都不高通常是 kernel 没打满。
2. **INT4 的收益在什么条件下成立？** —— 模型足够大、decode 阶段 batch 足够大、有专用 kernel，三者缺一收益都可能为负。
3. **端上还有别的坑吗？** —— ARM 缺少高效 4bit 解包指令，需 LUT 或 bit trick，NEON 实现质量差异很大。

## 易错点

- 认为"位宽减半速度就翻倍"
- 忽略解包/反量化开销，只算理论 FLOPs
- 只测 prefill 不测 decode，结论反了
