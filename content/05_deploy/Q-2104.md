## 题目

**背景**：推理节点里有一个"单槽邮箱"：回调只把最新一帧的 `shared_ptr` 放进一个槽位，覆盖旧的，worker 线程取走处理。

**问**：为什么"只保留最新一帧"是对的？什么场景下这个设计反而是错的？

## 口述答案

> 对实时感知是对的，因为**旧帧没有价值**。检测的目的是知道"现在有什么"，处理一帧 200 ms 前的图像，结果出来时场景已经变了；而且队列会让延迟累积——越排越久，最后彻底失控。
> 单槽的语义就是"永远处理最新"，天然把延迟钉在一个常数上。
> **反例是"不能丢"的场景**：比如录制、离线分析、或者要做多帧融合（跟踪、时序模型），这时候丢帧会破坏数据完整性，必须用有界队列 + 背压。

## 讲深一层

```cpp
// 单槽邮箱：覆盖式投递
void onImage(const sensor_msgs::msg::Image::SharedPtr msg) {
    std::lock_guard<std::mutex> lk(m_);
    if (mailbox_) ++dropped_;      // 上一帧还没被取走 → 记一次丢弃
    mailbox_ = msg;                // 覆盖
    cv_.notify_one();
}
```

| 策略 | 延迟 | 丢帧 | 适合 |
|---|---|---|---|
| 深队列（depth=10） | 会累积 | 不丢 | 离线、必须完整 |
| 单槽覆盖 | 恒定 | 丢旧帧 | **实时感知** |
| 有界队列 + 背压 | 有上限 | 反压上游 | 不能丢但要限流 |

**为什么"记一次丢弃"很重要**：丢帧是设计的一部分，不是错误。但要可观测——丢帧率飙高说明算力不够，是扩容信号，不是静默忍受。

**代价**：单槽假设"每帧独立"。做跟踪时丢帧会让 ID 跳变，此时应该改成"跳帧但保留轨迹预测"。

## 高频追问

1. **单槽和 depth=1 的 DDS 队列有什么区别？** —— 效果类似，但单槽的丢弃发生在你的代码里，可计数、可打日志、可换成别的策略。
2. **丢帧率多少算正常？** —— 取决于场景，一般超过 30% 说明算力不匹配，要么降分辨率要么降帧率。
3. **多相机怎么办？** —— 每路一个槽位，或按时间戳对齐后取最新的一组。
