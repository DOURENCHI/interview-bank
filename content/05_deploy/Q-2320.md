## 题目

**背景**：端上模型和云端模型回答风格、质量不一致，面试官问怎么对齐。

**问**：端上模型的效果怎么和云端对齐？有哪些可控变量和评估手段？

## 口述答案

> 结论：对齐要控住**输入、解码、权重**三处变量。1. 输入：同一套 prompt 与 chat 模板、同一 tokenizer、相同的 BOS/EOS 与特殊 token，截断策略也一致；2. 解码：temperature、top_p、repetition_penalty、max_tokens 全对齐，端上不能偷偷调低温度；3. 权重：端上用云端蒸馏 + 量化感知训练，而不是直接 PTQ。评估用 500~1000 条 prompt 双跑，算 embedding 余弦、ROUGE、偏好胜率、拒答率差，线上抽样监控。

## 讲深一层

| 变量 | 不对齐的表现 |
|---|---|
| chat template | 格式错乱、拒答 |
| tokenizer | 中文切分不同，长度差很多 |
| temperature | 端上更死板或更发散 |
| 截断长度 | 长文问答端上"忘了开头" |

```text
对齐度 = 0.4*cos_sim + 0.3*win_rate + 0.3*(1-|拒答率差|)
```

## 高频追问

1. **蒸馏数据怎么造？** —— 用云端模型对真实 prompt 采样，保留 logits 做 KD，或只用输出做 SFT；前者更好但工程重。
2. **量化后风格变了怎么办？** —— 检查是否只量化了 weight；激活量化对生成风格影响更大，可保留 fp16 激活。
3. **对齐到什么程度算够？** —— 偏好胜率不低于云端 45%，关键任务（格式抽取）准确率差距 <2%。

## 易错点

- 只比"看起来像不像"，没有量化指标
- 端上为了速度改了解码参数，却说模型对齐了
- 用测试集蒸馏，评估结果虚高
