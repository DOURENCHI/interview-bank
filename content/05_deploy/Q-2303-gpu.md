## 题目

**背景**：集群里同时有 A100、H100、4090，还有不同显存大小的卡。
**问**：深度学习平台怎么管理异构算力？

## 口述答案

> 分层来管。**注册层**：每台节点跑 device plugin（NVIDIA 的 k8s-device-plugin），把 GPU 按型号、数量、显存上报成 K8s 的扩展资源（`nvidia.com/gpu`），节点再打上型号标签。**调度层**：靠节点标签 + 亲和性/污点把任务路由到对的卡——训练任务按需求选 H100，推理小任务落到 4090；不同代次卡不混部时用 taint/toleration 隔离。**切分层**：大卡切小用 MIG（A100/H100 硬件级切分，隔离最干净）或时间片 vGPU。**队列层**：平台自己的调度器（Volcano 之类）按队列优先级和资源类型排队，配合配额。核心思想是：把"卡的差异"变成"可调度的标签与资源"，让算法同学只声明需求，不关心落在哪张卡。

## 讲深一层

| 层 | 机制 | 解决 |
|---|---|---|
| 上报 | device plugin + 节点标签 | 卡在哪、是什么 |
| 路由 | 亲和性/taint | 谁能用哪张卡 |
| 切分 | MIG / vGPU | 大卡化小 |
| 排队 | Volcano 队列 + 配额 | 公平与优先级 |

## 高频追问

1. MIG 和 vGPU 的区别？——MIG 硬件隔离粒度固定，vGPU 驱动层时分
2. 任务声明 `gpu: 1` 怎么保证落在想要的卡？——nodeSelector/affinity 配合型号标签

## 易错点

- 只答"打标签"，说不出 device plugin 这层资源上报机制
