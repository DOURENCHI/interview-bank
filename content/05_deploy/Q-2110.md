## 题目

推理阶段 GPU 利用率低，除了加卡还有什么办法？

## 口述答案

> 推理阶段 GPU 利用率低，先分清是**哪种低**：
> - **算力利用率低但显存忙**：多为 memory-bound（小 batch、频繁 kernel launch、KV cache 读写），优化：增大 batch/并发、kernel fusion、用 FlashAttention、量化；
> - **等待导致空闲**：请求排队不均、CPU 预处理/后处理成瓶颈、数据加载慢，优化：预处理上 GPU、异步流水线、多流并发；
> - **并行度不够**：单卡 batch 小，用 continuous batching / paged attention（vLLM 思路）提升并发；
> - **模型并行通信开销**：多卡 TP 时 all-reduce 占比高，优化：重叠通信与计算、调 TP 度、用 NVLink。
> 除加卡外的手段：量化（FP16/INT8/FP8）、KV cache 优化（PagedAttention/prefix cache）、投机解码、算子融合、编译优化（TensorRT-LLM）、请求调度（优先级/批处理）。

## 讲深一层

判断方法：`nvidia-smi` 看 SM 利用率与显存带宽，`nsys/ncu` 看 kernel 时间线，确认是 launch 间隙、访存瓶颈还是通信等待。

## 高频追问

1. **batch 越大越好吗？** —— 吞吐升但首 token 延迟升，要按 SLA 取平衡。
2. **prefix cache 能省多少？** —— 相同系统提示词/长文档场景可省大量 prefill，命中率是关键指标。

## 易错点

- 一上来就说"加卡/换卡"
- 不区分 compute-bound 与 memory-bound
