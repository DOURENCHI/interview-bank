## 题目

**题目**：视频标题是"手撕缓存聚合"，面试官要你设计一个支持多种淘汰策略的缓存。

**问**：手撕缓存聚合：多种淘汰策略的缓存怎么写？

## 口述答案

> 先抽象出**策略接口**，再用组合而不是一堆 if：
> - **接口**：`get(key)`、`put(key, value)`、`evict()`（淘汰谁由策略决定）
> - **通用骨架**：哈希表（O(1) 定位）+ 策略维护的"淘汰顺序"结构
> - **策略实现**：LRU 用双向链表、LFU 用"频率桶 + 最小频率指针"、FIFO 用队列
> 把"存哪里"和"淘汰谁"分开，加新策略只加一个类。

## 讲深一层

```cpp
struct EvictPolicy {           // 策略接口
    virtual void onAccess(int key) = 0;
    virtual void onInsert(int key) = 0;
    virtual int  pickVictim() = 0;
    virtual ~EvictPolicy() = default;
};
class LRUPolicy : public EvictPolicy { /* 双向链表 */ };
class LFUPolicy : public EvictPolicy { /* 频率桶 */ };
```
| 策略 | 结构 | 淘汰谁 |
|---|---|---|
| LRU | 哈希 + 双向链表 | 最久未用 |
| LFU | 哈希 + 频率桶 | 用得最少 |
| FIFO | 队列 | 最早进入 |
| ARC | 两组 LRU | 自适应 |
- 关键考点其实是**抽象能力**：把"策略"从"存储"里解耦，而不是写 10 个 if-else。
- 加分项：线程安全（分段锁）、过期时间（时间轮/最小堆）、统计命中率。

## 高频追问

1. **LFU 的难点在哪？** —— 要快速找到"最小频率"的桶，且频率变化时要移动节点。
2. **怎么做到线程安全又不太慢？** —— 分段锁（每段一把锁）或读写锁。

## 易错点

- 用 if-else 堆所有策略
- 忽略淘汰时的哈希表同步
