## 题目

**题目**：面试官让你手写一个跳表，并问"它凭什么能替代平衡树"。

**问**：手写一个跳表：它为什么能替代平衡树？

## 口述答案

> 跳表是**多层链表**：底层是完整有序链表，上面每层是下层的"抽样索引"（每个节点以 1/2 概率晋升）。查找时从最高层开始，能往右就往右，不能就往下一层，期望 **O(log n)**。
> 相比平衡树：**实现简单得多**（不用旋转/染色）、**并发友好**（局部加锁即可）、**范围查询自然**。Redis 的有序集合就是跳表。

## 讲深一层

```c
typedef struct Node { int val; struct Node* next[]; } Node;   // 柔性数组
// 查找
Node* find(int v) {
    Node* p = head;
    for (int i = level - 1; i >= 0; --i)
        while (p->next[i] && p->next[i]->val < v) p = p->next[i];
    return p->next[0];
}
```
| 维度 | 跳表 | 红黑树 |
|---|---|---|
| 查找 | 期望 O(log n) | O(log n) |
| 实现难度 | 低 | 高（旋转/染色） |
| 并发 | 易于局部加锁 | 旋转影响范围大 |
| 内存 | 每节点平均 2 个指针 | 每节点 3 指针 + 颜色 |
| 最坏 | O(n)（概率极低） | 严格 O(log n) |

## 高频追问

1. **层高怎么定？** —— 随机 1/2 晋升，最大层通常 log2(n)；也可设上限 32。
2. **为什么并发友好？** —— 插入只影响局部几个指针，可以分段加锁。

## 易错点

- 说跳表最坏也是 O(log n)（它是概率保证）
- 不会写"随机层高"这一步
