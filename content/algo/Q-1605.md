## 题目

**背景**：很多题一看是 O(n²) 的暴力，加个哈希表就变成 O(n)。但面试官常追问"为什么这里能用哈希"。

**问**：哈希表在这类题里一般解决什么问题？它把什么操作从 O(n) 降到了 O(1)？

## 口述答案

> 它解决的是**"我有没有见过这个值 / 它上次出现在哪"**这个问题。暴力解法里，判断"见过没有"要再扫一遍数组（O(n)），哈希把它降到 O(1)，于是整体从 O(n²) 降到 O(n)。
> 代价是**空间换时间**，而且哈希表无序——只要题目要求顺序或范围，就得换成有序结构（`map`、`set`）或排序。

## 讲深一层

三类典型用法：

| 用法 | 存什么 | 典型题 |
|---|---|---|
| 存在性 | `set` / `unordered_set` | 最长连续序列、两数之和 |
| 计数 | `unordered_map<elem,int>` | 字母异位词、和为 K 的子数组 |
| 位置映射 | `unordered_map<elem,index>` | 两数之和（返回下标） |

```cpp
// 两数之和：边遍历边建表，避免自己匹配自己
unordered_map<int,int> seen;
for (int i = 0; i < n; ++i) {
    auto it = seen.find(target - nums[i]);
    if (it != seen.end()) return {it->second, i};
    seen[nums[i]] = i;          // 放在判断之后，天然避免重复用同一元素
}
```

**顺序很重要**：先查后插，能避免"用同一个元素两次"。反过来写也能对，但要额外判断 `it->second != i`。

`unordered_map` 的最坏情况是 O(n)（哈希冲突），工程上一般可接受；如果对手写哈希不放心，或者需要稳定性能，用 `map`（O(log n)）更保险。

## 高频追问

1. **什么时候必须用 `map` 而不是 `unordered_map`？** —— 需要按 key 有序遍历、需要范围查询，或者 key 没有好的哈希函数。
2. **自定义类型当 key 要做什么？** —— `unordered_map` 要给哈希函数和 `operator==`；`map` 要给 `operator<`。
3. **哈希表能替代排序吗？** —— 不能。哈希不保序，涉及"第 k 大""区间"的题还是要排序或堆。

## 易错点

- 先插入再查询，导致同一个元素被用两次
- 用 `map` 却以为它是 O(1)
- key 是浮点数直接用（精度问题导致查不到）
