## 题目

**背景**：推荐系统召回阶段常用双塔结构，面试官想确认候选人是否理解两塔的特征边界。

**问**：双塔召回里，用户塔和物品塔分别喂哪些特征？为什么这样切分？

## 口述答案

> 结论：切分原则是**只放各自侧、请求时能独立拿到的特征**。用户塔：user id / 设备 id 的 embedding、人口属性、长期兴趣（行为序列 pooling 或 attention）、实时行为统计。物品塔：item id embedding、类目/品牌/店铺、价格档、标题与图文的内容 embedding、物品侧统计（历史 CTR/CVR、销量）。**任何交叉特征都不能进塔**——一旦用户塔需要 item 特征，物品向量就无法离线预计算，ANN 检索的前提就没了。

## 讲深一层

| 塔 | 输入 | 输出 |
|---|---|---|
| 用户 | id、画像、行为序列、实时统计 | 64~128 维 |
| 物品 | id、内容、类目、统计 | 同维，L2 归一化 |
| 交叉 | 不放 | 精排阶段做 |

训练用 in-batch softmax + sampled softmax；物品向量离线灌入 FAISS/HNSW，线上只算 user 向量做 ANN，延迟可压到毫秒级。

## 高频追问

1. **user id embedding 会不会过拟合？** —— 会，冷启动用户无 id 特征；用哈希分桶 + dropout，或退化到只用画像与行为。
2. **物品侧统计特征怎么防穿越？** —— 按样本时间做 as-of 聚合，只用该时刻之前的数据。
3. **两塔维度必须一样吗？** —— 内积要求一致；也可用双线性映射矩阵，但那会失去纯 ANN 的便利。

## 易错点

- 把 item 特征塞进用户塔，线上无法预计算
- 用未来统计量做物品特征，离线 AUC 虚高
- 两塔输出不归一化，内积被模长主导
