## 题目

**背景**：动态规划最难的一步不是写转移方程，是"想不出 `dp[i]` 该表示什么"。

**问**：状态定义该怎么想？什么样的状态定义是合格的？

## 口述答案

> 合格的状态定义要满足三条：**能覆盖所有情况**、**能写出转移**、**边界能初始化**。
> 实操上从"最后一步"倒推：问自己"答案的最后一步长什么样"，把最后一步需要的信息写成下标。比如"最大子数组和"，最后一步是"以 i 结尾"，那状态就是 `dp[i] 表示「以 i 结尾」的最大和——这个定义一写出来，转移自然就是"接上前面"或"从自己重新开始"。

## 讲深一层

三步法：

1. **确定"最后一步"**：答案由哪个决策产生？
2. **确定"需要的已知信息"**：做这个决策要查什么？把它变成下标。
3. **写出转移，再验证边界**。

| 题目 | 差的状态 | 好的状态 |
|---|---|---|
| 最大子数组和 | `dp[i]` = 前 i 个的最大和（无法转移） | `dp[i]` = **以 i 结尾**的最大和 |
| 最长递增子序列 | `dp[i]` = 前 i 个的 LIS | `dp[i]` = **以 i 结尾**的 LIS |
| 打家劫舍 | `dp[i]` = 前 i 间的最大金额 | 同左（可转移），但要定义"抢不抢 i" |
| 背包 | `dp[i]` = 前 i 件的最大价值 | `dp[i][j]` = 前 i 件、容量 j 的最大价值 |

**判断状态好不好用的土办法**：写转移方程时如果发现"需要知道更早的某个具体位置"，说明状态维度不够，要加一维。

```cpp
// 最大子数组和
int best = nums[0], cur = nums[0];
for (int i = 1; i < n; ++i) {
    cur = max(nums[i], cur + nums[i]);   // 接上 或 重新开始
    best = max(best, cur);
}
```

## 高频追问

1. **状态一定要用数组吗？** —— 不一定，能滚动就滚动（背包倒序、斐波那契用两个变量）。
2. **怎么判断能不能压缩空间？** —— 转移只依赖"上一轮"就能压；依赖"本轮更早的位置"要小心顺序。
3. **记忆化搜索和递推什么关系？** —— 同一个状态转移的两种写法，前者自顶向下、写起来快，后者自底向上、没有递归开销。

## 易错点

- 状态定义含糊（"前 i 个的最优"），导致转移写不出来
- 边界只初始化 `dp[0]`，忘了 `dp[1]`
- 压缩空间后忘了改遍历方向（背包必须倒序）
