## 题目

**背景**：模型需要实时行为特征，但流式计算有延迟，面试官追问链路的时效与兜底。

**问**：实时特征怎么接入线上推理？端到端延迟大概多少？延迟窗口内用什么补？

## 口述答案

> 结论：典型链路是**埋点 → Kafka → Flink 窗口聚合 → Redis/HBase → 推理时批量点查**，端到端 P99 约 1~5 秒，Flink 窗口触发占大头，点查本身通常 <5ms。延迟窗口内：1. 每条特征带 `feature_time`，只接受早于请求时刻的版本；2. 回退到离线 T+1 快照或上次成功值；3. 缺失填默认值，并把 `is_missing` 作为特征喂给模型；4. 特征服务设超时（如 20ms），超了直接降级，别拖垮主链路。

## 讲深一层

| 层 | 延迟量级 |
|---|---|
| 埋点上报 | 100ms~2s |
| Kafka 传输 | 10~100ms |
| Flink 窗口 | 1~60s（看窗口） |
| Redis 点查 | <5ms |
| 端到端 | 1~5s |

优化：滑动窗口用增量聚合而非全量重算；`MGET`/pipeline 批量取；本地 LRU 缓存热点用户特征，TTL 1~5s。

## 高频追问

1. **怎么保证实时和离线特征一致？** —— 复用同一份聚合逻辑，定期抽样比对数值分布。
2. **Flink 反压了怎么办？** —— 加并行度、预聚合、丢弃非关键维度；关键特征单独走低延迟链路。
3. **特征服务挂了降级到什么？** —— 离线快照（T+1）+ 默认值，同时打开降级开关并告警。

## 易错点

- 用"最新值"覆盖，导致训练看到旧值、线上看到未来值
- 特征服务无超时，一个慢查询拖垮整个推理
- 缺失值填 0 但不告诉模型，等于注入错误信号
