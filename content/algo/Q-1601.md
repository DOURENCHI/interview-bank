## 题目

**背景**：平时刷题用的是 LeetCode 那种「写个 `class Solution` 就交」的模式，函数签名都给你了。

**机考现场**：题目只给一段文字描述和一个样例，要求你自己读输入、自己打印输出，交上去是完整源文件。

**问**：为什么机考必须用 ACM 模式？「函数模式」和「ACM 模式」到底差在哪，最容易翻车的是哪一段？

## 口述答案

> 因为机考判题机只做一件事：**把输入喂给你的程序，比对标准输出**。它不知道什么是 `Solution` 类，也不调用你的函数，只认 `main` 里的 stdin 和 stdout。
> 所以差别不在算法，在**入口和 I/O**：函数模式你只管逻辑，输入输出由平台包好；ACM 模式这两件事全归你，读错一个空格、少打一个换行，逻辑再对也是 0 分。

## 讲深一层

| 维度 | 函数模式（LeetCode） | ACM 模式（机考） |
|---|---|---|
| 提交物 | 一个类 / 一个函数 | 完整可编译源文件 |
| 输入 | 平台构造参数传入 | 你自己从 stdin 读 |
| 输出 | 返回值 | 你自己往 stdout 打 |
| 多组用例 | 平台循环调用 | 你要写 `while (cin >> ...)` |
| 判分 | 比对返回值 | 逐字节比对输出文本 |

一个最小骨架：
```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    while (cin >> n) {          // 多组用例：读到 EOF 自动退出
        // ...
        cout << ans << '\n';    // 用 '\n' 不用 endl
    }
    return 0;
}
```

**为什么用 `'\n'` 不用 `endl`**：`endl` 每次都 flush，十万行输出能差出几百毫秒。机考时限紧的时候这就是超时原因。

## 高频追问

1. **多组用例怎么知道有几组？** —— 两种常见约定：先读一个 `T` 表示组数；或者读到 EOF。看到样例里有多段、又没说组数，就写 `while (cin >> ...)`。
2. **`bits/stdc++.h` 能用吗？** —— GCC 下能用，机考环境基本都是 GCC；但本地用 MSVC 会报错，写代码时注意别在 VS 里试。
3. **输入里有中文/特殊字符要注意什么？** —— 按字节读，别用 `scanf("%s")` 读含空格的整行，用 `getline`。

## 易错点

- 只写函数不写 `main`，交上去编译失败
- 每组用例之间忘了输出换行，答案全挤在一行
- 用 `endl` 刷输出，大数据量下超时
