## 题目

**场景**：小鹏嵌入式面经的手撕题（面经原话大意：给定两个非负整数，将它们的十进制数字分别反转后再相加），并追问末尾的 0、整数溢出和边界情况怎么处理。

**问**：给定两个非负整数，把它们的十进制数字各自反转后再相加，怎么实现？末尾的 0、溢出和边界怎么处理？

## 口述答案

> **思路：先各自反转，再相加，两步独立**。反转用逐位取余拼接：`rev = rev * 10 + x % 10; x /= 10;`。**末尾 0 不需要特判**：1200 逐位拼出的是 0→0→2→21，前导 0 在数学上自动消失，结果就是 21；这也是面试官追问末尾 0 时想听的点——拼接法天然消化，别去写特判逻辑。
>
> 边界两个：**0 反转还是 0**（循环不进，返回 0，天然正确）；**溢出是真正的坑**——int 上限 2147483647，而 1999999999 反转成 9999999991 直接炸掉，所以**用 long long 承接反转结果**。若题目进一步要求「结果也必须在 int 内」，反转超过 int 上界时按题意返回 -1 并说明；本题面只说非负整数相加，long long 即稳。
>
> 报复杂度：时间 O(位数) = O(log n)，空间 O(1)。

## 讲深一层

```cpp
#include <cstdio>

long long reverseDigits(long long x) {          /* 逐位取余拼接 */
    long long rev = 0;
    while (x > 0) { rev = rev * 10 + x % 10; x /= 10; }  /* 末尾 0 自动消失 */
    return rev;                                 /* x=0 时返回 0 */
}

long long reverseAdd(long long a, long long b) {
    return reverseDigits(a) + reverseDigits(b); /* long long 承接反转溢出 */
}

int main() {
    printf("%lld\n", reverseAdd(123, 456));      /* 321+654 = 975 */
    printf("%lld\n", reverseAdd(1200, 340));     /* 21+43   = 64，末尾 0 无需特判 */
    printf("%lld\n", reverseAdd(1999999999, 1)); /* 9999999991+1 = 9999999992，int 会炸 */
    return 0;
}
```

| 情形 | 处理 |
|---|---|
| 末尾 0（1200） | 逐位拼接自然吞掉前导 0 → 21，无需特判 |
| x = 0 | 循环不进，返回 0 |
| 反转溢出 | 用 long long 承接；要求 int 结果时按题意返回 -1 |
| 超大输入（超 long long） | 改字符串：反转即逆序去前导 0，相加用字符串加法 |

**记忆锚点**：「反转 = rev*10 + 余数；末尾 0 自动消化；溢出用 long long 兜底」。

## 高频追问

1. **末尾的 0 反转后期望是什么？** —— 1200 反转按定义是 0021，即 21，前导 0 自动消失；代码上逐位拼接天然正确，不需要也不应该写特判。
2. **负数怎么扩展？** —— 题设非负；扩展时先记符号、对绝对值反转，结果加回符号（-123 → -321）。
3. **输入超 long long 怎么办？** —— 按字符串处理：反转 = 逆序 + 去前导 0，相加 = 字符串加法（同大数相加套路，见 Q-1922）。
4. **溢出怎么显式判而不是靠换类型？** —— 拼接前检查 `rev > (LLONG_MAX - d) / 10`，即乘 10 加位之前先判上界；写出来是加分项。

## 易错点

- 用 int 存反转结果——1999999999 一反转就溢出成负数，结果全错。
- 给末尾 0 写特判逻辑——拼接法天然处理，特判反而引入 bug。
- 拼接顺序写反——是先乘 10 再加余数，不是先加后乘。
- 忘了 0 的边界——0 反转还是 0，循环写法天然正确，别额外 if。
