## 题目

**背景**：用户塔要建模历史行为，面试官关心序列长度这个工程与效果的折中。

**问**：用户塔里的历史行为序列一般取多长？超长时怎么截断？

## 口述答案

> 结论：**常规召回取最近 50~200 条**，DIN 一类典型是 100，再长收益递减且显存吃不消。截断策略有四种：取最近 N 条；时间衰减加权（软截断）；按重要性取 top-k（ETA 用 LSH 近似）；分层采样，近期全保留、中期按天抽、远期按周抽。无论哪种，**训练和线上的截断逻辑必须完全一致**，包括时间基准用请求时刻还是样本时刻，否则离线在线特征对不上，效果直接掉。

## 讲深一层

| 长度 | 显存/样本（d=64,fp32） | 适用 |
|---|---|---|
| 50 | 12.8KB | 常规召回 |
| 200 | 51KB | DIN/DIEN |
| 1000+ | 256KB+ | 需 GSU/ESU 两阶段 |

```
序列张量: [B, L, d] → B=1024, L=200, d=64 → 50MB
再加 attention 中间激活，实际 3~5 倍
```

## 高频追问

1. **为什么不是越长越好？** —— 噪声行为稀释信号，attention 在长序列上会弥散；收益通常在 200 条后饱和。
2. **冷启动用户序列为空怎么办？** —— 用默认向量或退化为画像塔，不要把空序列送进 attention 产生 NaN。
3. **序列里要不要去重？** —— 要，连续重复点击会主导 pooling，通常按 item 去重保留最近一次。

## 易错点

- 训练用样本时刻截断、线上用请求时刻，导致特征漂移
- 直接取前 N 条（最老的），丢掉近期兴趣
- 忽略空序列与 padding mask，attention attend 到 padding
