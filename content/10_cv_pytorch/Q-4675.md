## 题目

**背景**：面试官问架构选型：到底该把流程写死，还是交给模型自己决定，考的是工程判断而不是站队。

**问**：确定性工作流和自主 Agent 应该怎么选？你这个项目怎么划分？

## 口述答案

> 判据是任务空间是否可枚举、失败代价和可验证性。步骤固定、输入格式稳定、结果要可审计的场景，用确定性工作流：可测试、延迟可控、成本可预估、出错能定位到具体节点。输入开放、需要动态决定查什么调什么、步骤数事先说不清的，才用 Agent。我的划分方式是主干工作流化、局部 Agent 化：外层编排写死，比如取数、清洗、生成、校验、落库这几步固定；其中某一步如果需要在候选工具里自己选、或者要多次尝试，就在那个节点内放开给模型决策，但限定候选集和步数上限。这样既有灵活性，链路又不是黑盒。

## 讲深一层

| 维度 | 工作流 | 自主 Agent |
| --- | --- | --- |
| 执行路径 | 预定义 DAG | 运行时规划 |
| 可测试性 | 高，可逐节点断言 | 低，只能端到端 |
| 成本 | 可预估 | 随步数波动 |
| 适用 | 流程稳定、合规要求高 | 开放输入、工具组合不确定 |

## 高频追问

1. **怎么给 Agent 节点加约束** —— 限定候选工具集、最大步数、可用预算，超限就降级或转人工
2. **混合架构怎么测** —— 工作流部分做节点级单测，Agent 节点做场景级回归加人工抽检
3. **什么时候把 Agent 收回成工作流** —— 线上日志显示路径高度收敛（比如 90% 走同一条），就该固化

## 易错点

- 一上来就答"用 Agent 更先进" —— 选型要看任务性质，不是越自主越好
- 全流程写死却声称是 Agent —— 名不副实，追问几步就露馅
- 忽略可审计性 —— 涉及资金、合规的场景，路径不可解释是硬伤
