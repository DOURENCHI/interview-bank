## 题目

**问**：这是 PyTorch 新手最常忘的一行，忘了会出现什么现象？

## 口述答案

> 因为 PyTorch 的 `.grad` 是**累加**的，不是覆盖。
> 不清零的话，第二个 batch 的梯度会叠在第一个上，等效于把学习率不断放大，
> 训练很快就发散或者学不动。
> 设计成累加是为了支持**梯度累积**（小显存时攒几个 batch 再更新一次），
> 所以清不清零要你自己控制。

## 讲深一层

标准训练循环：

```python
optimizer.zero_grad()      # 清梯度
loss = model(x)            # 前向
loss.backward()            # 反向，梯度累加
optimizer.step()           # 更新参数
```

梯度累积的写法：

```python
for i, batch in enumerate(loader):
    loss = model(batch) / accum_steps
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

## 高频追问

1. **为什么除以 accum_steps？** —— 保持梯度的量级和单 batch 一致。
2. **zero_grad 和 optimizer.zero_grad 有区别吗？** —— 后者遍历管理的参数，前者要手动指定。
3. **set_to_none=True 是什么？** —— 把 grad 置为 None 而不是填 0，省一次写操作，更快。

## 易错点

- ❌ 忘了 zero_grad —— loss 不降
- ❌ 梯度累积时忘了除 —— 等效学习率变大
- ✅ 说清「累加是为了支持梯度累积」
