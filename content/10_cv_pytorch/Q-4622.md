## 题目

**背景**：聊到推荐系统技术选型，对方问生成式推荐是不是更省钱。

**问**：生成式推荐系统比传统推荐系统的训练成本更低吗？

## 口述答案

> 通常不会更低，多数情况下更高，要分训练和推理两段看。
> · 传统：LR/DLRM/双塔，稀疏特征加小 MLP，样本级算力很低，可 CPU 或单卡增量训练；
> · 生成式：把推荐转成序列生成（item 语义 ID + 自回归 Transformer），参数量和序列长度都大，训练 FLOPs 高一个量级，推理还要 beam search，单 QPS 成本更贵。
> 它真正省的是特征工程与多阶段漏斗的维护人力，换来统一建模和泛化能力；但如果只比 GPU 小时和线上推理账单，答案是否定的。

## 讲深一层

粗算：训练 FLOPs ≈ 6·N·D（N 参数、D token 数），推理每 token ≈ 2N，生成长度 L 时单请求 ≈ 2NL。传统 DLRM 单样本只有几万次浮点运算，生成式按 token 算是它的几个数量级。
| 维度 | 传统 | 生成式 |
|---|---|---|
| 训练 | 低，可日更 | 高，需多卡 |
| 推理 | 微秒级 | 十毫秒级 |
| 冷启动 | 依赖特征 | 依赖语义 ID 质量 |

## 高频追问

1. **语义 ID 冲突怎么办？** —— 用 RQ-VAE 多层量化加冲突消解，冲突率高会让模型混淆不同商品。
2. **什么场景值得上生成式？** —— 序列长、多目标统一、需要生成解释或对话式推荐时；纯 CTR 预估用 DLRM 更划算。
3. **成本能靠蒸馏压下来吗？** —— 可以，把生成式当 teacher 蒸馏到小模型或双塔，推理成本能降一个量级。

## 易错点

- 只比训练 GPU 小时，不比线上推理账单，而推理才是长期成本大头。
- 认为生成式一定效果更好，忽略数据规模和语义 ID 质量的门槛。
- 把"省了特征工程"直接等同于"总成本更低"。
