## 题目

**场景**：部署 LLM 推理服务选框架，vLLM 凭吞吐优势成了默认选项，需要能拆开讲它快在哪、请求怎么调度。

**问**：vLLM 的原理是什么？它是如何进行调度的？

## 口述答案

> vLLM 的核心是 **PagedAttention**：像操作系统虚拟内存分页那样管理 **KV cache**——把每个序列的 KV 切成固定大小的 block（如 16 个 token 一块），**按需分配物理块**，用块表做逻辑到物理的映射。传统做法按 max_seq_len 预分配一大段连续显存，内部碎片加外部碎片，实际利用率只有两三成；分页后能到 90% 以上，同样显存塞下**数倍并发**。
> 调度上是 **continuous batching（迭代级调度）**：不像静态 batch 要等整批都生成完，它每个 decode 迭代都重新组 batch——完成的请求立刻退出、新请求立刻加入；显存不够时对请求**抢占并换出**（swap 到 CPU 或丢弃重算）。
> 一句话总结：分页管「显存塞得下」，连续批处理管「GPU 转得快」。

## 讲深一层

```text
PagedAttention: KV cache → 逻辑块序列 → 块表 → 物理块(16 token/块)
  · 按需分配, 无 max_len 预留浪费
  · 相同前缀共享物理块, 写时复制(copy-on-write)
调度: continuous batching + 抢占(swap/recompute) + chunked prefill
```

| 机制 | 解决的问题 |
|---|---|
| PagedAttention 分页 | KV cache 预分配的内外碎片 |
| Continuous batching | 静态 batch 短请求等长请求 |
| 前缀共享 COW | 多请求重复前缀重复占显存 |
| 抢占/换出 | 显存耗尽时不丢请求 |

**判断技巧**：把 vLLM 记成「操作系统的两件套」——**内存分页＋进程调度**，分别对应 PagedAttention 和 continuous batching；它是 KV cache 的管理革新，不是新注意力算法。

## 高频追问

1. **PagedAttention 改变了注意力数学吗？** —— 没有，只改 KV cache 的存储与寻址，计算结果等价。
2. **为什么 KV cache 是主要矛盾？** —— 它随序列长度和并发数线性增长，长序列下轻松吃掉大部分显存。
3. **chunked prefill 是什么？** —— 把长 prompt 的预填充切成小块与 decode 混排，避免一个长请求阻塞整批。

## 易错点

- 把 PagedAttention 说成新注意力算法——它是 KV cache 的分页管理
- 只答 continuous batching，漏掉分页这个核心
- 说 vLLM 减少计算量——它提升的是显存利用率与吞吐
