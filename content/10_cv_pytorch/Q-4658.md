## 题目

**背景**：聊测试与回归时，面试官问同一个用例为什么跑两次结果不一样，考的是对 Agent 系统非确定性的认知深度。

**问**：外部环境、参数变化，会不会导致相同测试任务执行结果不一样？如何处理？

## 口述答案

> 会。来源分四类：一是采样随机性，temperature 和 top_p 让同输入不同输出；二是环境依赖漂移，模型版本更新、工具接口变更、时区或当前日期变化；三是数据漂移，同一 query 检索到的知识库内容变了；四是执行序，并发任务完成顺序影响上下文拼接。处理分三层：能固定的固定，seed、模型快照、prompt 版本、数据快照 hash 全记进 run manifest；不能固定的做容差，评测用 rubric 或断言而不是字符串 diff；再做录制回放，把外部依赖响应录下来，回归时重放，比的是 Agent 逻辑而不是外部抖动。

## 讲深一层

run manifest 建议字段：`model_id`（含快照日期）、`prompt_hash`、`tool_versions`、`dataset_snapshot`、`temperature/top_p/seed`、`runtime`（镜像 tag）。

注意 temperature=0 也不保证逐字可复现：GPU kernel 的非确定性归约、batch 组成变化、混合精度都会引入差异。所以断言要写成"包含关键实体且不违反约束"，而不是文本相等。

## 高频追问

1. **模型升级怎么评估影响** —— 固定测试集跑新旧两版，diff 失败 case 分类，不要只看总分涨跌
2. **怎么区分抖动还是 bug** —— 同版本同 seed 重跑 N 次，方差大是抖动，稳定错是逻辑问题
3. **时间相关怎么测** —— 注入可替换的 clock，测试里冻结时间，别直接读系统时间

## 易错点

- 只说"temperature 调到 0 就确定" —— 这句本身不准确，会被追打
- 不做数据快照 —— 知识库一更新，历史结论全部无法复现
- 用字符串相等做断言 —— 措辞变化就全红，测试失去信号价值
