## 题目

Agent 有哪些核心模块？ReAct 是怎么跑起来的？

## 口述答案

> Agent 核心模块：
> 1. **LLM（决策核心）**：理解任务、规划下一步、决定调哪个工具；
> 2. **工具层（Tools/Function Call）**：搜索、代码执行、数据库、业务 API，带 schema 描述；
> 3. **记忆**：短期（对话上下文）、长期（向量库/知识库）、工作记忆（任务状态）；
> 4. **规划器**：任务分解、ReAct 循环、反思/重试；
> 5. **执行器与状态机**：管理步骤、超时、重试、终止条件；
> 6. **可观测**：trace、日志、成本统计。
> **ReAct 怎么跑**：循环 `Thought（想）→ Action（调工具）→ Observation（看结果）→ Thought…`，直到给出 Final Answer。每轮把历史（含工具返回）拼进 prompt，靠 few-shot/指令约束输出格式。

## 讲深一层

```text
Thought: 需要查最新数据
Action: search("...")
Observation: ...
Thought: 信息够了，组织答案
Final Answer: ...
```
工程上会加最大步数、工具白名单、结果校验，防止死循环和越权。

## 高频追问

1. **ReAct 和 Plan-and-Execute 区别？** —— ReAct 边走边想（灵活但可能绕路），Plan 先出计划再执行（可控但计划可能过时）。
2. **工具返回太长怎么办？** —— 摘要/截断/结构化提取，避免上下文爆掉。

## 易错点

- 把 Agent 说成"加了 prompt 的模型"，讲不出工具/记忆/循环
- 不知道 ReAct 的三段结构
