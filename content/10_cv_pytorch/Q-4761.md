## 题目

**场景**：决定用 LoRA 微调一个开源基座模型做垂直任务，动手写训练代码之前要先回答数据问题。

**问**：LoRA 微调的数据从哪里来？数据结构是怎样的？

## 口述答案

> 数据来源和全参 SFT 完全一样，四条路：**开源指令集**（Alpaca、BELLE 这类）、**业务自有数据**（客服日志、工单、文档转 QA）、**人工标注**、**模型合成**（self-instruct 或强模型生成后过滤）。
> 结构上也没有 LoRA 专属格式：就是一条条「指令 → 回答」对，最常见是 **JSONL**，一行一条样本。Alpaca 格式三个字段：`instruction`（任务）、`input`（补充背景，可为空）、`output`（期望回答）；多轮对话用 `messages` 数组按 `role` 排。
> 一句话：LoRA 改的只是**训练哪些参数**，数据管线和全参微调一字不差，真正拉开差距的是数据质量和模板一致性。

## 讲深一层

```json
// train.jsonl —— 一行一条样本
{"instruction": "把下面的句子翻译成英文", "input": "今天天气很好", "output": "The weather is nice today."}
// 多轮对话格式
{"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
```

| 环节 | 做什么 |
|---|---|
| 收集 | 开源集 / 业务日志 / 人工标注 / 模型合成 |
| 清洗 | 去重、去乱码、长度过滤、抽检 |
| 格式化 | 统一为 instruction-input-output 或 messages |
| 训练时 | 套 chat template，**prompt 段 label=-100，只对回答算 loss** |

**判断技巧**：看到 LoRA 数据题，先答「与全参 SFT 同管线」，再谈质量——LoRA 省的是参数不是数据功夫；训练与推理用同一个 chat template 是最容易被忽略的翻车点。

## 高频追问

1. **prompt 部分算 loss 吗？** —— 一般不算，label 置 -100，只对 assistant 回答部分计算。
2. **要多少数据？** —— 高质量前提下几千条就能起效果，质量远比数量重要。
3. **多轮对话怎么组织？** —— messages 数组逐轮拼接，通常对每一轮的回答都算 loss。

## 易错点

- 以为 LoRA 有特殊数据格式——数据准备与全参 SFT 完全一致
- 训练用的 chat template 和推理时不一致，效果明显打折
- 把 `input` 背景字段漏拼或重复拼进 prompt
