## 题目

**背景**：快手大模型算法岗一面，注意力结构演进题。MHA→MQA→GQA→MLA 是一条完整的优化主线，动机全部指向 KV Cache 显存。考的是知不知道每一步省在哪、丢了什么、MLA 怎么做到「省到接近 MQA、质量保持 MHA」。
**问**：MHA 是什么？有哪些改进？介绍 DeepSeek 的 MLA？

## 口述答案

> MHA 多头注意力：Q、K、V 各拆成 h 个头，每个头独立算 attention。它的代价是推理时 KV Cache 巨大——每个头都要存自己的 K 和 V，等于 2×层数×h×d_head×序列长度，上下文一长、并发一高，KV Cache 比权重还占显存。所有改进都围绕「把 KV 存量压下来」这一条主线。
> 第一代改进 MQA：所有 Q 头共享同一组 K/V，KV Cache 直接缩 h 倍，代价是质量明显下降——头之间的 K/V 表达被压扁。第二代 GQA 折中：把 Q 头分组，每组共享一组 KV，Llama-2-70B、Llama-3 全系都用它，KV Cache 缩到 h/g 倍，质量损失很小，是目前最主流的方案。
> MLA 是 DeepSeek-V2/V3 的方案，思路从「共享」换成「低秩压缩」：把每层的 K、V 联合投影到一个低秩隐向量 c_KV（维度远小于 h×d_head），KV Cache 只存这个 latent 加一小段位置分量 k_pe，推理时再用上投影矩阵还原出各头的 K、V。因为低秩压缩保留了信息瓶颈里的主要内容，质量达到 MHA 水平；而 cache 大小只跟 latent 维度挂钩，压缩比接近 MQA 量级。两个实现细节决定成败：一是 RoPE 和低秩压缩不兼容——位置旋转是对每头 K 的非线性变换，没法先压进 latent 再还原，所以 MLA 把带位置信息的部分单独拆出来（解耦的 k_pe/q_pe 不压缩、直接带 RoPE），latent 只承载内容信息；二是上投影可以通过矩阵吸收融进 W_Q 和 W_O，推理时不产生额外计算，这是 MLA 能落地的关键——不然省了显存多了算力，等于白干。

## 讲深一层

- 三种方案的 KV Cache 量级对比要能报数：MHA 基准 1、GQA 缩 h/g 倍、MQA 缩 h 倍、MLA 压到与 latent 维度挂钩（DeepSeek-V2 相当于把 512+64 维压成 576 维存档 vs MHA 的几千维），MLA 质量曲线优于 GQA 是它敢用于主力模型的原因。
- 「矩阵吸收」是 MLA 工程上最精妙的一步：cache 里没有完整的 K/V，attention 计算需要的 K^T·Q 可以把上投影矩阵转置吸收进 Q 的投影里，直接在 latent 空间算，计算量不增——面试能主动讲出这一层就超过绝大多数候选人。
- GQA 为什么成了行业默认而不是 MLA：GQA 零训练改造成本（改结构微调即可），MLA 要重训且实现复杂；MLA 的价值在超长上下文+大规模并发场景，DeepSeek 的 API 成本优势很大程度来自它。

## 高频追问

1. MLA 的 cache 里到底存了什么？——c_KV latent（内容）、k_pe（解耦位置分量）、还有 c_K 同源的 q 压缩不需要存（当轮现算），V 不单独存（从 latent 还原）
2. 为什么 RoPE 没法低秩压缩？——旋转矩阵作用在每头 K 的具体方向上，压缩后再还原无法保持每头的相位信息，所以拆出来单独处理
3. GQA 和 MQA 质量差多少？——MQA 在大模型上可观测掉点，GQA 8 组对 64 头基本无损，所以 Llama 系选 GQA；极端压缩需求才上 MQA

## 易错点

- 只答 GQA 不知 MLA——2025 年起这是大模型岗高频题，DeepSeek-V2/V3 的核心结构，答不出说明没跟进主流开源模型
- 把 MLA 说成「GQA 的变体」——思路根本不同：GQA 是共享分组，MLA 是低秩压缩+还原，混淆两者会被「MLA cache 里存什么」一问击穿
- 忽略矩阵吸收——只讲压缩不讲「还原计算怎么消化」，会被追问「多了上投影计算量怎么办」，这正是 MLA 设计最精巧的地方
