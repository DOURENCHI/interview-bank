## 题目

**场景**：团队要做一个文本分类/信息抽取需求，有人提议直接调大模型 API，需要权衡小模型是否还值得用。

**问**：BERT 和 GPT 有什么区别？大模型时代，小模型还有用吗？

## 口述答案

> 区别一句话：**BERT 是双向 Encoder，GPT 是单向 Decoder**。BERT 用 MLM 完形填空预训练，看得见左右上下文，适合**理解类任务**（分类、NER、抽取），用法是微调；GPT 用因果掩码做 next token 预训练，只能看左边，天然适合**生成**，大模型时代靠 in-context learning 把各种任务统一成生成问题。
> 小模型当然有用，场景很明确：一是**任务单一固定**的判别任务，BERT 级模型微调后效果不输大模型，推理成本却低几个数量级；二是**端侧/低延迟**场景（手机、车机、实时风控），大模型放不下；三是**大模型管线里的配套位**——RAG 的 embedding 和 reranker、小模型先筛大模型兜底的级联路由、蒸馏出的学生模型。
> 分工是：大模型做生成、复杂推理和 Agent 大脑，小模型吃掉高并发、低成本的理解类活。

## 讲深一层

| | BERT | GPT |
|---|---|---|
| 结构 | Transformer Encoder，双向注意力 | Transformer Decoder，因果掩码 |
| 预训练 | MLM（+NSP） | next token prediction |
| 使用方式 | 微调＋任务头 | 提示词＋生成 / ICL |
| 擅长 | 判别：分类、NER、QA 抽取 | 生成、对话、通用推理 |

```text
大模型时代小模型的四个位置:
 ① 判别任务微调（分类/NER，推理成本约 1/100）
 ② RAG 配套: embedding / reranker
 ③ 级联路由: 小模型先筛, 大模型兜底
 ④ 端侧部署: 蒸馏小模型（DistilBERT / 0.5B 级）
```

**判断技巧**：问自己任务是「**理解这段话**」还是「**产出新内容**」——前者优先小模型微调，后者才轮到大模型；拿不准时先测大模型上限，再评估小模型能否追平。

## 高频追问

1. **大模型能直接做分类吗？** —— 能，但精度-成本通常不如微调小模型，调用量大时差距尤其明显。
2. **小模型怎么蹭大模型的能力？** —— 蒸馏（logits 或数据），或大模型造数据再训小模型。
3. **BERT 为什么做不了生成？** —— 双向注意力在自回归解码时看不见「未来」，且没有语言建模目标。

## 易错点

- 把 GPT 说成 BERT 的升级版——是 encoder/decoder 两种范式
- 断言小模型已死——判别、端侧、检索场景仍是首选
- 忽略 in-context learning 是 GPT 范式的关键差异
