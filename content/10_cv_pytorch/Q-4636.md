## 题目

**背景**：设计多 Agent 协议时，面试官问 Agent 之间的返回结构该怎么约定。

**问**：一个 Agent 调用另一个 Agent，返回值格式怎么定？

## 口述答案

> 定成固定信封加可扩展 payload。信封含 status（success/failed/partial）、summary 一句话结论、data 结构化结果、evidence 证据引用、error（code、message、retryable）、usage 步数和 token。data 按任务定 schema。三个要点：状态要有 partial 别只有成败；错误码要区分可否重试；summary 给人看、data 给程序用。

## 讲深一层

```json
{
  "status": "partial",
  "summary": "已查到订单，退款未执行",
  "data": {"order_id": "12345", "amount": 99.0},
  "evidence": [{"tool": "query_order", "raw_id": "r-88"}],
  "error": {"code": "UPSTREAM_TIMEOUT", "retryable": true},
  "usage": {"steps": 3, "tokens": 1820}
}
```

## 高频追问

1. **为什么不直接返回自然语言？** —— 上游无法可靠解析，也没法做重试判断；自然语言只适合放 summary。
2. **partial 怎么处理？** —— 编排层决定是补齐剩余部分还是整体回滚，不能当成功直接透传给用户。
3. **协议怎么演进？** —— 信封字段只增不改，data 带 schema_version，消费方忽略未知字段。

## 易错点

- 用 200/500 表达业务失败，重试逻辑会误判
- 把错误信息拼进 summary，程序无法分支处理
- 没有 evidence，上游无法验证结论真伪
