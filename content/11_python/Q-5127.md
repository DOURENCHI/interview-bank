## 题目

**题目**：

```python
with open("f.txt") as f:
    data = f.read()
```

**问**：`with` 是怎么实现的？为什么它能保证文件一定被关闭？

## 口述答案

> 因为文件对象实现了**上下文管理协议**：`__enter__` 在进入时调用（返回 `f`），`__exit__` 在**离开时一定调用**——包括正常结束、`return`、抛异常。
> 所以关闭动作写在 `__exit__` 里，就保证了"无论怎么离开 this block，资源都会释放"。

## 讲深一层

```python
class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                     # as 后面拿到的东西
    def __exit__(self, exc_type, exc, tb):
        print(f"耗时 {time.perf_counter()-self.t0:.3f}s")
        return False                    # False: 不吞异常；True: 吞掉

with Timer():
    do_work()
```

| `__exit__` 返回值 | 效果 |
|---|---|
| `False` / `None` | 异常继续传播 |
| `True` | **吞掉异常**（要非常谨慎） |

**参数含义**：`exc_type, exc, tb` 分别是异常类型、实例、traceback；没异常时都是 `None`。

**更简洁的写法：`contextlib.contextmanager`**
```python
from contextlib import contextmanager

@contextmanager
def timer():
    t0 = time.perf_counter()
    try:
        yield
    finally:
        print(time.perf_counter() - t0)

with timer():
    do_work()
```

**标准库里的例子**：`open`、`threading.Lock`、`tempfile.TemporaryDirectory`、`socket` 包装。

## 高频追问

1. **一个 with 能管多个资源吗？** —— 能，`with open(a) as f, open(b) as g:`。
2. **`__exit__` 里能抛异常吗？** —— 能，会替代原异常传播。
3. **`with` 能用在异步里吗？** —— 用 `async with`，对应 `__aenter__`/`__aexit__`。

## 易错点

- 用 `try/finally` 手写而不封装上下文管理器
- `__exit__` 返回 True 吞掉所有异常
- 忘记 `yield`（`contextmanager` 里）
