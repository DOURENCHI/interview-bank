## 题目

**题目**：一个 Python 服务偶尔整个卡住，日志停在"acquiring lock"，重启就好。

**问**：Python 里死锁是怎么产生的？怎么避免？

## 口述答案

> 最常见的是**加锁顺序不一致**：线程 A 先锁 1 再锁 2，线程 B 先锁 2 再锁 1，各持一把等对方，永久阻塞。
> 避免方法：**固定全局加锁顺序**、**用一个锁而不是两个**、**加超时**（`acquire(timeout=)`），以及**尽量不共享状态**。

## 讲深一层

```python
# ❌ 两个锁，顺序不一致
def a():
    with lock1:
        with lock2: ...
def b():
    with lock2:
        with lock1: ...     # 与 a 相反 → 可能死锁

# ✅ 加超时，至少不会永久挂住
if not lock.acquire(timeout=2):
    log.warning("lock timeout, skip")
    return
try:
    ...
finally:
    lock.release()
```

| 死锁成因 | 表现 | 解法 |
|---|---|---|
| 加锁顺序不一致 | 双方互等 | 统一顺序 |
| 忘记释放（异常路径） | 后续全阻塞 | `with` 或 try/finally |
| 递归获取非递归锁 | 自己等自己 | `RLock` |
| 持锁调用外部阻塞操作 | 长时间占用 | 缩小临界区 |
| 线程池里等待同一池的任务 | 池被占满 | 拆池或改异步 |

**`RLock`（可重入锁）**：同一线程可以重复获取，但**不能解决跨线程死锁**，只是防"自己锁自己"。

**排查手段**：`faulthandler.dump_traceback_later(30, exit=True)` 能在卡住时打印所有线程栈；或 `py-spy dump --pid`。

## 高频追问

1. **`with lock` 比手动 acquire 好在哪？** —— 异常时也会释放。
2. **死锁能被检测到吗？** —— Python 不主动检测，只能靠超时和栈转储。
3. **GIL 会导致死锁吗？** —— 会，C 扩展里释放/获取 GIL 不当会。

## 易错点

- 多层锁不加顺序约定
- 异常路径忘记 release
- 持锁做网络请求
