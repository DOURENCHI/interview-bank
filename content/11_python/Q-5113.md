## 题目

**题目**：循环里 `s += str(i)` 拼 10 万个字符串，跑了十几秒。

**问**：为什么循环里 `+=` 拼接字符串慢？正确写法是什么？

## 口述答案

> 因为字符串**不可变**，每次 `+=` 都要创建新字符串并把旧内容复制过去，第 i 次复制 i 个字符，总共 O(n²)。
> 正确写法是 `''.join(parts)`：先收集到 list，最后一次性拼接，O(n)。

## 讲深一层

```python
# ❌ O(n²)
s = ""
for i in range(100000):
    s += str(i)

# ✅ O(n)
parts = []
for i in range(100000):
    parts.append(str(i))
s = ''.join(parts)

# ✅ 更简洁
s = ''.join(str(i) for i in range(100000))
```

| 写法 | 复杂度 | 说明 |
|---|---|---|
| `s += x` | O(n²) | 每次复制 |
| `''.join(list)` | O(n) | **推荐** |
| `f"{a}{b}"` | O(n) | 少量拼接够用 |
| `io.StringIO` | O(n) | 流式写入，适合边生成边拼 |

**CPython 有个优化**：如果字符串引用计数为 1，`+=` 会尝试原地扩容（类似 list）。但这是**实现细节**，一旦有别的引用就失效，**不能依赖**。

**什么时候用 StringIO**：需要"边算边写、最后取整体"时，比如生成大段报表，避免维护一个巨大的 list。

## 高频追问

1. **`join` 对非字符串元素怎么办？** —— 先 `map(str, ...)`。
2. **f-string 比 `%` 和 `format` 快吗？** —— 快，编译期就优化成字节码拼接。
3. **list 的 `+=` 也慢吗？** —— 不慢，list 可变，`+=` 是原地扩展（`extend`）。

## 易错点

- 循环里 `+=` 拼字符串
- 依赖 CPython 的原地优化
- 用 `%` 做大量拼接
