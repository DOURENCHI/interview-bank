## 题目

**题目**：写一个计时装饰器，要求保留原函数的名字和文档字符串。

**问**：装饰器的本质是什么？为什么必须加 `functools.wraps`？

## 口述答案

> 本质是**接收函数、返回函数的高阶函数**，`@dec` 只是 `f = dec(f)` 的语法糖。
> 不加 `functools.wraps` 的话，包装后的函数 `__name__` 变成 `wrapper`、`__doc__` 丢失、签名也变了——这会让日志、调试、框架（如 Flask 路由、pytest）全部失灵。

## 讲深一层

```python
from functools import wraps
import time

def timer(fn):
    @wraps(fn)                      # ← 关键：复制 __name__/__doc__/__wrapped__
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__}: {time.perf_counter()-t0:.3f}s")
    return wrapper

@timer
def work(n): 
    """干活"""
    return sum(range(n))

work.__name__     # 'work'（没有 wraps 会是 'wrapper'）
```

| 写法 | 用途 |
|---|---|
| 函数装饰器 | 最常用 |
| 带参数的装饰器 | 需要三层（工厂 → 装饰器 → wrapper） |
| 类装饰器 | 用 `__call__`，适合需要状态的场景 |
| `functools.wraps` | **必加**，保留元数据 |

**带参数的装饰器要三层**：
```python
def retry(times=3):
    def deco(fn):
        @wraps(fn)
        def wrapper(*a, **kw): ...
        return wrapper
    return deco

@retry(times=5)
def f(): ...
```

**顺序**：多个装饰器**从下往上**应用（离函数最近的先生效）。

## 高频追问

1. **装饰器能拦住异常吗？** —— 能，在 wrapper 里 try/except。
2. **怎么拿到原函数？** —— `wrapper.__wrapped__`（`wraps` 自动设的）。
3. **类方法和静态方法能装饰吗？** —— 能，注意 `@classmethod` 要放最外层。

## 易错点

- 不加 `functools.wraps`，调试时全是 wrapper
- 带参数的装饰器少写一层
- 装饰器顺序搞反
