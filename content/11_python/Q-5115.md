## 题目

**题目**：读一个 10 GB 的日志文件，要逐行处理，不能一次读进内存。

**问**：生成器是怎么做到"惰性求值"的？`yield` 和 `return` 有什么不同？

## 口述答案

> `yield` 会把函数**暂停**在这一行，保存局部变量和指令指针，返回一个值；下次 `next()` 从暂停处继续。所以内存里只有一个元素的量级。
> `return` 是结束函数并返回值；`yield` 是**产出一个值后继续活着**。

## 讲深一层

```python
def read_lines(path):
    with open(path, encoding='utf-8', errors='ignore') as f:
        for line in f:            # 文件对象本身也是迭代器，天然流式
            yield line.rstrip('\n')

for line in read_lines("huge.log"):
    if "ERROR" in line:
        print(line)
```

| 对比 | 生成器 | 列表 |
|---|---|---|
| 内存 | O(1) | O(n) |
| 首次结果 | 立刻 | 要等全部算完 |
| 可重复遍历 | ❌ 只能一次 | ✅ |
| 支持索引/切片 | ❌ | ✅ |
| 适用 | 大数据流、无限序列 | 需要多次访问 |

**生成器函数的识别**：函数体里有 `yield`，调用它**不会执行任何代码**，只返回生成器对象——这是新手最容易误判的一点（以为调用了就开始跑）。

**`send()` 可以给生成器传值**，让它在暂停处接收：
```python
def acc():
    total = 0
    while True:
        x = yield total
        total += x
```

## 高频追问

1. **生成器能提前关闭吗？** —— `gen.close()`，会触发 `GeneratorExit`。
2. **生成器里的异常怎么抛进去？** —— `gen.throw(ValueError)`。
3. **`yield` 能出现在 try/finally 里吗？** —— 能，`close()` 时 finally 会执行。

## 易错点

- 以为调用生成器函数会立即执行
- 把生成器遍历两次（第二次为空）
- 生成器里持有大对象引用导致内存不释放
