## 题目

**题目**：`sum([x*x for x in range(10**7)])` 和 `sum(x*x for x in range(10**7))` 有什么区别？

**问**：生成器表达式和列表推导式该怎么选？

## 口述答案

> 后者是**生成器表达式**（没有方括号），惰性求值，内存 O(1)；前者是**列表推导式**，会先在内存里建一个 1000 万元素的列表。
> 除了 `sum`/`max`/`any` 这类"聚合消费"场景，生成器表达式更省内存；但如果要**多次遍历或索引**，必须用列表。

## 讲深一层

```python
# 列表推导：立刻算完，占内存
nums = [x*x for x in range(10**7)]        # 约 400 MB

# 生成器表达式：惰性，O(1)
total = sum(x*x for x in range(10**7))    # 几乎不占额外内存

# 需要多次用就必须落成 list
squares = [x*x for x in range(100)]
len(squares); squares[5]                  # 生成器都做不到
```

| 形式 | 类型 | 内存 | 可重复 |
|---|---|---|---|
| `[f(x) for x in it]` | list | O(n) | ✅ |
| `(f(x) for x in it)` | 生成器 | O(1) | ❌ |
| `{f(x) for x in it}` | set | O(n) | ✅（无序） |
| `{k: v for ...}` | dict | O(n) | ✅ |

**性能上的反直觉**：列表推导比 `for + append` 快（C 层优化），但**生成器表达式不一定更快**——它省内存，代价是每次 `next` 有额外开销。数据量小的时候列表推导反而更快。

**嵌套顺序**：`[(i,j) for i in A for j in B]` 等价于两层 for，外层在前。

## 高频追问

1. **推导式里能用 `if` 吗？** —— 能，`[x for x in it if cond]`。
2. **能写 `if/else` 吗？** —— 能，但要放前面：`[a if c else b for x in it]`。
3. **推导式有作用域吗？** —— 有，Python 3 里循环变量不泄漏到外面。

## 易错点

- 大数据用列表推导导致 OOM
- 生成器表达式遍历两次
- 把 `if/else` 写到 for 后面（语法错误）
