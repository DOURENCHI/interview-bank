## 题目

**题目**：要给自己写的工具加测试，`unittest` 和 `pytest` 怎么选？

**问**：单元测试该怎么写？pytest 和 unittest 怎么选？

## 口述答案

> **选 pytest**：语法更简洁（裸 `assert`）、fixture 管理依赖、参数化方便、失败信息可读。`unittest` 是标准库、无依赖，适合不能装第三方包的场景。
> 写测试的要点是：**一个测试只测一件事**、**用参数化覆盖边界**、**测试要快且可重复**。

## 讲深一层

```python
# pytest 风格
import pytest

def test_parse_ok():
    assert parse("1,2,3") == [1, 2, 3]

@pytest.mark.parametrize("raw,expect", [
    ("", []),
    ("1", [1]),
    ("1,,2", [1, 2]),
    ("x", ValueError),
])
def test_parse_edge(raw, expect):
    if expect is ValueError:
        with pytest.raises(ValueError):
            parse(raw)
    else:
        assert parse(raw) == expect

@pytest.fixture
def tmp_db(tmp_path):
    db = make_db(tmp_path / "t.db")
    yield db
    db.close()
```

| 对比 | pytest | unittest |
|---|---|---|
| 断言 | 裸 `assert` | `self.assertEqual` |
| 依赖注入 | `fixture` | `setUp/tearDown` |
| 参数化 | `@parametrize` | 手写循环 |
| 插件生态 | 丰富（覆盖率、并行） | 少 |
| 依赖 | 需安装 | 标准库 |

**好测试的三个特征**：**快**（毫秒级）、**独立**（不依赖执行顺序）、**确定**（不依赖时间/随机/网络）。

**怎么测依赖外部硬件/网络的代码**：抽接口 + mock，或者用依赖注入传入假的实现——这也是为什么"业务逻辑要和 IO 分离"。

## 高频追问

1. **覆盖率多少够？** —— 核心逻辑 80% 以上，别追求 100%（性价比低）。
2. **怎么测随机性？** —— 固定种子。
3. **集成测试和单元测试比例？** —— 金字塔：单元多、集成少。

## 易错点

- 测试之间共享状态、依赖执行顺序
- 测试里用真实网络/数据库
- 只测正常路径不测边界
