## 题目

**题目**：给函数加了类型注解，运行速度会变慢吗？

**问**：类型注解会影响运行速度吗？它到底解决什么问题？

## 口述答案

> **基本不影响**。注解在函数定义时求值一次、存进 `__annotations__`，函数体执行时完全不检查类型（除非用 `beartype`/`pydantic` 这类库强制校验）。
> 它解决的是**可读性和静态检查**：让 IDE 能补全、让 mypy 能在提交前发现类型错误，而不是运行时提速。

## 讲深一层

```python
def greet(name: str, times: int = 1) -> str:
    return ("hi " + name + "\n") * times

greet.__annotations__
# {'name': str, 'times': int, 'return': str}

greet(123)          # 照样能跑，不报类型错误
```

| 用途 | 谁在用 | 时机 |
|---|---|---|
| IDE 补全/跳转 | 编辑器 | 编辑时 |
| 静态检查 | mypy / pyright | CI |
| 文档生成 | Sphinx | 构建时 |
| 运行时校验 | pydantic / beartype | 运行时（**有开销**） |

**`from __future__ import annotations`**：让注解变成字符串（延迟求值），避免前向引用问题，也略微减少启动开销。3.11 起默认行为改成了字符串化（PEP 563 的方向）。

**`typing` 常用**：`Optional[X]`（= `X | None`）、`Union`、`List`/`Dict`（3.9 起可直接 `list[int]`）、`Callable`、`TypedDict`、`Protocol`。

**代价**：注解写得不对会误导人，比没有更糟；复杂泛型注解可读性差。

## 高频追问

1. **注解会在运行时被检查吗？** —— 不会，除非显式校验。
2. **`list[int]` 在 3.8 能用吗？** —— 不能，要 `List[int]`（或在 3.7+ 用 `from __future__ import annotations`）。
3. **怎么强制校验？** —— `pydantic` 模型或 `beartype` 装饰器。

## 易错点

- 以为注解能提速或强制类型
- 在 3.8 用 `list[int]` 语法
- 注解与实现不一致，误导调用方
