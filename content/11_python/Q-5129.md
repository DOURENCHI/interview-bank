## 题目

**题目**：自定义了一个异常，有人建议继承 `Exception`，有人说继承 `BaseException` 也行。

**问**：自定义异常该继承什么？为什么不该继承 `BaseException`？

## 口述答案

> **必须继承 `Exception`**。`BaseException` 是给 `SystemExit`、`KeyboardInterrupt`、`GeneratorExit` 用的——它们不该被普通业务代码捕获。
> 如果自定义异常继承 `BaseException`，`except Exception` 捕获不到它，很多框架的兜底逻辑会失效；反过来如果你写 `except BaseException`，会把 Ctrl+C 也吞掉。

## 讲深一层

```python
class ConfigError(Exception):
    """配置错误"""

class RetryableError(Exception):
    def __init__(self, msg, retries=0):
        super().__init__(msg)
        self.retries = retries
```

| 基类 | 用途 | 能否被 `except Exception` 捕获 |
|---|---|---|
| `BaseException` | 系统级退出信号 | ❌ |
| `Exception` | 业务异常 | ✅ |
| `ValueError` / `KeyError` 等 | 语义化细分 | ✅ |

**异常层次设计建议**：
1. 一个库定义**一个根异常**（如 `class MyLibError(Exception)`），所有子异常继承它；
2. 调用方可以只捕获根异常，也可以精确捕获子类；
3. 不要从 `ValueError` 这类内置异常派生出跨语义的异常（会误捕）。

**`except Exception` 已经足够宽**：它捕获了所有"正常"异常，唯独放过 `KeyboardInterrupt` 和 `SystemExit`——这正是你想要的。

## 高频追问

1. **能捕获 `KeyboardInterrupt` 吗？** —— 能，但要 `except KeyboardInterrupt` 显式处理。
2. **异常类能有状态吗？** —— 能，在 `__init__` 里存额外信息（如重试次数）。
3. **异常类要加 `__str__` 吗？** —— 可选，默认打印参数。

## 易错点

- 继承 `BaseException`
- 用 `except BaseException` 兜底
- 所有异常都直接继承 `Exception` 不加层次（无法分类处理）
