## 题目

**追问**：多进程里子进程改了全局字典，父进程看不到，为什么？

**问**：多进程之间怎么传数据？为什么不能用全局变量？

## 口述答案

> 因为每个进程有**独立的内存空间**，全局变量在 fork/spawn 时被复制一份，之后各改各的，互不可见。
> 传数据要用显式的 IPC：`Queue`（最常用）、`Pipe`（点对点）、`Manager`（代理对象）、`shared_memory`（大数组）。

## 讲深一层

```python
from multiprocessing import Process, Queue

def worker(q):
    q.put({"result": 42})

if __name__ == "__main__":
    q = Queue()
    p = Process(target=worker, args=(q,))
    p.start()
    print(q.get())          # {'result': 42}
    p.join()
```

| 方式 | 速度 | 适合 |
|---|---|---|
| `Queue` | 中 | 通用，多生产者多消费者 |
| `Pipe` | 快 | 两个进程点对点 |
| `Manager().dict()` | 慢（走代理） | 需要共享复杂结构 |
| `shared_memory` | 最快 | 大数组/图像 |
| 文件/socket | 慢 | 跨机器 |

**注意 pickle 限制**：进程间传的对象必须可序列化——lambda、打开的文件、数据库连接都不行。

**`Manager` 为什么慢**：它起了一个服务进程，所有操作都是 RPC，每次访问都有往返开销。别在循环里频繁访问。

**一个常被忽略的点**：`Queue` 里的数据在子进程退出前要 flush，否则可能丢；`join()` 前先 `q.close()` 更稳。

## 高频追问

1. **能用全局 list 累积结果吗？** —— 不能，子进程的修改不会回传。
2. **`Pool` 和 `Process` 怎么选？** —— 池化复用进程，适合大量小任务。
3. **共享 numpy 数组怎么做？** —— `multiprocessing.shared_memory` + `np.frombuffer`。

## 易错点

- 用全局变量收集子进程结果
- 传 lambda 或数据库连接给子进程
- 循环里用 Manager 频繁读写
