## 题目

**现象**：Windows 上跑 PyTorch 训练，`DataLoader(num_workers=4)` 直接卡死或报
`RuntimeError: An attempt has been made to start a new process before the current process has finished its bootstrapping phase`。

**问**：为什么会卡死？怎么解决？

## 口述答案

> 因为 Windows/macOS 用 **spawn** 启动子进程：子进程会重新 import 主模块。如果创建 DataLoader 的代码在模块顶层，子进程 import 时又会创建 DataLoader → 无限递归 → 卡死/报错。
> 解决：**把训练入口包进 `if __name__ == "__main__":`**。

## 讲深一层

```python
# ❌ Windows 下卡死
loader = DataLoader(ds, num_workers=4)   # 顶层执行

# ✅
def main():
    loader = DataLoader(ds, num_workers=4)
    train(loader)

if __name__ == "__main__":
    main()
```

| 平台 | 启动方式 | 注意 |
|---|---|---|
| Linux | fork（默认） | 一般没问题，但 fork 后 CUDA 状态不可靠 |
| Windows | spawn | **必须** `if __name__ == "__main__"` |
| macOS | spawn（3.8+） | 同上 |
| Jupyter/Colab | 无 `__main__` 概念 | `num_workers>0` 常出问题，设 0 |

**另一个坑：CUDA + fork**：父进程初始化了 CUDA 再 fork，子进程用 CUDA 会崩。所以 DataLoader 的 worker 只做 CPU 侧的加载/增强，不要在里面碰 GPU。

**worker 里的随机种子**：每个 worker 默认种子不同（否则数据顺序会重复）。`worker_init_fn` 可以显式设置。

**笔记本环境**：Jupyter 里 `num_workers>0` 经常直接卡住，设 0 最稳（性能靠预取和 batch 调）。

## 高频追问

1. **num_workers 设多少？** —— 通常 4–8；超过 CPU 核数无益，还可能拖慢。
2. **worker 里能用 CUDA 吗？** —— 不要，会崩或极慢。
3. **为什么第一个 epoch 慢？** —— worker 启动 + 数据预热。

## 易错点

- Windows 上不加 `if __name__ == "__main__"`
- 在 worker 里创建 CUDA tensor
- Jupyter 里开多 worker
