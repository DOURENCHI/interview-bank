## 题目

**题目**：面试官问"你这个模块为什么用 Python 写，而不是 C++？"

**问**：什么时候用 Python，什么时候必须换 C++？

## 口述答案

> 按三个维度判断：**性能要求**（毫秒级循环、大批量数值计算 → C++/numpy）、**部署环境**（无解释器、内存受限的嵌入式 → C++）、**开发迭代速度**（原型、脚本、胶水 → Python）。
> 实际上多数系统是**混合**的：Python 做编排和 IO，热点用 C++ 扩展或 numpy。

## 讲深一层

| 维度 | Python | C++ |
|---|---|---|
| 开发速度 | 快 | 慢 |
| 运行性能 | 慢 10–100 倍 | 快 |
| 内存占用 | 高 | 低（可控） |
| 部署 | 需要解释器/打包 | 单二进制 |
| 生态 | 数据处理/AI 最强 | 系统/实时/底层 |
| 并发 | GIL 限制 | 真并行 |

**典型的 Python 不该管的场景**：
1. **实时控制环**（1 kHz 以上，抖动要求严格）；
2. **嵌入式/无 OS 环境**；
3. **单机高吞吐服务**（GIL 是瓶颈）；
4. **需要精确内存布局**（与硬件/协议对接）。

**典型的 Python 最合适的场景**：训练脚本、数据预处理、测试与工具链、服务编排、快速验证算法。

**混合方案**：C++ 写核心库 → pybind11 暴露 → Python 调用。我们项目里 YOLO 推理就是 C++（ONNX Runtime/TensorRT），上层调度用 Python/ROS2。

## 高频追问

1. **pybind11 和 ctypes 怎么选？** —— pybind11 类型安全、易用；ctypes 无依赖但只适合 C 接口。
2. **Cython 呢？** —— 折中方案，改 Python 代码加类型声明即可编译。
3. **numba 呢？** —— JIT 编译热点函数，无需换语言，但只支持数值代码。

## 易错点

- 用 Python 写实时控制环
- 为了"性能"全面重写成 C++（可能收益不抵成本）
- 不知道 pybind11 / numpy 这类折中方案
