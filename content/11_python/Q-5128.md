## 题目

**题目**：调用第三方库报错，堆栈里出现两段：`During handling of the above exception, another exception occurred`。

**问**：`raise from` 是干什么的？异常链有什么用？

## 口述答案

> `raise NewError() from e` 会**显式建立异常链**：把原异常存进 `__cause__`，堆栈显示为
> `The above exception was the direct cause of the following exception`。
> 不写 `from` 也会有隐式链（`__context__`），显示为 "During handling..."。`from None` 则**切断链**，隐藏原异常。

## 讲深一层

```python
try:
    data = json.loads(text)
except json.JSONDecodeError as e:
    raise ConfigError("配置文件不是合法 JSON") from e   # 显式链

# 堆栈会同时显示两个异常，定位更快
```

| 写法 | `__cause__` | 显示 |
|---|---|---|
| `raise X` | None | 只有 X |
| `raise X from e` | e | 两段，**"direct cause"** |
| `raise X from None` | None（链被切断） | 只有 X |
| 在 except 里 `raise X` | 隐式设 `__context__` | "During handling" |

**为什么要包一层**：底层异常（如 `ConnectionResetError`）对调用方没意义，包成业务异常（`FetchFailed`）更清晰，同时用 `from` 保留根因——**既不丢信息，也不暴露实现细节**。

**什么时候 `from None`**：底层细节会误导用户时（比如把内部的重试失败包装成"服务不可用"）。

## 高频追问

1. **`except ... raise` 和 `raise e` 有什么区别？** —— 前者保留原 traceback，后者重置到当前行。
2. **怎么打印完整链？** —— `traceback.format_exception()` 会自动包含。
3. **`__context__` 和 `__cause__` 区别？** —— 前者隐式（处理中又抛），后者显式（`from`）。

## 易错点

- 包装异常时不写 `from`，根因被埋
- 用 `raise e` 丢失原始 traceback
- 到处 `from None`，出问题查不到根因
