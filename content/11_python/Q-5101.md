## 题目

**题目**：

```python
def add(item, bucket=[]):
    bucket.append(item)
    return bucket

add(1)      # [1]
add(2)      # 你以为是 [2]？
```

**问**：默认参数 `bucket=[]` 为什么会被"记住"？怎么正确写？

## 口述答案

> 因为**默认值在函数定义时求值一次**，之后每次调用都用同一个对象。所以两次 `add` 操作的是同一个 list，第二次返回 `[1, 2]`。
> 正确写法是用 `None` 做哨兵，在函数体内创建：
> ```python
> def add(item, bucket=None):
> if bucket is None:
> bucket = []
> bucket.append(item)
> return bucket
> ```

## 讲深一层

```python
def bad(x, acc=[]):
    acc.append(x)
    return acc

bad(1)   # [1]
bad(2)   # [1, 2]   ← 不是 [2]
bad.__defaults__      # ([1, 2],)   能直接看到被改掉的默认值
```

| 默认值类型 | 是否安全 | 原因 |
|---|---|---|
| `int` / `str` / `tuple` | ✅ | 不可变 |
| `[]` / `{}` / `set()` | ❌ | 可变，被所有调用共享 |
| `None` | ✅ | 哨兵，函数内再创建 |
| 自定义可变对象 | ❌ | 同上 |

**为什么这样设计**：默认值属于**函数对象**的一部分（存在 `__defaults__` 里），不是每次调用重新构造。这样省了重复求值的开销，代价是可变对象会被共享。

**同样的坑在类属性上**：`class A: items = []` 也是所有实例共享一个 list——这是 Python 里最经典的两个"共享可变状态"陷阱。

## 高频追问

1. **怎么发现这类 bug？** —— 看 `func.__defaults__`，或者在默认值里塞个可变对象跑两次。
2. **`None` 当哨兵有什么问题？** —— 如果 `None` 是合法值，就要用别的哨兵对象（`_sentinel = object()`）。
3. **类属性怎么避免？** —— 在 `__init__` 里 `self.items = []`，放到实例上。

## 易错点

- 用 `[]` / `{}` 当默认值
- 以为"每次调用会重新创建"
- 类属性当实例属性用
