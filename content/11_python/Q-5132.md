## 题目

**追问**：同一个循环，写在函数里比写在模块顶层快 20%，为什么？

**问**：为什么把变量放局部能变快？`LOAD_FAST` 是什么？

## 口述答案

> 因为**变量查找的成本不同**：局部变量用 `LOAD_FAST`（按数组下标取，O(1) 且无哈希），全局变量用 `LOAD_GLOBAL`（字典查找 + 检查内建）。
> Python 3.11 起 `LOAD_GLOBAL` 加了缓存，差距缩小，但局部仍更快。所以**把热循环里的全局变量赋给局部变量**是经典微优化。

## 讲深一层

```python
import dis
x = 1
def f():
    y = 1
    return y
dis.dis(f)
# LOAD_FAST   0 (y)      ← 快

def g():
    return x
dis.dis(g)
# LOAD_GLOBAL 0 (x)      ← 慢（新版有缓存）
```

| 字节码 | 查找方式 | 相对成本 |
|---|---|---|
| `LOAD_FAST` | 局部数组下标 | 最低 |
| `LOAD_DEREF` | 闭包单元 | 低 |
| `LOAD_GLOBAL` | 字典 + 缓存 | 中 |
| `LOAD_ATTR` | 属性查找（`__dict__`） | 高 |

**热循环里的三步优化**：
```python
def hot(data):
    append = data.append          # 1. 方法提到局部
    local_len = len              # 2. 内建提到局部
    for i in range(local_len(data)):
        append(i)                 # 3. 避免重复属性查找
```

**更大收益来自"减少工作"而不是"加速查找"**：用 numpy 向量化、用内置函数（`sum`/`any`/`map` 都是 C 实现），收益远超这类微优化。

## 高频追问

1. **`LOAD_ATTR` 为什么慢？** —— 要查实例 `__dict__`、类、MRO，还可能触发 `__getattr__`。
2. **这些微优化值得做吗？** —— 95% 的场景不值得，先 profile。
3. **`for i in range(len(x))` 有什么替代？** —— `enumerate` 或直接迭代元素。

## 易错点

- 一上来就做微优化
- 在热循环里反复 `.append`、`.attr`
- 忽略算法复杂度
