## 题目

**场景**：Demo 样机在工位上跑得好好的，要转量产了——设备会发到现场：电压波动、EMI 干扰、用户乱接电源、7×24 小时连续运行，现场没有调试器。

**问**：嵌入式软件层面要补充哪些容错逻辑？

## 口述答案

> 一句话概括：样机思维是"功能对"，量产思维是"**跑不死、坏了可查、恢复可自动**"。按四层补：
>
> ①**输入防御**：一切外部输入默认不可信——通信帧做校验和与长度检查、传感器值做量程钳位、通信加超时与重传。样机只跑"好数据"，量产要假设数据会坏。
>
> ②**异常兜底**：HardFault、断言失败、栈溢出钩子统一走同一条路——**先记录、进安全态、再复位**；IWDG 看门狗兜底一切死循环和调度卡死。
>
> ③**状态自愈**：上电进已知安全默认态（继电器断开、电机停）；通信断链自动重连并降级；异常计数超限主动复位，不带着坏状态硬跑。
>
> ④**黑匣子**：复位原因寄存器必查必存、关键错误写环形日志（备份域 RAM + Flash 分级）、带版本号，恢复后能上报。这样现场偶发问题回来才能定位。
>
> 底线原则：**每一次容错动作必须留痕**。不留日志的容错不是容错，是把 bug 藏成"偶发"。

## 讲深一层

样机 vs 量产的四层对照：

| 层 | 样机做法 | 量产做法 |
|---|---|---|
| 输入 | 假设传感器/通信正常 | 钳位 + 超时 + 校验和，坏帧丢弃计数 |
| 异常 | 调试器抓 HardFault | 钩子统一记录 → 安全态 → 复位 |
| 状态 | 每次上电人工确认 | 上电安全默认态 + 断链自愈 + 异常计数复位 |
| 定位 | 断点单步 | 黑匣子（复位原因/环形日志/版本） |

HardFault 统一出口（骨架）：

```c
__attribute__((naked)) void HardFault_Handler(void) {
    __asm volatile(
        "tst   lr, #4          \n"   // 判断用的是 MSP 还是 PSP
        "ite   eq              \n"
        "mrseq r0, msp         \n"
        "mrsne r0, psp         \n"
        "b     fault_capture   \n"); // 存 PC/LR/PSR 到 noinit RAM
    // fault_capture: 写黑匣子 -> 安全态(关输出) -> NVIC_SystemReset()
}
```

看门狗两条纪律：

- **喂狗位置**：在主循环/最低优先级任务里喂，不在高优先级定时器中断里喂——中断活着不等于系统活着，调度死了看门狗必须叫得出来。
- **IWDG vs WWDG**：IWDG 超时复位，兜底"卡死"；WWDG 窗口喂狗，抓"跑飞但还活着"（喂得太早太晚都复位），量产可双狗并用。

**判断技巧**：答这类题别堆名词，按"输入 → 异常 → 状态 → 定位"四层走，每层给一个具体机制，最后落到"容错必须留痕"——这是区分背题和做过工程的分界线。

**记忆锚点**：「**跑不死（兜底）、坏不了（防御）、查得到（黑匣子）、爬起来（自愈）**」。

## 高频追问

1. **怎么验证这些容错逻辑真的有效？** —— 故障注入：调试器手动改 PC 制造 HardFault、电源跌落/瞬断台架、随机断电老化跑一周、通信口注入坏帧和乱码。每一条容错路径都要有能触发它的测试用例，没被触发过的容错 = 没验证过的代码。
2. **什么情况不能"容错继续跑"，要进 fail-safe？** —— 涉及安全输出的路径（继电器、电机、加热）：检测到异常直接进已知安全态（断开/停机），不做"再试一次"。容错重试只用于通信、显示这类非安全路径；两类路径在代码里就要分开。
3. **黑匣子放 RAM 里，断电不就丢了吗？** —— 分级：实时日志放备份域 RAM（VBAT 供电，复位不掉）；关键事件（Fault 现场复位原因）在复位前挤时间写 Flash 一页，做磨损均衡；复位原因寄存器上电第一件事读出并存档。三层各保一档。

## 易错点

- 把"样机能跑"当"量产能卖"：只验证了功能路径，没验证过任何异常路径。
- 看门狗放定时器中断里喂：调度全死了狗还活着。
- 容错动作不留日志：bug 被藏成"偶发"，现场问题永远复现不出来。
- HardFault 直接 `NVIC_SystemReset()`：现场（PC/LR/栈）全丢，复位原因也从来不去看。
