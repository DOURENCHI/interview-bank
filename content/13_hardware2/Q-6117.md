## 题目

**场景**：设备已经卖到用户手里，固件通过 OTA 升级。升级程序往内部 Flash 写新固件写到一半，用户把电源拔了。

**问**：怎么设计 OTA，保证任何时刻断电设备都不变砖？校验和回滚怎么做？

## 口述答案

> 核心思想一句话：**Flash 里任何时刻都保留一份完整、校验通过的固件**。用 A/B 双分区做到这一点：Flash 划成 bootloader（永不 OTA）+ 槽 A + 槽 B + 元数据区四个部分。
>
> 升级流程：新固件**只写备用槽**（当前不在运行的那个），写完整槽校验（长度 → CRC → 版本 → 签名），全过之后才改元数据里的启动标记，复位后 bootloader 按元数据裁决从哪个槽启动。
>
> 断电安全性：切换标记之前的任何时刻断电，旧槽原封未动，bootloader 照常启动旧固件；切换之后断电，新槽已经校验通过，启动新固件。不存在"写了一半的固件被启动"的状态。
>
> 回滚：光校验不够，固件可能"校验对但跑不对"。所以新固件首次启动只算**试运行**，bootloader 里有个试启动计数器，新固件必须自检通过（外设 OK、关键任务起来、和服务器握上手）后主动写 confirmed 标志；超时没确认，bootloader 把计数加一，超过阈值自动切回旧槽。这样新固件有致命 bug 也不会把设备锁死。

## 讲深一层

分区布局（以 STM32 内部 Flash 为例，数值示意）：

```text
0x0800_0000  bootloader      16 KB   写保护，OTA 永远不碰
0x0800_4000  槽 A           128 KB
0x0802_4000  槽 B           128 KB
0x0804_4000  元数据 ×2 副本   4 KB    每份带 magic/version/序号/CRC
```

升级状态机（设备端）：

```text
IDLE ──收到升级指令──> DOWNLOAD（断点续传，写备用槽）
     ──收完──> VERIFY（长度→CRC→版本单调→签名）
     ──全过──> SWITCH（元数据写 status=active，boot_tries=0）
     ──复位──> BOOT 新槽（试运行）
     ──自检通过──> CONFIRM（status=confirmed，回收旧槽可复用）
     ──自检失败/超时──> boot_tries>=3 → bootloader 切回旧槽
```

元数据结构（这是整个方案的"单点"，必须防掉电）：

| 字段 | 作用 | 防护 |
|---|---|---|
| magic + version | 识别合法记录、防旧版本结构误读 | 固定魔数 |
| slot | 本记录指向的启动槽 | 双副本 |
| status | active / confirmed / invalid | 状态只能前进 |
| boot_tries | 试启动计数，bootloader 递增 | 双副本 |
| seq + crc | 序号定新旧，CRC 验完整性 | 双副本取一致且序号大的 |

**判断技巧**：讲 OTA 方案时先说"单点在哪"——bootloader 是单点（所以永不 OTA + 写保护），元数据是单点（所以双副本 + 序号 + CRC）。能把"哪里会坏、坏了怎么办"主动讲出来，比背流程加分。

**记忆锚点**：「**双槽是保险柜，元数据是钥匙，bootloader 是唯一守门人**」。

## 高频追问

1. **Flash 放不下两份固件怎么办？** —— 三条路：外挂 SPI Flash 当备用槽；差分包（bsdiff，只传差异，patch 小但依赖旧槽完好）；压缩镜像。后两种本质退化成"恢复区"方案——安全等级下降（旧槽在升级中被 patch 过），要主动说清这个代价。
2. **元数据区自己写坏了怎么办？** —— 双副本 + 递增序号 + CRC：写入永远是"写新副本 → 校验 → 新副本生效"，启动时读两份，取 CRC 对且序号大的那份；两份都坏则停在 bootloader 报错，绝不猜。
3. **校验链为什么要四步，只查 CRC 行不行？** —— 长度防截断，CRC 防位翻转，版本单调防刷旧版本（灰度回滚会造成版本震荡），签名防刷恶意镜像。量产设备能联网，刷入未签名固件等于留了后门。

## 易错点

- 双分区 ≠ 绝对安全：元数据不做双副本防掉电，照样变砖。
- 升级校验一过就把旧槽擦掉回收——必须等新固件自检 confirmed 之后，否则新固件跑不对时旧槽已没了。
- boot_tries 在新固件里自己计数自己清零——新固件一挂计数就没人动了，必须放 bootloader。
- 状态机漏了"试运行"环节，把"校验通过"当"升级成功"。
