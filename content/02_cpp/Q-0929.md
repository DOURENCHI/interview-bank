## 题目

**题目**：面试官问"不改类定义、不加 friend，你能读到私有成员吗"。

**问**：如何拿到一个类里私有成员变量的值？

## 口述答案

> 能，但都是**踩在未定义行为上**的手法：按内存布局算偏移，用 `reinterpret_cast` 直接把对象当成成员类型数组读。
> 这题的真正考点不是"能不能"，而是**说明访问控制是编译期约定，运行期没有保护**。

## 讲深一层

```cpp
class A { int x_ = 42; double y_ = 1.5; public: int pub() { return x_; } };

A a;
// 利用布局：第一个成员就在对象起始处
int v = *reinterpret_cast<int*>(&a);        // 42（未定义行为）
```
其他路子：
- `#define private public` 再包含头文件（会破坏标准库，慎用）；
- 模板特化/友元注入（`template<typename> struct Stealer;`）；
- gdb：`p *(A*)0x...`。
- 标准允许**标准布局类型**用 `offsetof` 算偏移，但访问仍需合法途径。

## 高频追问

1. **为什么说这是 UB？** —— 标准不保证成员顺序和填充，编译器也可能重排/优化。
2. **有合法办法吗？** —— 只能加 `friend` 或提供 getter；序列化库常用宏生成访问器。

## 易错点

- 在面试里只答"不可能"
- 真在生产代码里这么干（换编译器就崩）
