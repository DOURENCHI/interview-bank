## 题目

**题目**：`high_resolution_clock::now()` 两次相减，偶尔得到负数。

**问**：`high_resolution_clock` 为什么可能不单调？测耗时应选哪个？怎么验证？

## 口述答案

> 因为标准只规定它是"**精度最高的时钟**"，**没规定它必须单调**。libstdc++ 里它就是 `system_clock` 的别名——墙钟会被 NTP 往回调整，于是出现负的耗时。
> 测耗时必须用 `steady_clock`，标准明确保证它单调。验证方法是查类型的 `is_steady` 常量。

## 讲深一层

```cpp
static_assert(std::chrono::steady_clock::is_steady, "必须是单调时钟");
// 如果换成 high_resolution_clock，这个断言在 libstdc++ 上会失败

// 运行时检查
std::cout << "high_res: " << std::chrono::high_resolution_clock::is_steady
          << ", steady: " << std::chrono::steady_clock::is_steady << "\n";
// libstdc++ 输出: 0, 1
```

| 平台 | `high_resolution_clock` 的别名 | 单调 |
|---|---|---|
| libstdc++（GCC） | `system_clock` | ❌ |
| libc++（Clang） | `steady_clock` | ✅ |
| MSVC | `steady_clock` | ✅ |

**为什么会有"偶尔负数"**：云主机 / 容器里 NTP 校时频繁，墙钟回跳几十毫秒很常见。如果你的超时逻辑用墙钟，就会出现"刚设置 1 秒超时，立刻判定超时"的诡异现象。

**推论**：所有"间隔""超时""限流"的时间计算都必须用单调时钟。

## 高频追问

1. **`is_steady` 是编译期常量吗？** —— 是，可以 `static_assert`。
2. **`steady_clock` 精度够吗？** —— 通常纳秒级，足够。
3. **日志时间戳该用哪个？** —— `system_clock`（需要真实时间），但耗时字段用 `steady_clock` 算。

## 易错点

- 用 `high_resolution_clock` 测耗时
- 用墙钟实现超时逻辑
- 以为"高精度"就等于"单调"
