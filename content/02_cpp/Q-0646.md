## 题目

**场景**：一个类里有个 `char*` 成员，默认拷贝后两个对象指向同一块内存，一个析构另一个就悬垂了。

**问**：浅拷贝和深拷贝的区别是什么？「三法则 / 五法则 / 零法则」分别在说什么？

## 口述答案

> **浅拷贝**只复制成员的值（指针复制的是地址），两个对象共享同一资源；**深拷贝**重新分配一份资源并把内容复制过去。
> 三法则：需要自定义析构、拷贝构造、拷贝赋值中的任何一个，通常三个都要写。五法则加上移动构造和移动赋值。**零法则**是最推荐的：用 `unique_ptr`、`vector`、`string` 这类 RAII 成员，让编译器生成的版本自动正确。

## 讲深一层

```cpp
// 浅拷贝（编译器默认）
struct Shallow { char* p; };          // 两个对象共享 p

// 深拷贝
class Deep {
    std::unique_ptr<char[]> p_;       // 零法则：不写任何特殊成员
};
```

| 法则 | 需要写 | 适用 |
|---|---|---|
| 三法则 | 析构 + 拷贝构造 + 拷贝赋值 | 手动管资源 |
| 五法则 | 再加移动构造 + 移动赋值 | 需要移动优化 |
| 零法则 | 一个都不写 | **现代首选** |

**为什么零法则最好**：手写这三/五个函数极易出错（自赋值、异常安全、`delete[]` vs `delete`），而用 RAII 成员，编译器生成的版本天然正确。

**判断要不要写的信号**：类里有裸指针 / 文件描述符 / 锁，且自己负责释放。

## 高频追问

1. **浅拷贝一定错吗？** —— 不一定。如果成员是"不拥有资源"的观察指针，浅拷贝正是想要的。
2. **`shared_ptr` 算深拷贝还是浅拷贝？** —— 拷贝时共享同一对象、引用计数加一，语义上是"共享所有权"。
3. **移动之后原对象什么状态？** —— 有效但未指定，通常指针被置空。

## 易错点

- 用默认拷贝管理裸指针，双重释放
- 手写三法则但漏了自赋值检查
- 以为 `shared_ptr` 拷贝就是深拷贝
