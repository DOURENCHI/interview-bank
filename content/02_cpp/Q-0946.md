## 题目

**题目**：单例的 `getInstance()` 里 `new` 失败了怎么办？为什么线上会看到两个单例？

**问**：单例模式初始化失败怎么办？为什么会出现多份实例？

## 口述答案

> **初始化失败**：C++11 的局部静态（magic static）保证只初始化一次，但**如果构造函数抛异常，下次调用会重试**——所以失败不会"永久缓存"，但也不会自动降级。工程上应改成显式 `init()` 返回 `bool`，或捕获异常后进入降级模式。
> **多份实例**：最常见于**跨动态库**——每个 `.so` 各自有一份静态变量；其次是旧写法在头文件里定义全局对象；还有多线程下裸双检锁没加 `atomic`。

## 讲深一层

```cpp
// C++11 起线程安全且只初始化一次
static Config& instance() {
    static Config c;      // magic static
    return c;
}
```

| 多份来源 | 修法 |
|---|---|
| 多个 `.so` 各有一份静态 | 单例定义放主程序 / 用符号可见性控制 |
| 头文件里定义全局变量 | 改成函数内静态 + 声明放头文件 |
| 裸双检锁 | 用 `std::call_once` 或 magic static |
| fork 后子进程 | 明确是否需要重置状态 |

## 高频追问

1. **双检锁为什么需要 `atomic`？** —— 对象构造和指针赋值可能被重排，别的线程可能拿到半构造的对象。
2. **单例怎么保证可测试？** —— 提供 `setInstance()` 注入假实现，或干脆用依赖注入。

## 易错点

- 裸双检锁不加 `atomic`
- 在头文件里 `static T inst;` 被多个 TU 各定义一份
