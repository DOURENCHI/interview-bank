## 题目

**题目**：点"设置"按钮弹出子窗口，关掉后想再打开；同时纠结子窗口对象该 `new` 在堆上还是放成员变量。

**问**：子窗口用 `hide()` 还是 `close()`？对象放栈上还是堆上？

## 口述答案

> `close()` 默认只是**隐藏**（除非设了 `WA_DeleteOnClose`），对象还在，所以"关掉再打开"两种都能用。区别是：`hide()` 不触发 `closeEvent`，`close()` 会（可以在这里拦截"是否真的关闭"）。
> 对象**建议放堆上并用 `new` + 父对象**：Qt 的父子对象机制会在父销毁时自动 `delete` 子对象，不会有泄漏；放栈上则受作用域限制，容易悬垂。

## 讲深一层

```cpp
// 成员指针 + 懒创建
void MainWindow::openSettings() {
    if (!settings_) {
        settings_ = new SettingsDialog(this);   // this 作为父对象
        connect(settings_, &QDialog::finished, this, [this]{ settings_->hide(); });
    }
    settings_->show();
    settings_->raise();
    settings_->activateWindow();
}
```

| 方式 | 行为 | 对象是否销毁 |
|---|---|---|
| `hide()` | 隐藏 | 否 |
| `close()` | 隐藏 + 发 `closeEvent` | 否（默认） |
| `close()` + `WA_DeleteOnClose` | 关闭即销毁 | 是 |
| `deleteLater()` | 事件循环空闲时销毁 | 是（安全） |

**`exec()` vs `show()`**：`exec()` 是模态，阻塞到关闭；`show()` 非模态，立刻返回。模态用 `exec()`，非模态用 `show()`。

**`deleteLater()` 而不是 `delete`**：在槽函数里直接 `delete this` 很危险（后续代码还在用），`deleteLater` 把销毁推迟到事件循环安全点。

## 高频追问

1. **模态对话框返回值怎么拿？** —— `exec()` 返回 `Accepted` / `Rejected`，或读 `result()`。
2. **父对象机制会 double delete 吗？** —— 不会，Qt 会从父的子对象列表移除。
3. **子窗口为什么点关闭后没退出程序？** —— 最后一个窗口关闭才退出，或 `quitOnLastWindowClosed` 设置。

## 易错点

- 在槽函数里直接 `delete this`
- 子窗口无父对象，主窗口关了它还在
- 用 `exec()` 却期望非阻塞
