## 题目

**场景**：同事把 `it != end` 改成了 `it < end`，在 `vector` 上跑得好好的，换到 `list` 上编译不过。

**问**：为什么 `it < end` 不可移植？什么时候能用、什么时候不能用？

## 口述答案

> 因为 `<` 只有**随机访问迭代器**才提供。`vector`、`deque` 的迭代器支持 `<`，而 `list`、`map`、`set` 的迭代器是双向的，只能 `++`、`--`、`==`、`!=`，没有大小比较。
> 所以统一写 `!=` 才是正确习惯：它对所有迭代器类别都成立。

## 讲深一层

| 迭代器类别 | `!=` | `<` | `+ n` |
|---|---|---|---|
| 输入 / 输出 | ✅ | ❌ | ❌ |
| 前向 | ✅ | ❌ | ❌ |
| 双向（list/map） | ✅ | ❌ | ❌ |
| 随机访问（vector/deque） | ✅ | ✅ | ✅ |

```cpp
// ✅ 对所有容器都成立
for (auto it = c.begin(); it != c.end(); ++it) ...

// ❌ 只对 vector/deque 成立，list 编译不过
for (auto it = c.begin(); it < c.end(); ++it) ...

// 需要跳转时，用 std::advance / std::next，而不是 it + n
auto it2 = std::next(c.begin(), 3);      // 对 list 是 O(n)，对 vector 是 O(1)
```

**一个容易被忽略的坑**：`vector` 上用 `<` 看似没问题，但一旦容器类型换个 `typedef` 变成 `list`，代码就编不过。**模板代码里更要坚持 `!=`**，因为你不知道实例化时传进来的是什么容器。

## 高频追问

1. **`it < end` 在 `vector` 上一定安全吗？** —— 语法合法，但如果迭代器失效（如 `erase` 后），比较本身也是未定义行为。
2. **怎么知道某个容器的迭代器类别？** —— 查 `iterator_category`，或者记常用：连续内存 → 随机访问，节点式 → 双向，哈希 → 前向。
3. **`std::next` 和 `it + n` 有什么区别？** —— `std::next` 对所有迭代器可用（非随机访问时是 O(n)），`+` 只对随机访问可用。

## 易错点

- 在模板里写 `<`，换容器就编不过
- 以为"能编译就是对的"
- 用 `it + n` 遍历 `list`，编译失败才发现问题
