## 题目

**场景**：一段代码 `new` 了资源，中间某处 `throw`，后面的 `delete` 没执行，内存泄漏。

**问**：RAII 的核心思想是什么？它怎么保证异常安全？

## 口述答案

> RAII 是"**资源获取即初始化**"：把资源的生命周期绑定到一个栈对象上，构造时获取、析构时释放。因为**栈对象在异常展开时一定会被析构**，所以资源一定会释放。
> 关键不在"用了智能指针"，而在"**资源由对象的析构函数管理**"——这是 C++ 保证异常安全的唯一可靠机制（没有 `finally`）。

## 讲深一层

```cpp
// ❌ 异常会跳过 delete
void bad() {
    Resource* r = new Resource();
    mayThrow();          // 抛异常 → r 泄漏
    delete r;
}

// ✅ RAII
void good() {
    auto r = std::make_unique<Resource>();
    mayThrow();          // 抛异常 → unique_ptr 析构 → 自动 delete
}
```

| 资源 | RAII 包装 |
|---|---|
| 堆内存 | `unique_ptr` / `shared_ptr` |
| 文件 | `std::fstream` / `unique_ptr<FILE, fclose>` |
| 互斥锁 | `std::lock_guard` / `unique_lock` |
| 动态库 | 自定义 deleter + `unique_ptr` |
| 数据库连接 | 自定义 RAII 类 |

**为什么 `lock_guard` 是 RAII 的典型**：加锁在构造、解锁在析构，中途抛异常也会解锁——手写 `lock/unlock` 很容易漏。

**RAII 的代价**：几乎没有（析构是编译期确定的，不依赖 GC）；代价是不能忘记"对象的生命周期就是资源的生命周期"。

## 高频追问

1. **RAII 和 GC 的区别？** —— GC 只管内存且时机不定；RAII 管所有资源且**确定性释放**（离开作用域立刻释放）。
2. **析构函数能失败吗？** —— 不该，析构里抛异常会导致 `terminate`；失败要在显式 `close()` 里处理。
3. **成员初始化顺序影响 RAII 吗？** —— 影响，成员按声明顺序构造，析构逆序，所以资源之间的依赖要按顺序声明。

## 易错点

- 说"RAII 就是用智能指针"，漏掉锁、文件等资源
- 在析构函数里抛异常
- 用 `new` 之后手动 `delete`，中间有 `return` 或 `throw`
