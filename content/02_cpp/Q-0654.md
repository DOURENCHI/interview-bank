## 题目

**场景**：没有模板的年代，要写一个适用于 `int`、`double`、`string` 的 `max` 函数。

**问**：没有模板会遇到什么问题？宏、重载、`void*` 三种替代方案各自的缺陷是什么？

## 口述答案

> 三个替代方案都有硬伤：**宏**没有类型检查、参数可能重复求值；**函数重载**要为每种类型手写一遍，类型多了不可维护；**`void*`** 丢失类型信息，无法比较、需要强转、不安全。
> 模板把"类型"变成参数，一份代码在编译期为每种类型生成一份，既有类型安全又没有重复劳动。

## 讲深一层

```cpp
// 方案一：宏 —— 无类型检查，可能重复求值
#define MAX(a,b) ((a)>(b)?(a):(b))
MAX(i++, j)          // i 可能被加两次

// 方案二：重载 —— 每种类型一份，无法穷举
int    max(int a, int b);
double max(double a, double b);

// 方案三：void* —— 丢类型，无法比较
void* max(void* a, void* b, int (*cmp)(void*,void*));   // 调用方要传比较函数

// ✅ 模板
template <typename T>
const T& max(const T& a, const T& b) { return a < b ? b : a; }
```

| 方案 | 类型安全 | 代码量 | 性能 | 可调试 |
|---|---|---|---|---|
| 宏 | ❌ | 少 | 内联但可能重复求值 | ❌ |
| 重载 | ✅ | 随类型线性增长 | 好 | ✅ |
| `void*` | ❌ | 少 | 差（间接调用） | 难 |
| 模板 | ✅ | 一份 | 编译期内联 | ✅ |

**模板的本质**：**编译期的代码生成**，不是运行时多态。这也是它零开销的原因。

## 高频追问

1. **模板会增大二进制吗？** —— 会，每种类型实例化一份；可以用显式实例化控制。
2. **模板能约束类型吗？** —— C++20 的 concepts 可以做；之前靠 SFINAE 或 `static_assert`。
3. **模板和泛型（Java）区别？** —— Java 泛型是类型擦除（运行时一个版本），C++ 模板是编译期生成（每种类型一份），后者更快但代码更大。

## 易错点

- 用宏做泛型，踩重复求值的坑
- 用 `void*` 却忘了传比较函数
- 以为模板是运行时多态
