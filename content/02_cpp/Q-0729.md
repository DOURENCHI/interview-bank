## 题目

**场景**：一段 300 行的 `switch` 按类型分支处理，每加一种类型就要改三处。改成多态后代码短了，但有人说"性能变差了"。

**问**：用多态改写 if-else 分支，好处和代价各是什么？什么情况下不该改？

## 口述答案

> 好处是**开闭原则**：加新类型只需新增一个类，不改已有代码；分支逻辑分散到各子类，可读性和可测试性都更好。
> 代价是**间接调用**（无法内联）、**对象要动态分配**、**代码分散**（一个流程要跳好几个文件才能看全）。所以**分支少、逻辑简单、性能敏感**的地方不该改成多态。

## 讲深一层

```cpp
// ❌ 每加一种类型要改三处
double area(Shape* s) {
    switch (s->type) {
        case CIRCLE: return 3.14 * s->r * s->r;
        case RECT:   return s->w * s->h;
    }
}

// ✅ 多态
struct Shape { virtual double area() const = 0; };
struct Circle : Shape { double r; double area() const override { return 3.14*r*r; } };
```

| 维度 | if-else / switch | 多态 |
|---|---|---|
| 加新类型 | 改多处 | 加一个类 |
| 性能 | 直接调用，可内联 | 间接调用 |
| 逻辑集中度 | 集中（好读全貌） | 分散（好扩展） |
| 测试 | 难以单独测分支 | 每类可独立测 |
| 适合 | 分支少、稳定 | 分支多、会增长 |

**判断标准**：**变化的方向**。如果"类型"是主要变化维度且会持续增加，用多态；如果分支固定不变，switch 更简单直接。

**C++17 的中间选择**：`std::variant` + `std::visit`，静态分派、无堆分配、仍能集中写逻辑。

## 高频追问

1. **多态一定慢吗？** —— 一次间接跳转开销很小，真正的代价是无法内联。
2. **什么时候 switch 更好？** —— 分支少（3–5 个）、逻辑短、性能敏感（如热循环里）。
3. **`std::variant` 的优势？** —— 值语义、无堆分配、编译期检查是否覆盖所有类型。

## 易错点

- 无脑改成多态，代码反而更难读
- 忽略对象分配和间接调用开销
- 用继承改写的却是"数据分支"而非"行为分支"
