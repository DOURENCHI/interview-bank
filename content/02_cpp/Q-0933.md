## 题目

**题目**：面试官问"了解协程吗"，接着追问"它和线程、回调有什么区别"。

**问**：C++20 的协程是怎么工作的？

## 口述答案

> 协程是**能被挂起和恢复的函数**，用三个关键字标记：`co_await`（挂起等一个异步结果）、`co_yield`（产出一个值）、`co_return`（返回）。
> 编译器会把这个函数**改写成状态机**：局部变量放进堆上的协程帧，挂起点变成"保存现场 + 返回调用者"，恢复时跳回挂起点。所以它**没有线程切换开销**，一个线程能跑成千上万个协程。

## 讲深一层

```cpp
Task<int> fetch(url u) {
    auto r = co_await http_get(u);   // 挂起，不阻塞线程
    co_return r.size();
}
```
- **无栈协程**：状态存在堆上，不占用线程栈。
- 需要用户提供 `promise_type`（定义初始/最终挂起、返回值、异常处理），标准库只给了基础设施（`coroutine_handle`）。
- C++23 才有 `std::generator` 这类开箱可用的封装。
- 和线程相比：协程是**协作式**、单线程内切换；线程是抢占式、由 OS 调度。

## 高频追问

1. **协程能并行吗？** —— 不能，它只是"不阻塞地等待"，要并行还得靠线程池。
2. **和回调比好在哪？** —— 代码是同步写法，没有回调地狱，异常和局部变量都能正常工作。

## 易错点

- 以为协程等于多线程
- 不知道要自己实现 promise_type
