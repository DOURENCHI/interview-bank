## 题目

**题目**：信号参数用了自定义结构体 `struct Result { int id; double score; };`，运行时报
`QObject::connect: Cannot queue arguments of type 'Result'`。

**问**：为什么需要 `qRegisterMetaType`？什么时候必须注册？

## 口述答案

> 因为队列连接**不能直接传对象**，Qt 要把参数**拷贝进事件对象**，而拷贝需要一个"元类型"的构造/析构/拷贝函数指针。自定义类型默认不在元类型系统里，所以要注册。
> **只有队列连接（跨线程）才需要**；同线程的直接连接是普通函数调用，不需要注册。

## 讲深一层

```cpp
struct Result { int id; double score; };
Q_DECLARE_METATYPE(Result)          // 让 QVariant 能装它

// main() 里或首次使用前注册
qRegisterMetaType<Result>("Result");

// 现在可以跨线程发信号了
signals:
    void done(const Result& r);
```

| 场景 | 需要注册 |
|---|---|
| 队列连接 / 跨线程信号 | ✅ |
| 直接连接（同线程） | ❌ |
| 存进 `QVariant` | ✅（`Q_DECLARE_METATYPE`） |
| 用于 `Q_PROPERTY` | ✅ |
| 用于 `QMetaObject::invokeMethod` 的 `Q_ARG` | ✅ |

**两个宏的区别**：
- `Q_DECLARE_METATYPE(T)` 让 `QVariant` 能容纳 `T`（编译期）；
- `qRegisterMetaType<T>()` 把 `T` 注册到运行时类型系统（队列连接需要）。

**常见替代方案**：直接传 `QByteArray` 或 `QVariantMap`，省掉注册；或者用 Qt 已注册的类型（`QString`、`QPointF`、`QImage`…）。

## 高频追问

1. **`Q_DECLARE_METATYPE` 放哪？** —— 类型定义之后、全局作用域（通常在头文件里）。
2. **注册一次就够吗？** —— 是，整个进程一次即可（线程安全）。
3. **注册时为什么要传名字？** —— 旧式信号槽按名字匹配，现代写法可以省略。

## 易错点

- 只写了 `Q_DECLARE_METATYPE` 没 `qRegisterMetaType`，队列连接仍失败
- 在同线程测试正常，跨线程才报错
- 把注册放在使用之后的代码路径里
