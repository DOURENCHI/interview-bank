## 题目

**追问**：Qt 的示例代码里窗口总是 `new` 出来，`new` 了不 `delete` 不会泄漏吗？

**问**：Qt 的窗口对象为什么通常 `new` 在堆上？这个 `new` 会不会泄漏？

## 口述答案

> 两个原因：**窗口的生命周期要长于创建它的函数**（放栈上函数返回就销毁了）；**Qt 的父子对象机制会自动管理**——把父对象传给构造函数，父销毁时会 `delete` 所有子对象。
> 所以不会泄漏，前提是**设了父对象**或者**顶层窗口在程序退出时被清理**。

## 讲深一层

```cpp
// ✅ 有父对象，父销毁时自动 delete
auto* btn = new QPushButton("ok", this);

// ✅ 顶层窗口，用 WA_DeleteOnClose 或程序退出时随 QApplication 清理
auto* w = new MainWindow();
w->setAttribute(Qt::WA_DeleteOnClose);
w->show();
```

| 情况 | 会泄漏吗 |
|---|---|
| `new` + 传父对象 | ❌ 父销毁时清 |
| 顶层窗口，程序退出 | ❌ 通常由 `QApplication` 清理 |
| `new` 无父对象且不 delete | ✅ 泄漏 |
| 栈上创建（局部） | 函数返回即销毁（窗口一闪而过） |
| `new` 后 `deleteLater()` | ❌ |

**父子机制的实现**：`QObject` 构造时把子对象指针加入父的 `children()` 列表，父析构时遍历 `delete`。所以**不要手动 `delete` 一个有父对象的子对象**（Qt 会从列表移除，安全但容易搞混所有权）。

**顶层窗口的特殊性**：它不是任何对象的子对象，但 `QApplication` 析构时会清理剩余的窗口。所以"程序退出时"不会报泄漏，但**运行期间反复创建不销毁**就会累积。

## 高频追问

1. **怎么验证没泄漏？** —— valgrind / ASan，或在析构里打日志。
2. **能放栈上吗？** —— 只有"函数内用完就关"的临时对话框可以。
3. **`QScopedPointer` / `std::unique_ptr` 能用吗？** —— 能，但和有父对象混用容易出现双重释放，二选一。

## 易错点

- `new` 了窗口既不给父对象也不 delete
- 手动 delete 有父对象的子对象
- 以为 Qt 会垃圾回收所有对象
