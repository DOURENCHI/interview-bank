## 题目

**题目**：`int t = std::time(nullptr);` 存时间戳，2038 年会怎样？

**问**：为什么不能用 `int` 存时间戳？除了溢出还有什么坑？

## 口述答案

> `int` 只有 32 位，`time_t` 的秒数在 **2038-01-19 会溢出**（超过 `INT_MAX` 约 21.4 亿秒），变成负数——这是著名的"2038 问题"。
> 除此之外还有三个坑：**`time_t` 不保证是秒**、**不包含时区信息**、**精度只到秒**（测耗时完全不够）。

## 讲深一层

```cpp
// ❌
int t = std::time(nullptr);          // 2038 溢出

// ✅
std::int64_t t = std::time(nullptr); // 或 std::time_t
auto now = std::chrono::system_clock::now();
auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(
              now.time_since_epoch()).count();   // 毫秒，int64
```

| 类型 | 位宽 | 范围 | 适用 |
|---|---|---|---|
| `int`（32 位） | 32 | ±2.1e9 秒 | ❌ 时间戳 |
| `time_t` | 通常 64 位 | 足够 | ✅（但标准不保证） |
| `int64_t` | 64 | 约 ±2920 亿年（纳秒） | ✅ 显式 |
| `chrono::seconds` | 至少 35 位 | 标准保证 | ✅ 推荐 |

**三个额外注意点**：
1. **`time_t` 单位未规定**（通常是秒，但标准只说"实现定义"）；
2. **`std::time` 返回的是 UTC 秒数**，转本地时间要 `localtime`，而 `localtime` **不是线程安全的**（要用 `localtime_r`）；
3. **系统时间会被 NTP 调整**，用 `system_clock` 测耗时可能得到负数——测耗时必须用 `steady_clock`。

## 高频追问

1. **怎么存毫秒时间戳？** —— `int64_t` + `duration_cast<milliseconds>`。
2. **跨时区怎么处理？** —— 内部统一存 UTC，展示时按用户时区转换。
3. **`localtime` 为什么不安全？** —— 返回指向静态缓冲区的指针，多线程会互相覆盖。

## 易错点

- 用 `int` 存 `time_t`
- 用 `system_clock` 测耗时（可能被 NTP 调整）
- 多线程里用 `localtime`
