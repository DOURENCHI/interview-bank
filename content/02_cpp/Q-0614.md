## 题目

**场景**：一个小项目所有代码都写在 `main.cpp` 里，编译一次要 40 秒。改成多个文件后，每次只编改动的那个，2 秒完成。

**问**：为什么 C++ 项目必须分头文件和源文件？只为了编译快吗？

## 口述答案

> 编译快只是收益之一。更根本的是三件事：**接口与实现分离**（头文件声明、源文件定义）、**支持增量编译**（一个编译单元改动不影响其他）、**避免重复定义**（多个 `.cpp` 包含同一个头文件时，函数定义在头文件里会违反 ODR）。
> 另外它还让库可以只发布头文件 + 二进制，隐藏实现细节。

## 讲深一层

```
include/math_utils.h     ← 声明：int add(int, int);
src/math_utils.cpp       ← 定义：int add(int a, int b) { return a + b; }
src/main.cpp             ← #include "math_utils.h"，只看到声明
```

| 放头文件 | 放源文件 |
|---|---|
| 函数声明、类定义 | 函数定义（除非 inline） |
| 模板、inline 函数 | 静态局部变量 |
| 常量表达式、`constexpr` | 内部实现细节 |
| `extern` 变量声明 | 变量定义 |

**编译模型**：每个 `.cpp` 是独立编译单元，`#include` 本质是文本粘贴，所以头文件里放定义会导致每个包含它的 `.cpp` 都生成一份定义 → 链接时"multiple definition"。

**例外**：模板和 `inline` 函数必须放头文件，因为它们要在使用处实例化/内联。

## 高频追问

1. **`#pragma once` 和 include guard 哪个好？** —— `#pragma once` 简洁且被主流编译器支持；include guard 是标准做法，两者可以同用。
2. **为什么改一个头文件会导致全量重编？** —— 所有包含它的 `.cpp` 都要重编；这就是"编译防火墙"（pimpl、前置声明）要解决的问题。
3. **`static` 函数放头文件里行不行？** —— 行，但每个编译单元会有一份副本，浪费空间且容易混淆。

## 易错点

- 把函数定义放头文件，链接报 multiple definition
- 头文件里定义全局变量（应该 `extern` 声明 + 源文件定义）
- 以为分文件只是为了"看起来整洁"
