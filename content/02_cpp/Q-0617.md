## 题目

**场景**：新建一个 C++ 项目，只写 `main.cpp`，要一个能编译出可执行文件的 `CMakeLists.txt`。

**问**：最小可用的三条命令是哪三条？各自在做什么？

## 口述答案

> 三条：`cmake_minimum_required`、`project`、`add_executable`。
> 第一条告诉 CMake 需要的最低版本（影响策略和行为），第二条声明项目名和语言，第三条把源文件编成可执行目标。有这三行就能 `cmake -B build && cmake --build build`。

## 讲深一层

```cmake
cmake_minimum_required(VERSION 3.16)
project(hello LANGUAGES CXX)
add_executable(hello main.cpp)
```

| 命令 | 作用 | 不写会怎样 |
|---|---|---|
| `cmake_minimum_required` | 设最低版本和策略 | 警告，行为随版本变化 |
| `project` | 设项目名、语言、版本 | 报错（必须有） |
| `add_executable` | 定义可执行目标 | 没有构建目标 |

逐步加料：

```cmake
cmake_minimum_required(VERSION 3.16)
project(hello LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)          # 不用 gnu++17，用标准 c++17

add_executable(hello main.cpp)
target_compile_options(hello PRIVATE -Wall -Wextra)
```

**为什么用 `target_*` 而不是全局 `include_directories`**：`target_*` 的作用域是那个目标，不会污染其他目标；全局设置在一个大项目里是灾难。

## 高频追问

1. **`cmake .` 和 `cmake -B build` 区别？** —— 前者在当前目录生成一堆文件（污染源码树），后者生成到 `build/`（推荐）。
2. **`LANGUAGES` 一定要写吗？** —— 不写默认 C 和 CXX，写清楚能避免不必要的编译器检测。
3. **怎么指定 C++ 标准更稳？** —— 优先 `set(CMAKE_CXX_STANDARD 17)`，比手写 `-std=c++17` 更可移植（MSVC 也能识别）。

## 易错点

- 只写 `add_executable`，缺 `project`
- 用 `cmake .` 污染源码目录
- 全局 `include_directories` 而不是 `target_include_directories`
