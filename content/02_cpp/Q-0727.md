## 题目

**题目**：

```cpp
struct Base { Base(int x) {} };      // 只有有参构造，没有默认构造
struct D : Base {
    D() {}                            // 编译错误
};
```

**问**：为什么必须在初始化列表里显式调用父类构造？不写会怎样？

## 口述答案

> 因为派生类构造时**必须先构造基类部分**，而基类没有默认构造函数，编译器不知道传什么参数，所以报错。
> 必须在初始化列表里写 `D() : Base(42) {}`。如果不写，编译器尝试调用 `Base()`，但那个构造函数不存在。

## 讲深一层

```cpp
struct Base { Base(int x) { cout << "Base" << x; } };

struct D : Base {
    D() : Base(42) {}          // ✅ 显式调用
    // D() {}                  // ❌ no matching function for call to Base::Base()
};
```

| 基类情况 | 派生类要不要显式调用 |
|---|---|
| 有默认构造 | 不用（隐式调用） |
| 只有有参构造 | **必须** |
| 有默认构造但想用别的 | 要 |
| 多个基类 | 每个都可指定，按声明顺序构造 |

**顺序注意**：初始化列表里基类的书写顺序不影响实际顺序，**基类总按继承声明顺序构造**，且在成员之前。

**相关的坑**：如果基类构造可能失败（抛异常），派生类的成员还没构造，此时只有已完成的基类会被析构。

## 高频追问

1. **能在构造函数体里调基类构造吗？** —— 不能，基类在进入函数体前就已构造完；函数体里只能赋值。
2. **虚基类谁负责构造？** —— 最派生类，中间类对虚基类的初始化会被忽略。
3. **委托构造是什么？** —— `D() : D(0) {}`，一个构造函数调用同类的另一个。

## 易错点

- 忘了基类没有默认构造
- 在函数体里"调用"基类构造（实际是创建临时对象）
- 以为初始化列表顺序决定基类构造顺序
