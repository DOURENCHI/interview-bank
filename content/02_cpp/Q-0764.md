## 题目

**题目**：用 `QTableWidget` 循环 `setItem` 填 10 万行，界面卡了十几秒。

**问**：Qt 的 Model/View 架构比手动填表格好在哪？什么时候该换？

## 口述答案

> `QTableWidget` 是"**每一项都是一个对象**"的简单封装，10 万行就是 10 万个 `QTableWidgetItem`，内存和构建时间都爆掉。
> Model/View 把**数据**和**显示**分开：`QAbstractTableModel` 只在需要时通过 `data()` 提供当前可见的单元格，视图只渲染屏幕上那几十行。这才是能处理大数据量的结构。

## 讲深一层

```cpp
class MyModel : public QAbstractTableModel {
    QVector<Row> rows_;
public:
    int rowCount(const QModelIndex& = {}) const override { return rows_.size(); }
    int columnCount(const QModelIndex& = {}) const override { return 3; }
    QVariant data(const QModelIndex& idx, int role) const override {
        if (role != Qt::DisplayRole) return {};
        const auto& r = rows_[idx.row()];
        return idx.column() == 0 ? QVariant(r.id)
             : idx.column() == 1 ? QVariant(r.name)
                                 : QVariant(r.score);
    }
};
```

| 对比 | `QTableWidget` | Model/View |
|---|---|---|
| 数据存储 | 每项一个对象 | 你自己的容器 |
| 10 万行 | 内存爆炸、卡顿 | 流畅 |
| 排序/筛选 | 手动 | `QSortFilterProxyModel` |
| 多视图共享数据 | 难 | 天然支持 |
| 代码量 | 少 | 多（要写 model） |

**关键理解**：视图只调 `data()` 取**可见区域**的数据，所以 model 的 `data()` 必须**快**——不要在里面对整个数据集做遍历或 IO。

**`QSortFilterProxyModel` 的价值**：排序、筛选、多视图共享都能复用，不用改 model。

## 高频追问

1. **数据变了怎么通知视图？** —— `beginInsertRows/endInsertRows`、`dataChanged` 信号，必须成对调用。
2. **什么时候还用 `QTableWidget`？** —— 数据量小（几百行）、快速原型。
3. **`QTableView` 和 `QTableWidget` 什么关系？** —— 后者是前者的便捷子类（内置了默认 model）。

## 易错点

- 大数据量用 `QTableWidget`
- 改了数据不发 `dataChanged`，界面不刷新
- 在 `data()` 里做耗时计算
