## 题目

**场景**：`void f(int a, int b = 0);` 和 `void f(int a);` 同时存在时，`f(1)` 报"调用有歧义"。

**问**：函数重载的决议规则是什么？默认参数会带来什么坑？

## 口述答案

> 决议顺序：**精确匹配 → 类型提升 → 标准转换 → 用户定义转换**，同级别有多个候选就报歧义。
> `f(1)` 的歧义来自：`f(int)` 是精确匹配，`f(int, int=0)` 也是精确匹配（用了默认参数），两者同级，编译器无法选择。

## 讲深一层

```cpp
void f(int a, int b = 0);
void f(int a);
f(1);            // ❌ ambiguous

void g(int);
void g(double);
g(1);            // ✅ 精确匹配 int
g(1.0f);         // ✅ float → double（提升）优于 float → int（转换）
```

| 优先级 | 转换 |
|---|---|
| 1 | 精确匹配（含 `const` 调整、数组退化） |
| 2 | 提升（`char`→`int`、`float`→`double`） |
| 3 | 标准转换（`int`→`double`、指针转换） |
| 4 | 用户定义转换（构造函数、`operator T`） |

**默认参数的三个坑**：
1. 只能从右往左连续给默认值；
2. 默认值在**声明处**求值（虚函数用静态绑定）；
3. 和重载混用时容易产生歧义。

## 高频追问

1. **默认参数是编译期还是运行期？** —— 调用点展开，等价于显式传值；所以默认值不能是运行时才有的变量。
2. **虚函数能用默认参数吗？** —— 能，但默认值按**静态类型**取，容易出反直觉的结果。
3. **重载和模板谁优先？** —— 精确匹配时普通函数优先于模板实例化。

## 易错点

- 默认参数从中间开始给
- 虚函数 + 默认参数混用，行为与预期不符
- 重载只靠返回值区分（不允许）
