## 题目

**题目**：要存 10 万条"用户 ID → 信息"，需要频繁按 ID 查，偶尔要按 ID 排序输出。

**问**：map 和 unordered_map 有什么区别？怎么选？

## 口述答案

> `map` 是**红黑树**：有序、查找/插入 O(log n)、迭代器稳定（除被删元素）；`unordered_map` 是**哈希表**：无序、平均 O(1)、最坏 O(n)、扩容时迭代器全失效。
> 选法：**要排序或范围查询 → map；只按 key 查、追求性能 → unordered_map**。

## 讲深一层

| 维度 | map | unordered_map |
|---|---|---|
| 底层 | 红黑树 | 哈希桶 |
| 查找 | O(log n) | 平均 O(1)，最坏 O(n) |
| 有序 | ✅ | ❌ |
| 内存 | 每节点 3 指针 + 颜色 | 桶数组 + 节点 |
| key 要求 | `operator<` | `std::hash` + `operator==` |
| 迭代器失效 | 只失效被删的 | rehash 后全失效 |
- 自定义类型当 key：`map` 提供比较器；`unordered_map` 要特化 `std::hash` 并定义 `operator==`。
- `unordered_map` 可 `reserve` 预留桶数，避免反复 rehash。
- 遍历顺序稳定性的差别常导致"本地对、上线错"的 bug。

## 高频追问

1. **哈希冲突怎么处理？** —— 标准没规定，主流实现是链地址法（桶挂链表/或树化）。
2. **为什么 unordered_map 最坏 O(n)？** —— 所有 key 哈希到同一个桶，退化成链表。

## 易错点

- 依赖 `unordered_map` 的遍历顺序
- 自定义 key 只写了 hash 没写 `operator==`
