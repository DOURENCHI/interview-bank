## 题目

**追问**：编译器把引用编译成了什么？如果引用不占空间，函数参数是怎么传的？

**问**：从汇编看，引用和指针到底差在哪？「引用零开销」这个说法在什么情况下不成立？

## 口述答案

> 在**参数和局部变量**层面，引用通常被编译成指针——传引用就是传地址，用的时候解引用。所以"零开销"指的是**没有额外的拷贝**，不是"没有地址传递"。
> 不成立的情况有三种：**作为类成员**（必须存地址，占一个指针）、**需要运行时绑定且编译器无法优化掉**、**跨编译单元传递**（ABI 上就是指针）。

## 讲深一层

```cpp
int add1(int& a) { return a + 1; }
int add2(int* p) { return *p + 1; }
```

两者生成的汇编基本一致：
```asm
; int add1(int&):
    mov     eax, DWORD PTR [rdi]     ; 从 rdi 指向的地址读
    add     eax, 1
    ret
```

| 场景 | 引用的实现 | 是否占空间 |
|---|---|---|
| 函数参数 | 传地址 | 不额外占（复用寄存器） |
| 局部变量 | 编译器可完全优化掉 | 否 |
| 类成员 | 存一个指针 | 是（8 字节） |
| 返回值 | 返回地址 | 否 |
| 存进 `std::tuple` | 存指针 | 是 |

**"零开销"的准确含义**：相对"按值传递"没有拷贝开销；相对"传指针"没有性能差异。它是一个**语义工具**，不是性能工具。

**这也是 `const T&` 对小类型反而慢的原因**：传 `int` 用寄存器，传 `const int&` 要传地址再解引用，多一次内存访问。

## 高频追问

1. **引用做成员为什么必须初始化？** —— 它要存地址，没有默认值可填。
2. **引用成员能赋值吗？** —— 不能，赋值运算符被隐式删除（因为不能换绑）。
3. **`std::reference_wrapper` 有什么用？** —— 让引用可以放进容器、可以重新绑定（因为它是对象）。

## 易错点

- 认为"引用零开销"等于"没有地址传递"
- 用引用做成员却没意识到占 8 字节
- 对小类型参数用 `const&`，反而多一次间接寻址
