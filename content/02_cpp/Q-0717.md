## 题目

**追问**：类里同时定义了拷贝构造和移动构造，`T b = std::move(a);` 一定走移动构造吗？

**问**：什么情况下"有移动构造却还是走了拷贝"？这会造成什么后果？

## 口述答案

> 三种情况会退化成拷贝：**移动构造不是 `noexcept`**（某些容器如 `vector` 扩容时会选拷贝以保证异常安全）、**实参是 `const` 右值**（`const T&&` 只能绑到拷贝构造）、**类没有可移动的资源**（成员自己不可移动）。
> 后果是性能回退，而且很隐蔽——代码看起来用了 `std::move`，实际一次拷贝都没省。

## 讲深一层

```cpp
class Buf {
    char* p_;
public:
    Buf(Buf&& o) noexcept : p_(o.p_) { o.p_ = nullptr; }   // ✅ noexcept
    Buf(const Buf& o) : p_(new char[...]) { ... }
};

std::vector<Buf> v;
v.push_back(Buf{});      // noexcept → 走移动
```

| 条件 | 结果 |
|---|---|
| 移动构造 `noexcept` | 移动 ✅ |
| 移动构造可能抛异常，容器扩容 | 拷贝（保证强异常安全） |
| 实参是 `const T&&` | 拷贝 |
| 没有移动构造 | 拷贝（若有拷贝） |
| 移动构造被 `= delete` | 编译错误 |

**`noexcept` 为什么关键**：`vector` 扩容时如果移动中途抛异常，原容器已被破坏（元素被移走了一部分），无法回滚。所以标准库规定：**只有移动构造 `noexcept` 时才用移动**，否则用拷贝来保证强异常安全。

## 高频追问

1. **怎么确认真的移动了？** —— 在移动构造里打日志，或 `static_assert(std::is_nothrow_move_constructible_v<T>)`。
2. **`= default` 的移动构造是 `noexcept` 吗？** —— 取决于成员；成员都可无异常移动时，默认的才是 `noexcept`。
3. **容器里存 `unique_ptr` 为什么没这问题？** —— `unique_ptr` 的移动是 `noexcept` 的。

## 易错点

- 移动构造没标 `noexcept`，容器扩容仍走拷贝
- 对 `const` 对象用 `std::move`
- 以为写了移动构造就一定被调用
