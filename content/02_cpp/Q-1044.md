## 题目

有了 JSON Schema，是不是就不会出现工具调用错误了？

## 口述答案

> 不是。Schema 只保证**结构合法**，不保证语义正确：参数类型对但值离谱（城市填成"abc"、时间范围反了）、必填字段填了但业务上无效、多个工具选错、参数依赖关系不满足——这些 schema 都拦不住。
> 所以要补：①枚举/范围/正则等**值域约束**；②服务端**业务校验**（权限、资源存在性）；③错误信息可读，让模型能自我修正；④关键工具加人工确认或 dry-run。

## 讲深一层

| 层级 | 能拦住什么 |
|---|---|
| JSON Schema | 类型、必填、枚举 |
| 值域约束 | 范围、格式、依赖关系 |
| 服务端业务校验 | 权限、资源存在性 |
| 人工确认/dry-run | 高风险写操作 |

## 高频追问

1. **模型总选错工具怎么办？** —— 减少工具数量/按阶段注入、工具描述写清适用与不适用场景、给 few-shot。

## 易错点

- 认为 schema 校验过了就安全
- 错误直接抛 500，不告诉模型怎么改
