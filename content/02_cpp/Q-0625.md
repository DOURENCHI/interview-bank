## 题目

**场景**：每次新建项目都从别的项目拷 CMakeLists，改改名字。拷来的文件里有一堆用不上的配置，也不知道哪些是必需的。

**问**：一个可复用的 CMakeLists 模板应该包含什么？哪些是必需的、哪些是可选加料的？

## 口述答案

> 必需四块：**版本声明、项目声明、可执行目标、编译选项**。可选加料按需：依赖查找、安装规则、测试、导出配置。
> 我建议的骨架是"最小可用 + 按需追加"，而不是一上来堆全套——不知道在做什么的配置，出问题时最难排查。

## 讲深一层

```cmake
cmake_minimum_required(VERSION 3.16)
project(myapp VERSION 0.1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
if(NOT CMAKE_BUILD_TYPE)
  set(CMAKE_BUILD_TYPE Release CACHE STRING "" FORCE)
endif()

add_executable(myapp src/main.cpp src/util.cpp)
target_include_directories(myapp PRIVATE include)
target_compile_options(myapp PRIVATE -Wall -Wextra -Wpedantic)

# 可选：依赖
find_package(Threads REQUIRED)
target_link_libraries(myapp PRIVATE Threads::Threads)

# 可选：安装
include(GNUInstallDirs)
install(TARGETS myapp RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR})

# 可选：测试
enable_testing()
add_test(NAME smoke COMMAND myapp --version)
```

| 块 | 必需 | 说明 |
|---|---|---|
| `cmake_minimum_required` | ✅ | 版本策略 |
| `project(... VERSION ...)` | ✅ | 版本号后面 install 要用 |
| `CXX_STANDARD` | ✅ | 别依赖编译器默认值 |
| `CMAKE_BUILD_TYPE` 默认值 | 建议 | 避免误用 Debug 测性能 |
| `target_*` 而非全局命令 | ✅ | 避免污染 |
| `install` / `export` | 做库时必需 | 让别人 `find_package` 到你 |
| `enable_testing` | 建议 | 接 CI 的前提 |

**两个原则**：能用 `target_*` 就不用全局命令；默认构建类型设为 Release，开发时显式指定 `RelWithDebInfo`。

## 高频追问

1. **为什么要设默认 `CMAKE_BUILD_TYPE`？** —— 不设就是空（等价 `-O0`），性能测试会得到假数据。
2. **`-Wall -Wextra` 会不会太吵？** —— 一开始会，但能挡住大量真实 bug；可以用 `-Wno-` 精确关掉个别。
3. **库项目还要加什么？** —— `install(EXPORT ...)`、`xxx-config.cmake`、`soname` 版本管理。

## 易错点

- 不设默认构建类型，性能测试全错
- 用全局 `include_directories` 污染所有目标
- 模板里塞一堆看不懂的配置，出问题无法定位
