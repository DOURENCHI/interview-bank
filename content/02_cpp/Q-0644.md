## 题目

**题目**：读程序写结果的高频题型——

```cpp
struct A { A(){cout<<"A";} ~A(){cout<<"~A";} };
struct B { A a; B(){cout<<"B";} ~B(){cout<<"~B";} };
int main() { B b; }
```

**问**：输出是什么？如果 `B` 继承自 `A`，顺序会怎么变？

## 口述答案

> 输出 `AB~B~A`。规则是：**构造时先基类、再成员、最后自身；析构时完全逆序**。
> 如果 `B` 继承 `A`，且 `B` 里还有成员 `A a`，构造顺序是：基类 `A` → 成员 `a` → `B` 自身，即 `AA B`。

## 讲深一层

```cpp
struct A { A(){cout<<"A";} ~A(){cout<<"~A";} };
struct B : A {                       // 继承
    A a;                             // 成员
    B(){cout<<"B";} ~B(){cout<<"~B";}
};
int main() { B b; }
// 输出：A A B ~B ~A ~A
//       基类 成员 自身
```

| 阶段 | 顺序 |
|---|---|
| 构造 | 基类 → 成员（按**声明顺序**）→ 自身 |
| 析构 | 自身 → 成员（**逆序**）→ 基类 |

**两个高频陷阱**：

1. **成员按声明顺序构造，不看初始化列表顺序**。写成 `B() : a2(2), a1(1) {}`，如果 `a1` 先声明，仍然先构造 `a1`。
2. **虚基类最先构造**，且只构造一次。

**为什么必须这样**：派生类的构造函数体可能用到基类和成员，所以它们必须先就绪；析构反过来，因为派生类可能还要用基类资源。

## 高频追问

1. **初始化列表顺序重要吗？** —— 书写顺序不重要，实际顺序按声明；不一致时编译器会警告。
2. **析构函数里能调用虚函数吗？** —— 能，但已经退化为当前类的版本（派生部分已析构）。
3. **构造期间抛异常会析构哪些？** —— 已完成的基类和成员会逆序析构，当前对象自身不析构。

## 易错点

- 以为初始化列表顺序决定构造顺序
- 析构函数里调用依赖派生类的虚函数
- 忘记虚基类最先构造
