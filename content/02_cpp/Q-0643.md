## 题目

**题目**：

```cpp
struct T { int id; T(int i):id(i){ cout << "ctor" << id << " "; } ~T(){ cout << "dtor" << id << " "; } };
T arr[3] = {T(1), T(2), T(3)};
```

**问**：这段代码的输出是什么？对象数组的构造和析构分别是几次、什么顺序？

## 口述答案

> 构造 3 次、析构 3 次，**但顺序相反**：构造按 `1 2 3`，析构按 `3 2 1`。
> 这和 C++ 的对象生命周期规则一致：**后构造的先析构**（栈式语义，LIFO）。数组元素在栈上连续排列，销毁时从后往前。

## 讲深一层

```cpp
// 输出（不计临时对象）：
// ctor1 ctor2 ctor3  dtor3 dtor2 dtor1
```

| 场景 | 构造顺序 | 析构顺序 |
|---|---|---|
| 局部对象数组 | 下标 0 → n-1 | n-1 → 0 |
| 多个局部变量 | 声明顺序 | 逆序 |
| 类成员 | 声明顺序（不看初始化列表） | 逆序 |
| 基类 + 成员 | 基类 → 成员 → 自身 | 自身 → 成员 → 基类 |

**一个陷阱**：如果某个元素的构造函数抛异常，已经构造成功的元素会被**逆序析构**，未构造的不析构——这叫"栈解旋"。

**`new T[3]` 的区别**：在堆上分配，构造仍按 0→2，但析构要 `delete[]` 才触发（`delete` 只析构第一个，是未定义行为）。

## 高频追问

1. **`delete` 和 `delete[]` 混用会怎样？** —— 未定义行为，通常只析构第一个元素，其余泄漏。
2. **对象数组能 `memset(0)` 吗？** —— 不能，会破坏 vptr 和内部状态。
3. **`std::vector<T>` 的析构顺序？** —— 元素逆序析构（标准要求）。

## 易错点

- 认为析构和构造同序
- `new[]` 配 `delete`
- 对含虚函数的对象数组做 `memset`
