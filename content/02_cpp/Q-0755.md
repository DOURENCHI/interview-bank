## 题目

**题目**：`connectToHost` 之后调 `write()`，程序没报错但数据丢了。加日志发现 `connected` 信号比 `write` 晚到。

**问**：TCP 建连时 `connected`、`readyRead`、`disconnected` 的触发顺序是怎样的？为什么不能在 `connectToHost` 后立刻 `write`？

## 口述答案

> `connectToHost` 是**异步**的：它立刻返回，真正的连接建立后才会发 `connected`。在 `connected` 之前调用 `write()`，数据会进入 Qt 的写缓冲，等连接建立后再发——但如果你在这期间销毁了 socket，数据就丢了。
> 正确做法是**在 `connected` 槽里才开始收发**。断开时的顺序是 `disconnected` 最后，之前可能还有一次 `readyRead`（对端发完数据再关）。

## 讲深一层

```cpp
void MainWindow::onConnectClicked() {
    socket_->connectToHost(host, port);      // 立刻返回
    // ❌ 这里 write 会进缓冲，语义不明确
}

void MainWindow::onConnected() {
    qDebug() << "connected";
    socket_->write(hello);                   // ✅ 安全
}

void MainWindow::onReadyRead() {
    buf_ += socket_->readAll();
    parse();
}

void MainWindow::onDisconnected() {
    qDebug() << "disconnected";
}
```

| 信号 | 时机 | 注意 |
|---|---|---|
| `connected` | 三次握手完成 | 之后才能安全 write |
| `readyRead` | 有数据可读 | 可能多次、可能半包 |
| `bytesWritten` | 数据已交给系统 | 不等于对端收到 |
| `disconnected` | 连接关闭 | 之前可能还有 `readyRead` |
| `errorOccurred` | 出错 | 之后通常跟 `disconnected` |

**常见误判**：`write()` 返回正数只表示"进入缓冲"，不代表发送成功。要确认发送进度看 `bytesWritten`，要确认对方收到只能靠应用层 ACK。

## 高频追问

1. **连接失败怎么知道？** —— `errorOccurred` 信号 + `errorString()`。
2. **能同步等待连接吗？** —— `waitForConnected()`，但会阻塞，GUI 线程慎用。
3. **对端关闭和本地关闭有什么区别？** —— 对端关闭会触发 `readyRead`（读到 0 字节）+ `disconnected`。

## 易错点

- `connectToHost` 后立刻 `write` 并假设已发送
- 把 `write` 返回值当成"对端已收到"
- 忽略 `errorOccurred`，连接失败无感知
