## 题目

**题目**：`[=]`、`[&]`、`[this]`、`[x, &y]` 几种捕获方式，什么时候会捕获到悬垂引用？

**问**：`[=]` 和 `[&]` 有什么区别？什么情况下 lambda 会捕获到已销毁的对象？

## 口述答案

> `[=]` **按值捕获**（拷贝一份，lambda 内部只读，除非 `mutable`），`[&]` **按引用捕获**（引用原对象，能改，但有生命周期风险）。
> 危险的场景：**lambda 的生命周期超过被捕获对象**——比如把 `[&]` 的 lambda 存进回调、丢给线程、或返回出去，等它执行时局部变量已经销毁。

## 讲深一层

```cpp
// ❌ 悬垂引用
std::function<void()> f;
{
    int x = 1;
    f = [&x] { std::cout << x; };   // x 已经销毁
}
f();

// ✅ 按值捕获
std::function<void()> g;
{
    int x = 1;
    g = [x] { std::cout << x; };    // 拷贝 1
}
g();
```

| 捕获 | 拷贝 | 可修改 | 风险 |
|---|---|---|---|
| `[=]` | ✅ | 需 `mutable` | 拷贝开销、对象切片 |
| `[&]` | ❌ | ✅ | **悬垂**（生命周期） |
| `[this]` | 指针 | ✅ | `this` 悬垂 |
| `[x, &y]` | 混合 | y 可改 | y 悬垂 |
| `[p = std::move(ptr)]` | 移动 | ✅ | 无（C++14 初始化捕获） |

**`[=]` 也有坑**：它捕获 `this` 指针（不是对象副本），所以成员函数里用 `[=]` 返回 lambda，对象销毁后一样悬垂。C++20 起 `[=]` 捕获 `this` 被弃用，要求显式 `[this]` 或 `[*this]`。

**异步场景的铁律**：跨线程/跨回调的 lambda 一律按值捕获（或用 `shared_ptr` 保活），不要用 `[&]`。

## 高频追问

1. **`[*this]` 是什么？** —— C++17 起按值捕获整个对象副本，避免 `this` 悬垂。
2. **`[=]` 真的一律拷贝吗？** —— 数组会退化成指针、`this` 是指针、大对象会拷贝，不总是你想要的。
3. **怎么在 lambda 里改按值捕获的变量？** —— 加 `mutable`，但改的是副本。

## 易错点

- `[&]` 的 lambda 跨线程/跨回调使用
- 成员函数里 `[=]` 返回 lambda，`this` 悬垂
- 以为 `[=]` 拷贝了整个对象
