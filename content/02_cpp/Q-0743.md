## 题目

**场景**：写 ROS2 节点时，示例代码都是 `class MyNode : public rclcpp::Node`。而写普通工具类时，大家又说"优先用组合"。

**问**：为什么 ROS2 节点通常要继承 `rclcpp::Node`？这和"优先组合"矛盾吗？

## 口述答案

> 不矛盾，因为这里用的是**继承的另一个用途：实现接口 + 获得基类能力**。`rclcpp::Node` 提供了创建发布者、订阅者、定时器、参数等一整套基础设施，继承后直接 `this->create_publisher(...)`，代码最短。
> 如果改成组合（`class MyNode { rclcpp::Node node_; }`），也能工作，但要处处写 `node_.create_publisher(...)`，而且回调里拿不到 `this` 当节点用。

## 讲深一层

```cpp
// 继承（ROS2 官方风格）
class Detector : public rclcpp::Node {
public:
    Detector() : Node("detector") {
        sub_ = create_subscription<Image>("img", 10,
            [this](Image::SharedPtr m) { onImage(m); });
    }
private:
    rclcpp::Subscription<Image>::SharedPtr sub_;
};

// 组合（也能用，但啰嗦）
class Detector2 {
public:
    Detector2() : node_(std::make_shared<rclcpp::Node>("detector")) {
        sub_ = node_->create_subscription<Image>("img", 10, ...);
    }
private:
    std::shared_ptr<rclcpp::Node> node_;
};
```

| 方案 | 优点 | 缺点 |
|---|---|---|
| 继承 `Node` | 代码短、回调里 `this` 就是节点、官方示例一致 | 耦合框架，难单测 |
| 组合 `Node` | 可测试、可替换、符合"优先组合" | 代码啰嗦，要传 `node_` |
| 继承 + 抽接口 | 兼顾 | 多一层设计 |

**为什么这里继承是合理的**：`rclcpp::Node` 本质上是"给派生类提供能力的基类"（类似 `std::enable_shared_from_this`），不是"数据模型"。而且节点类通常只做一层派生。

**真正的代价**：难做单元测试——想脱离 ROS2 环境测逻辑，得把业务逻辑抽到独立的类里，节点只做胶水。这也是工程上推荐的写法。

## 高频追问

1. **怎么让节点可测？** —— 业务逻辑放独立类，节点只负责订阅、转换参数、调用业务类。
2. **`rclcpp::Node` 有虚析构吗？** —— 有，继承它并 `delete` 基类指针是安全的。
3. **一个进程能有多个节点吗？** —— 能，用 `rclcpp::executors::MultiThreadedExecutor` 把多个节点加进去。

## 易错点

- 把业务逻辑全写在节点类里，无法单测
- 认为"继承一定错、组合一定对"
- 忘了 `Node` 的构造函数要传节点名
