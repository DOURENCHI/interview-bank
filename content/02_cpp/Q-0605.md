## 题目

**场景**：`std::vector<Foo*> v;` 里装了一堆 `new` 出来的对象，`v` 析构后内存没释放。

**问**：容器析构时会 delete 里面的裸指针吗？为什么？正确做法是什么？

## 口述答案

> **不会**。容器析构时对每个元素调用**元素的析构函数**，而裸指针的析构函数什么也不做（它是平凡类型），所以指针指向的对象不会被释放。
> 正确做法是用智能指针：`std::vector<std::unique_ptr<Foo>>`，容器析构时 `unique_ptr` 的析构函数会 `delete`。

## 讲深一层

```cpp
// ❌ 泄漏
std::vector<Foo*> v;
v.push_back(new Foo());
// v 析构：只销毁指针本身，Foo 对象泄漏

// ✅ 独占所有权
std::vector<std::unique_ptr<Foo>> v2;
v2.push_back(std::make_unique<Foo>());

// ✅ 不拥有所有权时用裸指针，但要保证生命周期
std::vector<Foo*> view;      // 只是"引用"，不负责释放
```

| 容器元素类型 | 析构时是否释放所指对象 |
|---|---|
| `Foo` | 会（调用 `~Foo`） |
| `Foo*` | **不会** |
| `unique_ptr<Foo>` | 会 |
| `shared_ptr<Foo>` | 引用计数减一，为 0 时释放 |

**为什么 STL 不自动 `delete` 指针**：容器无法知道这个指针是 `new` 出来的、`new[]` 出来的、还是指向栈/静态对象的。所有权语义必须由使用者明确表达——这就是 `unique_ptr` / `shared_ptr` 存在的意义。

## 高频追问

1. **`vector<unique_ptr<T>>` 为什么不能 `push_back` 左值？** —— `unique_ptr` 不可拷贝，必须 `std::move` 或直接 `push_back(std::make_unique<T>())`。
2. **`shared_ptr` 能解决循环引用吗？** —— 不能，环上互相持有会永远不释放，要用 `weak_ptr` 打断。
3. **`vector<Foo>` 存对象本身行不行？** —— 行，只要 `Foo` 可拷贝或可移动；但会有拷贝开销，大对象优先存指针。

## 易错点

- 以为容器会负责 `delete` 裸指针
- 混用 `new[]` 和 `delete`（应该 `delete[]`）
- 用裸指针表达所有权，析构时靠人肉 `for` 循环 delete
