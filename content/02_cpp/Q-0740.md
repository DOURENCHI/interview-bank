## 题目

**题目**：

```cpp
struct Guard { ~Guard() { cout << "cleanup "; } };
void f() {
    Guard g;
    throw std::runtime_error("boom");
}
```

**问**：抛出异常后 `g` 会被析构吗？这个过程叫什么？有什么例外？

## 口述答案

> 会。异常抛出后，栈上**已经构造完成的对象会按构造的逆序逐个析构**，这个过程叫**栈解旋**（stack unwinding）。它是 RAII 能在异常下正确释放资源的基础。
> 例外是：**析构函数本身抛异常**会导致 `terminate`（栈展开过程中不能有第二个异常在传播）。

## 讲深一层

```cpp
void f() {
    Guard g1;
    Guard g2;
    throw std::runtime_error("boom");   // 依次 ~g2、~g1
}
// 输出：cleanup cleanup
```

| 情况 | 是否析构 |
|---|---|
| 已构造完成的局部对象 | ✅ 逆序析构 |
| 正在构造中的对象 | ❌ 只析构已完成的部分 |
| `new` 出来的裸指针对象 | ❌ 不析构（这才是泄漏的根源） |
| 析构函数抛异常 | ❌ `std::terminate` |

**为什么裸指针会泄漏**：栈解旋只对**栈对象**生效，`Foo* p = new Foo()` 里的 `p` 本身是栈对象，析构它不会 `delete` 指向的对象——这就是 RAII 存在的理由。

**析构函数的最佳实践**：标 `noexcept`（默认就是），内部捕获所有异常，失败要在显式 `close()` 里处理。

## 高频追问

1. **栈解旋的代价是什么？** —— 需要生成额外的清理代码（unwind table），二进制略大，正常路径几乎无开销。
2. **`noexcept` 函数里抛异常会怎样？** —— 直接 `terminate`，不展开栈。
3. **构造函数抛异常，对象算构造成功吗？** —— 不算，它的析构函数不会被调用，但已完成的成员会被析构。

## 易错点

- 认为 `new` 出来的对象会被自动清理
- 析构函数里抛异常
- 构造函数抛异常时试图 `delete this`
