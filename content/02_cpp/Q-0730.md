## 题目

**背景**：C/C++ 基础题，考察类型别名和宏的区别。

**问**：`typedef` 和 `#define` 有什么区别？分别在什么情况下使用？

## 口述答案

> typedef 是编译器处理的类型别名，有类型检查、遵守作用域；#define 是预处理器做的文本替换，发生在编译之前，没有类型概念，也不遵守作用域。定义指针类型时差别最明显：`typedef int* P` 之后 `P a, b` 两个都是指针；`#define P int*` 之后 `P a, b` 会展开成 `int* a, b`，b 只是 int。能不用宏定义类型就别用，C++ 里更推荐 using。

## 讲深一层

```c
typedef int* P1;   P1 a, b;   // a、b 都是 int*
#define P2 int*
P2 c, d;                       // 展开为 int* c, d;  → d 是 int
```

| 维度 | typedef | #define |
|---|---|---|
| 处理阶段 | 编译期 | 预处理期 |
| 类型检查 | 有 | 无 |
| 作用域 | 遵守 | 不遵守 |
| 调试信息 | 可见 | 被替换掉 |

## 高频追问

1. **`#define` 还有必要用吗？** —— 条件编译、头文件保护仍有价值；常量用 constexpr，类型别名用 using。
2. **typedef 能定义函数指针吗？** —— 能，`typedef void (*Cb)(int);` 比宏可读得多。
3. **C++ 的 using 好在哪？** —— 支持模板别名 `using Vec = std::vector<T>;`，typedef 做不到。

## 易错点

- 用 #define 定义指针类型，多变量声明出错
- 宏名与变量名冲突，替换后编译报错难查
- 认为 typedef 会创建新类型（它只是别名）
