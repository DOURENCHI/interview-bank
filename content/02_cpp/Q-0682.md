## 题目

**题目**：

```cpp
std::vector<double> v{1.5, 2.5};
double s = std::accumulate(v.begin(), v.end(), 0);    // 结果是 3，不是 4
```

**问**：为什么结果是 3？初始值为什么不能省？填 `0` 会踩什么坑？

## 口述答案

> 因为 `accumulate` 的**累加器类型就是初始值的类型**。这里初始值是 `0`（`int`），所以每次加法都按 `int` 进行，`1.5` 被截断成 `1`，`2.5` 截断成 `2`，最后 `1+2=3`。
> 正确写法是 `0.0`，或者显式指定类型 `std::accumulate<double>(...)`（C++20）。

## 讲深一层

```cpp
// ❌ 整数累加，小数被截断
double s1 = std::accumulate(v.begin(), v.end(), 0);

// ✅ 初始值类型正确
double s2 = std::accumulate(v.begin(), v.end(), 0.0);

// ✅ C++20 可以显式指定
double s3 = std::accumulate<double>(v.begin(), v.end(), 0);
```

| 初始值 | 累加器类型 | 结果 |
|---|---|---|
| `0` | `int` | 截断 |
| `0.0` | `double` | 正确 |
| `0LL` | `long long` | 防溢出 |
| `std::string{}` | `string` | 字符串拼接 |

**为什么初始值"不能省"**：它同时承担两个作用——**起点值**和**类型声明**。这也是为什么它对空区间返回的就是初始值本身。

**另一个常见用法**：拼接字符串 `std::accumulate(v.begin(), v.end(), std::string{})`，但注意每次 `+=` 可能重新分配，性能差；要拼大量字符串应先 `reserve` 或用 `std::ostringstream`。

## 高频追问

1. **能自定义操作吗？** —— 能，第四个参数传二元函数：`accumulate(..., 1, std::multiplies<>())` 求积。
2. **求和会溢出吗？** —— 会，元素接近 `INT_MAX` 时要用 `long long` 初始值。
3. **`reduce` 和 `accumulate` 区别？** —— `reduce`（C++17）允许乱序执行，要求操作满足结合律，可并行。

## 易错点

- 初始值填 `0` 累加浮点
- 忘记初始值类型决定返回值类型
- 用 `accumulate` 拼字符串却不预估容量
