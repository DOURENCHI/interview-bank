## 题目

**场景**：`for (auto it = v.begin(); it != v.end(); ++it)` 这行代码人人会写，但被问"为什么是左闭右开"时答不上来。

**问**：`[begin, end)` 这个区间表示法解决了什么问题？如果改成闭区间会有什么麻烦？

## 口述答案

> 它让**空区间有统一表示**：`begin == end` 就是空，不需要额外的哨兵值或特判。
> 同时长度计算变得统一：`end - begin` 直接就是元素个数（随机访问迭代器），不用 `+1`。改成闭区间的话，空容器就没法表示——`begin` 和 `end` 会指向一个不存在的元素。

## 讲深一层

```cpp
std::vector<int> v;
v.begin() == v.end();          // 空容器：成立
std::distance(v.begin(), v.end());   // 长度，通用写法

// 循环的三种等价写法
for (auto it = v.begin(); it != v.end(); ++it) ...
for (size_t i = 0; i < v.size(); ++i) ...
for (int x : v) ...
```

| 表示法 | 空容器 | 长度 | 循环终止条件 |
|---|---|---|---|
| `[begin, end)` | `begin == end` | `end - begin` | `it != end` |
| `[begin, end]` | 无法表示 | `end - begin + 1` | `it != end` 之后还要再处理一次 |
| `(begin, end)` | `begin == end` 语义冲突 | 麻烦 | 容易漏首元素 |

**一个实际后果**：`end()` 指向的位置**不能解引用**。`*v.end()` 是未定义行为，这也是新手最常见的崩溃原因之一——循环条件写成 `it <= v.end()` 就会踩到。

## 高频追问

1. **`end()` 指向哪？** —— 最后一个元素的**下一个位置**，可能是合法地址（`vector`）也可能是哨兵（`list`），但都不可解引用。
2. **为什么 `std::distance` 不直接用 `-`？** —— 只有随机访问迭代器支持减法，`distance` 对其他类别会退化成逐个走。
3. **反向迭代器怎么对应？** —— `rbegin()` 对应 `end()-1`，`rend()` 对应 `begin()-1`；`rit.base()` 返回的是它右边那个位置。

## 易错点

- 解引用 `end()`，崩溃或读到垃圾值
- 循环条件写 `it <= v.end()`
- 以为 `end()` 指向最后一个元素
