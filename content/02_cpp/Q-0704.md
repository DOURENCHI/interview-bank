## 题目

**场景**：两个不同的库都提供了一个 `Logger` 类，你的代码同时 `#include` 了它们的头文件，编译报 `Logger is ambiguous`。

**问**：命名空间解决什么问题？为什么头文件里不该写 `using namespace std;`？

## 口述答案

> 命名空间给名字加了一层**作用域前缀**，让 `libA::Logger` 和 `libB::Logger` 可以共存。没有它，两个库的同名符号在链接期或编译期直接冲突。
> 头文件里禁止 `using namespace` 的原因是：`#include` 是**文本插入**，头文件里的 `using` 会污染所有包含它的文件。别人写了个 `count` 函数，包含你的头之后可能被解析成 `std::count`，报错位置完全对不上原因。

## 讲深一层

```cpp
// lib_a.h
namespace libA { class Logger { ... }; }

// lib_b.h
namespace libB { class Logger { ... }; }

// 使用处
libA::Logger a;              // ✅ 明确
using libA::Logger;          // ✅ 局部引入一个名字
```

| 写法 | 作用域 | 结论 |
|---|---|---|
| `std::cout` | 单处 | ✅ 最安全 |
| `using std::cout;` | 当前作用域 | ✅ 推荐 |
| `using namespace std;` 在 `.cpp` | 该文件 | ⚠️ 可接受 |
| `using namespace std;` 在头文件 | 传染所有包含者 | ❌ 禁止 |
| 匿名命名空间 `namespace { }` | 当前编译单元 | ✅ 替代 `static` |

**匿名命名空间**值得单独记：里面定义的符号只在当前 `.cpp` 可见，等价于 C 的 `static`，现代 C++ 更推荐这种写法。

**C++17 的嵌套命名空间**：`namespace a::b::c {}` 可以一行写完，不用层层嵌套。

## 高频追问

1. **命名空间能嵌套吗？** —— 能，`A::B::C`；C++17 起可以 `namespace A::B::C {}`。
2. **命名空间别名有什么用？** —— `namespace fs = std::filesystem;` 缩短长名字。
3. **匿名命名空间和 `static` 的区别？** —— 效果类似，但匿名命名空间能给类型用（`static` 只能给函数和变量）。

## 易错点

- 在头文件里 `using namespace std;`
- 用 `using namespace` 解决所有名字冲突（应该用限定名）
- 以为命名空间有运行时开销（完全没有）
