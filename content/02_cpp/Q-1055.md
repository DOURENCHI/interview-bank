## 题目

**场景**：全局配置/日志器只允许一个实例。面试官问：**C++ 单例怎么写才是线程安全的？双检锁为什么要判两次？**

## 口述答案

> C++11 之后最简写法就是**函数内静态局部变量**：`static Logger& inst(){ static Logger s; return s; }`。标准保证局部静态变量**首次初始化是线程安全的**（magic statics），不需要自己加锁。
> 双检锁（DCLP）是另一种写法：先判 `if (!p)` 避免每次都加锁，加锁后再判一次 `if (!p)`，防止两个线程同时通过第一次判断后各创建一次。
> 关键在指针必须是 `std::atomic` 并用 acquire/release 语义：否则「分配内存 → 构造 → 赋值给指针」可能被重排，另一个线程会拿到**还没构造完的对象**。

## 讲深一层

```cpp
// 推荐：C++11 起线程安全，且析构在程序退出时自动执行
Logger& Logger::inst() { static Logger s; return s; }

// 双检锁：指针必须 atomic
static std::atomic<Logger*> p{nullptr};
Logger* q = p.load(std::memory_order_acquire);
if (!q) {
  std::lock_guard<std::mutex> lk(m);
  q = p.load(std::memory_order_relaxed);
  if (!q) { q = new Logger(); p.store(q, std::memory_order_release); }
}
```

- 静态局部变量的问题：**析构顺序**在程序退出时不确定，如果别的静态对象在析构时还调用它，可能用到已销毁的单例。
- 防拷贝：拷贝构造和赋值 `= delete`，否则 `Logger b = Logger::inst();` 会产生第二个实例。
- 需要延迟销毁/多次初始化（测试场景）时，可用 `shared_ptr` + `call_once`，但通常不值得。

## 高频追问

1. **magic statics 在 GCC 里怎么实现的？** —— 编译器生成一个 guard 变量 + `__cxa_guard_acquire/release`，本质是加锁 + 双重检查。
2. **多线程第一次调用会阻塞吗？** —— 会，初始化期间其他线程等待；初始化很慢时会成为启动瓶颈。
3. **单例为什么常被批评？** —— 隐式全局状态、难测试、析构顺序问题；能用依赖注入就别用单例。

## 易错点

- 写双检锁但指针不是 `atomic`，只加 `volatile`——C++11 起 `volatile` 不解决重排
- 忘记禁用拷贝构造/赋值，单例被复制出第二个实例
- 说「加锁了就线程安全」，忽略锁外那次读取的可见性

## 关联项目

- 二维云台：全局配置（舵机脉宽范围、限位角度）适合用单例或静态配置表，但要保证初始化在任务启动前完成
- Linux 日志分析工具：日志器/配置可用单例；析构顺序问题在多线程退出时要注意
