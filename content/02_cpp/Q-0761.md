## 题目

**题目**：工作线程算出了结果，想更新界面上的 label，直接 `ui->label->setText(...)` 偶尔崩溃。

**问**：子线程怎么把数据送回界面？为什么不能直接改控件？

## 口述答案

> 因为**Qt 的 GUI 类不是线程安全的**，所有控件操作必须在**主线程（GUI 线程）**执行。子线程直接改控件可能导致重绘竞态、崩溃，Qt 会打印
> `QObject::setParent: Cannot set parent, new parent is in a different thread` 之类的警告。
> 正确做法是**发信号**：信号通过队列连接投递到主线程的事件队列，槽函数在主线程执行。

## 讲深一层

```cpp
class Worker : public QObject {
    Q_OBJECT
signals:
    void resultReady(const QString& text);     // 只传数据，不传控件
public slots:
    void doWork() {
        QString r = compute();
        emit resultReady(r);                  // 跨线程 → 队列连接
    }
};

// 主线程
connect(worker, &Worker::resultReady, this, [this](const QString& s) {
    ui->label->setText(s);                    // 在主线程执行 ✅
});
```

| 方式 | 线程安全 | 说明 |
|---|---|---|
| 直接改控件 | ❌ | 未定义行为 |
| 信号槽（队列连接） | ✅ | **推荐** |
| `QMetaObject::invokeMethod` | ✅ | 指定 `Qt::QueuedConnection` |
| `postEvent` 自定义事件 | ✅ | 较繁琐 |

**关键细节**：信号参数必须是**可拷贝、已注册元类型**的。传 `QString`、`QImage` 没问题；传自定义结构体要 `qRegisterMetaType`。

**为什么"偶尔"崩溃**：多数时候队列恰好排上了，看起来正常；负载高或重绘频繁时才暴露。所以"跑了很多次没事"不能作为证据。

## 高频追问

1. **能传指针吗？** —— 能传 `QImage*` 但要管生命周期，更安全的是传值（Qt 隐式共享，拷贝很便宜）。
2. **`invokeMethod` 怎么用？** —— `QMetaObject::invokeMethod(obj, "slot", Qt::QueuedConnection, Q_ARG(QString, s))`。
3. **`QImage` 跨线程安全吗？** —— `QImage` 可以（隐式共享 + 写时复制），`QPixmap` 只能在 GUI 线程用。

## 易错点

- 子线程直接 `setText` / `repaint`
- 传 `QPixmap` 到子线程处理
- 信号参数是自定义类型却没注册元类型
