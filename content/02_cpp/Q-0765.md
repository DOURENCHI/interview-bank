## 题目

**题目**：`moveToThread` 之后，槽函数一定在新线程执行吗？有人说"看连接类型"。

**问**：槽函数在哪个线程执行？由什么决定？

## 口述答案

> 由**接收者对象所属的线程**和**连接类型**共同决定：
> - **直接连接**：在**发送者**线程执行（就是普通函数调用）；
> - **队列连接**：在**接收者所属**线程执行（通过事件循环投递）；
> - **自动连接**：两者同线程则直接，跨线程则排队。
> 所以同一个槽，连接方式不同可能跑在不同线程——`moveToThread` 只是改变了"接收者属于哪个线程"。

## 讲深一层

```cpp
// worker 已被 moveToThread(workerThread)
connect(this, &Main::request, worker, &Worker::doWork);        // Auto → Queued（跨线程）
connect(this, &Main::request, worker, &Worker::doWork,
        Qt::DirectConnection);                                  // 在主线程执行！
```

| 连接类型 | 槽在哪个线程 |
|---|---|
| `DirectConnection` | 发送者线程 |
| `QueuedConnection` | 接收者所属线程 |
| `AutoConnection` | 同线程直接，跨线程排队 |
| `BlockingQueuedConnection` | 接收者线程，发送者阻塞 |

**判断方法**：槽函数里打 `QThread::currentThreadId()`，和 `worker->thread()` 比较。

**一个高频误解**：以为"信号发出去就在子线程跑"。实际上槽的执行线程只由接收者决定，与信号在哪发射无关。

## 高频追问

1. **怎么确认对象属于哪个线程？** —— `obj->thread()`，创建时确定，`moveToThread` 可改。
2. **`BlockingQueuedConnection` 同线程会怎样？** —— 死锁（自己等自己）。
3. **lambda 连接时线程归属怎么算？** —— 第三个参数传 `this`，则按 `this` 的线程算；不传则按发送者。

## 易错点

- 以为槽永远在子线程执行
- 跨线程用 `DirectConnection`，槽在错误线程操作 UI
- lambda 槽没传上下文对象，线程归属判断错
