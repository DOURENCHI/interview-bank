## 题目

**场景**：同时存在 `template<typename T> void f(T);` 和 `void f(int);`，调用 `f(1)` 走哪个？

**问**：模板函数和同名普通函数都在时，重载决议谁优先？为什么这样设计？

## 口述答案

> **精确匹配时普通函数优先**。`f(1)` 里 `f(int)` 是精确匹配，模板也能实例化成 `f<int>(int)` 也是精确匹配，两者同级时标准规定**非模板优先**。
> 这样设计的理由是：普通函数是作者**显式写下的特例**，应该能覆盖泛化的模板实现。

## 讲深一层

```cpp
template <typename T> void f(T x)   { cout << "template"; }
void f(int x)                       { cout << "int"; }

f(1);      // "int"        （普通函数优先）
f(1.0);    // "template"   （没有 f(double)，只能实例化）
f<int>(1); // "template"   （显式指定模板参数，强制用模板）
```

| 场景 | 结果 |
|---|---|
| 普通函数精确匹配 | 普通函数 |
| 模板实例化更匹配 | 模板 |
| 两者同级匹配 | **普通函数** |
| 显式 `f<int>(...)` | 模板 |

**这条规则的实用价值**：可以给模板写"特例重载"，比如 `std::swap` 对数组有专门的重载，比泛化版本更高效。

**相关坑**：如果在调用点之前没看到普通函数的声明，编译器只会看到模板，行为就变了——**声明顺序会影响重载决议**。

## 高频追问

1. **模板特化和函数重载谁优先？** —— 显式特化优先于普通函数；但**函数模板特化**的规则很绕，一般用重载代替特化。
2. **为什么有人建议"不要特化函数模板"？** —— 特化的重载决议规则反直觉，用普通重载更清晰。
3. **`std::swap` 怎么优化数组？** —— 提供 `swap(T (&a)[N], T (&b)[N])` 重载，走 memmove。

## 易错点

- 以为模板总是优先
- 普通函数声明写在调用点之后，行为不同
- 用函数模板特化代替重载
