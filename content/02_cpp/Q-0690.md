## 题目

**题目**：每个函数里都写 `auto t0 = now(); ... auto dt = now() - t0;`，十几个函数重复，而且中途 `return` 就漏了。

**问**：怎么用 RAII 封装一个计时器？为什么这样比手动打点好？

## 口述答案

> 构造时记录起点，析构时算差值并输出——这样**任何退出路径（`return`、`throw`、提前 `break`）都会触发计时**，不会漏。
> 这就是 RAII 在"测量"上的应用：把"收尾动作"绑到对象生命周期上。

## 讲深一层

```cpp
class ScopedTimer {
    using clock = std::chrono::steady_clock;
    const char* name_;
    clock::time_point start_;
public:
    explicit ScopedTimer(const char* name) : name_(name), start_(clock::now()) {}
    ~ScopedTimer() {
        auto ms = std::chrono::duration_cast<std::chrono::microseconds>(
                      clock::now() - start_).count() / 1000.0;
        std::cout << name_ << ": " << ms << " ms\n";
    }
    ScopedTimer(const ScopedTimer&) = delete;             // 禁止拷贝
    ScopedTimer& operator=(const ScopedTimer&) = delete;
};

void work() {
    ScopedTimer t("work");     // 作用域结束自动输出
    if (bad) return;           // 也会输出
    doSomething();             // 抛异常也会输出
}
```

| 关键点 | 原因 |
|---|---|
| 禁止拷贝 | 否则会输出两次 |
| 用 `steady_clock` | 墙钟可能回跳 |
| 析构里不抛异常 | 抛了会 `terminate` |
| 单位用浮点 | 避免截断成 0 |

**进阶用法**：把结果累加到线程局部统计里，最后统一输出；或用宏 `#define TIME_SCOPE(name) ScopedTimer _t(name)` 省去起名。

## 高频追问

1. **怎么只在调试时启用？** —— 用宏包起来，Release 下展开成空。
2. **能测嵌套吗？** —— 能，每层一个对象，输出顺序是逆序（内层先结束）。
3. **多线程会串行输出吗？** —— `cout` 的每次 `<<` 不是原子的，多线程要加锁或用独立缓冲。

## 易错点

- 计时器可拷贝，输出两次
- 用 `system_clock`
- 析构函数里 `throw`
