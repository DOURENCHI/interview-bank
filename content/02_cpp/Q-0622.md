## 题目

**背景**：要把 ONNX Runtime 接进现有工程，有人建议先写完整推理代码再一起调。

**问**：为什么应该先跑通「能链接、能加载库」，再写推理逻辑？这个顺序省了什么？

## 口述答案

> 因为它把**两类完全不同的故障隔离开了**：环境问题（找不到库、版本不匹配、符号缺失）和逻辑问题（预处理错、后处理错）。
> 先跑通链接，只需要十几行代码：`#include` 头文件、创建一个 `Ort::Env`、打印版本号。这一步过了，说明编译器、头文件、库、运行时都能对上。后面再出问题，就只可能是逻辑问题。

## 讲深一层

```cpp
// 最小验证：只证明"能链接、能加载"
#include <onnxruntime_cxx_api.h>
#include <iostream>

int main() {
    Ort::Env env(ORT_LOGGING_LEVEL_WARNING, "probe");
    std::cout << "ORT version: " << Ort::GetVersionString() << "\n";
    Ort::SessionOptions opts;
    opts.SetIntraOpNumThreads(1);
    std::cout << "ok\n";
    return 0;
}
```

```bash
g++ probe.cpp -o probe \
  -I/opt/ort/include \
  -L/opt/ort/lib -lonnxruntime
ldd ./probe | grep onnx        # 确认运行时能找到 .so
./probe                        # 打印版本号就通过
```

| 阶段 | 验证什么 | 失败说明 |
|---|---|---|
| 编译 | 头文件路径、语法 | include 路径或版本不对 |
| 链接 | 库路径、库名 | `-L` / `-l` 错，或 ABI 不匹配 |
| 运行加载 | 动态库可被找到 | `LD_LIBRARY_PATH` 或 rpath 没设 |
| 创建 Session | 模型文件、算子支持 | 模型路径或版本问题 |
| 推理 | 预处理 / 后处理 | 逻辑问题 |

**为什么值得多花这 10 分钟**：不做这一步，一旦推理结果不对，你要同时怀疑五层。做了之后，只剩最后一层。

## 高频追问

1. **`ldd` 显示 `not found` 怎么办？** —— 设 `LD_LIBRARY_PATH`，或在 CMake 里设 `BUILD_RPATH` / `INSTALL_RPATH`。
2. **为什么要打印版本号？** —— 现场经常出现"装了两个版本，加载的是旧的那个"，打印是最快的确认方式。
3. **静态链接能避免这个问题吗？** —— 能避免运行时找不到 `.so`，但会带来许可证和体积问题。
