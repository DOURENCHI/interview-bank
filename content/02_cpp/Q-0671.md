## 题目

**场景**：`T&&` 有时是右值引用，有时是"万能引用"，同一个写法两种含义。

**问**：左值、右值、将亡值怎么区分？`T&&` 在什么情况下才是右值引用？

## 口述答案

> 按"能不能取地址、是不是临时"分：**左值**有名字、可取地址（变量、`*p`）；**纯右值**是临时量（字面量、函数返回的临时对象）；**将亡值**是"即将被移动"的对象（`std::move(x)` 的结果）。
> `T&&` 只有在 **`T` 是具体类型**时才是右值引用（如 `int&&`）；如果 `T` 是模板参数且需要推导（`template<typename T> void f(T&&)`），它是**转发引用**，能绑定左值也能绑定右值。

## 讲深一层

| 类别 | 例子 | 可取地址 | 能绑定到 |
|---|---|---|---|
| 左值 | `x`、`*p`、`a[i]` | ✅ | `T&`、`const T&` |
| 纯右值 | `1`、`f()` 返回临时 | ❌ | `const T&`、`T&&` |
| 将亡值 | `std::move(x)` | ✅（原对象） | `const T&`、`T&&` |

```cpp
template <typename T> void f(T&& x);   // 转发引用（需要推导）
void g(int&& x);                       // 右值引用（具体类型）

int a = 1;
f(a);        // T = int&，x 绑定左值
f(1);        // T = int，x 绑定右值
// g(a);     // ❌ 右值引用不能绑左值
```

**判断口诀**：出现**类型推导** + `T&&` 才是转发引用。`const T&&` 不是（有 `const` 就推导不出来）。

**为什么需要区分**：移动语义只在"知道对象即将销毁"时才安全；把左值当右值移动会导致原对象被清空，是常见 bug。

## 高频追问

1. **`std::move` 之后原对象还能用吗？** —— 能，但处于"有效但未指定"状态，通常为空。
2. **`const T&&` 有什么用？** —— 很少用，因为 `const` 对象无法被移动（移动要修改源对象）。
3. **转发引用怎么保持值类别？** —— 用 `std::forward<T>(x)`，不能直接用 `x`（具名变量是左值）。

## 易错点

- 认为 `T&&` 一定是右值引用
- `std::move` 之后继续依赖原对象的值
- 在转发函数里直接传 `x` 而不是 `std::forward<T>(x)`
