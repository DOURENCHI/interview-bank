## 题目

C++ 智能指针有哪几种？分别解决什么问题，安不安全？

## 口述答案

> C++ 四类智能指针：
> - **unique_ptr**：独占所有权，不能拷贝只能 move，零额外开销（和裸指针一样大），默认首选；
> - **shared_ptr**：共享所有权，引用计数归零才释放，有控制块开销（2 个指针大小）和原子计数成本；
> - **weak_ptr**：不增加引用计数，用来打破 shared_ptr 循环引用，用前要 `lock()` 提升；
> - **auto_ptr**：C++98 的废弃产物，拷贝即转移所有权，已被 unique_ptr 取代，别用。
> "安不安全"要分开说：它们解决的是**异常安全与所有权泄漏**（析构自动释放），但不解决**线程安全**（shared_ptr 的引用计数是原子的，但指向的对象不是）、也不防**循环引用**（shared_ptr 互相持有就泄漏，要用 weak_ptr）。

## 讲深一层

```cpp
auto p = std::make_unique<Foo>();          // 推荐，异常安全
std::shared_ptr<Foo> a = std::make_shared<Foo>();  // 一次分配控制块+对象
std::weak_ptr<Foo> w = a;                   // 观察，不增计数
```
`make_shared` 比 `shared_ptr(new Foo)` 少一次分配，但会让对象内存延迟到 weak_ptr 全部消失才释放。

## 高频追问

1. **shared_ptr 线程安全吗？** —— 引用计数增减原子安全；同一对象的读写仍需自己加锁。
2. **怎么检测循环引用？** —— 用 weak_ptr 打断，或工具（ASAN/valgrind）看泄漏点。

## 易错点

- 说 shared_ptr 完全线程安全
- 用 shared_ptr 管理数组却不用自定义 deleter
