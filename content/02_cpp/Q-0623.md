## 题目

**场景**：ONNX Runtime 的 C++ 接口里，要先建 `Env`，再建 `SessionOptions`，再建 `Session`。有人把 `Session` 建在函数里、`Env` 建在函数外，程序偶尔崩。

**问**：ORT 的初始化顺序是怎样的？为什么顺序不能乱？生命周期该怎么管？

## 口述答案

> 顺序是：**`Ort::Env` → `Ort::SessionOptions` → `Ort::Session` → 查输入输出 → `Run`**。
> 不能乱是因为有依赖链：`Session` 构造时要读 `Env` 和 `Options`，`Run` 要用 `Session` 里已绑定的分配器。而**生命周期必须覆盖使用期**——`Env` 必须先于 `Session` 存活，`Session` 可以先于 `Options` 销毁但反过来不行。
> `Env` 全局**只应有一个**，它管理线程池和日志，多个会互相干扰。

## 讲深一层

```cpp
Ort::Env env(ORT_LOGGING_LEVEL_WARNING, "app");     // 进程级，只建一次

Ort::SessionOptions opts;
opts.SetIntraOpNumThreads(4);
opts.SetGraphOptimizationLevel(GraphOptimizationLevel::ORT_ENABLE_ALL);

Ort::Session session(env, model_path, opts);        // 依赖 env 和 opts

// 输入输出名要在 Session 之后查
Ort::AllocatorWithDefaultOptions alloc;
auto in_name  = session.GetInputNameAllocated(0, alloc);
auto out_name = session.GetOutputNameAllocated(0, alloc);
```

| 对象 | 生命周期 | 能否多份 | 说明 |
|---|---|---|---|
| `Ort::Env` | 进程级 | **不建议** | 管线程池、日志 |
| `SessionOptions` | 可短于 Session | 可以 | 只在构造 Session 时用 |
| `Session` | 长期 | 可以（多模型） | 线程安全，可多线程 Run |
| `Value`（张量） | 单次推理 | 每次新建 | 或用 `IoBinding` 复用 |

**线程安全**：`Session::Run` 是线程安全的，可以多个线程同时调；但 `SessionOptions` 的修改不是。

## 高频追问

1. **`Session` 能跨线程共享吗？** —— 能，`Run` 是 const 且线程安全的；但每个线程要自己的输入输出 `Value`。
2. **`Env` 建两个会怎样？** —— 线程池翻倍、日志重复，某些版本会报错；统一用一个。
3. **模型换了怎么办？** —— 重新建 `Session`，不要试图改已有的。

## 易错点

- 把 `Env` 建在会先销毁的作用域里
- 每个请求都新建 `Session`（加载耗时几百毫秒到几秒）
- 多线程共享同一个输入 `Value`
