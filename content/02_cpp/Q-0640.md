## 题目

**题目**：

```cpp
struct A { char c; int i; char d; };
sizeof(A)   // 12，不是 6
```

**问**：`sizeof` 为什么比成员之和大？对齐规则是什么？怎么减小浪费？

## 口述答案

> 因为**内存对齐**：每个成员的起始地址必须是它自身大小的整数倍，结构体总大小要是最大对齐数的整数倍。`char c` 后要空 3 字节才能放 `int i`，末尾还要补 3 字节让总大小是 4 的倍数。
> 减小浪费的办法是**按大小从大到小排列成员**：`int, char, char` 只需 8 字节。

## 讲深一层

```
struct A { char c; int i; char d; };        // 12 字节
偏移:     0        4-7        8     9-11(填充)

struct B { int i; char c; char d; };        // 8 字节
偏移:     0-3      4           5     6-7(填充)
```

| 规则 | 内容 |
|---|---|
| 成员对齐 | 起始偏移是该成员大小的整数倍 |
| 结构体对齐 | 总大小是最大成员对齐数的整数倍 |
| 数组元素 | 每个元素都要对齐，所以会有内部填充 |

```cpp
#pragma pack(push, 1)     // 取消对齐，按 1 字节
struct Packed { char c; int i; };   // sizeof = 5
#pragma pack(pop)
```

**为什么需要对齐**：CPU 访问未对齐地址可能慢（跨缓存行）甚至硬件异常（某些 ARM 架构）。`#pragma pack` 常用于网络协议、文件格式，但要清楚会牺牲性能。

**`offsetof` 可以验证**：`offsetof(A, i)` 返回 4。

## 高频追问

1. **空结构体的 `sizeof` 是多少？** —— 1（保证每个对象有唯一地址）。
2. **有虚函数的结构体呢？** —— 多一个 vptr（8 字节），且对齐按指针。
3. **`alignas` 能干什么？** —— 手动指定对齐要求，用于 SIMD 或缓存行对齐。

## 易错点

- 以为 `sizeof` 等于成员大小之和
- `#pragma pack` 后忘了恢复
- 用 `memcmp` 比较含填充的结构体（填充字节值不确定）
