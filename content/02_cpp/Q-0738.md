## 题目

**面试官问**：`friend` 是不是破坏了封装？既然破坏了，为什么还要有？

**问**：友元会破坏封装吗？什么时候该用友元？

## 口述答案

> 它**削弱**了封装，但没有"破坏"到不可控——因为授权是**显式写在类里**的，看类的定义就知道谁能访问私有成员。相比之下，全 public 才是真正无法追踪的。
> 该用的场景：**运算符重载**（`<<`、`==`）、**需要访问两个类的内部**（如 `Matrix` 和 `Vector` 的乘法）、**测试类**、**工厂函数**。

## 讲深一层

```cpp
class Matrix {
    std::vector<double> data_;
    int rows_, cols_;
public:
    friend Matrix operator*(const Matrix&, const Matrix&);   // 需要同时访问两个对象内部
    friend std::ostream& operator<<(std::ostream&, const Matrix&);
    friend class MatrixTest;                                  // 测试类
};
```

| 用法 | 合理 | 说明 |
|---|---|---|
| `friend operator<<` | ✅ | 无法用成员函数表达 |
| `friend operator*`（双操作数） | ✅ | 需要访问双方私有 |
| `friend class XxxTest` | ✅ | 测试专用 |
| 大量 `friend` 互相访问 | ⚠️ | 说明类边界没划清 |
| 用 `friend` 图省事 | ❌ | 应该设计接口 |

**友元的三个特点**：
1. **单向**：A 声明 B 是友元，B 能访问 A，反之不行；
2. **不传递**：B 是 A 的友元，C 继承 B，C 不是 A 的友元；
3. **不被继承**：派生类不会自动成为基类友元的友元。

## 高频追问

1. **友元函数能访问派生类私有成员吗？** —— 不能，除非派生类也声明它是友元。
2. **友元声明放哪？** —— 类的任意位置（public/private 都一样，因为友元不是成员）。
3. **有替代方案吗？** —— 提供公有 getter、或用 pimpl 暴露内部实现类。

## 易错点

- 认为友元会传递或继承
- 用友元代替设计良好的接口
- 把友元声明当成成员函数声明
