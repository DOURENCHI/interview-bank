## 题目

**场景**：`sizeof(带虚函数的类)` 比预期大 8 字节。面试官追问"这 8 字节是什么、虚函数调用怎么找到实际函数"。

**问**：vtable 和 vptr 分别是什么？一个对象里存的是哪一个？

## 口述答案

> **vptr** 是对象里的一个隐藏指针（通常 8 字节），指向该类的**虚函数表**；**vtable** 是每个类一份的静态数组，存着虚函数的地址。
> 对象里只存 vptr，不存 vtable。所以 `sizeof` 多出 8 字节；同一个类的所有对象共享同一张 vtable，但各有各的 vptr。

## 讲深一层

```
对象 Obj:  [ vptr ] → vtable of Derived
                       ├─ [0] &Derived::f
                       ├─ [1] &Derived::g
                       └─ [2] &Base::h        ← 未覆写，指向基类版本
```

```cpp
struct Base { virtual void f(); virtual ~Base(); };
struct Derived : Base { void f() override; };
// sizeof(Derived) = 8（vptr）+ 其他成员
```

| 问题 | 答案 |
|---|---|
| vtable 存在哪？ | 只读数据段（每个类一份） |
| vptr 何时设置？ | 构造函数里（所以构造期间虚调用不生效） |
| 多继承有几个 vptr？ | 每个有虚函数的多重基类各一个 |
| 虚析构怎么实现？ | 析构函数也是 vtable 里的一个槽位 |

**为什么构造/析构期间虚函数"失效"**：构造基类部分时 vptr 指向基类 vtable，此时派生类还没构造，调用派生版本会访问未初始化成员。所以标准规定此时按当前构造层次调用。

**vtable 的开销**：一次间接跳转，无法内联，分支预测可能失败——这是虚函数比普通函数慢的原因。

## 高频追问

1. **`final` 能优化什么？** —— 标记类或函数不可覆写，编译器可以**去虚化**（直接调用或内联）。
2. **`dynamic_cast` 靠什么实现？** —— 依赖 RTTI，vtable 里有类型信息指针。
3. **能手动调虚函数表吗？** —— 能（取对象头部指针强转），但属于未定义行为，只在逆向分析里用。

## 易错点

- 说"对象里存了 vtable"（存的是 vptr）
- 认为每个对象有一份 vtable
- 以为构造函数里调虚函数会走派生版本
