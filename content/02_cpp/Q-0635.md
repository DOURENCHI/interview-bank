## 题目

**题目**：三个词经常被混着说——野指针、悬垂指针、内存泄漏。

**问**：这三个分别是怎么产生的？哪个最危险、为什么？

## 口述答案

> **野指针**是没初始化的指针，指向随机地址；**悬垂指针**指向已被释放的内存；**内存泄漏**是分配了没释放，指针丢了但内存还在。
> 野指针最危险，因为它可能指向任意位置，读写都可能直接崩或悄悄改坏别的数据——**行为完全不可预测**。悬垂指针至少范围可控（曾经合法过），漏掉的是"用已释放内存"这一类。

## 讲深一层

```cpp
int* p;             // 野指针：未初始化
*p = 1;             // ❌ 未定义行为

int* q = new int(1);
delete q;
*q = 2;             // ❌ 悬垂指针

void f() { int* r = new int(1); }   // 泄漏：r 出了作用域，内存还在
```

| 类型 | 成因 | 表现 | 防法 |
|---|---|---|---|
| 野指针 | 声明未初始化 | 随机崩溃/静默改数据 | 声明即初始化 `= nullptr` |
| 悬垂指针 | 指向已释放内存 | 崩溃或读到脏数据 | 释放后置 `nullptr`，用智能指针 |
| 内存泄漏 | 分配未释放 | 内存缓慢增长 | RAII / 智能指针 / valgrind |

**`delete` 后置 `nullptr` 的价值**：`delete p; p = nullptr;` 之后 `if (p)` 能正确判断，重复 `delete nullptr` 也安全（标准保证）。

**检测工具**：`valgrind --leak-check=full`、ASan（`-fsanitize=address`）、`_GLIBCXX_DEBUG`。

## 高频追问

1. **`delete` 两次会怎样？** —— 未定义行为，可能崩溃；`delete nullptr` 是安全的空操作。
2. **怎么系统性避免？** —— 用 `unique_ptr` / `shared_ptr`，让所有权明确，几乎消除这三类问题。
3. **泄漏在长跑服务里有多严重？** —— 每小时漏几 MB，几天后 OOM；这类问题只能靠压测发现。

## 易错点

- 认为"程序退出时系统会回收，所以泄漏无所谓"（长跑服务不适用）
- `delete` 后不置空，后续误用
- 用 `free` 释放 `new` 出来的内存
