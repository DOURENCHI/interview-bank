## 题目

**题目**：面试官让你说说用 `chrono` 计时踩过哪些坑。

**问**：用 `chrono` 计时的三个常见错误是什么？各自的现象和修法？

## 口述答案

> 三个最常见的：**用错时钟**（墙钟被 NTP 调整，出现负耗时）、**单位截断**（纳秒转秒变 0）、**只测一次**（缓存预热、CPU 频率变化导致数据不可信）。
> 前两个是正确性问题，第三个是方法论问题——单次测量几乎总是错的。

## 讲深一层

| 错误 | 现象 | 修法 |
|---|---|---|
| 用 `system_clock` / `high_resolution_clock` | 偶发负耗时、极端值 | 换 `steady_clock` |
| `duration_cast<seconds>` | 结果恒为 0 | 用毫秒/微秒或浮点 |
| 只跑一次 | 数据抖动大、不可复现 | 预热 + 多次取中位数/p99 |
| 循环里混入 I/O | 测的是 I/O 不是计算 | 把测量范围缩到核心逻辑 |
| 编译器把被测代码优化掉 | 耗时接近 0 | 用 `benchmark::DoNotOptimize` 或累加结果输出 |

```cpp
// ✅ 一个可信的最小模板
auto bench = [](auto&& f, int n = 100) {
    for (int i = 0; i < 10; ++i) f();          // 预热
    std::vector<double> ts;
    for (int i = 0; i < n; ++i) {
        auto t0 = std::chrono::steady_clock::now();
        f();
        ts.push_back(std::chrono::duration<double, std::milli>(
                         std::chrono::steady_clock::now() - t0).count());
    }
    std::sort(ts.begin(), ts.end());
    return ts[ts.size() / 2];                  // 中位数
};
```

**为什么用中位数不用平均**：偶发的调度抖动会严重拉高平均值，中位数更能代表典型情况；同时报告 p99 反映最差情况。

## 高频追问

1. **为什么要预热？** —— 首次调用有冷缓存、动态链接、CPU 升频等一次性开销。
2. **`DoNotOptimize` 是什么？** —— Google Benchmark 提供的屏障，防止编译器把被测代码优化掉。
3. **测出来波动 20% 正常吗？** —— 在多任务系统上正常，要报告分布而不是单值。

## 易错点

- 用墙钟测耗时
- 只跑一次就下结论
- 被测代码被优化掉，耗时接近 0
