## 题目

**题目**：

```cpp
struct Base { ~Base() {} };
struct D : Base { std::vector<int> v; };
Base* p = new D;
delete p;        // 只调了 ~Base，v 没析构
```

**问**：为什么基类的析构函数必须是虚函数？不写会漏什么？

## 口述答案

> 因为 `delete p`（`p` 是基类指针）时，如果析构函数不是虚的，编译器**静态绑定**到 `~Base`，只析构基类部分，派生类的成员（如 `vector`）不会被析构——内存泄漏。
> 虚析构让 `delete` 通过 vtable 找到真正的派生类析构函数，先析构派生部分再析构基类。

## 讲深一层

```cpp
struct Base { virtual ~Base() = default; };   // ✅
struct D : Base { std::vector<int> v; };

Base* p = new D;
delete p;      // 虚析构 → 先 ~D（释放 v），再 ~Base
```

| 场景 | 非虚析构 | 虚析构 |
|---|---|---|
| `delete 基类指针` | 只析构基类 → 泄漏 | 正确析构全部 |
| `delete 派生类指针` | 正确 | 正确 |
| 无多态、不通过基类删 | 无影响 | 多一个 vptr 开销 |

**代价**：加虚析构会让类多一个 vptr（8 字节），且不能作为聚合类型。所以**不是所有类都要虚析构**——只有"会被当作基类并通过基类指针删除"的类才需要。

**一条实用规则**：只要类里有其他虚函数，就应该有虚析构；如果类不打算被继承，用 `final` 明确表达。

## 高频追问

1. **虚析构函数里能调虚函数吗？** —— 能，但已经退化为当前类的版本（派生部分已析构）。
2. **纯虚析构可以吗？** —— 可以，但必须提供定义（因为派生类析构会调用它）。
3. **`shared_ptr<Base>` 指向 `Derived` 会泄漏吗？** —— 不会，`shared_ptr` 构造时记住了删除器，即使析构非虚也能正确删除。

## 易错点

- 基类析构不写 virtual，通过基类指针 delete
- 给所有类都加虚析构（不必要的开销）
- 以为 `shared_ptr` 也需要虚析构（它自己记了删除器）
