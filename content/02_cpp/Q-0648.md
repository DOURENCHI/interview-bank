## 题目

**场景**：`class D : protected B` 之后，外部代码 `D d; d.publicMethod();` 编不过。

**问**：`public` / `protected` / `private` 三种继承方式区别在哪？为什么默认是 `private`？

## 口述答案

> 继承方式决定了**基类成员的可见性在派生类中如何"收缩"**：public 保持原样，protected 把 public 降为 protected，private 全部降为 private。
> `class` 默认 private 继承，`struct` 默认 public 继承——这是为了兼容 C 的 struct 语义。

## 讲深一层

| 基类成员 | public 继承 | protected 继承 | private 继承 |
|---|---|---|---|
| public | public | protected | private |
| protected | protected | protected | private |
| private | 不可见 | 不可见 | 不可见 |

```cpp
class B { public: void f(); protected: void g(); };
class D1 : public B    {};   // d1.f() ✅
class D2 : protected B {};   // d2.f() ❌（在 D2 内部可调）
class D3 : private B   {};   // d3.f() ❌（在 D3 内部可调）
```

**语义上的区别比可见性更重要**：
- **public 继承** = "is-a"，`D` 可以当 `B` 用（能传给 `B*` 参数）；
- **private 继承** = "用 B 实现 D"，不是 is-a，外部不能把 `D*` 转成 `B*`；
- **protected 继承** = 介于两者，少见。

**实践建议**：绝大多数情况用 public 继承表达 is-a；想复用实现用**组合**（成员对象），比 private 继承更清晰。

## 高频追问

1. **private 继承和组合什么区别？** —— private 继承能访问 protected 成员、能覆写虚函数；组合不能。除此之外组合更简单。
2. **能把 private 继承的对象转成基类指针吗？** —— 类内部可以，外部不行。
3. **`using B::f;` 能恢复可见性吗？** —— 能，在派生类里 `using` 可以把被收缩的成员重新暴露。

## 易错点

- 以为继承方式只影响"能不能访问"，不知道它改变 is-a 关系
- 用 private 继承做代码复用，应该用组合
- 混淆 `class` 和 `struct` 的默认继承方式
