## 题目

**场景**：一个类只写了析构函数去 `delete` 内部指针，没写拷贝构造和拷贝赋值。结果对象被拷贝后，两个对象都去 `delete` 同一块内存。

**问**：拷贝构造、拷贝赋值、析构，什么时候必须一起写？「三法则」到底在说什么？

## 口述答案

> 当类**管理了一个资源**（堆内存、文件句柄、锁）时，三者必须一起写。因为编译器生成的拷贝是**浅拷贝**（只复制指针值），两个对象指向同一资源，析构时就会重复释放。
> 三法则说的是：**如果你需要自定义其中任何一个，通常三个都需要**。现代 C++ 的补充是「五法则」（加移动构造、移动赋值）和「零法则」（用 RAII 成员，一个都不写）。

## 讲深一层

```cpp
class Buffer {
    char* data_; size_t n_;
public:
    explicit Buffer(size_t n) : data_(new char[n]), n_(n) {}
    ~Buffer() { delete[] data_; }                        // 1. 析构

    Buffer(const Buffer& o) : data_(new char[o.n_]), n_(o.n_) {   // 2. 拷贝构造：深拷贝
        std::copy(o.data_, o.data_ + n_, data_);
    }
    Buffer& operator=(const Buffer& o) {                 // 3. 拷贝赋值
        if (this != &o) {                                // 自赋值保护
            Buffer tmp(o);                               // copy-and-swap
            std::swap(data_, tmp.data_);
            std::swap(n_, tmp.n_);
        }
        return *this;
    }
};
```

| 法则 | 内容 | 适用 |
|---|---|---|
| 三法则 | 析构 + 拷贝构造 + 拷贝赋值 | C++98 风格，手动管资源 |
| 五法则 | 再加移动构造 + 移动赋值 | 需要移动优化 |
| 零法则 | 用 `unique_ptr` / `vector` 成员，一个都不写 | **现代首选** |

**copy-and-swap 的好处**：异常安全（`tmp` 构造失败时原对象不变）、自动处理自赋值。

## 高频追问

1. **不写拷贝构造会怎样？** —— 编译器生成浅拷贝，双重释放。
2. **为什么拷贝赋值要返回 `*this` 的引用？** —— 支持链式赋值 `a = b = c`。
3. **移动构造什么时候被调用？** —— 传右值时；如果没定义移动构造，会退化成拷贝。

## 易错点

- 只写析构不写拷贝，双重释放
- 拷贝赋值不检查自赋值
- 用 `delete` 而不是 `delete[]` 释放数组
