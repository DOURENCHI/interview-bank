## 题目

**题目**：构造函数里 `new` 了资源，后面抛异常了，会不会泄漏？

**问**：构造函数或析构函数抛异常会发生什么？

## 口述答案

> **构造函数抛异常**：对象**没有构造完成**，它的析构函数**不会被调用**；但已经构造完成的成员和基类会被正常析构。所以构造函数里裸 `new` 的资源会泄漏——要用 RAII 成员或智能指针接住。
> **析构函数抛异常**：如果是栈展开过程中再抛，C++11 起析构默认 `noexcept`，直接 `std::terminate`。所以析构函数**绝不能抛异常**。

## 讲深一层

| 场景 | 结果 |
|---|---|
| 构造函数抛 | 对象析构函数不调用，已构造成员/基类会析构 |
| 构造函数体内裸 `new` 后抛 | **泄漏** |
| 析构函数抛（栈展开中） | `std::terminate` |
| 析构函数抛（无异常传播时） | 也会 terminate（默认 noexcept） |
```cpp
class A {
    std::unique_ptr<int> p_;      // RAII：抛异常也会释放
public:
    A() { p_ = std::make_unique<int>(1); mayThrow(); }
};
```
- 想在析构里做可能失败的操作：提供显式 `close()`，让调用方处理错误。
- 构造函数可以用 **function-try-block** 捕获成员初始化时的异常。

## 高频追问

1. **析构函数能声明 `noexcept(false)` 吗？** —— 能，但极不推荐。
2. **构造失败后能重试吗？** —— 对象已不存在，只能重新构造。

## 易错点

- 构造函数里裸 `new` 后抛异常
- 析构函数里抛异常（默认 terminate）
