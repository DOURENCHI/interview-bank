## 题目

**题目**：代码评审时有人把 `if (a == 0)` 改成 `if (0 == a)`，说这样更安全。

**问**：if 判断写 0 == a 和 a == 0 有什么讲究？

## 口述答案

> 这是 C 时代的老技巧：`if (a = 0)` 少写一个等号时**编译能过**（赋值表达式有值），而 `if (0 = a)` 会直接报错"左值不可赋值"，把 bug 挡在编译期。
> 但在现代工程里这个理由基本不成立了：**`-Wall` 会报 `suggest parentheses around assignment used as truth value`**，静态分析也能查出来；而且反着写**降低可读性**（主语在后，读起来别扭）。

## 讲深一层

- 唯一还有意义的场景：老编译器/无警告选项的嵌入式工具链。
- 对指针写 `if (NULL == p)` 同理，现代写法是 `if (p == nullptr)`。
- 更值得关注的是"用 `=` 还是 `==`"之外的坑：浮点比较要用容差，`if (ptr)` 判空比 `if (ptr != nullptr)` 简洁但要注意重载 `operator bool`。

## 高频追问

1. **C++ 里 `if (a = 0)` 会编译通过吗？** —— 会（int 可转 bool），但 GCC 默认给警告。
2. **更好的做法是什么？** —— 开 `-Wall -Wextra`，用 `nullptr`，浮点用 `std::abs(a-b) < eps`。

## 易错点

- 把老技巧当规范强制推行
- 以为 `if (0 == a)` 能防所有手误（`a != 0` 写错照样不报）
