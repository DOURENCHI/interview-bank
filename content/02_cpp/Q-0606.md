## 题目

**场景**：`vector<vector<int>> grid(3, vector<int>(4));`，有人以为它在内存里就是一块 3×4 的连续区域，于是用 `memcpy` 或 `&grid[0][0]` 加偏移访问。

**问**：`vector<vector<int>>` 的真实内存布局是什么样的？能当二维数组用吗？

## 口述答案

> **不能当连续二维数组用**。外层 `vector` 连续存放的是 3 个 `vector<int>` 对象（每个通常是 3 个指针），每个内层 `vector` 各自持有一块**独立的堆内存**，彼此不相邻。
> 所以 `&grid[0][0] + i*4 + j` 这种算法完全错——它只在内层那块 4 个 int 里滑动，跨行就跑到别的内存了。

## 讲深一层

```
grid (栈/堆上的对象)
 ├─ [0] vector<int> ──→ 堆块 A: [1][2][3][4]
 ├─ [1] vector<int> ──→ 堆块 B: [5][6][7][8]     ← 三块内存互不相邻
 └─ [2] vector<int> ──→ 堆块 C: [9][0][1][2]
```

| 写法 | 内存 | 能否 `memcpy` 整体拷贝 | 行长度可变 |
|---|---|---|---|
| `int a[3][4]` | 连续 | 能 | 否 |
| `vector<vector<int>>` | 分散 | 不能 | 能（锯齿数组） |
| `vector<int> flat(12)` | 连续 | 能 | 否（自己算下标） |

```cpp
// ✅ 连续二维：一维数组 + 手动下标
std::vector<int> flat(rows * cols);
auto at = [&](int i, int j) -> int& { return flat[i * cols + j]; };

// ✅ C++23 起可以用 mdspan 做视图，零拷贝
```

**什么时候该用哪种**：需要和 C 接口 / BLAS / 图像库交互，用连续布局；每行长度不一（如稀疏结构、变长序列），用 `vector<vector>`。

## 高频追问

1. **`&grid[0][0]` 能不能当 `int*` 传给 C 函数？** —— 只能在单行内这么做，跨行不行；正确做法是先把数据压平。
2. **`vector<vector<int>>` 有什么开销？** —— 每行一次独立分配、一次指针跳转，缓存局部性差；小矩阵建议压平。
3. **怎么安全地展平？** —— 遍历每行 `insert` 到一个一维 `vector`，或用 `reserve` 预估总容量。

## 易错点

- 用 `&grid[0][0] + i*cols + j` 跨行访问
- 对 `vector<vector>` 整体 `memcpy`
- 以为 `grid.size()*grid[0].size()` 一定等于总元素数（锯齿数组不一定）
