## 题目

**面试官问**：这个功能你用继承还是组合？很多人答"继承更面向对象"。

**问**：继承和组合该怎么选？为什么《Effective C++》说「优先用组合」？

## 口述答案

> 判断标准是 **is-a 还是 has-a**：`Circle` 是 `Shape`（继承）；`Car` 有 `Engine`（组合）。
> 优先组合的理由：继承是**最强的耦合**——派生类依赖基类的实现细节，基类一改可能破坏所有派生类；而且继承把接口全部暴露（包括 protected 成员），组合只暴露你想暴露的那部分。

## 讲深一层

| 维度 | 继承 | 组合 |
|---|---|---|
| 关系 | is-a | has-a |
| 耦合 | 强（依赖实现） | 弱（只依赖接口） |
| 复用 | 白盒（能看到 protected） | 黑盒 |
| 运行时替换 | 需要虚函数 | 换成员对象即可 |
| 编译依赖 | 头文件必须完整 | 可用前置声明 + pimpl |
| 菱形问题 | 有 | 无 |

```cpp
// ❌ 用继承复用代码
class Stack : public std::vector<int> { };   // 现在 Stack 也有 insert/erase，破坏语义

// ✅ 组合
class Stack {
    std::vector<int> v_;
public:
    void push(int x) { v_.push_back(x); }
    void pop() { v_.pop_back(); }
};
```

**经典反例**：`Stack` 继承 `vector` 后，用户可以直接 `insert` 到中间，栈的语义被破坏。这是"用继承复用实现"的典型错误。

**什么时候必须用继承**：需要**运行时多态**（通过基类指针统一处理）、或者确实表达 is-a。

## 高频追问

1. **private 继承算什么？** —— "用基类实现"，本质是组合的替代品，但耦合更强，一般不推荐。
2. **什么时候用组合 + 虚函数？** —— 想在运行时替换行为（策略模式），组合一个基类指针比继承更灵活。
3. **继承的层数多少合适？** —— 一般不超过 2–3 层，深继承层次难以理解和维护。

## 易错点

- 为了复用代码而继承（应该组合）
- 继承 `std::vector` / `std::string` 这类标准容器
- 认为"继承更面向对象"
