## 题目

**题目**：`auto d = end - start;` 之后 `cout << d.count()` 输出 `0`，明明跑了几百毫秒。

**问**：为什么直接相减得到 0？`duration_cast` 在做什么？不做会怎样？

## 口述答案

> 因为 `steady_clock` 的 `duration` 单位通常是**纳秒**，而如果代码里把结果赋给了默认构造的 `seconds` 类型，整数除法会**截断**——几百毫秒变成 0 秒。
> `duration_cast` 负责**在不同时间单位之间转换**，并且它做的是**截断（向零取整）**，不是四舍五入。

## 讲深一层

```cpp
auto t0 = std::chrono::steady_clock::now();
doWork();
auto t1 = std::chrono::steady_clock::now();

// ❌ 隐式转换到 seconds，截断
std::chrono::seconds s = t1 - t0;      // 编译不过（duration 精度不同不能隐式转）

// ✅ 显式转换
auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(t1 - t0);
std::cout << ms.count() << " ms\n";

// ✅ 直接打印（C++20 有 operator<<）
std::cout << std::chrono::duration<double>(t1 - t0).count() << " s\n";
```

| 转换方式 | 精度损失 | 说明 |
|---|---|---|
| `duration_cast<ms>` | 截断 | 精度降低时截断 |
| `duration<double>` | 无（浮点） | 保留小数 |
| 隐式转换 | 只允许精度提升 | `ms` → `us` 可以，反之不行 |

**为什么不允许隐式降精度**：会静默丢失信息。C++ 规定只有"精度提升"（如秒→毫秒）才能隐式转换，降精度必须显式 `duration_cast`。

**测极短操作用纳秒**：`duration_cast<nanoseconds>`，或者直接用 `duration<double, std::nano>`。

## 高频追问

1. **能四舍五入吗？** —— `duration_cast` 是截断；要四舍五入得手动处理。
2. **浮点 duration 有什么用？** —— 保留小数，适合算平均耗时。
3. **两个 `steady_clock` 相减的类型是什么？** —— `steady_clock::duration`，单位由实现决定。

## 易错点

- 相减后直接 `count()` 就打印，单位搞错
- 用整数除法换算（精度丢失）
- 以为 `duration_cast` 会四舍五入
