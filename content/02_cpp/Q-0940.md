## 题目

**题目**：引用计数的对象在计数归零时调用 `delete this`，这样写有问题吗？

**问**：在成员函数里 delete this 有什么问题？

## 口述答案

> 能用，但风险很大：`delete this` 之后**对象已销毁**，任何对成员变量、虚函数、`this` 的访问都是 UB；如果对象不是 `new` 出来的（栈对象/静态对象），直接崩溃。
> 另外在**析构函数里**写 `delete this` 会无限递归。

## 讲深一层

```cpp
void release() {
    if (--ref_ == 0) delete this;   // 之后不能再碰任何成员
}
```
安全使用的前提：
1. 对象必须是 `new` 分配的；
2. `delete this` 之后**立刻 return**，不做任何访问；
3. 调用方之后不能再使用该指针（要提前置空）；
4. 不能在构造函数/析构函数里调用。
- 现代替代：`std::shared_ptr` + `enable_shared_from_this`，或 `unique_ptr` 明确所有权。

## 高频追问

1. **`delete this` 后能调用虚函数吗？** —— 不能，vptr 已随对象销毁。
2. **为什么析构里不能 `delete this`？** —— 析构中再 delete 会再次进入析构，无限递归/双重释放。

## 易错点

- `delete this` 之后继续访问成员
- 对栈对象 `delete this`
