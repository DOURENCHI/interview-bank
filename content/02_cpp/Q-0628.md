## 题目

**题目**：`if (a & b)` 和 `if (a && b)` 在 `a=1, b=2` 时结果不同。

**问**：位运算和逻辑运算的区别是什么？为什么 `&` 和 `&&` 不能混用？什么场景必须用位运算？

## 口述答案

> `&` 是**按位与**，对每一位做运算，结果是整数；`&&` 是**逻辑与**，把两边转成 `bool`，结果只有 0 或 1，而且**有短路**——左边为假时右边不执行。
> `a=1, b=2` 时：`1 & 2 = 0`（二进制 01 & 10），`1 && 2 = 1`（都非零）。判断条件时用 `&&`，操作位时用 `&`。

## 讲深一层

| 运算符 | 类型 | 结果 | 短路 |
|---|---|---|---|
| `&` `|` `^` `~` | 位运算 | 整数 | 否 |
| `&&` `||` `!` | 逻辑运算 | `bool` | 是 |

```cpp
if (ptr != nullptr && ptr->valid())   // ✅ 必须用 &&：短路保护空指针
if (flags & MASK)                     // ✅ 必须用 &：检查某一位

if (ptr != nullptr & ptr->valid())    // ❌ 右边照样执行，空指针崩溃
```

**短路的实际价值**：`if (i < n && a[i] == x)` 里，`i < n` 为假时不会越界访问——这是 `&` 做不到的。

**必须用位运算的场景**：标志位（`flags & MASK`）、权限位、哈希、压缩存储、硬件寄存器操作。这些场景用 `&&` 会得到错误结果（把整数当布尔）。

## 高频追问

1. **`|` 和 `||` 在标志位合并时用哪个？** —— `flags |= MASK` 用 `|`；`||` 只会得到 1。
2. **`^` 有什么实用技巧？** —— 交换两数（`a^=b; b^=a; a^=b;`）、找只出现一次的数（全部异或）。
3. **`~` 对无符号数是什么？** —— 按位取反；对有符号数结果依赖补码表示。

## 易错点

- 判断条件用 `&`，丢了短路保护
- 合并标志位用 `||`，只剩 1
- 对 `bool` 做位运算，语义混乱
