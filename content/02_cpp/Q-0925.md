## 题目

**题目**：老代码里到处是 `(int*)p` 这种 C 风格转换，重构时被要求换成 C++ 的 cast。

**问**：C++ 的四种 cast 和 C 风格强制转换有什么区别？

## 口述答案

> 四种分工明确：**`static_cast`**（编译期能检查的转换，如数值、上行转换、void* 互转）、**`dynamic_cast`**（运行期检查的向下转换，需 RTTI，失败返回 `nullptr` 或抛 `bad_cast`）、**`const_cast`**（只去/加 const）、**`reinterpret_cast`**（重新解释位模式，最危险）。
> C 风格转换 `(T)x` 会**依次尝试** const_cast / static_cast / reinterpret_cast，取第一个能编过的——所以它能做的事最多、也最容易掩盖错误，而且在代码里搜不到。

## 讲深一层

| cast | 检查时机 | 典型用途 | 失败表现 |
|---|---|---|---|
| `static_cast` | 编译期 | 数值转换、基类→派生类（不检查） | 编译错误 |
| `dynamic_cast` | 运行期 | 多态类型安全的向下转换 | 返回 nullptr / 抛异常 |
| `const_cast` | 编译期 | 去掉 const（调用旧接口） | 编译错误 |
| `reinterpret_cast` | 无 | 指针↔整数、位模式重解释 | 无（UB 自负） |
- `dynamic_cast` 有运行时开销（查 RTTI），高频路径慎用。
- `static_cast` 做向下转换**不做检查**，转错了是 UB——这是最容易出事的地方。
- 用 `const_cast` 修改真正的 const 对象是 UB。

## 高频追问

1. **`dynamic_cast` 为什么慢？** —— 要沿继承链查 RTTI 表，且通常无法内联。
2. **什么时候必须用 `reinterpret_cast`？** —— 硬件寄存器地址、和 C 库的 opaque 指针互转。

## 易错点

- 用 `static_cast` 做向下转换以为安全
- 用 C 风格转换后搜不到转换点
