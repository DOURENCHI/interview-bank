## 题目

**场景**：`std::move(x)` 之后 `x` 还是原值，有人以为 `std::move` 把数据搬走了。

**问**：`std::move` 到底做了什么？为什么它「不移动任何东西」？

## 口述答案

> `std::move` 只做一件事：**把左值强制转换成右值引用**（本质是一个 `static_cast<T&&>`）。它不读内存、不拷贝、不释放，一行代码都没执行。
> 真正"移动"的是随后调用的**移动构造函数**或**移动赋值**——它们才负责把资源从源对象转移到目标对象。所以如果类没有移动构造，`std::move` 只会退化成一次拷贝。

## 讲深一层

```cpp
// 标准库里的 std::move（简化）
template <typename T>
constexpr typename std::remove_reference<T>::type&& move(T&& t) noexcept {
    return static_cast<typename std::remove_reference<T>::type&&>(t);
}
```

```cpp
std::string a = "hello";
std::string b = std::move(a);   // 调用 string 的移动构造
// 此时 a 通常是空串（未指定状态），b 拿到原缓冲区
```

| 表达式 | 做了什么 |
|---|---|
| `std::move(x)` | 类型转换，零开销 |
| `T b = std::move(a)` | 调用移动构造，转移资源 |
| `v.push_back(std::move(s))` | 调用移动构造，避免拷贝 |
| `return std::move(x)` | **阻止 NRVO**，反而更慢 |

**为什么它叫 move 却不动东西**：命名是"标记为可移动"，不是"执行移动"。这是 C++ 里典型的"类型层面的操作"。

**一个必须知道的坑**：`return std::move(local);` 会阻止返回值优化（NRVO），强制一次移动构造——比直接 `return local;` 慢。

## 高频追问

1. **`std::move` 对 `const` 对象有效吗？** —— 无效，`const T&&` 无法调用移动构造，退化成拷贝。
2. **移动后原对象一定为空吗？** —— 标准只说"有效但未指定"，`string` 通常为空，但不要依赖。
3. **为什么移动构造要标 `noexcept`？** —— `vector` 扩容时只有在移动构造 `noexcept` 时才用移动，否则用拷贝保证异常安全。

## 易错点

- 以为 `std::move` 会清空源对象
- `return std::move(x)` 阻止 NRVO
- 移动构造没标 `noexcept`，`vector` 扩容仍走拷贝
