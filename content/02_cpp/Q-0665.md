## 题目

**场景**：

```cpp
try { ... }
catch (std::exception e) { ... }     // 按值捕获
catch (std::runtime_error e) { ... } // 永远进不来
```

**问**：catch 的顺序为什么重要？为什么必须按引用捕获？

## 口述答案

> `catch` 从上往下**第一个匹配的就执行**，不会继续往下找。`runtime_error` 派生自 `exception`，按值捕获 `exception` 会先匹配（且发生**对象切片**，丢失派生信息），后面的分支永远进不来。
> 所以顺序必须是**从最具体到最一般**。按引用捕获（`catch (const std::exception& e)`）避免切片，也能拿到正确的 `what()`。

## 讲深一层

```cpp
try {
    throw std::runtime_error("boom");
} catch (const std::runtime_error& e) {   // ✅ 最具体在前
    std::cout << "runtime: " << e.what();
} catch (const std::exception& e) {        // ✅ 引用，不切片
    std::cout << "std: " << e.what();
} catch (...) {
    std::cout << "unknown";
}
```

| 捕获方式 | 切片 | 拷贝 | 推荐 |
|---|---|---|---|
| `catch (E e)` | ✅ 发生 | 有 | ❌ |
| `catch (E& e)` | ❌ | 无 | 一般 |
| `catch (const E& e)` | ❌ | 无 | ✅ **首选** |
| `catch (...)` | — | — | 兜底，拿不到信息 |

**为什么不能 `catch (E& e)` 捕获临时异常对象？** —— 标准允许绑定到异常对象（它不是临时量），所以没问题；但用 `const&` 更明确表达"不修改"。

**`what()` 为什么能工作**：`exception` 的 `what()` 是虚函数，按引用捕获时虚调用才能走到派生类实现。

## 高频追问

1. **`catch (...)` 能拿到异常信息吗？** —— 不能，只能知道"有异常"，通常用于最后兜底并重新抛出。
2. **异常能跨线程传播吗？** —— 不能，`std::thread` 里未捕获的异常会直接 `terminate`。
3. **析构函数能抛异常吗？** —— 不该抛，栈展开过程中再抛会导致 `terminate`。

## 易错点

- 基类异常写在前面，派生分支永远不执行
- 按值捕获导致切片，`what()` 返回基类信息
- 析构函数里抛异常
