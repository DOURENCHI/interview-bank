## 题目

**背景**：高频写日志时，写线程和落盘线程抢同一块缓冲区，加锁后吞吐掉一半；不加锁又会丢日志或写出半行。

**问**：双缓冲区的日志库是怎么设计的？

## 口述答案

> 核心是**两块缓冲区轮换**：写线程只往"当前缓冲"追加，落盘线程只读"另一块缓冲"。写满（或定时到）时**交换指针**，写线程立刻换到空的那块，落盘线程慢慢把旧块刷到磁盘。
> 这样"写"和"刷"**几乎不需要同时持锁**，只在交换的那一瞬间加一次锁。

## 讲深一层

```cpp
class DoubleBufferLog {
    std::vector<char> buf_[2];
    int write_idx_ = 0;
    std::mutex swap_mtx_;
public:
    void append(const char* s, size_t n) {
        auto& b = buf_[write_idx_];
        if (b.size() + n > kMax) flush_or_drop();   // 满了赶紧换
        b.insert(b.end(), s, s + n);                // 无锁写
    }
    void flush_or_drop() {
        std::lock_guard<std::mutex> lk(swap_mtx_);
        int old = write_idx_;
        write_idx_ ^= 1;                            // 原子地换指针
        buf_[write_idx_].clear();
        // 把 buf_[old] 交给后台线程（swap 到待写队列）
    }
};
```
| 设计要点 | 解决什么 |
|---|---|
| 双缓冲 + 换指针 | 读写不互相阻塞 |
| 只在交换时加锁 | 锁竞争降到极低 |
| 满则丢弃或降级 | 防止日志拖垮业务 |
| 后台线程批量落盘 | 减少 `write` 系统调用 |
- 变体：**队列 + 批量拷贝**（一次把整批移到待写队列），或 **ring buffer + 单消费者**。
- 必须处理"日志写不完"：丢弃策略要计数并告警，不能默默丢。
- 进程崩溃时未刷的日志会丢，关键日志要 `fsync` 或单独走同步通道。

## 高频追问

1. **为什么不直接无锁队列？** —— 无锁队列适合定长消息；变长日志用双缓冲拷贝更简单可靠。
2. **怎么保证不丢最后一段？** —— 退出时强制 flush，或 `atexit` 里做一次交换落盘。

## 易错点

- 双缓冲但仍在写路径加锁（等于没优化）
- 不设上限，日志把内存吃满
