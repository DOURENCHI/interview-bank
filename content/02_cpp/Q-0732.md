## 题目

**追问**：`template<typename T> T add(T a, T b)` 用了 10 种类型，可执行文件会变大吗？

**问**：模板在编译期还是运行期展开？代码膨胀怎么控制？

## 口述答案

> **编译期**。每组模板参数都实例化出一份独立的代码，所以 10 种类型就是 10 份 `add` 函数，二进制会变大。
> 这是模板"零开销"的另一面：没有运行时类型分发，代价是**代码体积**。控制手段有显式实例化、抽公共基类、以及接受"体积换速度"。

## 讲深一层

```cpp
template <typename T> T add(T a, T b) { return a + b; }
add(1, 2);        // 实例化 add<int>
add(1.0, 2.0);    // 实例化 add<double>
add(1.0f, 2.0f);  // 实例化 add<float>
```

| 控制手段 | 做法 | 效果 |
|---|---|---|
| 显式实例化 | `template int add<int>(int,int);` 放一个 `.cpp` | 避免每个编译单元各生成一份 |
| 抽公共实现 | 模板调用非模板函数 | 减少重复代码 |
| 类型擦除 | `std::function`、虚函数 | 一份代码，但失去内联 |
| 接受膨胀 | — | 换性能 |

**显式实例化声明（C++11）**：头文件里写 `extern template class Stack<int>;`，告诉编译器"别在这里实例化"，只在指定 `.cpp` 里实例化一次。

**典型膨胀场景**：`std::vector<MyType>` 在每个 `.cpp` 里都实例化一遍，链接后代码重复（链接器可能合并，但不保证）。

## 高频追问

1. **链接器会去重吗？** —— 模板实例化的符号是弱符号，链接器通常会合并，但优化级别不同时可能不合并。
2. **`extern template` 有什么用？** —— 抑制隐式实例化，加快编译并减小体积。
3. **什么时候会真的膨胀严重？** —— 模板里有大量代码（如 `std::sort` 嵌在多层模板里）。

## 易错点

- 以为模板是运行时多态，只有一份代码
- 不知道 `extern template` 能抑制实例化
- 在头文件里放大量模板实现，编译时间爆炸
