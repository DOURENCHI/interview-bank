## 题目

**题目**：`weak_ptr` 本身不持有对象，它怎么知道对象已经被 `shared_ptr` 释放了？

**问**：weak_ptr 怎么知道 shared_ptr 已经把对象释放了？

## 口述答案

> 因为**控制块是共享的**。控制块里有两个计数：**强引用计数**（`shared_ptr` 个数）和**弱引用计数**（`weak_ptr` 个数）。
> 强计数归零时对象被析构，但控制块**要等弱计数也归零才释放**。`weak_ptr::lock()` 就是去读强计数：为 0 返回空 `shared_ptr`，否则原子地加一返回有效指针。

## 讲深一层

```cpp
std::weak_ptr<int> wp = sp;
if (auto p = wp.lock()) {        // 原子地"检查 + 提升"
    use(*p);
} else {
    // 对象已释放
}
```
- `expired()` 等价于 `lock() == nullptr`，但**单独用它再访问是不安全的**（检查和使用之间有窗口），必须 `lock()` 一次拿到 shared_ptr。
- 弱计数的作用：让 `weak_ptr` 能安全存在，同时控制块不提前释放。
- 控制块还存删除器、分配器，所以即使对象已销毁，删除器仍可用。

## 高频追问

1. **`weak_ptr` 能直接解引用吗？** —— 不能，必须先 `lock()`。
2. **控制块什么时候释放？** —— 强、弱计数都归零时。

## 易错点

- 先 `expired()` 再 `*wp`（有竞态）
- 以为 `weak_ptr` 会增加强计数
