## 题目

**背景**：tplink联洲（TP-Link 子公司）Java 岗三面的集合框架细节题。Stack vs Deque 是 Java 官方文档里点名的设计遗产问题——考的是「知不知道 Stack 类是历史包袱、以及为什么 Deque 接口是正解」，能引述 Javadoc 原文理由的候选人非常少。
**问**：为什么用 Stack？与 Deque 有何区别、为何更倾向 Deque？

## 口述答案

> 先说结论：Java 里要栈这种数据结构，官方自己都不推荐用 Stack 类，Javadoc 明确写着「应该优先用 Deque」——Deque<Integer> stack = new ArrayDeque<>()。理由我分三点讲。
> 第一，设计缺陷：Stack 继承自 Vector。Vector 是 JDK 1.0 的遗产类，所有方法带 synchronized。栈本来就是一个单线程场景为主的结构，锁在绝大多数时候是白付的代价；而真需要线程安全时，方法级 synchronized 也保护不了复合操作（先 peek 再 pop 两步之间照样有竞态），等于锁了个寂寞。这个继承还带来语义污染：Stack 是 Vector，意味着它继承了 get(int)、insertElementAt、remove(int) 这些随机访问和中间插入的方法——从栈中间插元素、按下标取第几个元素，这根本不是栈的操作，破坏了栈「只能操作栈顶」的语义约束。数据结构的价值就在于操作受限带来的不变量，继承把不变量打破了。
> 第二，Dequeue 的优势：Deque 是接口（double-ended queue，双端队列），ArrayDeque 是推荐实现。push/pop/peek 三个栈方法它都有（用栈顶视角用即可），此外既能当栈也能当队列（offerLast/pollFirst），API 设计干净；ArrayDeque 底层是循环数组，没有 synchronized，单线程性能比 Stack 高一个量级，内存也更紧凑。链表场景用 LinkedList（它也实现了 Deque）。
> 第三，什么时候「用 Stack」：一是遗留代码维护得兼容；二是面试手撕题里说一句「我用 Deque 模拟栈」反而加分；三是 LeetCode 语境下很多人写 Stack 只是习惯。另外要注意 java.util.Stack 与栈这个概念本身是两回事——单调栈、函数调用栈这些是概念，具体用什么容器实现都行。
> 一句话收尾：Stack 是 JDK 1.0 的历史包袱（同步开销、语义污染），Deque 加 ArrayDeque 是现代 Java 的正解——接口抽象干净、双端语义灵活、循环数组实现快。

## 讲深一层

- Vector/Hashtable/Stack 是 JDK 1.0 三件遗产：同步包装的设计后来被 ArrayList/Collections.synchronizedList/并发包取代——Stack 的替代路径正是「ArrayDeque（单线程）或 Deque 加外部同步/并发方案」。
- 方法级 synchronized 不能保证复合操作原子：check-then-act（if not empty then pop）在两把锁之间照样竞态，这是「同步类反而给假安全感」的经典案例。
- ArrayDeque 的循环数组细节：head/tail 双指针环形缓冲，扩容翻倍，无节点对象开销；LinkedList 每个元素一个 Node 对象，内存和缓存局部性都差一截——同为 Deque 实现也分高下。
- 语义污染的深层教训：继承是实现复用的强耦合，Effective Java「组合优于继承」的例证之一；栈如果真要线程安全版，也应该是组合 ArrayDeque 加显式锁。

## 高频追问

1. ArrayDeque 为什么快？——循环数组加无锁：数组内存连续缓存友好，没有 Node 包装对象，没有 synchronized；扩容均摊 O(1)
2. 需要线程安全的栈怎么办？——ConcurrentLinkedDeque（无锁 CAS，非阻塞）、或 ArrayDeque 自己加锁、或 BlockingDeque（LinkedBlockingDeque，阻塞语义）；按需要非阻塞还是阻塞选
3. 单调栈题用什么？——Deque<Integer> 或 int[] 手写栈都行；题目只关心栈顶，ArrayDeque 就够，面试手写数组栈更省事

## 易错点

- 只答「Stack 是栈、Deque 是双端队列，都能用」——没抓住考点：Stack 继承 Vector 的同步开销和语义污染才是「为什么不推荐」的根
- 说「Stack 方法级 synchronized 所以线程安全放心用」——复合操作不原子，peek 后 pop 之间照样有竞态，这是反向扣分
- 不知道 ArrayDeque，以为 Deque 只能配 LinkedList——ArrayDeque 才是官方推荐实现，LinkedList 是链表实现用于中间插删多的场景
