## 题目

**场景**：代码里一段 200 行的 if-else 在判断「用哪种算法/协议」。面试官问：**什么时候该上策略模式？工厂又负责什么？**

## 口述答案

> 两个模式解决的不是同一件事：**工厂解决「创建哪个对象」**，**策略解决「运行时用哪个算法」**，工程里常常是工厂造策略、调用方只依赖接口。
> 判断要不要拆，我看三条：
> 一是分支**会不会随业务持续增长**（每加一种协议就改一次主流程，说明该拆）；
> 二是每个分支**能不能独立测试/独立替换**（有状态、依赖外部资源，拆出来更好测）；
> 三是分支体量（几十行以上、还带嵌套）。
> 如果只有 2~3 个稳定分支、每个几行，直接 if-else 更清楚，硬拆反而增加跳转成本。

## 讲深一层

```cpp
struct Codec { virtual Bytes encode(const Frame&) = 0; virtual ~Codec() = default; };

// 策略：运行时选
std::unique_ptr<Codec> pick(Proto p);      // 工厂：按配置/协议号创建
Bytes out = pick(p)->encode(frame);        // 调用方不关心具体实现

// 轻量替代：分支只是函数，不必为每个建类
std::unordered_map<Proto, std::function<Bytes(const Frame&)>> table;
```

- 策略的代价：**类膨胀**、调用方需要知道有哪些策略、调试时多一层间接。
- 工厂的代价：新增类型要改工厂（开闭原则的经典破口），可用注册表 + 静态注册规避。
- 何时用 `std::function` 代替类：策略无状态、逻辑短、不需要继承层次时。

## 高频追问

1. **策略和状态模式的区别？** —— 策略由外部选择、策略之间不知道彼此；状态由对象内部状态驱动切换，状态之间会互相转移。
2. **怎么做到新增策略不改工厂？** —— 注册表：每个策略在静态初始化时把自己注册进 `map<string, Factory>`。
3. **虚函数开销大吗？** —— 一次间接跳转，通常可接受；热路径可用模板/CRTP 或 `std::variant` + `visit` 静态分派。

## 易错点

- 为了「用模式」而拆，结果 3 个分支变成 3 个类 + 1 个工厂，可读性更差
- 策略对象里塞了可变状态，多线程共享时出问题
- 工厂里用 `new` 返回裸指针，调用方忘了 delete

## 关联项目

- Linux 日志分析工具：关键词过滤、统计口径可以做成策略，新增一种统计不用改主流程
- 二维云台：不同舵机型号的脉宽换算可抽成策略，但型号只有两三种时直接表驱动更简单
