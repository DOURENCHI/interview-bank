## 题目

项目背景，为什么引入 Agent？

## 口述答案

> 先给约束再给理由：任务是**步骤不固定**的（比如排障要先探查环境、再选工具、再看结果决定下一步），固定流水线写死会非常脆弱；且需要调多个工具（检索、执行命令、查库），Agent 的 ReAct 循环能把"观察结果→决策下一步"交给模型。
> 同时说明代价与兜底：步数上限、工具白名单、关键动作人工确认，避免失控。

## 讲深一层

```text
固定 chain：输入 → 步骤1 → 步骤2 → 步骤3（编译期定死）
Agent：输入 → 规划 → 调工具 → 观察 → 再规划 → …（运行期决定）
```
判断标准只有一条：下一步做什么是否依赖上一步的结果。

## 高频追问

1. **不用 Agent 能怎么做？** —— 把高频路径固化成 chain，只有异常分支才进 Agent，成本和稳定性都更好。

## 易错点

- 只讲"Agent 很火"没有任务特征依据
- 不提兜底，被追问"模型乱调工具怎么办"就答不上
