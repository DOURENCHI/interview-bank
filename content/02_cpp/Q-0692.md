## 题目

**题目**：`std::bind(&Foo::bar, this, _1)` 和 `[this](int x){ bar(x); }` 功能一样。

**问**：`std::bind` 和 lambda 都能做绑定，为什么现在更推荐 lambda？

## 口述答案

> lambda 更**易读、易调试、类型安全**，而且没有 `bind` 的那些怪癖：参数求值时机、嵌套 `bind` 的 `std::placeholders` 冲突、重载函数无法直接绑定。
> 性能上 lambda 通常更好（编译器容易内联），`bind` 返回的对象类型复杂，容易生成难读的错误信息。

## 讲深一层

```cpp
struct Foo { void bar(int, double); int v = 0; };
Foo f;

// bind
auto b = std::bind(&Foo::bar, &f, std::placeholders::_1, 3.14);

// lambda（推荐）
auto l = [&f](int x) { f.bar(x, 3.14); };
```

| 维度 | `std::bind` | lambda |
|---|---|---|
| 可读性 | 差（占位符多） | 好 |
| 重载函数 | ❌ 无法直接绑定 | ✅ 可写清楚 |
| 参数求值时机 | 调用时（易错） | 显式决定 |
| 内联 | 较难 | 容易 |
| 嵌套 | `_1` 冲突 | 天然支持 |
| C++ 状态 | C++11 起可用，C++20 起 `bind_front` 更好 | 首选 |

**`bind` 的经典坑**：`std::bind(&Foo::bar, f, _1)` 传的是**对象副本**，调用的是副本的成员函数，修改不到原对象。必须写 `std::ref(f)` 或传指针。

**替代品**：C++20 的 `std::bind_front` 比 `bind` 简单安全（不支持重排参数，只支持前置绑定）。

## 高频追问

1. **什么时候还必须用 `bind`？** —— 需要重排参数顺序、或用 `_1` 做占位时；`bind_front` 做不到。
2. **lambda 能存进 `std::function` 吗？** —— 能，但有类型擦除开销。
3. **`bind` 传成员函数为什么要对象？** —— 成员函数需要 `this`，`bind` 把第一个参数当 `this`。

## 易错点

- `bind` 传对象副本，改不到原对象
- 嵌套 `bind` 的 `_1` 全部指向最外层
- 绑定重载函数时出现歧义
