## 题目

**题目**：知道对象里有 vptr，但怎么验证它真的指向 vtable、vtable 里的顺序又是什么？

**问**：怎么验证虚函数表在内存里的布局？

## 口述答案

> 把对象**前 8 字节**当成 `void**` 读出来，那就是 vptr；再把它当成函数指针数组，逐个调用并与成员函数地址比对。
> 顺序规律：**按声明顺序**，先基类后派生类；派生类覆写的槽位被替换成派生版本。

## 讲深一层

```cpp
struct Base { virtual void f(); virtual void g(); virtual ~Base(); };
struct D : Base { void f() override; };

D d;
void** vptr = *reinterpret_cast<void***>(&d);   // 取对象头部
using Fn = void(*)(void*);
reinterpret_cast<Fn>(vptr[0])(&d);              // 等价于 d.f()
```
- 用 `nm`/`objdump` 能看到 `vtable for D` 符号，地址与 `vptr` 一致。
- 多继承时对象里有**多个 vptr**（每个带虚函数的多重基类一个），`dynamic_cast` 需要做指针调整。
- 这些全是实现细节（Itanium ABI），面试可讲，代码里别依赖。

## 高频追问

1. **虚析构在 vtable 里占几个槽？** —— 通常两个（complete 和 deleting destructor）。
2. **`typeid` 信息存在哪？** —— vtable 前面（Itanium ABI 的 offset-to-top 和 typeinfo 指针）。

## 易错点

- 说"vtable 存在对象里"（存的是 vptr）
- 在 ARM/多继承场景下套用单继承的槽位假设
