## 题目

**题目**：

```cpp
int& bad() { int x = 1; return x; }
int& ok()  { static int x = 1; return x; }
```

**问**：`bad()` 为什么危险？返回引用什么时候才是安全的？

## 口述答案

> `x` 是局部变量，函数返回时它的生命周期就结束了，返回的引用指向**已销毁的栈内存**。调用方拿到的是一个悬垂引用，读写都是未定义行为——可能"看起来正常"，也可能被后续函数调用覆盖。
> 安全的情况只有三种：**返回静态/全局变量**、**返回成员变量**（对象还活着时）、**返回参数引用**（调用方保证生命周期）。

## 讲深一层

```cpp
int& bad()  { int x = 1; return x; }        // ❌ 悬垂
int& ok1()  { static int x = 1; return x; } // ✅ 静态存储期
int& ok2()  { static int x; return x; }
struct S { int v; int& get() { return v; } };  // ✅ 成员，对象活着就有效

const std::string& bad2() { return "tmp"; } // ⚠️ 临时量，返回后销毁
int&& rref() { return 1; }                  // ❌ 悬垂右值引用
```

| 返回类型 | 安全性 |
|---|---|
| `T&`（局部变量） | ❌ 悬垂 |
| `T&`（静态/全局） | ✅ |
| `T&`（成员） | ✅ 对象存活期间 |
| `const T&`（临时量） | ⚠️ 生命周期延长只在本函数内 |
| `T`（按值） | ✅ 拷贝，最安全 |

**为什么"看起来能跑"**：栈内存还没被覆盖，读到的是旧值。这类 bug 在加了日志、换了编译器、开了优化之后才暴露，极难排查。

**诊断手段**：`-fsanitize=address` 能直接报 `stack-use-after-return`；`-Wall` 会给 `-Wreturn-local-addr` 警告。

## 高频追问

1. **返回 `const T&` 绑定临时量安全吗？** —— 在**同一表达式**里安全（生命周期延长），但返回出去就悬垂。
2. **`std::string f()` 和 `const std::string& f()` 哪个好？** —— 前者靠 RVO 零拷贝且安全；后者容易悬垂。
3. **成员函数返回成员引用有什么风险？** —— 对象被销毁后引用悬垂；链式调用时尤其要注意。

## 易错点

- 返回局部变量的引用（或指针）
- 返回形参的引用（调用方传临时量时悬垂）
- 以为"能打印出来就是对的"
