## 题目

**场景**：`const int* p`、`int* const p`、`const int* const p` 三种写法，背了口诀还是容易记混。

**问**：「const 在 `*` 左边还是右边」这个口诀到底在说什么？三种写法各锁住了什么？

## 口述答案

> 口诀是"**const 在 `*` 左边，锁的是指向的内容；在 `*` 右边，锁的是指针自己**"。
> 三种分别是：指向常量的指针（能改指向，不能改内容）、常量指针（能改内容，不能改指向）、两者都不能改。

## 讲深一层

```cpp
int x = 1, y = 2;

const int* p1 = &x;   // 指向的内容不可改：*p1 = 3 ❌，p1 = &y ✅
int* const p2 = &x;   // 指针本身不可改：*p2 = 3 ✅，p2 = &y ❌
const int* const p3 = &x;  // 都不可改
```

| 声明 | 改 `*p` | 改 `p` | 读法 |
|---|---|---|---|
| `const int* p` | ❌ | ✅ | pointer to const |
| `int* const p` | ✅ | ❌ | const pointer |
| `const int* const p` | ❌ | ❌ | const pointer to const |

**更好的读法**：从右往左读。`const int* const p` → `p is a const pointer to const int`。

**为什么接口里常用 `const T*`**：表达"我只读，不会改你的数据"，同时能接受 `const` 和非 `const` 实参；反过来 `T*` 拒绝 `const` 实参。

## 高频追问

1. **`const` 成员函数里的 `this` 是什么类型？** —— `const T* const`，所以不能改成员变量（除非 `mutable`）。
2. **`const_cast` 能去掉 const 吗？** —— 语法上能，但如果原对象本身是 const，修改它是未定义行为。
3. **`constexpr` 和 `const` 区别？** —— `constexpr` 要求编译期可求值，`const` 只要求运行期不变。

## 易错点

- 口诀记反，`const int* const` 说成"都不能改"却写错位置
- 用 `const_cast` 修改真正的 const 对象
- 以为 `const` 指针不能传给非 const 参数（其实 `T*` 参数会拒绝 `const T*`）
