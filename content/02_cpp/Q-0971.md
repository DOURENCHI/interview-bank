## 题目

**追问**：**为什么这里需要 Agent？直接一次调用模型不行吗？**

## 口述答案

> 判断标准就一条：**任务能否预先写死步骤**。能写死的用固定流水线（一次调用或 chain），成本可控、结果稳定；**步骤依赖中间结果、无法预先确定**的才需要 Agent——让模型自己规划、调用工具、根据观察决定下一步。
> 我项目里的例子：解析一份未知格式的日志，可能要先探查结构、再选解析器、再修复字段——每步怎么做取决于上一步结果，这种"边走边看"的任务用 Agent 合理；而"把这段文本翻译成英文"就完全不需要。
> Agent 的代价也要说：多次调用成本翻倍、路径不可复现、可能死循环，所以我的实现里加了最大步数和超时兜底，关键步骤落盘可回放。

## 讲深一层

```text
Chain:   输入 → [步骤1 → 步骤2 → 步骤3] → 输出     （步骤编译期定死）
Agent:   输入 → LLM 规划 → 工具调用 → 观察结果 → 再规划 → … → 输出
```

追问会朝"怎么防失控"走：最大迭代次数、工具白名单、每步结果校验、全程 trace。能主动讲这些说明真做过。

## 高频追问

1. **Agent 和 Function Call 什么关系？** —— Function Call 是 Agent 的手脚（单轮能力），Agent 是循环调度框架。
2. **怎么评测 Agent 好坏？** —— 端到端任务成功率 + 步数/成本，不能只看单步对错。

## 易错点

- 为用而用 Agent——面试官反问"这步为什么不用固定流程"就露馅
- 没有兜底设计，答不出"模型抽风了怎么办"
