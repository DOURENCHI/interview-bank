## 题目

**追问**：**如果我要建立只读映射，mmap 的参数应该怎么传？**

## 口述答案

> 三处配合：
> ```c
> int fd = open("a.bin", O_RDONLY);          /* ① fd 以只读打开 */
> char *m = mmap(NULL, sz,
> PROT_READ,                   /* ② 保护位只读 */
> MAP_SHARED, fd, 0);
> ```
> 关键约束：**PROT 与 open 的 flags 不能矛盾**——fd 是 `O_RDONLY` 却给 `PROT_WRITE|MAP_SHARED`，mmap 直接 `EACCES` 失败。`MAP_SHARED` 只读映射也可以（映射是共享的，但页面无写权限，写会 SIGSEGV）。

## 讲深一层

写被拒的两种层次要分清：**权限层**（PROT_READ 页写触发 SIGSEGV，进程级）和 **文件层**（映射时 inode 以只读打开，压根不允许建共享写映射，mmap 返回 EACCES，调用期）。

只读映射的典型用途：加载配置/模型文件、程序代码段；配合 `madvise(MADV_SEQUENTIAL)` 还能提示内核预读。

## 高频追问

1. **MAP_PRIVATE + PROT_WRITE 打开只读 fd 行不行？** —— 行，COW 私有副本随便改，不回写文件。
2. **mmap 之后 fd 能不能马上 close？** —— MAP_SHARED 映射建立后可以 close，映射仍有效。

## 易错点

- 只答 PROT_READ，忘了 fd 打开方式必须匹配——这是最常见的 EACCES 来源
- 以为只读映射必须 MAP_PRIVATE
