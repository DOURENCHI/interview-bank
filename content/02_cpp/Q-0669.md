## 题目

**场景**：多个线程同时对同一个 `shared_ptr` 做拷贝和析构，程序偶发崩溃。

**问**：`shared_ptr` 的引用计数存在哪？为什么它「本身」不是线程安全的？

## 口述答案

> 引用计数存在**堆上的控制块**里（和对象分开），和 `shared_ptr` 对象本身是两处内存。
> 计数操作是原子的（`atomic`），所以**多个线程各自持有一份 `shared_ptr` 副本**时，拷贝/析构是安全的。但**同一个 `shared_ptr` 对象被多个线程读写**（比如一个线程 `reset()`、另一个线程拷贝它）不是安全的——因为 `shared_ptr` 对象本身（两个指针：对象指针 + 控制块指针）的读写不是原子的。

## 讲深一层

```
shared_ptr<T> ──┬→ 对象 T
                └→ 控制块 { 强引用计数, 弱引用计数, 删除器 }
```

| 场景 | 安全 |
|---|---|
| 每个线程有自己的 `shared_ptr` 副本，指向同一对象 | ✅ |
| 多线程读写**同一个** `shared_ptr` 对象 | ❌ 需要加锁 |
| 多线程 `shared_ptr<const T>` 只读 | ✅（C++20 起有原子特化） |
| 修改所指对象的内容 | ❌ 需自己加锁 |

```cpp
// ❌ 危险：两个线程操作同一个 sp
std::shared_ptr<Foo> sp = ...;
// 线程 A: sp.reset();
// 线程 B: auto copy = sp;      // 数据竞争

// ✅ 安全：各持一份
void worker(std::shared_ptr<Foo> local) { ... }
```

**为什么控制块要单独分配**：为了支持"对象已销毁但 `weak_ptr` 还在"的状态；`make_shared` 会把对象和控制块合并成一次分配（更快，但 `weak_ptr` 存活时对象内存不能释放）。

## 高频追问

1. **`make_shared` 比 `shared_ptr<T>(new T)` 好在哪？** —— 一次分配（对象 + 控制块连续），少一次 malloc，缓存更友好。
2. **`weak_ptr` 怎么影响释放？** —— 强计数为 0 时对象析构，弱计数为 0 时控制块释放。
3. **C++20 的 `atomic<shared_ptr>` 是什么？** —— 提供原子操作，解决"同一个 `shared_ptr` 跨线程读写"的问题。

## 易错点

- 以为 `shared_ptr` 整体线程安全
- 多线程 `reset` 同一个 `shared_ptr`
- 用 `shared_ptr` 传参却不必要地增加原子操作开销（用 `const T&` 更好）
