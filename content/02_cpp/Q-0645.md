## 题目

**题目**：

```cpp
struct S { S(){cout<<"ctor";} S(const S&){cout<<"copy";} };
S make() { return S(); }
int main() { S s = make(); }
```

**问**：C++17 下这段输出什么？复制省略省掉的是哪一次拷贝？

## 口述答案

> 只输出 `ctor`，一次拷贝都没有。C++17 起这是**保证的**（不是优化）：`S()` 直接构造在 `s` 的位置，`return` 和初始化都不产生临时对象。
> 省掉的是**两次**：函数返回时的临时对象拷贝、以及用它初始化 `s` 的拷贝合并成零次。

## 讲深一层

| 场景 | C++14 | C++17 |
|---|---|---|
| `S s = S();` | 通常省略（不保证） | **保证**省略 |
| `S s = make();` | 可能省略 | **保证**省略（纯右值） |
| `return std::move(x);` | 阻止省略 | 仍阻止，且更糟 |
| 具名返回值 NRVO | 可能省略 | 不保证，但编译器普遍做 |

```cpp
S s = make();          // C++17：零拷贝
S s2 = std::move(s);   // 一次移动（不是省略）
S make2() { S x; return x; }   // NRVO，多数编译器省略，但标准不保证
```

**关键区分**：
- **纯右值（prvalue）** 的复制省略在 C++17 是**语言规则**，即使拷贝构造被删除也能编译；
- **具名返回值（NRVO）** 仍是优化，标准不保证。

**为什么 `return std::move(x)` 反而更慢**：它把 `x` 变成右值，阻止了 NRVO，强制一次移动构造。

## 高频追问

1. **为什么 C++17 能让拷贝构造被 delete 也编过？** —— 因为根本没发生拷贝，不要求拷贝构造可用。
2. **什么情况下不会省略？** —— 返回的是函数参数、或者返回不同类型的转换。
3. **`-fno-elide-constructors` 有什么用？** —— 关闭省略，用来观察到底发生了几次拷贝（教学用）。

## 易错点

- 认为复制省略只是"编译器优化"，不知道 C++17 已标准化
- 写 `return std::move(x)` 以为能加速
- 依赖 NRVO 写必须拷贝的代码
