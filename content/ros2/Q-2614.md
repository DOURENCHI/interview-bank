## 题目

**现象**：实验室里两台同型号机器人同时开机，结果一台的指令发出去，另一台也跟着动。查了代码，话题名写的是 `/cmd_vel`。

**问**：为什么会串？ROS2 里怎么隔离，命名空间和重映射各自起什么作用？

## 口述答案

> 因为两台机器在**同一个 ROS_DOMAIN_ID**，又都往同一个绝对话题 `/cmd_vel` 发。ROS2 的话题名是全局的，同名就通，跟机器在哪无关。
> 隔离有两层手段：**命名空间**（`/robot1/cmd_vel` 与 `/robot2/cmd_vel`，靠 launch 里的 `namespace` 或 `__ns` 参数）和**domain id**（彻底分成两个逻辑网络）。命名空间解决逻辑分组，domain 解决物理隔离。

## 讲深一层

```bash
# 方式一：启动时给命名空间
ros2 run my_pkg my_node --ros-args -r __ns:=/robot1

# 方式二：话题重映射（只改一个话题）
ros2 run my_pkg my_node --ros-args -r /cmd_vel:=/robot1/cmd_vel

# 方式三：彻底隔离网络
export ROS_DOMAIN_ID=11     # 另一台用 12
```

launch 里更常用：
```python
Node(package='my_pkg', executable='my_node',
     namespace='robot1', remappings=[('cmd_vel', 'cmd_vel')])
```

| 手段 | 作用范围 | 适合场景 |
|---|---|---|
| 命名空间 | 节点内所有相对话题 | 多机器人、多实例 |
| 重映射 | 单个话题 | 对接第三方包、接口改名 |
| domain id | 整个 DDS 网络 | 同网段多套系统互不干扰 |

**关键区分**：`/cmd_vel` 是**绝对名**，命名空间对它无效；`cmd_vel` 是**相对名**，会拼上节点命名空间。代码里写死绝对名，是串号的最常见原因。

## 高频追问

1. **怎么确认自己发到哪个话题了？** —— `ros2 node info /节点名` 看订阅和发布列表，比看代码可靠。
2. **`__ns` 和 `-r __ns:=` 有什么区别？** —— 前者是命令行参数语法，后者是 remap 规则语法，效果一样，`-r` 形式更通用。
3. **多机同名话题一定会串吗？** —— 同 domain、多播可达就会；不同 domain 或 `ROS_LOCALHOST_ONLY=1` 就不会。

## 易错点

- 代码里写死绝对话题名，还以为命名空间能救
- 用 domain id 隔离后忘了改回来，排查时「什么都看不到」
- 只改发布端没改订阅端，一半通一半不通
