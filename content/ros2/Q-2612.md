## 题目

**场景**：系统里同时存在 `/opt/ros/humble` 和两个自建工作空间 `ws_a`、`ws_b`，三处都有 `my_nav` 包。启动后发现跑的不是最新改的那份。

**问**：ROS2 是怎么决定「用哪个包」的？source 顺序为什么会影响结果？

## 口述答案

> 靠环境变量 `AMENT_PREFIX_PATH` 的**顺序**决定优先级，**后 source 的排在前面**，先被找到。
> 所以先 `source ws_a` 再 `source ws_b`，用的就是 `ws_b` 里的。这就是 overlay 机制：后 source 的覆盖前面的。
> 排查用 `ros2 pkg prefix my_nav`，它直接告诉你实际用的是哪个路径。

## 讲深一层

```bash
source /opt/ros/humble/setup.bash
source ~/ws_a/install/setup.bash
source ~/ws_b/install/setup.bash     # 最后 source，优先级最高

ros2 pkg prefix my_nav               # 实际加载路径
echo $AMENT_PREFIX_PATH | tr ':' '\n'    # 完整优先级列表
```

| 概念 | 含义 |
|---|---|
| underlay | 底层环境（如 `/opt/ros/humble`） |
| overlay | 叠加在上面的工作空间 |
| 覆盖规则 | 后者优先，同名包被遮蔽 |

为什么要这样设计：允许在不改系统 ROS 的前提下覆盖某个包（打补丁、试新版本），这是 ROS 生态快速迭代的基础。

副作用：overlay 叠多了环境会不可预测。工程上的做法是**每次开终端只 source 一条固定的链**，写进 `.bashrc` 或用统一的 `env.sh` 管理；调试时先 `ros2 pkg prefix` 确认，再怀疑代码。

## 高频追问

1. **`--symlink-install` 和这个有关系吗？** —— 有，它让 install 目录里是指向源码的软链接，改了立刻生效，减少「改了没生效」的误判。
2. **怎么彻底避免混淆？** —— 用 `--packages-select` 精确编译，用独立终端或容器隔离不同工作空间。
3. **`ros2 run` 找不到包怎么办？** —— 先看 `AMENT_PREFIX_PATH`，再看 `install/` 里是否真有那个包，最后确认有没有 `COLCON_IGNORE`。

## 易错点

- 认为「装了就在用」，不查 `ros2 pkg prefix`
- 在同一终端反复 source 不同工作空间，环境越叠越乱
- 改了代码没重新编译，却去怀疑系统缓存
