## 题目

**场景**：`view_frames` 出来是 `map → odom → base_link`。有人问，里程计已经能给出 `odom → base_link` 了，为什么不让里程计直接发布 `map → base_link`，少一层不是更简单？

**问**：这多出来的一层 `map → odom` 到底在起什么作用？

## 口述答案

> 因为里程计**会漂，而且漂得连续**；地图**是全局正确的，但会突然跳**。两者性质相反，必须分开存放。
> `odom → base_link` 由里程计发布，保证**短时间连续、不跳变**，控制环依赖它；`map → odom` 由定位或 SLAM 发布，是一个**缓慢修正量**，把漂移一点点拉回来。SLAM 需要纠正时只改 `map → odom`，`base_link` 在 odom 系里的位姿完全不动，机器人的运动估计就不会突跳。

## 讲深一层

```
map ──(定位/SLAM 修正，可跳变)──> odom ──(里程计，连续但漂移)──> base_link ──(静态)──> laser
```

| 变换 | 发布者 | 特性 | 谁依赖它 |
|---|---|---|---|
| map → odom | SLAM / 定位 | 低频、可跳变、全局正确 | 导航、路径规划 |
| odom → base_link | 轮式里程计 / VIO | 高频、连续、会累积漂移 | 局部控制、避障 |
| base_link → 传感器 | static_transform_publisher | 恒定不变 | 感知 |

**如果合并成一层会发生什么**：

1. SLAM 每一次回环检测都要改 `map → base_link`，机器人在图上会**瞬移**；
2. 局部控制器用的是这个变换，输出会突跳，实车表现就是抖一下、甚至急刹；
3. TF 树里 `base_link` 的父节点被 SLAM 抢走，里程计就没法发了（一个 frame 只能有一个父）。

**所以这层不是冗余，是"把连续量和跳变量分离"的标准做法。** 单靠里程计的系统（没有地图）可以不要 map 层；一旦有全局地图，这层就必须存在。

## 高频追问

1. **没有 SLAM 只有里程计，还需要 map 吗？** —— 不需要。TF 树可以是 `odom → base_link → sensors`，导航用 odom 当全局系即可。
2. **为什么不用 `map → base_link` 加一个平滑滤波？** —— 平滑会引入滞后，而定位要的是"尽快收敛"；分层是更干净的解耦。
3. **`map → odom` 断了会怎样？** —— 导航节点查 `map` 到 `base_link` 直接抛异常；常见于 SLAM 没启动或定位丢失。

## 易错点

- 说"多一层是为了兼容"，讲不出连续量与跳变量的区别
- 认为 `map → odom` 是固定值（它是缓慢变化的）
- 忘了每个 frame 只能有一个父节点这个硬约束
