## 题目

**背景**：医院影像科的 CT / MR / X 光片子都是 DICOM 格式，一个检查动辄几百个文件。

**问**：一个 `.dcm` 里除了像素，还存了什么？为什么不能直接用 PNG 或 JPEG？

## 口述答案

> 一个 DICOM 文件是**像素 + 一整套元数据**。元数据里最关键的是三组：
> 空间信息（像素间距、层厚、图像位置、方向余弦）——没有它就无法把 2D 切片还原成 3D 体；
> 灰度映射（如 CT 的 RescaleSlope / RescaleIntercept）——没有它就无法把存下来的整数还原成 HU 值；
> 以及患者、设备、采集参数等临床信息。
> 用 PNG 只能存像素，这些全丢了，图片就不能用于测量和定位。

## 讲深一层

| 类别 | 关键字段 | 丢了会怎样 |
|---|---|---|
| 空间 | PixelSpacing、SliceThickness、ImagePositionPatient、ImageOrientationPatient | 无法重建 3D、无法量尺寸 |
| 灰度 | RescaleSlope、RescaleIntercept | 无法还原 HU，窗宽窗位失效 |
| 临床 | PatientID、StudyInstanceUID、SeriesNumber | 无法归档、无法关联 |
| 采集 | KVP、ExposureTime、ConvolutionKernel | 无法做质控与复现 |

一个 CT 序列通常按 `SeriesInstanceUID` 归组，按 `InstanceNumber` 或 `ImagePositionPatient` 排序。

## 高频追问

1. **DICOM 是单文件还是目录？** —— 单切片单文件，一个序列是几百个文件的集合；也有封装成多帧的格式。
2. **怎么读？** —— Python 用 pydicom，C++ 用 DCMTK / GDCM，ITK 也能读。
3. **压缩过怎么办？** —— JPEG Lossless 等传输语法要先解码，pydicom 需要额外插件。

## 易错点

- ❌ 把 DICOM 当「带标签的图片」 —— 元数据是核心，不是附属
- ❌ 忘了 Rescale —— 直接读像素值当 HU，窗宽窗位全错
- ✅ 说清「空间 + 灰度 + 临床」三类元数据各自的作用
